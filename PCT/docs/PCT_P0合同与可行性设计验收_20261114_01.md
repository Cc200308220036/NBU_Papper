## 公共链路和模型合同

数据认证 → 容量 1 派生任务 → 封闭配置和 Schema → 公共到货和候选 → 容量 1 公开上下文 → 保存选择 → 精确 v3 选后监测 → 公共提交或停止 → journal 和恢复 → 完整分母与账目。

容量 1 时仍有多位置决策。真实状态继续由 `run_episode`、`buffer_state` 和 `commit_physical` 维护。新协议采用精确版本注册和延迟加载。扩展缺失时，旧协议沿现有路径加载，新协议报告 `PCT_B1_EXTENSION_MISSING`。跨目录提案列出九处路由候选，其中候选构造现有版本拼接可复用，额外改动收敛到公共池绑定所需的位置。公共提交可通过已注册的版本、Schema、上下文及监测直接消费新记录，留待 P1-B 验证。[跨目录提案](../outputs/PCT_P0_CONTRACT_20261114_01/external_changes.json)

第三方环境会在候选阶段做虚拟稳定检查，执行时重新确定落箱高度。已放箱第 7 槽连续环境写零，离散环境写 density。原分布模块会修改全局 Torch 类，随机选择路径会给 padding 加极小概率。PCT 适配器仅对公共候选评分，几何版保留叶节点容器高度 H，承载版使用实际动作顶面和公共质量、承载特征。真实提交的姿态取自公共 mapping。严格 mask 与原生 padded 行为的差异单列，原生一致性比较限定同权重、全有效输入的概率、价值和梯度。[字段、接口和反例](../outputs/PCT_P0_CONTRACT_20261114_01/p0_contract.json)

P3 冻结 `NEW_00100027_controlled_base` 和 `NEW_00100090_controlled_heterogeneous`，共 33 箱、6 个本地 job，最多 99 次监测、66 次网络选择推理。承载版小步训练上限为 16 次订单尝试、264 个动作、2 次更新。正式设计为两版各用 11、23、37 三个训练种子，最终选 epoch 125，每模型 2,000 次订单尝试、33,000 动作上界、250 次更新。A2C 使用实际分段长度处理末段，singleton 保留奖励和 critic 学习，单独计其训练价值前向。比较矩阵为 22 × (1 + 3 + 3 + 3) = 220 槽，Jev 请求上界 1,284。P4-C 的首个请求属于已有的 r0 槽位。此规格当前无发送准入。
