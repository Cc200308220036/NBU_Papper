## 实现、实际效果与公开入口

PCT内新增persistence、recovery、saved模块及三个封闭Schema。`pct_b1_recovery_execution_v1`是独立恢复准入，绑定完整任务、配置、job及身份，限定构造、geometry_b1和零网络请求。没有放宽旧`pct_b1_constructed_execution_v1`的resume=false，旧P1-B入口带resume仍拒绝。现有b1检查点格式不变，恢复授权由新permit与journal链提供，不借training_fork或旧Schema扩容。

journal为连续编号、不可覆写的记录文件，每条包含完整检查点、前序摘要、检查点摘要和记录摘要。写入顺序是同目录临时文件→文件fsync→原子rename→目录fsync，避免检查点文件与另一个HEAD指针分步更新的窗口。同job归档目录使用POSIX非阻塞flock，争用返回JOB_LOCK_CONTENDED；锁文件inode保留，不通过删除锁文件解除锁。

原公共run_episode仍是唯一订单循环。episode.py仅传递已获准的resume、复用DECISION_READY事实、避免重复保存阶段及保留监测事实，并处理跨进程未知连续耗时。monitor.py将新协议的保存检查点交给PCT验证器。候选ID与精确位置、选后独立副本监测和原commit_physical均复用。公共提交中的原一致性检查仍可能在私有副本重算公开事实，这不是重新生成候选或覆盖已保存决策。

恢复前检查所有journal链、阶段推进、原选择/候选/监测绑定及提交账目，再核对当前源码、原物理/算法文件、解释器二进制、依赖版本、HiGHS/NumPy二进制和依赖RECORD。不会重签旧检查点迁就源码变化。

提交前另存commit intent。若intent存在但没有对应的已保存COMMITTED记录，返回COMMIT_OUTCOME_UNKNOWN，保留证据而不猜测重试。若COMMITTED已保存，只是intent尚未清理，恢复只清理intent并继续后续记账，不重复提交。该限制是对保存不确定窗口的明确停单，不声称覆盖所有外部设备或断电事务。

新CLI分别为：

```bash
PYTHONPATH=PCT/src:semantic_pallet_planner/src "$NBU_PY" -m pct_baseline.cli prepare-recovery --task <构造任务.json> --output <新任务目录>
PYTHONPATH=PCT/src:semantic_pallet_planner/src "$NBU_PY" -m pct_baseline.cli resume-recovery --run <任务目录>
PYTHONPATH=PCT/src:semantic_pallet_planner/src "$NBU_PY" -m pct_baseline.cli verify-saved --run <任务目录>
```

前两个入口是明确受限的业务准备/恢复；verify-saved只消费保存事实，不选择、不生成候选、不执行订单、不调用transport或LP，也不修改归档。它验证阶段链、Schema/摘要、公开事实与精确动作映射、监测凭证、独立副本上的原物理检查与账目重建、终止原因和已保存summary。离线验证不要求本机源码身份等于归档身份；实际恢复另行执行当前身份核对，二者不能混淆。
