旧train_model先恢复最近initial/update的批首RNG；BatchController跳过已存attempt，却没有恢复采集完成后的状态。旧选择记录与整单结果也没有结果绑定的post-RNG。仅恢复权重、避免重跑，并不能保证后续随机抽样位置相同。

RNG记录均保存Python random、NumPy MT19937（含位置/高斯缓存）和Torch CPU完整状态。协议限CPU，CUDA已初始化时拒绝，沿用CPU模型/环境约束，不默默遗漏其他设备RNG。验证使用独立局部发生器，无全局随机抽样；恢复直接set_state，不通过额外抽样追赶。

## 恢复合同与所有权

独立版本为 `pct_p4b_rng_resume_v3`、`pct_p4b_rng_wal_v3`、`pct_p4b_state_v3`；operation/selection/job/attempt结果各自使用v3标记。公共配置/执行扩展仍为已注册v2，Store压缩/原子事务载体不变；新恢复语义显式记录在job header、训练Store identity与记录版本中，不放宽旧公共Schema或增加公共注册。

每个RNG envelope带规范摘要、Store身份绑定、owner游标、result摘要、pre与post。生产Store身份包含源码/依赖/配置/数据/策略相关身份或其header摘要，具体owner再绑定决策context、policy或完整attempt slot。两层摘要同时保留，文件容器未损坏也不能随意换结果、游标或策略。

| 边界 | 所有权及保存点 | 恢复规则 |
|---|---|---|
| initial/update | 模型、Adam、全部适用RNG、policy、游标及batch引用原子发布；RNG二进制载荷新增v3标记 | load恢复更新边界；不得从旧格式无标记载荷猜状态 |
| batch-start | 固定策略与计划policy标签绑定，保存批首完整RNG | 当前状态须与批首一致；已存attempt必须为连续前缀；同一controller重复消费同一batch拒绝 |
| attempt-pre/result | collector调用前保存pre；完成结果与post在同一不可变记录发布，owner含attempt/next_attempt/slot摘要 | 跳过保存结果前校验pre、结果、策略、源码绑定并直接恢复post；不调用collector推进随机数 |
| operation | 调用前INTENT保存完整pre；返回值、result摘要和post同一op-end记录发布 | 有唯一已完成operation时复用返回值和post；缺end、失败或owner多义停止，不重推理 |
| decision/selection | 决策pre绑定did/context/policy；选择记录绑定结果及post | 选择记录存在则恢复post并记实际reuse；op-end已存但selection未发布可无前向重建选择记录 |
| WAL阶段 | RNG与checkpoint/events引用在同一fsync/不可变WAL记录发布；owner含序号、阶段、前序记录摘要 | READY/DECISION_READY/SELECTED/MONITORED/COMMITTED从最后保存阶段的RNG开始；验证历史选择不回退到历史RNG |
| job-result | checkpoint/summary摘要与post同记录保存；pre引用最后WAL状态 | 整单结果复用恢复其post后才返回，之后attempt-result接管外层状态 |

WAL是边界快照，因此其pre=post；它不冒充某个操作的调用前后状态。恢复按唯一durable tail确定阶段，而不是按时间猜“最近一次随机数”。Session入口只接受已知保存边界的状态；source/结果/状态缺失或漂移时停止。消费器拒绝重复推进；同一选择结果在同一post位置重复读取可幂等返回，但若后续已消费随机数，再用旧结果回退会被拒绝。

Session.start/end记录恢复引用、起止RNG摘要、消费引用与实际post消费数。计划复用仍只在planned_reuses，实际调用/返回/结果保存/操作结果复用/选择复用/监测与提交复用分别记账。恢复不增加实际前向或collector次数。构造进程退出点设在第N个attempt结果**原子发布之后、下一collector之前**，避免把未完成回调伪称完成。
