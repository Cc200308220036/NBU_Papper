日期为 2026-11-13。适用工程为 `NBU_Papper`，工作分支为 `dev/PCT`，文档版本为 `PCT-plan-v1`。

本文供后续窗口按阶段实施。用户本轮授权覆盖源码审查与方案编写。开发、依赖安装、权重下载、训练和真实 Jev 实验按照后续指定阶段执行。方案中的模块、Schema、命令与实验参数均为拟议设计，当前实现状态见第 2 节。

## 1. 目标、交付范围与研究问题

目标是在现有包装订单上建立可审计的 PCT 学习基线，与 Jev 无经验方法及公共几何启发式比较。统一缓冲容量为 1，箱体保持直立，允许 0/90 度旋转。各方法共用到货协议、公共候选器、原物理检查、精确位置静态监测、提交、恢复及评价口径。

最终交付包含以下内容。

1. 可加载现有两类数据的容量 1 派生运行视图。
2. 复用公共订单循环的独立版本协议，以及 PCT 几何特征版和包装承载特征扩展版。
3. 可复现的第三方集成、网络一致性检查、训练与模型选择记录。
4. 容量 1 下重新运行的现有任务比较矩阵、逐单结果、完整失败分母及成本。
5. 支持新窗口恢复工作的阶段收据、身份清单和验收报告。

需要回答的研究问题分别为以下三项。

| 编号 | 问题 | 所需证据 |
|---|---|---|
| Q1 | 在相同当前候选集合中，PCT 学习策略与 Jev 的位置选择表现如何 | 同协议、同订单的完整轨迹比较，统一公开信息权限 |
| Q2 | 显式加入质量和包装承载特征后，PCT 适配基线是否发生变化 | 两个 PCT 版本按相同数据、训练预算与种子执行 |
| Q3 | 结论在什么数据范围成立 | 训练内复测、熟悉原型组合诊断、独立留出来源分别给出证据 |

本方案采用公共候选池适配路线，论文方法名包含 `PCT-adapted`。容量 1 实验研究放置策略。容量 3 选箱与 T/E 经验研究沿原有阶段合同继续管理。本方案的首轮方法集合见第 10 节。

## 3. 接入架构与跨目录依赖

### 3.1 公共状态的唯一维护路径

```text
冻结原始任务 + 容量 1 执行规格
                 |
          新派生运行任务
                 |
          公共 run_episode
                 |
       公共到货与 CandidateProvider
                 |
        新容量 1 公开上下文
          /         |          \
      几何评分    PCT 适配     Jev Choice
          \         |          /
           保存同一种选择结果
                 |
         精确位置选后监测 v3
                 |
      公共 commit_physical 或停单
                 |
        检查点、账本与完整订单指标
```

真实状态由 `run_episode`、`buffer_state` 和 `commit_physical` 维护。PCT 模型是无状态候选评分器，其输入从本次公开决策重建。容量 1 下当前箱体成功提交后再接收下一箱。当前箱体失败时订单按相应原因终止。

公共候选为当前几何、原支撑及面积分载检查合格动作。候选可包含尚未通过精确静态监测的动作。网络可以使用公共面积分载派生事实，精确静态监测在保存选择后执行。

### 4.2 派生运行视图

拟议 `derive_task` 输入原冻结任务及独立执行规格，输出容量 1 运行任务。输出包括以下身份。

| 身份字段 | 内容 |
|---|---|
| `parent_data_identity` | 原数据包身份 |
| `parent_task_sha256`、`parent_task_digest` | 文件字节摘要与规范化 JSON 摘要 |
| `execution_spec_digest` | 容量 1、候选合同、旋转和运行版本 |
| `derived_task_digest` | 新任务完整内容摘要 |

完整订单以 `arrival_order` 排列。检查它与 item ID 一一对应，既有运行投影 `items` 的排序与其一致。规划器逐步接收箱体，选择器可见当前 pending、已放箱体和当时到货状态。完整计划箱数、后续尺寸、剩余序列、来源 key、订单 ID 及参考轨迹均不进入网络或 Jev 请求。结束流信号按公共引擎实际 EOS 事件给出，保持相同事件顺序。

### 5.2 原生参考检查与实现缺陷

原生检查在 `PCT/outputs/` 的独立工作副本与独立进程执行，输出路径全部指向该目录。先修复已发现的 evaluation 语法问题，再逐项检查运行时问题。

- 原生评价强制 CPU/GPU 与 `num_processes` 的实际约定。
- `shuffle` 与 `LNES` 传参是否被环境真正消费。当前连续环境初始化直接设 `self.LNES='EMS'`，命令行字段传入不等于参数生效。
- `LoadBoxCreator` reset 游标及追加大箱 sentinel 的行为。正式任务以真实 EOS 结束，sentinel 只属于原生参考检查。
- 原生 candidate 的第 6 个几何字段写入容器高度 H。论文文字和 tools 注释中的箱体顶面说明需结合实际生产代码解读。
- `evaluate=True` 参数影响注意力屏蔽数值，与 `.eval()`、`deterministic=True` 分别核对。
- 原分布采用 padding 后概率重归一化，随机路径含 epsilon。新实现应确保 padding 概率为零，空池由引擎终止。

原生网络核验使用隔离进程保存参考张量与输出。相同结构和权重在全有效候选 fixture 上比较概率、价值、argmax及梯度。建议 float32 容差为绝对 `1e-6`、相对 `1e-5`，接近并列时比较概率误差并采用事前定义的 tie-break。padding 修复引入的差异单列反例。

原生完整论文成绩复现所需训练数据、权重或条件缺失时，标记该项 `NOT_RUN` 或 `PARTIAL`，同时交付具体缺口。架构与前向/梯度一致性、适配版训练与实验有各自独立验收。后续论文按完成范围描述复现程度。

## 6. 网络输入、动作与算法适配

### 6.1 公共候选的动作语义

公共候选已经包含 pick item、中心 x/y、底面 z、yaw、朝向尺寸与 ID。对当前唯一 pending 箱生成的每个候选建立一个叶节点。

`leaf_index → candidate_id → candidate_digest → exact pose → display_label` 完整保存。以公开 context 的展示映射顺序编码候选，训练采样由单独 RNG 驱动。全方法使用同一事前冻结的展示种子，既有显示逻辑随各自状态产生确定性排列。概率并列时取最小有效叶索引。

不对候选做网络外重排、原生稳定性筛选或最近位置匹配。对称箱产生的动作身份按公共候选原有去重结果处理，姿态仍从 mapping 读取。空池、单候选、多候选分别进入公共停止、自动执行和选择路径。

沿用每箱 TopK 16、联合上限 48 的原候选配置，容量 1 下实际最多 16 个动作。首版网络叶容量暂定 16，若审查发现实际候选可超过 16，先修订冻结合同并重验。原始任务内容与 candidate manifest 绑定。

### 6.2 坐标与无损几何编码

容器底面中心是公共坐标原点。对于候选朝向尺寸 `(l,w,h)` 和中心底面姿态 `(x,y,z)`，PCT 角点坐标为

```text
x0 = x - l/2 + container_length/2
y0 = y - w/2 + container_width/2
z0 = z
x1 = x0 + l
y1 = y0 + w
z1 = z0 + h
```

转换包含容器原点平移和箱体中心到角点平移。现有 `pose_from_corner` 只处理箱体中心差，不能单独完成上述全部转换。

使用 `Lref=max(container_length, container_width, container_height)` 归一化几何，保留 float64 转换计算，网络使用 float32。动作始终从原始 mapping 读取。验证负中心坐标、非整数毫米、紧贴边界、z 接触、对称尺寸、90 度和正反转换。

节点上限冻结为本计划所有任务的最大完整箱数，当前 22 任务为 40。已放节点建议容量 40，并保留原生空托盘的零值有效上下文节点约定。该占位不增加已放箱数、体积或质量。未来引入超过 40 箱的新留出任务时，更新模型结构身份并按可变节点一致性验证结果确定权重能否复用。

### 6.3 几何特征版 `pct_adapted_geo_v1`

保留 PCT 的三类独立 MLP、图注意力、全局聚合、候选指针和 critic。

| token | 输入字段 | 维度 |
|---|---|---:|
| 已放箱体 | 实际角点 `(x0,y0,z0,x1,y1,z1)/Lref` | 6 |
| 候选叶 | `(x0,y0,z0,x1,y1,H)/Lref` 与两个保留零槽 | 8 |
| 当前箱 | `[1/Lref,0,0,sort(l,w,h)/Lref]` | 6 |

该几何版遵循所核对连续环境的原生字段约定。当前箱第 1 槽保留原生名义密度常量 1 经全局归一化后的数值，它没有表达当前箱的实际质量。叶节点顶部 H 与实际箱体顶面通过 mapping 分开保存。mask 另行传入，布尔位不参与几何归一化。原生 9 槽打包适配时使用 `normFactor=1`，避免重复缩放。

已放节点、叶节点和当前箱的有效掩码单独维护。全有效 fixture 应通过原生网络一致性检查。几何版可见特征子集记录在方法卡中，公共载荷过滤与监测依然使用真实质量和承载。

### 6.4 包装承载特征版 `pct_adapted_load_v1`

为当前任务提供能够显式利用质量和承载的学习对照，保留 PCT 的注意力和候选指针核心，扩展三个输入 MLP 的维度。从头训练并独立命名，权重结构不与几何版混用。

首版特征采用下面的明确合同。质量标尺 `Mref=9 kg`，沿用既有训练包装标尺，按配置冻结。字段缺失一律报错，NA 使用显式适用位。

| token | 输入字段 | 维度 |
|---|---|---:|
| 已放箱体 | 实际角点 6维、mass/Mref、stackable、capacity/Mref、current_top_load/Mref、remaining_top_load/Mref | 11 |
| 当前箱 | 原顺序 `(l,w,h)/Lref`、mass/Mref、stackable、capacity/Mref | 6 |
| 候选叶 | 实际角点 6维、support_ratio、com_margin/Lref、resulting_max_height/Lref、max_after_area_load_utilization、min_affected_remaining/Mref、affected_support_applicable | 12 |

`max_after_area_load_utilization` 按该候选的公开 `load_changes` 与箱体容量计算。`min_affected_remaining` 取承载发生正增量的已放箱体的剩余承载最小值。落地候选没有受影响箱体时，两个聚合值记 0，适用位记 false。容量为 0 的分母通过适用性与公共物理检查处理。不得用任意 epsilon 伪造可承载性。

例如，10 kg 当前箱均匀分载到两个承托箱，二者顶部原载荷均为 0、承载上限分别为 27 kg 与 9 kg，则两个 after load 为 5 kg，最大利用率为 `5/9`，最小剩余为 `4 kg`，适用位为 true。该数字例用于验证公开特征计算，实际运行以已保存的公共 `load_changes` 为准。

这些量来自原面积分载账本和公开候选派生事实。精确静态内核输出、反力、未选动作的监测标签与后续订单信息不参与特征。

首版不添加额外手工策略排序、辅助预测头或经验检索。特征采用固定缩放，不用测试分布重新估计均值或分位数。超出训练范围的值按原数值保留并记录，禁止未经登记的裁剪。

### 6.5 网络、概率与推理

- 初始结构沿原代码默认采用 embedding 64、图注意力层数 1、head 1、tanh clipping 10，critic 为全局上下文上的线性输出。全部结构值写入模型 manifest。
- 对有效候选 logits 做 masked softmax，padding 概率严格为 0，输出必须有限且和为 1。没有有效候选时返回引擎空池状态。
- 训练按分布采样，评价使用 argmax。`.train()`/`.eval()`、attention mask 路径、device、dtype 与 tie-break写入配置。
- 单候选由公共循环自动执行，既不计网络决策，也不计真实模型请求。
- 本地 `inference`、远程 `request`、单候选自动执行分别计数。PCT 的本地推理耗时及训练消耗随实验报告。

## 7. 完整订单、持久化与训练采集

### 7.1 拟议可调用接口

以下均须新实现或显式桥接后才可调用。

```python
derive_task(parent_task, *, execution_spec, parent_identity) -> dict
build_config(*, derived_task, method, model_manifest, run_spec) -> dict
encode_decision(context, *, model_manifest) -> EncodedDecision

```

`EncodedDecision` 包括三类 token、mask、叶索引映射与输入摘要。`run_job` 调用同一公共 `run_episode`。训练选择器与评价选择器共用特征和动作映射，只由冻结配置决定采样或 argmax。

### 7.2 阶段与恢复

执行保存顺序为 `READY → DECISION_READY → SELECTED → MONITORED → COMMITTED/TERMINATED`。每个阶段带 job、decision、前序 journal 摘要和运行身份。

| 恢复位置 | 行为 |
|---|---|
| READY | 读取当前状态并执行下一公共事件 |
| DECISION_READY | 复用已存公开状态、候选与 mapping，校验权重和 RNG 后选择 |
| 本地推理完成但 SELECTED 尚未保存 | 用该决策保存的 RNG 状态与同一模型确定性重建，追加恢复计数 |
| SELECTED | 读取已保存精确选择，执行尚缺监测 |
| MONITORED | 读取已保存结果，按状态提交或停止 |
| COMMITTED | 追加尚缺终结记录，使用已提交状态继续 |
| 远程 SENDING/UNKNOWN_SEND | 记录实际发送不明并停止任务，保留后续矩阵未运行 |

JSON/二进制写入采用临时文件、原子替换及内容摘要，复用现有 exclusive 锁，单 job 单写者。训练快照保存模型、optimizer、RNG、采样位置、已采集 batch 和已完成 update ID。每次 optimizer update 以同一快照原子保存权重与 update ID，恢复时使用保存的更新边界。

权重、特征、父/派生任务、候选器、监测、代码或依赖身份变化时拒绝旧运行恢复。新解释器路径变化是否属于环境变化，由 P0 的环境合同按版本与二进制身份定义。

### 7.3 监测与失败

新协议显式冻结 `pct_exact_pose_network_v3`，通过 `stability.monitor.exact_freeze` 与 `kernel_interface` 路由，保存算法源码摘要及依赖环境。

STABLE 后调用公共提交。UNSTABLE、UNASSESSABLE、ERROR 分别停止。失败箱留在缓冲，已装统计不增加。监测异常和原物理提交异常保留独立技术类别。原面积分载与静态反力分别记录。

自然终止允许完成、空池和预测失稳。不可评价单列并继续保留矩阵分母。默认出现网络非法输出、技术异常、身份漂移、未知发送或 watchdog 时停批并交付诊断，固定剩余 job 标记未运行。是否对确定为任务几何边界的不可评价继续后续 job，在正式计划中预先登记。

### 7.4 训练轨迹复用公共循环

训练时让权重在一次 batch 采集期间固定，运行完整订单收集保存的公开决策、精确动作、监测、提交和终止。策略梯度只在采集结束后更新。无需为训练另写物理 step 引擎。

每个采集 batch 保存独立 policy snapshot ID 与权重摘要，所属订单的 config 绑定该快照。optimizer update 后的新订单绑定新快照，已经保存的训练订单仍指向原快照。最终模型 manifest 引用全部训练快照链，历史配置摘要保持可核验。

每个有物理动作的决策形成一条 transition，包含选择或 singleton、提交奖励、下一公开决策和终止标记。WAIT/EOS 事件串入相邻 transition。singleton 的 actor loss 权重为 0，critic 与回报保留该步收益。空池结束时不对空候选网络前向，其 done 附着于前一个有效 transition。全单没有选择动作时仍计订单结果与采集成本。

训练使用分片存储避免每个更新反复复制完整历史。每条 transition 能定位公开 context、选择、监测及前后状态摘要。正式评价保存完整逐阶段 journal，训练分片保留可验证的状态转移和更新输入。保存量与磁盘容量在 P3 实测后写入预算。

技术失败轨迹记录在训练尝试分母，停批诊断。自然空池和预测失稳是有效训练终止。训练达到预算时在完整订单边界结束，临时采集截断必须保留 truncated 标志并正确 bootstrap。

## 8. 训练目标与模型选择

### 8.1 首版优化器选择

本方案选择上游已提供的 A2C 路径作为首版适配训练器，优化器用 Adam。上游默认 ACKTR 的 KFAC 与旧版本依赖留作后续可选复现项目。方法卡登记 `PCT-adapted + A2C`，并保留相对上游默认优化器的差异。

采用相同策略与 critic、n-step return 以及 actor/critic 损失。一个 batch 先采集 8 个完整订单，保持策略版本固定，再将轨迹按 n=5 分段计算回报并进行一次更新。每个 transition 参与损失一次。bootstrap 的下一个状态价值由本次采集权重计算，terminal 截断后续回报。

```text
r_t = 10 × 本次成功提交箱体积 / 固定容器体积
G_t = sum(k=0..n-1, gamma^k × r_(t+k)) + gamma^n × V(s_(t+n))
A_t = G_t - V(s_t)
L_actor = mean_over_choice_steps(-stop_gradient(A_t) × log pi(a_t|s_t))
L_critic = mean_over_valid_steps((G_t - V(s_t))^2)
L = L_actor + L_critic
```

失稳或物理拒绝时提交体积为 0，订单终止。gamma=1 时累计提交奖励与固定容器利用率成正比。相同订单内它与装入体积比例单调一致。训练各任务的奖励尺度随总体积需求变化，任务采样权重需公开。训练目标暂不添加高度、质量奖励或后验综合权重。

首版 entropy 系数为 0，保持所读上游训练损失的行为。记录 entropy 曲线以诊断探索情况。批量中没有 choice 时 actor loss 取有定义的 0，critic 正常训练。loss、梯度或概率出现非有限数立即停批。

### 8.2 拟议冻结参数与预算

以下参数用于使下一窗口有明确首版，均属于方案制定选择。P0/P3 若发现实际数值或计算问题，应在正式冻结前出具理由和新配置。正式训练后更改参数须使用新 experiment ID。

| 项目 | 首版值 |
|---|---|
| 训练数据 | 现有 16 包装任务，保持 4 层完整 |
| 遍历 | 每 epoch 每任务 1 次，任务顺序用 seed+epoch 的哈希排列 |
| 训练种子 | 11、23、37 |
| 模型 | 几何版与承载版各 3 个，合计 6 个模型 |
| 训练轮数 | 每模型 125 epochs，即 2,000 个完整订单尝试 |

### 9.4 P3 验收与限定范围

固定任务为 `NEW_00100027_controlled_base` 和 `NEW_00100090_controlled_heterogeneous`，合计 33 箱。PCT 两版使用 seed=0 的明确随机初始化工程权重，几何启发式共用同一配置，共 6 个本地 job，最多 99 次选后监测。两版网络推理最多 66 次，实际 singleton 另计。

训练小步检查最多 16 个完整订单尝试，仅使用上述两任务交替各 8 次、承载版、seed=0，batch 8，最多 2 次 optimizer update、264 个动作。损失和梯度须有限，更新前后参数摘要改变，奖励与公共提交体积一致，保存/恢复 optimizer 后结果符合冻结数值约定。该权重仅供工程诊断。

- B30 六个 job 均可审计，包含自然失败和技术类别，指标由保存布局重算。
- B31 两次小步更新及恢复正确，技术错误有明确记录，随机/小步权重标签清楚。
- B32 统计监测次数、推理次数、时延、峰值内存与保存量，得到正式运行资源估计。
- B33 若发现零 choice 或候选覆盖不足，报告原固定任务观测并分析原因。后续覆盖构造由新计划登记，不为追求收益替换本轮任务。

## 10. 实验矩阵与执行顺序

### 10.1 方法集合

| 方法 ID | 运行规则 | 当前任务中的职责 |
|---|---|---|
| `geometry_b1` | 复用 `baseline_label(...,'shared_geometry')` 评分与 tie-break | 公共确定性对照 |
| `pct_geo_b1` | 几何版，三个训练 seed 的最终权重，argmax | PCT 架构几何适配基线 |
| `pct_load_b1` | 承载版，同样三个 seed 的最终权重，argmax | 当前包装任务的物理特征学习基线 |
| `jev_none_b1` | 真实 Jev，空 memories，三个独立重复槽位 | 用户方法的无经验比较 |

固定顺序仅用于构造回归。T/E 经验、其他 LLM、GOPT 和容量 3 对照可通过后续独立计划加入。

### 10.2 现有任务诊断矩阵

| 分层 | 任务数 | geometry | PCT 几何 | PCT 承载 | Jev | 合计 job |
|---|---:|---:|---:|---:|---:|---:|
| 包装训练内复测 | 16 | 16×1 | 16×3 | 16×3 | 16×3 | 160 |
| 熟悉原型组合诊断 | 6 | 6×1 | 6×3 | 6×3 | 6×3 | 60 |
| 合计 | 22 | 22 | 66 | 66 | 66 | 220 |

上述 22 任务总计 428 箱，Jev 正式请求理论上界为 `428×3=1,284`。PCT 本地网络选择上界为 `428×3×2=2,568`。自动单候选与停单会减少实际数目。每个槽位最多每个计划箱一次选择发送，逐 job 与全局余额均须保存。

P4-C 的最多 1 个请求计入 `NEW_00100027_controlled_base` 的 Jev 重复槽位 r0，P4-D 从其保存状态接续。若该协议试验已发送但技术失效，保留该槽位失效状态，额外重复需新计划。P3 随机权重本地实验独立归档。

Jev 重复槽位 r0/r1/r2 与训练 seed 11/23/37 属于不同随机机制。按任务先分别平均三次结果，再比较方法均值。只有同步同前缀反事实才具有动作因果解释。

运行顺序由 P4-A 固定。首任务 block 为 `NEW_00100027_controlled_base`，其 `jev_none_b1/r0` 作为 P4-C 的首个槽位。随后按任务为 block，对其余方法/seed/repeat 使用固定 seed 的哈希排列。完成首任务 block 后，按同样冻结规则接续剩余 blocks。技术停批后不以已观察成绩改顺序或换任务。

### 10.3 来源与独立评价

16 任务参与 PCT 训练，其复测报告为训练内表现。6 个合成组合已经在历史项目中暴露，共享原型，报告为现有组合诊断。本方案首次对照采用固定最终 epoch，六组合的结果不用于权重选择。

独立评价后续可沿已审查的真实来源路线，或公开声明的合成留出路线开展。先冻结来源组件、暴露记录、生成规则和样本选择，再物化任务。独立留出的任务与新权重选择不得交叉。

独立评价建议先以每档 14—20、21—30、31—40 箱各 2 个组件构成至少 6 个不同组件的可行性先导。该数量用于先导，正式样本量根据来源级配对方差、目标效应和资源确定，不能将 6 个组件自动称为统计充分。试验结果不得用于反复调整正式提示、权重或数据种子。

本机历史来源合格准入数为 0。独立留出阶段的接口可完成，实际数据缺口保留。现有任务完整诊断可按授权继续交付。

## 11. 指标、统计与结果解释

### 11.1 指标定义

| 指标 | 计算 |
|---|---|
| 完整完成、稳定完整完成 | 全部计划箱已提交，稳定完整完成还要求所有提交动作的监测为 STABLE |
| 件数/体积/质量装入比例 | 已提交量除以完整计划量，包含未到货部分的分母 |
| 固定容器利用率 | 已提交体积 / `(L×W×Hmax)` |
| 垛高 | 已提交箱体顶面最大 z，空布局按 NA 记录用于布局比较 |
| 垛高包络利用率 | 已提交体积 / `(L×W×实际垛高)`，空布局为 NA，沿既有指标合同 |
| 紧致三维包围盒利用率 | 如新增，采用实际 dx×dy×dz 并独立版本化，首轮可记 NOT_IMPLEMENTED |
| 监测可评价覆盖 | `(STABLE+UNSTABLE)/已选动作数` |
| 首次预测失稳进度 | 按既有监测指标合同，已提交与失败尝试分别记录 |
| 终止与技术状态 | 完成、空池、预测失稳、不可评价、技术异常、取消、未运行等完整计数 |
| 时延 | 候选、特征、推理/远程等待、监测、提交、IO、整单分段及 p50/p95、样本数 |
| 成本 | Jev 请求/失败/未知发送、token与可得费用，本地推理次数、训练时长、设备和可得能耗 |

面积账本剩余承载按原定义记录，解释为当前约束资源。PCT 反力单列诊断。GPU与CPU延迟比较注明设备、batch size、预热、同步及计时边界。训练成本和推理成本分别报告，本地模型成本按可得计量记录。

### 11.2 配对与汇总

沿用已有 `jev_branch_comparison_rule_v2` 的分层思想并在新整单比较 Schema 内冻结具体实现。主比较依次考虑稳定完整完成、体积装入比例、件数/质量关系及装入等价时的垛高/包络。完整原值和反向次要指标均保留。

技术无效 job 对不按部分布局排名，原诊断数值可保留。不可评价作为独立类别单列。失败和未运行进入整个矩阵的完整分母，同时报告有效策略比较的分母。

包装数据先在原始来源内等权汇总四个变体，再按保守来源组件汇总。组件只含部分相关来源时按实际关系图处理。合成六任务给出任务级描述和共享原型说明，不把箱体、决策、训练 seed 或 Jev 请求当独立来源。

主要对比为 `pct_load_b1 - jev_none_b1`，补充为 PCT 两版差、各学习方法相对 geometry。方向在计划内固定，所有正负差值保留。现有组件很少且已暴露，首轮以逐任务表和描述统计为主。独立来源足够时按来源组件做配对区间估计，模型/重复嵌套在来源内，事先登记统计程序与多重比较处理。

### 11.3 论文中的方法表述

论文列出原 PCT 作者代码版本、三类 token、图注意力、候选指针、公共候选替换、精确监测、A2C训练和包装特征扩展。几何版与承载版各有方法卡与消融关系。

可支持的结论按实际完成范围书写，包括容量 1 的公共候选选择比较、已暴露任务的描述性结果，以及独立留出完成后的相应泛化证据。容量 3 经验增益、原生论文成绩复现、真实坍塌率与全局最优性各有自己的证据要求。

## 12. 拟议运行入口与阶段操作

下列命令是需要开发的 CLI 合同，当前不可执行。后续实现 `--help`、参数校验与实际入口后，在阶段报告中给出最终命令。示例均在仓库根运行，`python` 指向后续核验过的环境解释器。

```bash
python -m pip install -e PCT

python -m pct_baseline.cli inspect --repo . --output PCT/outputs/P0_INSPECTION

python -m pct_baseline.cli prepare-data \
  --spec PCT/configs/data_b1_v1.json --output PCT/outputs/DATA_B1_V1

python -m pct_baseline.cli validate-data --dataset PCT/outputs/DATA_B1_V1

python -m pct_baseline.cli prepare-smoke \
  --dataset PCT/outputs/DATA_B1_V1 --output PCT/outputs/P3_SMOKE_PLAN

python -m pct_baseline.cli run-local \
  --plan PCT/outputs/P3_SMOKE_PLAN/plan.json --job-id JOB_ID

python -m pct_baseline.cli prepare-training \
  --dataset PCT/outputs/DATA_B1_V1 --spec PCT/configs/training_v1.json \
  --output PCT/outputs/P4_TRAIN_PLAN

python -m pct_baseline.cli train \
  --plan PCT/outputs/P4_TRAIN_PLAN/plan.json --model-id MODEL_ID

python -m pct_baseline.cli prepare-evaluation \
  --spec PCT/configs/evaluation_known_v1.json --output PCT/outputs/P4_EVAL_PLAN

python -m pct_baseline.cli run-job \
  --plan PCT/outputs/P4_EVAL_PLAN/plan.json --job-id JOB_ID

python -m pct_baseline.cli resume-job \
  --plan PCT/outputs/P4_EVAL_PLAN/plan.json --job-id JOB_ID

python -m pct_baseline.cli verify-saved --run PCT/outputs/RUN_ID

python -m pct_baseline.cli analyze \
  --plan PCT/outputs/P4_EVAL_PLAN/plan.json --output PCT/outputs/P4_ANALYSIS
```

安装时还需定位现有 planner 依赖的实际导入方式。运行参数、凭证来源及执行授权以新协议的配置和任务收据绑定，CLI 示例不含密钥。inspect、validate-data、verify-saved 与 analyze 保持无 transport 的边界，verify-saved 不调用网络、选择器或 LP。

## 13. 阶段产物、交接和窗口启动

每阶段交付位于 `PCT/outputs/<阶段标识>/`，阶段报告位于 `PCT/docs/`。至少保存以下文件。

| 文件 | 必要内容 |
|---|---|
| `acceptance.json` | 本阶段每个验收 ID 的状态、证据路径及范围 |
| `handoff.json` | 完成单元、实际接口、下一阶段入口、剩余缺口、停止原因 |
| `delivery_manifest.json` | 本交付文件路径与 SHA256 |
| `commands_and_results.json` | 实际命令、解释器、退出码、范围和日志位置 |
| `identity.json` | 主工程/第三方/适配源码、数据、Schema、模型、依赖、算法身份 |
| `limitations.json` | 未运行、未实现、未知、数据暴露和论文结论边界 |

P4 额外保存逐 job ledger、逐阶段 journal、请求/响应原件、模型与优化器检查点、训练曲线、分层 metrics、配对结果、方法差异卡和可复现命令。费用不可得填 UNKNOWN，CPU/GPU消耗按实际可测项目报告。

新窗口启动时执行以下步骤。

1. 确认工程为已有 `NBU_Papper`、分支为 `dev/PCT`，检查用户和其他窗口的工作区修改。
2. 阅读根 AGENTS、`PCT/README.md`、本文以及最近实际完成阶段的验收与 handoff。
3. 核对前置阶段逐项状态，读取对应实现与 manifest。区分报告声明、代码、归档和本次复验。
4. 按用户指定阶段完成实现、必要验证、报告和交接。新阶段验收以实际范围为准，不要求历史全量重跑。
5. 达到该任务停止条件后交付。正式执行中的技术停批按计划保存完整分母，恢复范围由剩余槽位和已有授权决定。

可直接交给新窗口的首个任务为 P0。该任务应交付可应用的接口与跨目录范围设计、解释器/依赖方案、两版特征及实验冻结规格，并列明尚需实施的补丁。按用户后续指定阶段继续开发。
