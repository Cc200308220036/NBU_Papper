# O4属性观测与公共/私有隔离协议

版本：`o4_request_v1`。范围：A/B离线核心；不含整单提交、缓冲状态或正式图像验收。

## 字段与来源

| 字段 | 来源与约束 |
|---|---|
| object_id | 一对一映射V1 item_id，场景内唯一；不携带源订单ID |
| mass_kg、dimensions_mm、fragile、weight_class、stackable | 只读复制原箱体事实，分别用于质量/几何、条件筛选和物理检查 |
| cargo_category | electronics保留对应类别；general来源通过种子与SHA256确定性派生food/glassware/household_cleaner/general |
| packaging.reinforced | 独立摘要位派生准确加固事实，不自动改变承载 |
| labels.no_top_load、labels.max_top_load_kg | 独立摘要位派生，非负有限kg；禁压不从类别推导，标签限载与物理限载分开 |
| physical_top_load_limit_kg | 精确映射原top_load_limit_kg_synthetic；不得修改旧stackable或物理限载以预过滤业务答案 |
| placed_objects | 已码对象准确事实及pose、oriented_size_mm；单位mm，底面中心坐标系 |
| available_objects | 仅当前已到货未码箱，A/B单箱长度≤1；不含虚构码放位姿 |

属性为仿真派生，不声称工业测量。无A/B抽象业务组；字段白名单不允许旧product_category与新cargo_category混用。禁压标记和限载数值均保留；业务说明未启用的标签不自动生成规则。

## 绑定和可见性

公共请求包括request_id、container、units、placed_objects、available_objects、instruction_text、images和三种摘要。state_hash绑定容器和两组对象；instruction_digest绑定完整文本；observation_digest绑定除request_id和自身之外的全部请求字段。JSON以UTF-8、键排序、紧凑序列化和禁止NaN/Inf方式求SHA256。

响应使用o4_response_v1，必须精确回显request_id及三种摘要。语法合法但过期的响应仍拒绝。闭合schema拒绝未知字段；对象ID重复、朝向尺寸不符、属性物理限载与原值不符均拒绝。

公共构造函数只接受真实当前状态、属性侧表和文本，不接收整个场景、未来顺序或参考AST。侧表即使包含后续对象，序列化时也只索引实际已到货ID。来源、split、原始案例关联、规则参考与候选答案保存在private/，不进入编译请求。候选集合不输入编译器，只在编译之后执行和评价。

images仅规定path和sha256元数据及离线附件传递。A5正式渲染/图像事实一致性未验收；模拟附件不代表实际视觉模型已调用。缓冲专用协议留待O4-F，不向当前版本增加占位字段。

## 数据交付

固定种子20261021，选择train中排序靠前的12个独立来源。每来源两个固定决策状态，共24个依赖锚点、72对/144条固定记录；12×6配置的72个整单任务仅定义、不执行。来源/模板/反事实均为development，不作为未见test。复现时输出到新目录，禁止覆盖V1或已有实验。
