# 测试数据集设计（最小完整版本 V1）

## 1. 目标与边界

本文档定义一个可复现、可扩展的最小语义三维码垛数据集，用于后续构建：

> GOPT/EMS-style几何候选生成 + VLM高层候选决策 + ReMe动态程序性经验记忆。

实验逐步扩展为：

1. 真值状态三维规划与固定决策点评测；
2. Gazebo物理仿真；
3. RGB-D感知；
4. Aubo i5 + MoveIt 2机器人闭环验证。

第一版只制作前三个算法模块需要的任务、候选、隐藏标注和连续任务流，不预先生成RGB-D图像、机械臂轨迹或ReMe记忆内容。

`/home/cyw/aubo_ros2_ws`仅作为后续验证平台，复用Gazebo、Aubo模型、吸盘、MoveIt 2、RGB-D和ROS 2框架。正式数据集不继承其原有单层区域、箱体尺寸、固定箱体高度或单层目标函数。

## 2. 最小研究问题

1. EMS/GOPT能否为多SKU、多高度箱体生成高质量三维合法候选？
2. 候选相同时，VLM能否根据自然语言选择语义更合适的候选？
3. ReMe能否利用历史经验改善后续决策，并在规则变化时修正过时经验？
4. 从真值状态切换到物理、感知和机器人执行后，性能损失来自哪个环节？

V1不追求覆盖所有仓储业务。

## 3. 任务定义

### 3.1 固定三维空间

每个场景的码垛空间是固定的轴对齐长方体：

```text
Container = (length, width, max_height, max_payload)
```

V1主容器采用MixedPalletBoxes论文的基准空间：

```text
P1210-H085 = 1200 mm × 1000 mm × 850 mm
```

几何泛化可选容器：

```text
P1208-H085 = 1200 mm × 800 mm × 850 mm
```

容器Z边界固定为`[0, max_height]`；变化的是SKU高度及堆叠后的放置高度。

### 3.2 箱体、姿态与Z坐标

V1箱体均为刚性长方体，长宽高和质量不同，只允许直立并绕竖直轴旋转：

```text
yaw ∈ {0°, 90°}
```

候选动作为完整三维位姿`(x, y, z, yaw)`：

```text
z_base   = support surface height
z_center = z_base + box_height / 2
z_base + box_height <= container.max_height
```

底层`z_base=0`，上层`z_base`为有效支撑面顶部高度。VLM只能选择候选ID，不能修改坐标或朝向。

### 3.3 在线到货

- `buffer_size=1`：主实验，严格在线，只能放当前箱体；
- `buffer_size=3`：扩展实验，可从当前3个箱体中选择；
- `buffer_size=-1`：仅作未来离线上界，V1暂不生成。

`buffer_size=3`的候选必须同时确定`pick_item_id + placement pose`。不支持选箱的原始GOPT只能参加`buffer_size=1`主实验。

### 3.4 单步可见状态

```text
container
placed_items
available_items
buffer_size
instruction_text
past_execution_summary（仅允许历史信息）
```

未来未到达箱体、隐藏规则、参考计划和当前答案不可见。

## 5. 几何、商品与属性

### 5.1 避免SKU概念混淆

```text
geometry_id：规范化(length, width, height)三元组
article_id：BED-BPP商品身份，仅用于生成和分组
item_id：场景内匿名箱体ID，模型可见
```

完整数据保留所有通过清洗的真实尺寸。后续Gazebo/Aubo可通过K-Medoids选约24种代表性几何，但只作为抽样索引，不替换主数据。模型不得看到来源订单和商品ID。

### 5.2 V1属性

| 字段 | 来源 | 作用 |
|---|---|---|
| `length_mm/width_mm/height_mm` | BED-BPP | 三维几何 |
| `mass_kg` | BED-BPP | 承重和重心 |
| `weight_class` | 训练集质量分位数 | 语言软规则 |
| `material` | MixedPalletBoxes-derived | 属性生成中间变量 |
| `fragile` | MixedPalletBoxes-derived | 语义标签 |
| `stackable` | MixedPalletBoxes-derived | 物理硬约束 |
| `top_load_limit_kg_synthetic` | MixedPalletBoxes-derived | 合成顶部承重约束 |
| `product_category` | SPB受控合成 | `general/electronics`业务规则 |

`top_load_limit_kg_synthetic`不声称是真实工业抗压测量值。

### 5.3 属性不得混用

- `fragile=true`不自动等于`stackable=false`；
- `stackable=false`禁止作为其他箱体的直接支撑；
- `top_load_limit_kg_synthetic`决定允许的数值载荷；
- `fragile`主要用于自然语言规则；
- `electronics`只有当前指令要求时才影响决策。

同一`geometry_id`必须对应多种属性组合，防止模型通过尺寸猜标签。

### 5.4 偏差审计

属性按`source_article_id`确定性生成，种子由`dataset_seed`与其SHA-256摘要确定。必须统计：

- 尺寸与`fragile`、顶部承重的相关性；
- 重量与`electronics`的相关性；
- `geometry_id`与语义标签的分层比例或互信息；
- 材料与易碎/可堆叠分布；
- 各约束实际改变候选可行性或排序的激活率。

`electronics`按尺寸和重量分层采样，避免集中在特定几何或质量区间。

## 6. 约束与动态规则

### 6.1 通用物理硬约束

1. 容器边界；
2. 三维不重叠；
3. 允许旋转方向；
4. 支撑面积比例不低于`0.70`；
5. 重心投影位于支撑区域或支撑凸包；
6. `stackable=false`箱体不能作为直接支撑；
7. 传播后的载荷不超过`top_load_limit_kg_synthetic`；
8. 配置时，总载荷不超过容器上限。

共同支撑时按底面重叠面积比例向下传播载荷，并保存支撑有向图。

### 6.2 最小动态业务规则

| 规则 | 含义 | 默认性质 |
|---|---|---|
| `heavy_low` | 重物优先位于较低位置 | 软规则 |
| `heavy_center` | 重物尽量靠近底面中心 | 软规则 |
| `fragile_protect` | 易碎品尽量不承载其他箱体，并优先放在较高层 | 软规则 |
| `category_group` | 指定类别尽量集中 | 软规则 |
| `category_separate` | 指定类别避免接触或上下支撑 | 可配置硬/软 |

`non_stackable`和顶部承重属于通用物理约束，不作为VLM语言能力的主要测试规则。负载平衡、优先装载、目的地和标签朝外延后。

每个规则集保存标准指令、两条人工检查的同义改写和隐藏结构化真值。结构化真值至少包含`rule_type`、`target_attribute`、`priority`、`hard_or_soft`和阈值参数。模型只能看到自然语言。

软规则必须转换为范围固定的`[0,1]`分项得分，并在配置中冻结计算公式。多条软规则按隐藏真值中的优先级进行字典序比较；不要为不同实验临时调整权重。

### 8.3 过滤与Top-K审计

至少保存拒绝原因计数：

```json
{
  "rejection_histogram": {
    "out_of_bounds": 12,
    "overlap": 18,
    "insufficient_support": 15,
    "overload": 8,
    "non_stackable_support": 4
  }
}
```

通用物理约束在返回前过滤；动态业务规则不能使用隐藏真值提前过滤。

Top-K应覆盖不同高度、中心/边缘、支撑关系及可选箱体，不能只保留相似的几何高分候选。

非平凡语义决策点标记为：

```json
{"semantic_decision_required": true}
```

其定义为：至少两个物理合法候选的隐藏语义效用显著不同，且几何最优不等于语义最优。

## 9. 三层数据结构

### 9.1 Scenario Set

保存初始容器、箱体、顺序和指令，用于完整在线Rollout。不同方法可产生不同后续状态。

### 9.2 Decision Case Set

保存固定中间状态和统一候选集，用于公平比较选择器：

```json
{
  "decision_case_id": "DC_00124",
  "base_scenario_id": "SCN_0031",
  "step_index": 4,
  "placed_items": [],
  "available_items": [],
  "instruction_text": "...",
  "candidate_set_id": "CSET_..."
}
```

Decision Case由参考策略和少量扰动策略Rollout自动采集，不人工标注坐标。隐藏标注使用`decision_case_id`关联，不在可见样本中提供标注路径或标注ID。

### 9.3 Memory Stream Set

保存有序场景引用和规则变化事件，基础数据不预写记忆：

```json
{
  "stream_id": "STREAM_SHIFT_007",
  "stream_type": "policy_shift",
  "memory_reset_group": "RESET_007",
  "episodes": [
    {"episode_index": 0, "scenario_id": "SCN_001", "policy_version": "P1"},
    {
      "episode_index": 6,
      "scenario_id": "SCN_021",
      "policy_version": "P2",
      "change_event": "electronics_group_to_separate"
    }
  ]
}
```

## 10. 配对、场景族与ReMe流

```json
{
  "scenario_family_id": "FAM_001",
  "pair_group_id": "PAIR_001",
  "variant_id": "canonical_instruction",
  "stream_id": null,
  "split_group_id": "GROUP_001"
}
```

- `scenario_family_id`：同类几何/语义任务族；
- `pair_group_id`：相同容器、箱体和顺序，仅指令、缓存或记忆条件变化；
- `variant_id`：无规则、标准指令、同义改写或规则变化；
- 同一pair、family和stream整体划分，不能跨split。

同一基础几何场景至少支持无规则、标准指令、同义改写和真实规则变化四种用途。

### 10.1 两类最小任务流

- `Stationary Stream`：规则不变，几何变化，测试经验复用；
- `Policy-Shift Stream`：中途由P1改为P2，测试负迁移、重写和恢复。

严格时序：

```text
检索历史记忆 → 当前决策 → 记录结果 → 获得反馈 → 写入/重写记忆
```

必须分开报告：

- `Frozen Memory`：获取后冻结，测试只读；
- `Online Refinement`：每条流从同一快照开始，episode结束后更新。

## 11. 数据划分与泄漏控制

| 子集 | 改变内容 | 保持不变 |
|---|---|---|
| ID | 新订单、新顺序 | 几何、属性、规则分布 |
| Geometry-OOD | 保留的尺寸簇、比例或高度区间 | 规则类型 |
| Semantic-OOD | 未见属性组合，如`fragile+electronics` | 单个属性均已见 |
| Language-OOD | 未见模板和句式 | 结构化规则相同 |
| Policy-Shift Stream | 规则/优先级随时间变化 | 流接口 |

原Instruction Shift拆成Language-OOD和Policy-Shift。

必须先划分来源池，再生成场景：

- ID订单互斥，允许几何和商品重现；
- Geometry-OOD保留几何簇不得进入训练；
- Semantic-OOD保留组合不得进入训练；
- Language-OOD模板族不得用于训练；
- 完整pair/family/stream只能属于一个split；
- ReMe检索键不能含场景、订单和商品唯一ID。

## 12. Baseline与消融

### 12.1 Track A：几何规划

严格在线、无业务规则，比较EMS启发式、原始/适配GOPT及其他几何排序器。

### 12.2 Track B：固定候选语义选择

所有方法使用相同缓存Candidate Set：

| 方法 | 语义输入 | 记忆 |
|---|---|---|
| Geometry-only | 无 | 无 |
| Oracle-Rule | 结构化真值 | 无 |
| VLM | 自然语言 | 无 |
| VLM+Frozen Retrieval | 自然语言 | 只读 |
| VLM+ReMe | 自然语言 | 检索、写入、重写 |

Oracle-Rule是结构化上界，不是与VLM信息相同的普通baseline。

### 12.3 Track C：完整Rollout

从相同初始场景开始，允许轨迹分叉，比较最终任务结果。

### 12.4 公平性固定项

- 同一Track使用相同物理约束和单位；
- 选择器使用相同Candidate Set和展示字段；
- VLM方法使用相同模型、温度、提示模板和候选顺序种子；
- VLM+ReMe相对VLM只增加记忆；
- 相同stream重复前恢复相同记忆快照；
- 记录模型、提示、生成器配置Hash和随机种子。

## 13. 评价指标

### 13.1 候选生成器

- `physical_valid_rate`；
- `candidate_recall@K`和`epsilon_optimal_recall@K`；
- 高度、区域、支撑和可选箱体多样性；
- 原始/过滤后/返回候选数；
- 各拒绝原因；
- 生成时间。

这里的参考集合只使用几何和物理信息：先从未截断的物理合法候选中取得几何指标的Pareto前沿，再按预先冻结的`geometry_score_config`确定几何Oracle。`candidate_recall@K`报告Top-K对Pareto参考集合的覆盖率；`epsilon_optimal_recall@K`表示Top-K中是否至少存在一个几何得分距离Oracle不超过`epsilon`的候选。位置和朝向容差必须写入评价配置。动态业务规则不得参与这两个指标。

### 13.2 几何规划

- 已装箱体比例和体积利用率；
- 占用包络体积和最大高度；
- 支撑比例、重心裕量和承重违规；
- 坍塌、滑移；
- 单步及整场时间。

### 13.3 VLM语义决策

- 规则类型Macro-F1；
- 参数和优先级准确率；
- 动态业务硬规则违反率；
- 软语义得分；
- 同义指令和候选乱序一致性；
- 无效Candidate ID率；
- 推理延迟、Token成本和`soft_selection_regret`。

```text
先比较动态业务硬规则违反数；仅在双方均无硬规则违反时计算：
soft_selection_regret = 同一候选集Oracle最佳软语义效用 - 模型所选候选软语义效用
```

Oracle只在同一个缓存Candidate Set内选择，不额外生成候选。硬规则违反率与`soft_selection_regret`分开报告；若软规则存在优先级，则同时报告逐规则得分向量，避免单一加权分掩盖差异。

### 13.4 ReMe

- 相对无记忆VLM的配对提升；
- episode性能曲线及AULC；
- 达标所需episode；
- Policy Shift后恢复长度；
- 旧经验负迁移率；
- 检索经验使用率；
- 记忆接受、拒绝、重写、淘汰数量；
- 记忆规模、检索延迟和Token开销；
- Frozen与Online结果差异。

### 13.5 感知和机器人（后续）

- 尺寸、位姿、高度图和标签误差；
- 真值与感知规划差异；
- MoveIt 2规划、抓取和放置成功率；
- 放置误差、重试、重规划和危险动作；
- 执行后的规则满足率。

不以单一综合分作为主要结论：

```text
硬约束违规 → 完成率 → 语义得分 → 几何效率 → 时间和成本
```

## 14. 最小数据规模（MVD-v0.1）

MVD-v0.1只用于跑通接口，不承担最终统计结论。

### 14.1 100个基础场景

| 用途 | 数量 |
|---|---:|
| train/acquisition | 50 |
| validation | 10 |
| test-ID | 20 |
| test-Geometry-OOD | 10 |
| test-Semantic-OOD | 10 |

Language-OOD复用test-ID物理场景的配对指令，不新增物理场景。

每个场景：

- 8～20个箱体；
- 至少3种`geometry_id`和3种高度；
- 总体积率35%～80%；
- 参考方案至少一个箱体`z_base>0`；
- 主要为`buffer_size=1`；
- 20个场景增加`buffer_size=3`配对变体。

### 14.2 Decision Case

每场景采集3～5个固定决策点，共约300～500个；至少一半测试决策点满足`semantic_decision_required=true`。

### 14.3 Memory Stream

- 4条Stationary Stream，每条10个episode；
- 4条Policy-Shift Stream，每条10个episode，第6个episode切换规则；
- 优先复用已有场景族，不要求80个新场景；
- 每种方法至少3个随机种子重复。

功能验证后再扩大规模。

## 15. 生成流程

### 15.1 原始数据

```text

├── bed_bpp/bed-bpp_v1.json
└── mixed_pallet_boxes/MixedPalletBoxes-v1.0/
```

记录来源URL、版本、许可证、下载日期和SHA-256。

### 15.2 顺序

```text
1. 定义Schema、可见字段和隐藏字段
2. 按订单、几何簇和语义组合预划分来源池
3. 清洗BED-BPP尺寸、重量、商品和顺序
4. 生成geometry_id和匿名item_id
5. 确定性加入MixedPalletBoxes-derived属性
6. 审计属性相关性和约束激活率
7. 生成100个SPB-BED多层场景
8. 生成无规则、标准指令、同义指令和规则变化配对
9. EMS生成原始候选并执行通用物理过滤
10. 生成多样化Top-K并缓存Candidate Set
11. 生成几何Pareto参考集合与几何Oracle标注
12. 用隐藏规则评价同一Candidate Set并生成Decision Case
13. 组织Stationary和Policy-Shift流
14. 验证pair/family/stream没有跨split
15. 输出统计、候选覆盖和泄漏检查报告
```

SPB-CUT、Gazebo、RGB-D和机器人导出均在此流程稳定后实现。

## 18. 验收标准

- 所有JSON/JSONL通过Schema；
- 相同配置和种子可逐字节复现；
- 可见文件不含隐藏规则、来源ID、参考计划和Oracle分数；
- 常规场景有`reference_feasible_plan`，但不宣称全局最优；
- 测试场景实际形成多层，不存在固定高度退化；
- 同一几何对应多种语义属性；
- 有属性偏差、约束激活率和异常统计；
- Candidate Set包含配置、状态Hash、过滤和多样性信息；
- 至少一半测试Decision Case是非平凡语义决策；
- pair、family、stream整体划分，无跨split泄漏；
- Stream严格执行先决策、后反馈、再写记忆；
- Scenario可导出为Gazebo配置，但不依赖Aubo原型尺寸。
