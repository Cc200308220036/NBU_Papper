# 阶段1C实验方案：固定候选上的VLM语义决策

> 文档版本：V1.0  
> 前置条件：阶段1A、1B正式验收通过  
> 对应代码：`semantic_pallet_planner/`  
> 数据版本：`semantic_pallet_dataset_v1` V0.1  
> 本阶段范围：固定Decision Case上的VLM-Text与VLM-Visual语义候选选择  
> 后续阶段：阶段1D在线完整episode，阶段1E动态经验记忆  
> 明确不包含：Gazebo、RGB-D、MoveIt 2、Aubo执行、ReMe动态记忆、VLM自由生成连续坐标

## 1. 阶段目标

阶段1C的目标是在候选集合完全相同、状态完全相同、评价规则完全相同的条件下，验证VLM能否理解自然语言业务指令，并在物理合法候选中作出比纯几何方法更符合语义要求的选择。

本阶段回答三个问题：

1. VLM-Text读取自然语言、结构化状态和候选特征后，能否相对Geometry-Greedy提高语义表现？
2. 在结构化输入之外加入选择前3D图像后，VLM-Visual是否产生额外收益？
3. VLM的格式失败、位置偏差、延迟和调用成本是否处于可接受、可审计、可复现的范围？

阶段1C只做固定Decision Case单步决策。每种方法面对同一个冻结Candidate Set，选择不会改变下一题的状态。完整episode中由早期选择引起的轨迹分叉留到阶段1D评估。

```text
冻结Decision Case + 冻结Candidate Set
                    ↓
候选确定性随机排列并重新编号C01…CK
                    ↓
构造VLM白名单文本 / 选择前图像
                    ↓
VLM只返回一个显示候选编号
                    ↓
本地映射回真实candidate_id并执行协议校验
                    ↓
失败时最多一次格式修复；仍失败则Geometry-Greedy fallback
                    ↓
选择完成后读取隐藏Oracle和规则进行评价
                    ↓
记录语义、几何、协议、时延、token和成本指标
```

## 2. 当前工程基础与冻结项

### 2.1 已有可复用能力

阶段1A、1B已经提供：

| 已有模块 | 阶段1C直接复用的能力 |
|---|---|
| `repository.py` | 只读加载Scenario、Decision Case、Candidate Set、Oracle和split |
| `domain.py` | 不可变状态、候选、请求、响应和步骤快照 |
| `protocol.py` | 白名单请求、`state_hash`、响应Schema和真实候选恢复 |
| `selectors/baselines.py` | 统一`Selector.select()`接口、基线和注册表 |
| `runners/core.py` | 固定案例运行、选择前图像钩子、fallback及动作后评价 |
| `visualization/renderer.py` | 只消费公开选择前状态的工作区图和候选蒙版图 |
| `evaluation/` | Oracle比较、语义规则评价、统计聚合、回放和泄漏检查 |
| `logging/artifacts.py` | 追加式日志、CSV、配置快照、代码/数据哈希和manifest |

正式证据表明阶段1A、1B均为PASS。1C沿用validation上冻结的`Top-K=16`。固定Decision Case仍使用数据集原有冻结Candidate Set，不在线替换或重新生成候选。

### 2.2 进入1C后必须冻结的内容

以下内容在阶段1C正式实验中不得根据test结果修改：

1. 数据集版本和train/validation/test/OOD划分；
2. 360个Decision Case及其Candidate Set；
3. 物理合法性定义、支撑率阈值0.70和0°/90°旋转集合；
4. 几何评分分项、权重和Geometry-Greedy tie-break；
5. 候选预算`K=16`；
6. 隐藏语义评价器和Candidate Oracle定义；
7. 候选随机化算法及随机种子派生方法；
8. 正式测试使用的prompt、模型、温度、最大输出长度、超时、重试和fallback策略。

允许在train和validation上调整prompt及失败处理。配置冻结后才可运行Test-ID、Language-OOD、Semantic-OOD和Geometry-OOD；不得依据测试结果返回修改prompt后覆盖原结果。

## 3. 方法与公平比较矩阵

阶段1C主实验至少包含以下六种方法：

| 方法 | 自然语言 | 候选结构化数据 | 3D图像 | 特权输入 | 作用 |
|---|---:|---:|---:|---:|---|
| Random-Valid | 否 | 是 | 否 | 否 | 随机下界 |
| Geometry-Greedy | 否 | 是 | 否 | 否 | 主要几何基线 |
| Handcrafted-Rule | 结构化真值规则 | 是 | 否 | 是 | 显式规则上界型基线 |
| VLM-Text | 是 | 是 | 否 | 否 | 检验文本和结构化状态理解 |
| VLM-Visual | 是 | 是 | 是 | 否 | 检验视觉信息的增量价值 |
| Candidate Oracle | 隐藏Oracle | 是 | 否 | 是 | 当前Candidate Set内上界 |

Handcrafted-Rule和Candidate Oracle必须继续记录`privileged_input=true`。它们不能被表述为与普通VLM具有相同信息条件的方法。

VLM-Text和VLM-Visual必须使用同一个模型版本、同一系统指令、同一候选随机顺序、同一响应协议和同一失败处理。两者唯一计划内差异是VLM-Visual额外接收选择前图像。

本阶段暂不加入Frozen Retrieval或Dynamic ReMe。经验输入固定为`memories=None`，避免把记忆收益与基础语义能力混在一起。

### 4.1 `vlm/client.py`：通用模型客户端协议

职责：将模型供应商与Selector隔离，使运行器不依赖GLM的具体SDK或HTTP格式。

建议接口：

```python
class VLMClient(Protocol):
    def complete(self, request: "ModelRequest") -> "ModelResult": ...
```

输入`ModelRequest`：

```json
{
  "model": "配置中的模型名",
  "system_prompt": "冻结系统提示词",
  "user_content": ["文本块或图像块"],
  "temperature": 0.0,
  "max_output_tokens": 512,
  "timeout_s": 60
}
```

输出`ModelResult`：

```json
{
  "raw_text": "模型原始输出",
  "finish_reason": "stop",
  "input_tokens": 0,
  "output_tokens": 0,
  "latency_s": 0.0,
  "provider_request_id": null,
  "estimated_cost": null,
  "cache_hit": false
}
```

客户端只负责一次模型调用及供应商错误归一化，不负责候选选择规则、Oracle评价或Geometry fallback。

### 4.2 `vlm/glm_client.py`：GLM适配器与API占位

职责：实现`VLMClient`协议，读取运行配置并调用GLM接口。

密钥只允许从环境变量读取：

```text
GLM_API_KEY=<后续由用户在运行环境中填写>
```

禁止把API Key写入：

- YAML配置；
- Python源码；
- prompt缓存；
- `config.snapshot.json`；
- `manifest.json`；
- 异常堆栈或实验日志。

建议配置位置：

```yaml
vlm:
  provider: glm
  model: GLM_MODEL_PLACEHOLDER
  api_key_env: GLM_API_KEY
  base_url: GLM_BASE_URL_PLACEHOLDER
  temperature: 0.0
  max_output_tokens: 512
  timeout_s: 60
  max_format_repairs: 1
```

`GLM_MODEL_PLACEHOLDER`和`GLM_BASE_URL_PLACEHOLDER`在正式接入时按实际账号和模型能力填写。配置快照可保存环境变量名称，但不得保存变量值。

如果缺少`GLM_API_KEY`，真实API模式必须在创建实验目录或发出请求前快速失败，并给出明确错误；离线测试使用FakeClient，不依赖网络或真实密钥。

### 4.3 `vlm/candidate_mapping.py`：候选确定性随机化与编号映射

这是阶段1C的关键公平性模块。

输入：

```text
SelectionRequest
experiment seed
method-independent request key（建议decision_case_id）
```

处理：

1. 从`seed + request_id + mapping_version`派生局部随机种子；
2. 对候选做确定性排列；
3. 重新分配`C01…CK`；
4. 生成VLM可见候选列表；
5. 保存显示编号到真实`candidate_id`的内部映射；
6. 文本和图像必须消费同一份重排结果。

输出：

```json
{
  "public_request": "重排且隐藏真实ID后的VLM请求",
  "display_to_candidate": {
    "C01": "cand_xxx",
    "C02": "cand_yyy"
  },
  "mapping_sha256": "...",
  "mapping_version": "stage1c_v1"
}
```

公平性要求：

- 同一个Decision Case的VLM-Text和VLM-Visual使用完全相同的显示顺序；
- 显示顺序不能以method名称派生，否则Text和Visual不再是配对比较；
- VLM输入中不得出现真实`candidate_id`、原候选数组位置或几何排名；
- 映射可以保存在审计日志中，但不能进入模型prompt；
- baseline仍可以使用原始真实ID，评价时所有方法最终统一为真实`candidate_id`。

当前`protocol.public_candidate()`会公开真实`candidate_id`，因此不能把现有request原样发送给VLM。应构造专用的VLM投影，或者扩展协议为“内部请求”和“模型可见请求”两层。不得通过删除核心内部ID破坏现有Environment和回放逻辑。

### 4.4 `vlm/prompt_builder.py`：白名单Prompt构造

职责：把模型可见请求转换为稳定、版本化的提示内容。

输入：

- 重排后的VLM公开请求；
- `mode=text|visual`；
- 冻结prompt模板版本；
- VLM-Visual所需的选择前图像路径。

输出：

```json
{
  "prompt_version": "stage1c_prompt_v1",
  "system_prompt": "...",
  "user_content": [],
  "prompt_sha256": "..."
}
```

系统提示词至少明确：

1. 只能从给出的`C01…CK`中选择；
2. 所有候选已经通过物理合法性检查；
3. 优先减少自然语言业务硬违规；
4. 再比较语义软偏好；
5. 语义效果接近时保持较好的几何质量；
6. 不推测未来物料，不生成新坐标；
7. 只输出规定JSON。

候选结构化字段建议保留：

- 显示编号；
- 当前箱体及已放箱体可见属性；
- 位姿和旋转后尺寸；
- 支撑箱体的公开属性摘要；
- 支撑率和承重余量摘要；
- 动作后的最大高度、利用率和质心偏移；
- 四项几何分项。

不得加入：

```text
oracle_candidate_id
candidate_evaluations
ground_truth_rule
semantic_decision_required
split
source_order_id
真实candidate_id
原始候选排名
未来到货物料
当前选择后的语义反馈
```

### 4.5 `vlm/response_parser.py`：响应解析与一次格式修复

建议模型输出协议：

```json
{
  "schema_version": "pallet_vlm_choice_v1",
  "request_id": "DC_00001",
  "state_hash": "64位SHA256",
  "display_candidate_id": "C07",
  "confidence": 0.82,
  "applied_rule": "fragile_protect",
  "reason": "避免让易碎箱承担上层载荷"
}
```

其中真正可执行的最小字段为：

```text
schema_version
request_id
state_hash
display_candidate_id
```

处理顺序固定为：

```text
提取原始文本
  → 严格JSON解析
  → VLM输出Schema校验
  → request_id校验
  → state_hash校验
  → display_candidate_id存在性校验
  → 本地映射为真实candidate_id
  → 构造现有pallet_selector_response_v1
  → 调用现有resolve_response()再次校验
```

禁止接受模型返回的`x/y/z/yaw`或其他坐标覆盖。若出现额外执行字段，应判为非法响应。

首次响应只允许以下可修复错误进入一次格式修复：JSON语法错误、代码围栏、缺少必填协议字段或字段名轻微错误。未知候选、错误request ID、错误state hash和坐标注入不得通过猜测修复。修复请求只能包含原始输出、合法显示编号和输出Schema，不得加入Oracle或正确答案。

一次修复仍失败后抛出分类错误，由现有Runner按配置执行Geometry-Greedy fallback，并记录VLM原始失败。fallback后的合法动作不能计作VLM合法响应。

### 4.6 `vlm/cache.py`：请求响应缓存

目的：避免重复收费，使同一冻结调用可以审计和复算。

建议缓存键：

```text
SHA256(
  provider + model + model_revision
  + prompt_version + prompt_sha256
  + image_sha256列表
  + temperature + max_output_tokens
  + response_schema_version
)
```

缓存记录至少包含：

- 缓存键和Schema版本；
- 不含密钥的模型配置；
- prompt和图像哈希；
- 原始模型响应；
- token、时延和供应商request ID；
- 解析结果和错误分类；
- 创建时间与文件哈希。

默认行为建议为：开发运行允许读写缓存；正式复现实验可选择`cache_mode=read_write`或`read_only`，并在报告中区分真实调用时延和缓存读取时延。缓存命中不能伪装成新的API调用。

### 4.7 `vlm/leakage.py`：模型输入泄漏扫描

输入：最终发送给模型的文本、结构化JSON、图像清单和候选映射。

输出：

```json
{
  "passed": true,
  "forbidden_key_hits": [],
  "forbidden_value_hits": [],
  "real_candidate_id_hits": [],
  "future_item_hits": [],
  "checked_text_sha256": "..."
}
```

扫描不仅检查字段名，还要检查隐藏值是否以文本形式被复制进prompt。至少扫描Oracle ID、真实候选ID、split、原始订单ID、结构化规则标签、未来物料ID和动作后评价字段。

图片必须通过来源约束防泄漏：只允许`prepare_visual_request()`使用选择前公开request生成，禁止读取`frame_selected.png`、最终布局、Oracle标注目录或动作后状态。自动扫描无法证明图像像素中绝对无泄漏，因此还要保存图像来源、生成参数和SHA-256供抽查。

### 4.8 `selectors/vlm.py`：VLM选择器

建议接口：

```python
class VLMSelector:
    name: str
    privileged_input = False
    future_visible = False

    def select(self, request, *, rng, memories=None) -> dict:
        ...
```

建议提供两个注册名：

```text
vlm_text
vlm_visual
```

属性：

| 属性 | VLM-Text | VLM-Visual |
|---|---:|---:|
| `requires_images` | `False` | `True` |
| `privileged_input` | `False` | `False` |
| `future_visible` | `False` | `False` |

选择器内部依次调用候选映射、泄漏扫描、prompt builder、缓存、客户端和响应解析器。输出必须转换成现有的`pallet_selector_response_v1`，因此Environment和`resolve_response()`无需为GLM建立特殊分支。

Selector还应暴露本次调用元数据，例如通过`last_trace`只读属性或结构化返回包装器交给Runner记录：

```text
prompt_version、mapping_sha256、cache_hit、attempt_count、repair_count、
input_tokens、output_tokens、latency_s、estimated_cost、error_category
```

不建议把这些非执行字段加入现有Selector响应，因为`response.schema.json`明确禁止额外字段。

### 4.9 `runners/stage1c.py`：阶段1C固定案例编排

职责：在现有`FixedCaseRunner`基础上装配VLM依赖、保存调用追踪并执行阶段矩阵。

可采用两种实现：

1. 扩展`FixedCaseRunner`，让它可从Selector读取标准化trace；
2. 新建`Stage1CFixedRunner`复用固定案例核心函数。

优先选择第一种，避免复制动作后评价和fallback逻辑。无论哪种方式，都不得把Repository或Oracle对象传入普通VLM Selector。

Runner新增职责：

- 为同一案例生成方法无关的候选显示映射；
- VLM-Visual调用选择前渲染器；
- 保存发送前prompt和泄漏报告；
- 保存首次响应、修复响应及最终解析状态；
- 将API指标写入事件和`per_decision.csv`；
- 区分`vlm_response_valid`、`final_response_valid`和`fallback`；
- 任一失败案例仍写入结果，不能丢弃后重跑到成功为止。

## 5. 与现有代码框架的接入方式

### 5.1 不改变的主链路

现有主链路保持：

```text
FixedCaseRunner
  → Selector.select(public_request)
  → pallet_selector_response_v1
  → resolve_response()
  → evaluate_fixed()
  → Experiment.append()/metric()
```

VLM接入位于Selector内部：

```text
现有SelectionRequest
  → candidate_mapping（重排、显示ID、隐藏真实ID）
  → prompt_builder
  → leakage scan
  → cache
  → GLM API【后续填写API Key后启用】
  → response_parser
  → 显示ID映射回真实candidate_id
  → 现有SelectorResponse
```

Environment、几何生成器、物理检查器和隐藏评价器不应感知GLM供应商。

### 5.2 VLM-Text数据流

```text
DC + CSET
  → 内部SelectionRequest
  → 确定性重排
  → 删除真实ID的结构化候选文本
  → GLM文本请求
  → Cxx响应
  → 本地恢复真实candidate_id
  → 现有协议校验与隐藏评价
```

VLM-Text不得把图片路径或图片内容发送给模型。其`visual_inputs`可以保留在内部审计request中，但必须从最终模型内容中移除。

### 5.3 VLM-Visual数据流

```text
DC + CSET
  → 与VLM-Text相同的确定性重排
  → 使用重排后的公开请求重新渲染workspace和candidate montage
  → 结构化文本 + 两张选择前图像
  → GLM视觉请求
  → Cxx响应
  → 本地恢复真实candidate_id
  → 现有协议校验与隐藏评价
```

不能直接复用阶段0按原几何顺序保存的候选蒙版作为正式输入；正式图像必须根据本次重排映射重新生成，确保图上编号与JSON一致。

### 5.4 API Key接入位置

代码只读取：

```python
api_key = os.environ[config["vlm"]["api_key_env"]]
```

后续运行前由用户在终端环境中设置：

```bash
export GLM_API_KEY="由用户填写的真实密钥"
```

文档、样例配置和测试中只使用占位符或FakeClient。任何测试都不得要求提交真实密钥。

## 6. Prompt与响应的冻结策略

### 6.1 Prompt开发流程

1. 使用train案例检查语义表达、JSON格式和基本错误；
2. 使用validation比较少量预先记录的prompt版本；
3. 冻结一个prompt版本、模型参数和失败策略；
4. 生成冻结清单及SHA-256；
5. 一次性运行正式测试划分；
6. 测试后发现的问题作为新版本或补充实验，不覆盖原正式结果。

每个prompt版本必须保存：模板文本、字段顺序、数值格式、候选映射版本、图像生成版本和哈希。不得只在实验记录中写“使用默认prompt”。

### 6.2 输出长度与理由

`reason`用于审计，不能作为动作执行依据，也不能在动作后被改写。建议限制为简短中文说明，防止输出过长增加成本。主评价使用最终候选选择与隐藏评价器结果，不使用模型自报的`confidence`或`applied_rule`代替客观指标。

### 6.3 随机性

正式实验建议温度设为0或供应商允许的最低确定性值。即使如此，远程API也可能存在版本漂移，因此必须记录模型名、可获得的模型修订信息、供应商request ID、时间和原始响应。

核心数值复现分为两类：

- 缓存回放复现：相同缓存与代码应得到完全相同的选择和指标哈希；
- 真实API重复性：单独抽样报告一致率，不要求远程服务字节级一致。

## 7. 实验数据划分与运行顺序

### 7.1 开发阶段

- train：prompt结构、异常处理和泄漏测试；
- validation：选择冻结prompt版本、修复规则和超时设置；
- 不读取test Oracle来调整任何模型输入或决策规则。

### 7.2 正式评测阶段

在冻结配置后，六种方法运行相同固定Candidate Set。推荐至少报告：

1. Validation；
2. Test-ID；
3. Language-OOD；
4. Semantic-OOD；
5. Geometry-OOD。

其中主结论应优先来自Test-ID和Language-OOD。若数据集某些split为配对或重叠设计，统计时按现有scenario簇处理，不能把同一场景的多个Decision Case当作完全独立样本。

### 7.3 调用顺序与配对

同一Decision Case的所有方法共享同一CSET。VLM-Text和VLM-Visual共享同一显示映射。调用顺序不应影响映射或模型输入；缓存键也不能包含实验目录名。

正式实验出现失败时必须保留该行：

- 首次合法：记录无修复成功；
- 修复后合法：记录修复成功；
- 最终非法：记录失败并按冻结策略fallback；
- API超时或服务错误：记录对应错误并fallback；
- 禁止因为结果不理想而删除或人工替换响应。

## 8. 评价指标与统计方法

### 8.1 语义主指标

- `semantic_hard_violations`：业务硬违规数；
- `soft_utility`：隐藏语义软得分；
- `oracle_hit`：是否选中Candidate Oracle候选；
- `oracle_regret`：Oracle软分减方法软分；
- `oracle_hard_violation_regret`：方法硬违规数减Oracle硬违规数；
- 非平凡语义Decision Case上的胜/平/负率；
- VLM相对Geometry-Greedy的逐案例语义增益。

硬违规优先于软分解释。不能用软分提升掩盖业务硬违规增加。

### 8.2 几何代价指标

- 选中候选的几何总分与分项；
- 最大高度差；
- 体积利用率差；
- 质心偏移差；
- 支撑率差；
- 相对Geometry-Greedy的配对几何退化。

固定Decision Case只评价单步假设动作后的几何结果，不将其解释为完整episode最终利用率。

### 8.3 协议和可靠性指标

- 首次响应Schema通过率；
- 修复后VLM合法响应率；
- 最终合法动作率；
- invalid JSON、非法显示ID、错误哈希、超时和供应商错误率；
- 修复率与修复成功率；
- fallback率；
- 位置选择分布和`C01`选择率；
- 泄漏命中数。

“协议最终合法响应率”指VLM首次或一次修复后自身产生合法响应的比例，不包含Geometry-Greedy fallback。最终合法动作率可以包含fallback，但二者必须分开报告。

### 8.4 成本指标

- 输入token均值、中位数、p95和总量；
- 输出token均值、中位数、p95和总量；
- API时延均值、中位数、p95和最大值；
- 每个Decision Case成本和实验总成本；
- 缓存命中率；
- Text与Visual的token、时延和成本差异。

若供应商未返回精确token或价格无法可靠换算，对应字段应为`null`并解释来源，不能虚构估计值。成本估算必须记录价格表版本或人工配置版本。

### 8.5 配对统计

至少进行：

- VLM-Text vs Geometry-Greedy；
- VLM-Visual vs Geometry-Greedy；
- VLM-Visual vs VLM-Text；
- 两种VLM vs Handcrafted-Rule和Candidate Oracle的差距。

报告均值、中位数、样本标准差和95%置信区间。置信区间继续按Scenario聚类bootstrap，保持与1A、1B相同口径。胜/平/负的“平”需预先定义容差，建议语义分使用现有数值精度或冻结epsilon。

## 9. 候选位置偏差专项检查

由于原候选列表按几何逻辑排列，如果始终把首项编号为C01，模型可能通过“总选第一项”获得虚高结果。阶段1C必须做以下检查：

1. 真实Oracle候选在C01…CK上的位置分布；
2. Geometry-Greedy候选在显示位置上的分布；
3. VLM-Text和VLM-Visual选择位置分布；
4. 每个位置的选择次数及相对均匀性；
5. `C01`选择率是否显著异常；
6. 同一案例改变显示排列后，语义选择是否只跟位置变化。

建议在validation上增加一个位置稳健性审计：对同一批案例使用两个预先冻结的映射种子运行缓存允许范围内的重复测试，报告真实候选选择一致率。该审计用于发现位置依赖，不参与挑选test上表现更好的种子。

位置分布不要求严格均匀，因为模型可能有合理偏好；验收要求是不存在由实现错误造成的固定首项、JSON与图像编号错配或未随机化。

## 11. 测试方案

### 11.1 单元测试

候选映射：

- 相同seed和request产生相同排列及哈希；
- Text与Visual产生相同映射；
- 不同预设seed能够改变排列；
- 所有真实候选恰好映射一次；
- VLM公开请求不含真实candidate ID和原始排名；
- 图像标签与JSON显示编号完全一致。

响应解析：

- 合法Cxx成功恢复为真实ID；
- 非JSON、缺字段、未知Cxx、错误request ID和错误state hash被分类；
- 坐标字段注入被拒绝；
- 只允许一次格式修复；
- 修复失败触发现有fallback而不执行非法坐标。

Prompt与泄漏：

- Text模式不包含图片内容；
- Visual模式只包含选择前图片；
- Oracle、规则真值、split、未来物料和动作后反馈命中数为0；
- prompt版本和哈希稳定；
- API Key不会进入任何序列化对象。

缓存与客户端：

- 相同请求命中缓存；
- 模型、prompt、图像或参数变化会改变缓存键；
- 缓存损坏或Schema不匹配不会静默返回；
- FakeClient可以覆盖成功、超时、错误、修复成功和修复失败；
- 缺少API Key时真实客户端快速失败且日志不泄漏密钥。

### 11.2 集成测试

- 使用FakeClient完整运行至少一个固定Decision Case；
- VLM-Text和VLM-Visual经过现有`resolve_response()`；
- VLM-Visual确实调用`prepare_visual_request()`；
- 非法响应最多修复一次，随后确定性fallback；
- fallback结果记录为合法动作，但`vlm_response_valid=false`；
- 同一CSET的六种方法使用同一真实候选集合；
- 隐藏Oracle只在Selector返回后读取；
- 保存实验可通过validate和缓存回放；
- 旧的39项平台测试和阶段0的7项测试继续通过。

### 11.3 真实API冒烟测试

在正式批量运行前，用train中的少量案例执行：

1. 一个VLM-Text成功请求；
2. 一个VLM-Visual成功请求；
3. 缓存命中重放；
4. 人工检查模型所见prompt和两张图；
5. 确认日志包含token、时延和供应商request ID；
6. 确认所有产物中不存在API Key。

冒烟测试产物必须与正式实验目录分开，不能混入正式统计。

## 12. 阶段1C验收标准

验收分为“工程硬门槛”和“实验完整性”。研究效果单独报告，不用预设结论替代真实结果。

### 12.1 工程硬门槛

- [ ] `vlm_text`和`vlm_visual`均实现统一Selector接口并注册成功。
- [ ] GLM客户端从`GLM_API_KEY`环境变量读取密钥，源码、配置、缓存和日志中密钥出现数为0。
- [ ] VLM只选择显示编号，不能生成或覆盖候选坐标。
- [ ] 候选顺序按冻结算法确定性随机化，Text与Visual的同一案例映射完全一致。
- [ ] VLM输入中真实candidate ID、原始几何排名和所有隐藏字段出现数为0。
- [ ] VLM-Visual图像由重排后的选择前公开请求生成，JSON与图像编号错配数为0。
- [ ] 响应依次通过JSON、Schema、request ID、state hash、显示ID和现有协议校验。
- [ ] 每次调用最多进行一次格式修复；最终失败执行冻结fallback并完整记录。
- [ ] 任意非法响应均不能导致未验证坐标或未知候选被执行。
- [ ] 所有最终提交候选经独立几何验证后硬约束违规数为0。
- [ ] 自动泄漏扫描覆盖文本、结构化字段、候选映射和图像来源，正式请求泄漏命中数为0。
- [ ] 旧平台39项测试、阶段0的7项测试以及新增1C测试全部通过。

### 12.2 实验完整性门槛

- [ ] Random-Valid、Geometry-Greedy、Handcrafted-Rule、VLM-Text、VLM-Visual和Candidate Oracle在同一批冻结Candidate Set上完成评测。
- [ ] train/validation只用于开发与冻结；正式test运行使用冻结prompt、模型配置和失败策略。
- [ ] 全部调用均保留，包括超时、格式错误、修复和fallback，不删除失败样本。
- [ ] VLM自身最终合法响应率达到98%以上；该比例不包含Geometry-Greedy fallback。
- [ ] fallback率、超时率、非法JSON率、未知候选率、修复率和修复成功率均单独报告。
- [ ] 所有案例均记录选择位置，完成C01偏差和JSON/图像映射审计。
- [ ] 每个VLM案例记录模型、prompt版本、映射哈希、原始响应、token、时延、缓存状态和成本信息。
- [ ] 输出逐案例结果、分组汇总、配对比较、95%置信区间、位置偏差报告和成本报告。
- [ ] 保存的实验能够在不调用API的情况下使用缓存重放，选择和核心指标哈希一致。
- [ ] 至少人工抽查20个案例，覆盖Text/Visual、语义成功、语义失败、修复和fallback类别；抽查结果有记录。

### 12.3 研究结果报告要求

以下结果必须如实报告，但不预设为PASS条件：

- VLM-Text相对Geometry-Greedy的语义增益；
- VLM-Visual相对VLM-Text的增量；
- 与Handcrafted-Rule和Candidate Oracle的差距；
- Test-ID与Language-OOD的性能差；
- 语义提升对应的几何退化；
- API成本和延迟。

如果VLM没有优于Geometry-Greedy，或Visual没有优于Text，只要实验链路公平、完整且可复现，阶段工程验收仍可通过，论文结论应解释失败类型和适用边界。

### 12.4 阶段退出条件

只有同时满足以下条件才进入阶段1D：

1. 工程硬门槛全部通过；
2. 固定案例六方法矩阵完整；
3. 泄漏数和物理硬违规均为0；
4. VLM自身最终合法响应率达到98%；
5. prompt、模型、映射、缓存和实验结果可追溯；
6. 已选定一个用于在线episode的冻结VLM配置。

进入1D不要求VLM必须显著胜过所有基线，但需要根据1C结果明确选择继续使用VLM-Text、VLM-Visual或两者都保留。如果两种VLM均出现系统性语义失败，应先完成错误分析和prompt版本修订，再进入在线闭环。

## 13. 推荐开发顺序

1. 扩展配置和Schema，建立FakeClient；
2. 实现候选随机化、显示ID映射及测试；
3. 实现VLM公开投影、prompt builder和泄漏扫描；
4. 实现响应Schema、解析和一次修复；
5. 实现缓存与标准化调用trace；
6. 实现`VLMSelector`并注册Text/Visual；
7. 扩展FixedCaseRunner、指标和实验产物；
8. 使用FakeClient完成端到端测试与回放；
9. 接入GLM客户端占位配置；
10. 用户设置`GLM_API_KEY`后运行train冒烟测试；
11. 在train/validation完成prompt开发并冻结；
12. 运行正式六方法矩阵、统计、审计和验收。

## 14. 风险与处理原则

| 风险 | 处理方式 |
|---|---|
| 模型总选C01 | 确定性随机排列、位置分布报告和双映射种子审计 |
| JSON与图像编号不一致 | 二者消费同一Mapping对象，并保存映射哈希 |
| 隐藏标注泄漏 | 发送前白名单投影、键和值扫描、图像来源约束 |
| API输出不稳定 | 低温度、原始响应落盘、缓存回放、模型版本记录 |
| 调用失败导致样本缺失 | 冻结一次修复和fallback，失败样本仍进入统计 |
| 真实ID被模型利用 | VLM投影删除真实ID，仅本地审计映射保留 |
| 密钥进入日志 | 只读环境变量、配置脱敏、产物密钥扫描 |
| 成本失控 | 先FakeClient和小规模冒烟，再validation，最后一次性test |
| 视觉结果虚高 | 只使用选择前图像，禁止选中帧和动作后布局 |
| 根据test反复调prompt | 冻结清单和哈希；修改后作为新实验版本保留旧结果 |

## 15. 论文表述边界

阶段1C完成后，可以表述为：

> 在冻结的固定Decision Case与统一合法候选集合上，本文将VLM作为高层语义候选选择器。模型接收自然语言业务指令、当前公开状态、候选几何摘要以及可选的选择前3D可视化，只能返回经确定性随机编号的候选ID。系统在本地恢复真实候选并执行协议及物理复核，隐藏规则和Oracle仅在选择完成后用于评价。该设计将语义理解能力与候选生成和轨迹分叉因素分离。

不能将阶段1C描述为：

- VLM完成了连续坐标规划；
- VLM验证了机械臂可执行性；
- 固定Decision Case结果等同于完整episode表现；
- 程序化3D图像等同于真实RGB-D感知；
- Candidate Oracle代表全局装箱最优；
- GLM调用本身构成ReMe动态记忆。

阶段1C证明的是：在相同且物理合法的有限候选中，VLM是否具有可测量的自然语言语义选择价值。轨迹累积影响由阶段1D验证，动态经验获取、检索、验证和改写由阶段1E验证。
