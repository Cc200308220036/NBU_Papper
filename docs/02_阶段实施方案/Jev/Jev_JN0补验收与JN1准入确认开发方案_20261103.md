### 3.1 输出目录准入

路径以resolve后的真实路径核验，必须位于 `semantic_pallet_planner/outputs/` 内且不能等于该根目录，目标必须不存在。解析后逃逸目录的软链接/父目录和目录穿越须拒绝；不能删除已有目录后复用。

允许新的JN交付根下使用 `plan/`、`run/` 等正常子目录，无论它们被忽略还是允许归档。Git跟踪与忽略状态用于说明归档政策，不作为执行安全许可。不得为兼容本次开发扩大 `.gitignore` 例外或撤销既有JN例外。

### 3.2 正式收尾与派生错误

核对以下顺序：检查点持久化 → 原因/技术状态保存 → 最终布局和物理评价 → job指标 → 批次账本/汇总/配对 → manifest → 标准校验。自然空池的未选择事件允许 `monitor=None`，检测数为0而不是STABLE。

若派生指标或批次汇总再次报错：保存独立技术失败收据和原检查点，停止后续job；不得只打印异常后输出总PASS，不覆盖已写原始事件，也不以离线诊断代替正式闭环。异常兜底不得再次调用同一失败派生函数而丢失错误收据。

CLI退出成功只表示相应命令合同完成，不表示所有订单完成、研究收益成立或JN1准入。技术错误必须由机器可读状态和退出行为明确表达。若现有接口无须变更，用测试证明即可。

### 3.3 新身份与版本

完成必要源码修改及测试后，重新准备计划，冻结当前源码、依赖、配置、数据、物理与策略身份。旧计划在源码变化后拒绝恢复仍是正确保护。
