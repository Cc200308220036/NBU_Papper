### 1.2 本路线要回答的四个问题

1. 在相同公开前状态、同池候选和无经验Jev后续下，哪些动作差异呈现可重复的装入收益、代价或无收益？
2. DeepSeek能否从这些比较中提炼具体、条件化、可反驳的经验，而非统一的泛泛提醒？
3. 固定经验库时，新检索是否更准确地接受适用经验、拒绝不适用经验？
4. 冻结经验和检索后，是否在独立留出任务上改善整单结果，且收益超过无关上下文与通用提醒对照？

对应四层验收：**工程正确、内容可用、检索适用、策略收益**。前一层通过不能替代后一层；允许得到“工程完成、收益未建立”的结论。

### 1.3 本版的成功层次与结论边界

| 层次 | 必要证据 | 不能替代的下一层 |
|---|---|---|
| 修复实现缺陷 | 特征同口径、非空投影、真实后续、恢复和拒绝机制正确 | 不等于经验适用 |
| 降低无效干扰 | 错误注入减少，仍覆盖合格正例，退化有所缓解 | 回到无经验水平不等于经验有增量 |
| 内容产生局部增量 | 同状态内容对照与同策略后续提供支持 | 不等于跨订单持续收益 |
| 建立留出收益 | 冻结新任务中优于N，并按声明超过U1/G1 | 不自动证明某个几何机制或任意场景泛化 |

同起点重复用于观察波动；不同起点/来源用于检查迁移。当前看不到的后续箱型可以影响历史结果，但不能成为卡片的隐含在线前提。任何单点正例均不得自动升级为通用策略。

## 3. 范围与不可突破的公共合同

### 3.1 本路线允许规划的改动

- 新训练采点、真实无经验Jev分叉后续、比较证据与有界重复。
- 可表达非空垛体的公开历史投影、T案例、DeepSeek条件化E及独立审核。
- 场景/动作适用性门控、召回、准入、空视图及逐步审计。
- 固定库比较检索、固定检索比较表示、开发先导、独立冻结评价。
- 必要的新协议、Schema、方法注册、账本绑定、指标和分析。

### 3.2 不做事项

- 不修改候选器、TopK、物理容差、承载参数或稳定性算法来提高成绩；若发现问题，单独报告和立项。
- 不恢复食品清洁品、区域规则、AST、视觉VLM，不训练模型或下载权重。
- 不删除旧保护语句、不放宽旧封闭Schema、不重签历史摘要。
- 不将旧36槽位或其变体当新未见测试；不把熟悉原型的新组合称真实独立来源。
- 不使用在线测试结果更新经验、调阈值、选择种子或补采获胜分支。
- 不自动commit/push、安装依赖、执行历史全量回放或启动子代理。

### 3.3 所有新方法共用的链路

`当前公开状态 → 原公共候选 → 检索/选择 → 保存选择 → 独立副本监测 → STABLE原提交或分类停单`。

禁止PCT预过滤/排序、监测诊断进入查询或请求、失稳后换第二动作。失败动作不提交、不移出缓冲、不计装入。UNSTABLE、UNASSESSABLE、ERROR、UNKNOWN_SEND独立保留；关闭监测记录DISABLED，不称STABLE。旧面积分载账本与PCT反力分离。

新路线拟沿用已验收`pct_exact_pose_network_v3`，执行身份独立版本化。历史v2/v3继续分层；不从根包旧算法入口回退。恢复绑定数据、源码、依赖、策略、快照、查询及监测身份；已存选择、监测和提交不重发、不覆盖、不重复执行。

### 6.2 JM1-B：训练任务、采点和有限分支冻结

目标：按当前可观察决策问题采集，不再固定“第一步＋中点”，不根据终态赢家倒选采点。

拟议首轮范围：**最多6个训练订单，分两个预登记波次3＋3；每单最多2点，总最多12点。** 真实来源按来源分组；合成任务按生成家族/共享原型另列，不把6订单自动称6独立真实来源。数量是工程采集上限，不是统计充分性声明。

拟议采点规则：

1. 对原始响应概率做严格解析，精确动作去重；不从四位显示值判断并列。
2. 分开登记精确最高并列和近最高候选，后者使用冻结的`epsilon_near_top`；该值仅由训练概率分布及预定规则确定，在后缀结果产生前冻结，不按收益改阈值。

5. 每点最多3分支：原动作参考、一个同箱替代、一个跨箱替代。替代必须来自注册的高概率集合；类别缺失保留缺口，不自动拿低概率动作填补。

### 7.2 JM2-B：DeepSeek内容与独立审核工程

目标：从同源对比提炼能区分候选的条件化经验，替代固定两类提醒的内容限制。

**拟议E卡片字段：**

| 字段 | 要求 |
|---|---|
| `usage_scenario` | 何时适用；与公开ScenarioSignature对应 |

审核分三层：

1. **程序事实审计**：数值、单位、比较方向、分母、引用及成本完整；生成模型不能改事实。
2. **声明范围审核**：建议是否具体、前提是否可观察、是否越过证据范围、是否保留反例；条件谓词必须绑定注册特征，不允许自由文字偷偷定义不可计算门槛。
3. **内容有效性评审**：是否比一般提醒更能区分候选、能否被反驳。若采用人工审核，必须有真实署名记录；若采用独立模型审核，单列预算/模型/提示，不能把生成器自评写成独立通过。

拟议最多4个开发状态，覆盖至少两个来源组、多个起点和实际声明的动作类别；若声称支持中期，必须有合格非空状态。用先冻结的定位程序筛选，缺覆盖记PARTIAL，不换状态找正结果。每族的执行资格按其实际核验覆盖判断；最多4状态不能默认验证全部8族。

固定同一公开状态、完整候选池、提示、模型与展示配置，每状态最多5个条件，每条件只发1次：

| 条件 | 实际输入 | 回答的问题 |
|---|---|---|
| L-N | 空记忆 | 无经验会如何选择 |
| L-T | 冻结T候选片段 | 具体案例提供什么 |
| L-E | 同源冻结E候选片段 | 完整条件化建议提供什么 |
| L-A | E的预登记删减版 | 删除关键比较结论后是否仍表现相同 |
| L-G | 固定通用提醒 | 专门经验是否超越一般建议 |

L-A删除`advice`中的关键方向与对应预测，保留事实、适用条件及代价等约定字段；须保存逐字段diff，不加入新建议，不伪称等token。残留事实可能仍让Jev推断相同方向，因此这是删减诊断，不是纯粹单因素因果证明。L-G只提醒比较空间连续性、支撑、承载及装入取舍，不含训练案例、结果或当前答案；文本在结果前冻结，不按结果挑最佳措辞。

每状态合计最多5次选择请求，总最多20次。请求均为诊断，实际保存/映射/监测与状态恢复沿公共合同；不据某个响应反复抽样。同一精确动作跨条件去重后，每状态最多保留3个动作（必须含L-N），超额按冻结的条件优先级取，未执行动作明确记NOT_RUN。

对保留动作在同一前状态强制首步，全部接无经验Jev后续；每动作预登记2个独立后缀槽位，总最多`4×3×2=24`条。该数量仅为筛查上限，不能据两次一致声称稳定收益。动作相同也保留对照记录，不重复算作不同动作证据。首步监测结果复用规则须预先冻结，只有身份完全一致时允许复用；动作未获STABLE不提交、不派后续。局部与整单真实实验均冻结启用v3选后监测，DISABLED不能满足执行验收。未保留动作或未完成后缀的条件不能提供相应效果证据，缺关键对照时该卡DEFER，不能由其他动作代替；不因此扩大3动作上限。

输出`local_content_plan.json`、状态/来源清单、5条件正文、删减diff、动作保留程序、重复/预算和`execution_admission_policy.json`。收益容限、明显反向判据、证据不足处理与多起点覆盖在发送前冻结，不能看结果后决定“多大改善算通过”。

#### 9.2.2 JM4-M2：有限执行、内容诊断与逐卡准入

### 12.3 失败与恢复

每个运行创建独立输出，不覆盖已有封存目录。新分叉不是把父checkpoint改task/config后继续，必须保存父证据绑定和新分支身份。

- 请求前持久化context/body和预约；结果不明保留UNKNOWN_SEND，禁止跨窗口重新发送同一未决请求。
- 新决策保存检索事实；已有DECISION_READY/SELECTED/MONITORED/COMMITTED按原语义复用，不因新检索规则重算。
- 生成原响应已保存则恢复审核，不重发；文本不合格记拒绝/PENDING，不自动返修。
- 计划、源码、依赖、模型、提示、数据、特征或快照变化拒绝恢复；只能创建新身份，不重签旧摘要。
- 保存事实验证与真实执行分离；校验中不得候选重建、模型调用或重算监测。必要行为回归使用构造材料独立运行。
