# O3 在线码垛框架与论文创新验证路线

> 2026-10-11。此文是下一阶段执行方案，不表示 O3 已实现或研究假设已获支持。旧 V1/V2/O2b 实验目录、数据、代码快照和费用字段保持原样。O3 新产物使用 `EXP_OPT_O3A_ONLINE_PILOT_*`、`EXP_OPT_O3B_ONLINE_VALIDATION_*` 等新目录。

## 当前能作出的判断

O2b `_05` 在原 train 来源的 30 个独立订单、180 道固定候选题上完成六方法共 1080 条记录；独立回放 1080/1080 通过，已提交物理违规 0。[验收报告](../../../semantic_pallet_planner/outputs/EXP_OPT_O2B_AST_PILOT_20261009_05/acceptance_report.json)显示离线和远程矩阵工程检查均为 PASS，完整统计设计仍待完成。以下指标来自[原始汇总](../../../semantic_pallet_planner/outputs/EXP_OPT_O2B_AST_PILOT_20261009_05/metrics/summary.json)，不是新 test 结论：

| 方法 | 可避免的原始业务硬违规 | 最优等价候选率 | 结论 |
|---|---:|---:|---|
| Geometry-Greedy | 27/111 | 48.2%（分母 168） | 几何目标本身不足以落实业务要求 |
| 固定属性启发式 | 3/111 | 76.8%（分母 168） | 属性启发有明显价值 |
| Flash Direct-Text | 21/111 | 55.7%（分母 167） | 直接选编号仍有关系/数值决策错误 |

Flash AST 的**严格字符串/结构精确率**为 80/180；需要将冗余条件包装与执行语义错误分开报告，不能仅用选址 100% 反推解析准确率 100%。O2b 使用的是文本与 JSON，尚不能称为视觉贡献。O2b 的统计状态是 `PENDING_STATISTICAL_DESIGN`；当前可以进入 O3 工程开发，但不得宣称已通过 O2b 完整研究验收或证明 VLM 优势。

## 立即开发的框架：O3a

现有 [`PalletEnvironment`](../../../semantic_pallet_planner/src/semantic_pallet_planner/environment.py) 已能逐箱到货、从实际状态重新生成候选并独立复核物理合法性；[`EpisodeRunner`](../../../semantic_pallet_planner/src/semantic_pallet_planner/runners/core.py) 能记录在线步骤。但它们沿用早期指令/评价协议，尚未把 O2b 的 `policy_digest`、受限 AST、属性关系评价和业务屏障贯穿至在线提交。O3a 的代码目标是新增版本化在线 runner/adapter，不改写旧 runner 或任何 `EXP_1C_*`、O2b 目录。

```text
公开自然语言 + 当前真值状态 + 当前箱（buffer_size=1）
              ↓ 只解析公开事实
Public Parser 或 Flash Policy Parser → 受限 AST / 解析失败
              ↓
现有物理候选生成器（Top-K=16）→ 公开关系特征 → 共享确定性执行器
              ↓
原始提议记录 → 确定性物理复核与公开业务屏障 → 提交 / abstain / abort
              ↓
实际新状态 → 下一箱重新生成候选 → episode 终止与独立回放
```

关键接口：每个请求绑定 `request_id`、`state_hash`、`policy_digest`、公开候选映射摘要；模型和公开 Parser 只见同一公开当前状态、属性、指令与候选事实。隐藏真值 AST、Oracle 分数、真实候选 ID 映射和未来箱体只留在评测端。策略改变必须刷新 `policy_digest` 和响应缓存键。业务屏障拦截时保留原始提议、原因、可行候选覆盖及终止状态；不能把屏障挡下的错误计为模型本身正确。物理不可行候选绝不提交。模型输出异常、无物理候选、无业务可行候选、API 错误、正常完成各有不同终止码。

O3a 首批只跑离线策略与少量开发 episode，优先复用 O1b 已有规则 AST、属性评价器和现有生成器；不先加入新物理生成器、lookahead、Gazebo、记忆或图像独有属性。真实 DeepSeek 调用在在线离线回放和泄漏审计通过后进行，新调用使用新输出目录。现有固定候选题不能直接当在线 episode：在线每步要按各方法**自己的已提交状态**重新生成候选，轨迹可分叉。

**O3a 工程验收**：至少 Geometry、固定属性、Public Parser＋Executor、Flash AST＋Executor、真值规则在线贪心参考五臂；同初始订单与到货顺序，`buffer_size=1`、Top-K=16；每个计划 episode 都有完整终止记录；已提交物理违规 0；状态/载荷/哈希可独立回放；每步原始提议、屏障干预、候选覆盖、属性 before/after/delta 可追溯；新目录保存源码摘要、配置、请求与响应，旧目录哈希不变。真值规则在线贪心仅是参考，不是全局最优。工程验收不要求 Flash 获胜，也不要求账单或费用字段。

## 再做 O3b：完整在线 validation 对照

先从与 O1b 开发来源独立的订单组形成 validation 在线场景；各方法用同一初始订单，但后续状态允许分叉。预先确定主终点为 **Episode Attribute Success**，同时报告完成率、已放件数/体积比例、最终易碎箱承载、禁止接触对、重箱高度/中心距离、业务屏障干预率和已提交物理违规。失败与拒放均留在计划分母。按来源订单聚类比较，而不按步骤数虚增样本量。至少保存三组同初始场景的对照动画，包括成功和失败。

O3b 首先检验**在线架构是否可靠、固定候选收益能否延续到完整订单**。由于 O2b 公共 Parser 已在已公布语法上达到上界，若 O3b 仍使用同一语法，Flash 与它持平也不能支持“VLM 更优”。如果所有方法都无法完成多数订单，先诊断候选覆盖与订单难度；不要改候选器后仍把收益归因于 VLM。

## 论文创新点怎样形成可检验证据

1. **语言到可审计策略的安全编译**：模型解释自然语言和条件例外，确定性模块负责接触、载荷与排序，错误可归因到语义解析、候选覆盖或执行。现有 Code as Policies 与 SayCan 分别启发语言转程序、语言与可执行性分工；本项目的可研究点必须是**属性业务政策在在线码垛中的可核验表示与闭环效果**，不能仅把两种现有思想拼接称为创新。[Code as Policies](https://arxiv.org/abs/2209.07753)、[SayCan](https://arxiv.org/abs/2204.01691)。
2. **政策改变下的在线属性布局**：同一初始物理场景切换公开保护阈值、作用对象、条件例外或软目标优先级，比较完整轨迹的业务结果。与同权限、充分开发的公开 Parser 和固定属性策略比较；只在未见表达/组合上出现稳定增量，才可主张语言模型适应性。受约束在线装箱研究支持把可行动作与在线到货明确建模，但不直接证明本项目的语义增量。[Online 3D Bin Packing with Constrained Deep Reinforcement Learning](https://arxiv.org/abs/2006.14978)。
3. **视觉属性缺口作为后续独立问题**：目前真值 JSON 已含属性，图像没有必要信息。要写“VLM”视觉创新，必须另建真实或可审计的包装标签/图像独有属性轨道，比较 OCR＋相同执行器、Visual＋执行器、完整真值 Text 上界，记录属性识别错误与布局错误；不能通过给 JSON 随意删字段制造优势。此项属于 O4，不能从当前 Text 实验提前认定成功。

**论文主张的停止条件**：若强公开 Parser 在未见语言和在线任务上仍与模型相当，承认该规则域无需 VLM；可把论文贡献转向“何时使用语言模型、何时安全回退规则”的可证边界，但这也需要预定义触发条件和强对照。若只有混合架构优于 Direct，结论是“解析后确定性执行更可靠”，不能写成“VLM 比规则强”。

## 阶段顺序与实验纪律

- **现在：O3a**，接好在线协议、AST、关系特征、屏障、完整回放；只用开发订单和离线方法完成工程验收。
- **随后：O3b**，少量真实 Flash 在线 validation 调用，分析轨迹分叉、完成率与业务布局；远程环境由本地 `pallet_vlm` 运行，密钥仅经环境变量提供。
- **再后：语言泛化轨道**，用未见的自然表述和政策组合检验模型相对强 Parser 的增量；人工核对指令真值，来源订单/模板族不跨 train、validation、test。
- **最后：冻结新 test**，根据独立 validation 的组间差异和失败率决定独立来源组数、重复次数与阈值，再运行一次正式矩阵。旧已查看 test 仅作回归。

按当前决定，O3a/O3b **不记录、不估算、不考核费用**；费用字段可省略或置 `null`，不把未知费用当作 0。仍保留方法、请求次数、失败、修复、模型/Prompt 版本及必要时延，以确保对照可复算。以后若要研究效率，可另立协议，不回改这轮历史产物。
