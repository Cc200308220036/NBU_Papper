## 1. 起点与研究对象

以[B1-A报告](../../03_阶段产出分析/O4/Jev_J4_B1_A开发与验收_20261030.md)、[B1-B报告](../../03_阶段产出分析/O4/Jev_J4_B1_B开发与验收_20261030.md)和实际代码/清单核实起点。已完成的是检索、固定库运行、恢复与记录工程；非空M0依赖fixture。当前真实训练为同一来源组的两条旧J3轨迹、24事件，R0为0/24可注入，没有真实生成并通过支持审核的活跃卡。249个历史通过测试不是B2完成证据，后续报告列实际运行的测试和真实调用。

本轮研究对象是“具有适用范围、比较依据和可复核证据的经验声明”。DeepSeek提出候选声明，事实核验与语义审核分别判断证据和支持范围；Jev仍在同一物理池中以原生Choice选择。结构化本地证据与模型可见经验文本并存；不要求用外部加分替代Jev，不训练其权重。

PUSNet提供研究动机，不作为本项目收益证据。原研究方案的具体表格、掩码与奖励细节须补原文页码/表号核对；本细则不依赖未经复核的论文数值制定验收门槛。

## 3. 两种文本预算与输入选择

| 对象 | 合同 | 超限/不足处理 |
|---|---|---|
| R0注入正文 | 一次实际决策的自包含事件；单条≤1600 UTF-8字节，canonical数组≤4800，最多3条；R0/M0规则共用 | 整事件排除，不删负反馈；报告可注入比例和原因 |
| 总结请求 | 独立冻结模型上下文、输入/输出预算、安全余量、单位与计算方法，不能视整单必然装得下 | 记录GENERATION_INPUT_TOO_LARGE和未覆盖事件；不偷偷逐窗调用 |

B2-A对同一训练语料分别给出上述两种预检。R0为0%不直接阻止总结候选，但会阻止将原始历史臂称为可用的非空对照。先核查可确定性消除的冗余表达，再核查不可省略的规则、资源和反馈。不按好坏结果筛事件，不将字段句柄替代必要定义，不靠截断求入选。改进投影必须有版本、完整语义对照、训练预检、B1预算/检索回归及新快照；若需变更统一预算，另交校准修订方案并在正式实验前冻结，不在B2暗改或改旧结果。

总结输入保留实际选箱/位姿、公共属性、必要资源、真实新增反馈和终局信息；服务故障截断明确标记。完整未来序列、私有reference/AST、候选业务答案、未执行分支收益和验证/测试轨迹不能进入。终局信息可作为事后观察，不能据此把相关性写成因果。每个请求附确定性的事件/字段覆盖清单；卡只能引用该请求真正看到的证据。

## 4. 声明、证据和审核的待实现合同

以下为概念到现有结构的开发映射，未表示当前Schema已经具备这些字段。实现前检查既有结构，按需要扩展并版本化；不建立另一套平行卡库，也不强制重复存两份可冲突的advice/claim。

| 概念/记录 | 开发要求 |
|---|---|
| 声明 `claim` | 清楚描述什么情境下应比较什么资源；与既有advice对应，泛化空话不直接激活 |
| 比较依据 `comparison_basis` | 面向已观察的空间/区域/支撑/载荷/缓冲取舍；不能输出内部Cxx或未见箱体需求 |
| 引证 `evidence_links` | 关联已有evidence_refs、episode/decision/export/源码、实际请求、字段路径和值，说明支持/反例/未知范围 |
| 效果假设 | 若模型输出expected_effect，只登记hypothesis，不默认positive，更不作为数值加分 |
| 限制与反例 | 完整保留；“未观察到反例”不是不存在反例；缩小适用范围生成新版本并重审 |
| knowledge_role | 保存分类依据和判定者；纯规则复述不进主M0，模糊/冲突保持candidate |
| 自动核验 | 来源允许、路径可解析、字段值相符、引证在实际输入内、摘要/版本/生命周期相容 |
| semantic_review | 独立保存审核者、协议版本、理由与结论；未审核不伪造accepted，代理自我打分不冒充独立人工审核 |
| 分支诊断关联 | 当前只关联独立诊断报告摘要，不进入生产observational支持数或总结请求 |

支持来源按独立来源组去重，同源业务B1/B2、重复决策和重复导出只计一个来源。至少两个不同真实训练来源均能核对适用事实和所述观察，且完成支持审核，才可能active；两个引用不是两个支持证据。第一版evidence_level仍为observational。

不把模型自评confidence、检索分数、Choice概率、引用次数和局部收益融合成单个“可信度”。先分别报告事实一致性、来源支持、审核、限制和诊断结果。当前Jev返回的Choice概率不是经过校准的Q值；不读取或假设不存在的logit/critic接口。

“连续空间”“资源唯一性”“碎片化风险”等新门控必须先有公共输入、定义、单位/精度和未知状态；未经实现核验的文字不直接变成true/false。若后续新增公共特征，应三臂共享、另行冻结并回归，不能只向M0提供诊断业务成本或物理替代结果。

| 配置 | 用户已指定的值 |

| 授权范围 | B2必要文本调用可直接读取使用，无需再次请求许可；不额外设置总次数/费用硬上限 |

本次文档修订不执行调用或读取凭证。后续实现须核对官方合同，冻结采样/思考模式、上下文和输出预算、超时、提示及模型身份，记录服务返回信息和别名变化，不能悄悄切换模型。此授权不含新增Jev采集、B3或C付费矩阵，也不等于人工审核已通过。

取消额外总额硬上限不取消实验频次：每个终止训练episode最多一次生成、最多2张候选；每4个训练episode最多一次合并；每次生成/合并最多一次格式修复，只反馈结构错误。第一轮60次是既定训练矩阵推导的自然上限，不额外添加一个任意总额阈值，也不通过隐藏审核/逐窗调用突破频次；需增加操作类型时先修订明确的实验协议。

账目身份绑定输入、配置、提示、模型、操作类型与输入版本，成功/失败/修复/usage/延迟及费用分账。已有正式响应直接复用，未知发送不自动重试；不以换目录、换run ID或从B2-A切到B2-B触发重复付费。新输入版本是否允许再次生成须有显式协议和原因，不能靠改摘要绕过每episode限制。usage未知保持null，费用估算与实际账单分开。

B2-A可进行必要最小真实联调，优先使用核验后的真实输入；合成协议探针标记fixture_only，不计训练支持。若已正式生成某episode，B2-B复用该响应。服务失败保留脱敏证据，不改用fixture冒充成功；本地不受影响的工作继续交付。

## 6. 审核、合并、激活与冻结

先提供可审阅的候选原文、逐声明事实和值、支持来源、反例及未验证范围，再请求必要的语义审核。用户的远程调用许可不是审核结论。需要人工时，可以接受、拒绝或退回candidate；不允许直接补策略、改写成成功卡、删反例或按测试表现筛卡。缺少审核时继续完成账目、测试和文档，卡保持candidate。另用文本审核器须有独立、明确的冻结协议和账目，不因生成授权就默认启用。

只合并适用范围和建议相容的卡，保留父卡、原文、支持及反例。正文变化生成新版本，不覆盖旧包。冲突不能划分时不激活。未到四个训练episode不为凑流程执行真实合并；NOT_APPLICABLE与工程测试结果分开。

active仍需满足主规范的真实来源、两来源支持、审核、限制、角色及泄漏条件。最多64卡，按支持组数降序、内容摘要升序保留，超额retired并保留原件。单源candidate、被拒绝或空活跃库都记录真实原因。

冻结新包包含正文、证据、实际输入覆盖、生成配置/响应、审核与生命周期、corpus及索引身份和文件清单。只读、可迁移、篡改拒绝；B1消费相同BM25、门控和预算，不改变物理候选、业务规则、评分公式或原生Choice。只有合法active卡才能进入生产M0；candidate不能为展示非空而注入。

主矩阵保留G0/H0/D0/R0/M0；规则提醒S0按既有校准合同。不要把“验证经验＋重排序＋更多训练数据”打包成一个新臂后宣称验证机制独立有效。相同Choice不证明经验未用，动作变化不证明收益；概率、动作、来源覆盖和独立订单结果分别报告。当前为文本原生选择，未实现图像输入时不宣称视觉感知实验。
