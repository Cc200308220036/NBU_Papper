本次修订按用户最新要求将“只读旁路、不影响运行”改为“**选后监测、失稳停止**”，并提供开启/关闭接口。为保留已有链接，文件名仍含“旁路”；正文为后续开发依据。历史旁路设想不再限制本次运行接入，候选预过滤仍明确禁止。

## 1. 开发目标与完成定义

将PCT静态稳定性算法接入现有包装运行链路，作为所有方法共用的**选择后监测模块**。候选池及排序保持原样，选择器先独立选出完整动作，然后在状态副本中检测该动作：STABLE才正式提交；UNSTABLE则不放置该箱，保存失败动作并结束当前订单。不是预过滤，也不允许根据检测结果重新选择。

必须同时完成：

1. 固定上游源码、许可、最小依赖与补丁，真实调用堆叠树内核。
2. 精确恢复位姿、真实质量和当前支撑结构，关键稳定/祖先失稳案例通过。
3. 统一开启/关闭接口接通候选选择后的调度；开关关闭不运行PCT，开启对模型、本地方法及单候选自动路径同样生效。
4. 开启时稳定提交、失稳终止，无法评价和程序错误独立结束为监测故障；无改选、无隐式重试、无输入污染。
5. 选择、监测、提交与恢复账目完整，新运行身份不混用历史v4检查点；完成构造集成及最多两个受限本地前缀冒烟。
6. 已有记录只作独立事后分析，不重写为“当时已监测”；S01—S30有逐项证据。

不以导入成功、仅返回True、只检查新箱中心，或用旧oracle替代PCT宣称完成。不要求真实Jev/经验效果或完整订单正收益。

## 2. 范围、开关与公平条件

继续采用均匀单箱质量、刚性长方体、准静态近似。排除区域、食品清洁品相容性、相对方位、冲击、摩擦滑移、变形及真实破坏过程。

### 2.1 开启/关闭接口

统一使用`stability_monitor.enabled`布尔值，默认false，禁止多个相互矛盾的enabled/mode开关。配置示意，不是现有CLI可直接运行的完整配置：

```json
{
  "stability_monitor": {
    "enabled": true,
    "algorithm": "pct_static_v1",
    "config_digest": "<冻结后的算法配置摘要>"
  }
}
```

- 关闭：不导入/实例化PCT内核、不检测、不产生稳定性终止，沿用原候选和执行行为；记`monitor_status=DISABLED`、检查次数0，不能记成STABLE。允许未安装稳定性可选依赖的旧运行正常工作。
- 开启：每次成功选定动作后检测，包括单候选自动动作；同一决策监测结果落盘后恢复可复用，不重复选或调用模型。
- 无法评价/错误：不能放行或当成预测失稳，分别以`STABILITY_UNASSESSABLE`和`STABILITY_MONITOR_ERROR`结束该订单并保留分母，不静默关闭开关。
- 开关及算法配置在计划启动前冻结，进入检查点和摘要；恢复时切换开关/算法须拒绝。要比较开关效果，另开运行，不能半单切换。

### 2.2 不进行候选过滤

开启前后，同一公共状态的候选内容、数量、顺序、局部编号及选择请求body必须相同。监测不改变原TopK、几何评分或概率，不向选择器传稳定性标签/分数，不预评第二/第三候选后代选。

原边界、碰撞、70%支撑、局部中心及包装承载硬检查仍保留，不表示取消所有既有物理过滤。**只有新增PCT不作为候选过滤条件，而作为选后任务停止条件。**

所有对比方法采用同一开关、算法版本、数值参数和终止规则；只检测被选动作，不强制对全池逐项检测。候选池穷尽分析仅属于构造/离线诊断，不参与在线选择。

本开发只做本地替身、构造案例及受限前缀，不读取密钥，不新增真实模型请求、RL训练、订单效果矩阵、分支搜索或全量回放。监测接口须与通用选择后入口对齐，但不因此打开当前v4未提供的远程/非空记忆功能。

## 4. 源码审计中已发现的具体风险

| 位置/行为 | 必须处理的事项 |
|---|---|
| Box.mass = x*y*z*density | 每箱density由实际mass_kg和转换后体积计算；禁止统一密度代替异质质量 |
| drop_box()/drop_box_virtual() | 输入只有水平位置，垂直位置由内核求max_h；必须与原候选z_base核对，不能自动吸附后冒充原动作 |
| check_box(setting=2) | 直接返回True，必须封禁；稳定性启用值须用反例确认而非猜测配置名 |
| 虚拟分支up_virtual_edges/involved等 | 可能存在状态修改；初版每个候选用全新状态，不能只相信virtual命名意味着只读 |
| scale_down() | 对支撑凸包向中心收缩10%，是上游内核语义，必须登记；不得把它当项目既有70%面积规则 |
| convex_hull.py中的np.float | 记录最小兼容补丁，如改成float；不全局修改numpy命名空间，不为兼容升级整套训练环境 |
| 凸包坐标微扰、取整与1e-6常量 | 在采用单位下解释实际尺度；边界/退化输入有专门测试，不能静默放大容差 |
| 两支撑及多支撑分流/最小二乘 | 检查零距离、非有限值、负质量/异常分配和质量守恒；异常记ERROR，不裁剪为正数或静默归一后声称原算法结果 |
| PctContinuous0/__init__.py导入bin3D | 不照搬该初始化以免引入Gym/训练环境；vendor使用无副作用最小__init__，声明适配差异 |
| Space holder默认60 | 按已有状态箱数＋候选预留容量，越界显式报错；本轮不加载权重或训练日志 |

## 6. 输入和坐标转换合同

输入仅包括当前已放箱体及其实际放置顺序、容器和待评价候选对应箱体。不得将未到货箱、完整task、见证、经验或旧成绩传入内核。所有箱体的质量、尺寸和位姿须合法且有限。

初版统一采用毫米坐标、kg质量，保留上游常量在mm下的含义。若选择其他尺度，须另冻配置并测试；不能将mm误当m使上游容差物理尺度改变。

项目原点为托盘底面中心，上游Space使用非负角点。对于托盘长L、宽W、候选底面中心(x,y,z)、旋转后尺寸(sx,sy,sz)：

```text
lx = x + L/2 − sx/2
ly = y + W/2 − sy/2
lz = z
world_COM = (x, y, z + sz/2)
density = mass_kg / (sx*sy*sz)     # 当几何单位mm时为kg/mm³
```

核实Space的width/length参数实际对应plain_size[0]/[1]，不要凭名称对调轴。传入已经旋转后的尺寸时`flag=False`，防止二次交换长宽。仅支持既有0/90轴对齐姿态；有符号yaw手性未认证时写明“不依赖有符号变换”，禁止宣称已支持任意角度。

每个Box构建后核对`mass`及中心、vertex_low/high。原始质量不变，相同体积不同重量必须得到不同密度与等效重心。密度不是新数据集物理测量字段，只是适配桥梁。

高度核对容差在配置显式声明，报告内核max_h与候选z_base的差值；只有语义相符才评价该动作。超差返回UNASSESSABLE/POSE_HEIGHT_MISMATCH，不按新高度“修复”候选。

## 7. 状态恢复与无污染评估

建议接口均为本项目拟议接口，不假定上游同名：

```python
assess_candidate(placed_state, candidate, config) -> StabilityResult
monitor_selected_action(state, candidate, monitor_config) -> MonitorDecision
assess_saved_decision(saved_record, config) -> DecisionShadowReport
inspect_saved_runtime(artifact, config, output) -> ShadowReport
```

在线仅对已选动作执行以下流程；离线候选分析亦须逐项独立：

1. 校验输入和原状态/候选摘要，创建独立Space实例。
2. 按真实提交顺序重建已放箱体，逐箱检查位姿、质量与稳定性；不按尺寸、质量或z排序替换原顺序。
3. 若已有前缀被PCT判失稳，则记UNASSESSABLE/BASELINE_UNSTABLE，定位首个箱体；不能强行绕过以继续作正式候选结论。
4. 保存基线内核摘要。对候选调用实际内核试放入口，核对落箱高度及几何一致性。
5. 对原本可评价基线，True映射STABLE，False且明确为稳定性失败才映射UNSTABLE；边界/高度/输入原因不得混记为倾覆。
6. 采集可获得的支撑对象、组合质量/中心与数值诊断；无法从内核可靠定位失稳箱则字段为null，不编造原因或“概率”。
7. 校验质量守恒及数值有效；销毁该独立实例。调用前后项目state、candidate与输入报告字节/摘要不变。

在线每步只有一个选定动作，第一版允许每步重建已有状态；离线多候选诊断允许逐候选重建，优先保证隔离正确，不承诺论文复杂度或速度。增加缓存须单独证明候选顺序不影响结果；本轮不强制优化。

异常分流与支撑未覆盖等应记录明确错误或不支持，不把ERROR、UNASSESSABLE变成STABLE。输入前缀已被新算法否定不代表新候选“导致”了该失稳。

## 8. 选后监测、提交与中断恢复合同

### 8.1 正常执行顺序

```text
生成原候选 → 方法选定具体箱体/位姿 → 保存选择与精确动作
    → 在独立副本中监测选后布局 → 保存监测结果
       ├─ STABLE：原commit_physical复核并正式提交 → COMMITTED → 更新评价
       ├─ UNSTABLE：不提交该箱 → 保存失败事件及终态 → 停止订单
       ├─ UNASSESSABLE：不提交 → 监测不可评价终止（非失稳）
       └─ ERROR：不提交 → 监测技术故障终止（非失稳）
```

检测的是候选放置后的预期布局，但不先污染真实state。预测失稳不模拟倒塌、不调用place、不增加已放箱数/体积/质量、不从缓冲区移除该箱；保存该箱为attempted/uncommitted动作，其质量不进入最终垛体指标。

STABLE后旧物理复核仍可能失败，按原提交错误独立报告，不归为PCT失稳。DISABLED路径没有算法结果，但按原commit_physical执行。合法选择数、监测次数、成功提交数分别计，不能要求三者总相等。

### 8.2 终止与故障分类

终止码至少为`PREDICTED_STATIC_INSTABILITY`、`STABILITY_UNASSESSABLE`、`STABILITY_MONITOR_ERROR`；与全单完成、原候选空池、选择/接口错误、原物理提交错误及冒烟事件上限分别统计。

前缀在PCT下已不稳定时，返回UNASSESSABLE/BASELINE_UNSTABLE，不归因为新动作导致失稳。监测开关开启但缺依赖/配置非法，应启动预检失败，不让订单悄悄降级。批处理中单订单终止不自动取消其他订单；后续受限开发不因此扩大任务矩阵。

### 8.3 持久化与恢复

复用现有持久化架构新增`SELECTED`、`MONITORED`等语义阶段，确切枚举通过新Schema冻结。选择必须在检测前保存，检测必须在正式提交前保存；保留UNKNOWN_SEND与旧模型账目语义。

- 选择已保存、监测未完成：恢复相同动作并检测，不重选、不重发模型；残留临时文件不当有效结果。
- 检测结果已保存、未提交：核对状态/动作/配置，STABLE进入一次原提交；UNSTABLE及监测故障只补齐终态，不重复试放其他候选。
- COMMITTED后：不能重复place，只恢复必要评价/记录；监测结果不能被新算法重新覆盖。
- 已停止订单：恢复只验记录/补落盘，不继续执行后缀。
- 原件被篡改、缺有效监测凭证却声称已提交、enabled/算法或任务身份变化：明确拒绝恢复。

真正掉电发生在提交已持久化与阶段标记之间时，沿用并扩展既有COMMITTED状态恢复规则，用原子检查点/幂等事件确认提交是否发生，不能仅凭缺一个阶段标签再放一次。

### 8.4 结果字段

StabilityResult保留`STABLE/UNSTABLE/UNASSESSABLE/ERROR`，额外开关状态在外层monitor记录，不增加虚假的STABLE。至少绑定：

- algorithm_identity、vendor/补丁/依赖/数值配置摘要；
- 数据、原物理检查、策略、监测、任务及决策身份；
- enabled、state_digest、selected_candidate_id/digest、精确位姿、旧物理结果；
- baseline_status、reason_code、首个异常前缀/可获得的失稳对象；
- 实际评价位姿与height_delta_mm、可获得支撑/组合中心事实、duration_s；
- attempted、committed、decision_stage、termination_reason及记录摘要。

无法可靠定位的失稳对象或解释记null，不编造力矩、概率或真实破坏结果。保存脱敏stage/code，不读取凭证。

## 9. 新旧判定、评价指标与公平性

原oracle继续执行其几何、stackable和承载检查；PCT在选择之后监测等效重心及支撑稳定性，不替代包装容量。面积分流与PCT分流分开标注，不写回对方账目。

新增协议不计划升级为候选硬过滤。若未来用户另行改变此范围，必须重新定义任务；本目标与默认后续路线均为选后监测。凸包判断、70%面积与中心矩形差异须在报告解释，但本轮不删除旧规则。

主结果至少包括：

| 指标 | 定义/限制 |
|---|---|
| 监测开启的稳定完整完成率 | 所有箱真实提交且每次提交前STABLE的订单数/所有计划订单；仅enabled=true有定义 |
| 预测静态失稳终止比例 | PREDICTED_STATIC_INSTABILITY订单数/所有计划订单；不称实际坍塌率 |
| 终止前件数/体积/质量装入比例 | 仅统计已提交箱，失败尝试不计装入 |
| 首次预测失稳进度 | 事件前已提交箱数/计划箱数，另列尝试步号；其他终止为未观察，不补0或100% |
| 终止原因分布 | 原空池、预测失稳、不可评价、监测错误、提交错误、接口错误、未运行、冒烟上限等 |
| 监测调用与覆盖 | 选定动作、开启检查、各status、关闭次数、成功提交分别计；保存结果复用单列 |
| 成本/耗时 | 选择与监测时延分开，前缀冒烟不作整单效率结论 |

计划分母和检测可评价子集分别展示。较少失稳可能来自更早空池/故障，不能单独代表策略更好；失败动作触发停单后不观测后续风险，不把缺失后缀算稳定。关闭实验的稳定完整完成率应为NOT_APPLICABLE，不能凭未检测称全程稳定。

同状态开关开/关时，候选和去除本地运行身份后的实际request_body应相同；运行配置和检查点摘要可以不同。选择器不可读取监测报告或预评结论；不允许失稳后按概率第二名补救。所有未来方法均须经过同一monitor入口，不能只监测Jev。

构造案例可覆盖旧拒绝、新接受情形；真实旧候选已被原oracle过滤，不能据此宣称全域判定比较。

## 10. 构造案例与验收期待

使用明确标记的fixture，不进入正式训练经验库。每类检查给出尺寸、质量、位姿、支撑关系及预期的可解释依据，不从被测代码输出反推期望值。

| 案例 | 期待 |
|---|---|
| 地面箱、居中单支撑 | 合法输入下PCT稳定，质量与几何一致 |
| 单箱中心明显超出有效支撑 | 静态失稳，不用贴边退化点作唯一反例 |
| 新箱局部有支撑，但上载使祖先等效中心越界 | 新算法必须实际传播并识别；仅当前箱检查不足以通过此项 |
| 双支撑跨接 | 凸包与当前单矩形检查可能不同，记录差异；不要求现有候选器Top16能返回fixture |
| 多层、三支撑 | 所有质量/中心有限；质量守恒，异常分配不伪装通过 |
| 同体积不同质量 | 恢复的mass不同，构造偏心案例时质量变化能影响等效中心/判定 |
| 0/90尺寸、非方形托盘 | 中心↔角点往返准确，无二次旋转/轴交换 |
| 自动落高与候选z不一致 | UNASSESSABLE，原候选与状态不变 |
| 基线已失稳 | 标BASELINE_UNSTABLE，不归因于待测动作 |
| 重复、反序评估同一候选池 | 按candidate_id映射的非时间结果相同，无状态污染 |
| 退化凸包、零面积、重合中心、NaN/负质量 | 明确非法/不支持/错误；不得作为稳定样本 |
| setting=2误配置 | 配置加载即拒绝，不调用绕过路径 |
| 开启＋已选动作稳定 | 先持久化监测，再准确提交一次，继续后续事件 |
| 开启＋已选动作失稳 | 保存动作及理由，不place、不换选、不调用后续选择；订单结束 |
| 单候选自动执行 | 仍先监测，不能绕过 |
| 关闭开关 | 不加载PCT、不增加监测判断，原动作/状态和终止行为一致 |
| 监测不可评价/异常 | 分别以技术原因结束，非预测失稳，不静默放行 |
| 中断恢复 | SELECTED/MONITORED/COMMITTED/终止各边界不重复选、不重复提交 |
| 恢复时切换enabled或算法 | 身份错误，拒绝 |

不要求把真实库里不适用的情形硬凑为PASS。声明不支持的几何用UNASSESSABLE并报告覆盖；关键祖先反例不能NOT_RUN后仍宣布模块验收完成。

## 11. 运行接入与拟议CLI

以下为拟实现命令，不代表当前可运行：

```text
python -m semantic_pallet_planner.jev_select smoke-packaging-monitor --dataset <目标二冻结数据> --stability-monitor on|off --output <新目录>
python -m semantic_pallet_planner.jev_select inspect-packaging-stability --artifact <既有运行> --config <监测算法配置> --output <事后报告>
python -m semantic_pallet_planner.jev_select validate-stability-report --report <报告目录>
```

CLI的on/off归一到唯一布尔字段，在启动前写入配置；配置与命令冲突必须报错，不能以未记录的运行参数覆盖。Python入口为monitor_selected_action；关闭时返回DISABLED外层记录而不是实际StabilityResult。

smoke使用本地测试替身，最多目标二相同两个任务、每任务最多8事件；开关配对最多4个受限运行。开关开启的订单可提前预测失稳结束，不补跑到8事件凑数量；另用构造任务确保失稳分支和单候选路径必被覆盖。不得扩大成16任务全单/真实模型矩阵。

inspect是只读事后分析，默认检查历史已选动作；可配置全池仅供诊断，绝不把结论反向用于在线选择。可以从保存事件恢复公共几何事实，不运行旧选择器、不重新生成候选。标`POSTHOC_ONLY`；历史记录第一次预测失稳之后的状态若继续分析，标历史反事实后缀，不当成当前监测策略可达到的结果，不重写历史终止/完成指标。

旧报告及源码用原归档身份核对，当前新增模块有新运行/监测身份，不能重签旧记录。validator仅核对保存记录、摘要和状态机，不重跑PCT；有复算入口须单列。缺少记录标缺口，不伪造结果。

## 12. 产物与身份

```text
semantic_pallet_planner/outputs/VERIFY_JEV_PCT_MONITOR_<ID>/
  upstream_manifest.json environment.json
  source_identity.json config.snapshot.json
  fixtures/                       # 构造状态及真实内核结果
  monitor_smokes/                 # 有限开/关配对运行，不是Jev效果实验
  posthoc/                        # 既有记录分析，独立标记
  monitoring_results/             # 逐已选动作、提交/终止与阶段绑定
  comparison.json summary.json
  engineering_acceptance.json delivery_manifest.json handoff.json
```

最小vendor、补丁及LICENSE可纳入源码；完整下载仓库不自动提交。实验报告进Git忽略的outputs。数据、原物理检查、策略、监测身份分别保存并共同绑定运行；enabled是身份组成部分，关闭时算法执行身份可为null，但配置摘要仍可核对。

summary保留计划任务、选择/检测/提交分母、各status、终止原因、配对差异、开关状态与真实覆盖。原前缀不足以宣称完整可满足或稳态保证；所有16个UNKNOWN任务不因模块接入自动升级。

用户关闭监测不删除代码或日志，不修改历史；用户开启监测也不代表新配置支持真实Jev远程路径。

## 13. 开发阶段与退出条件

| 阶段 | 必做任务 | 完成标准 |

| P0 源码/合同 | 固定提交许可、结果分类、enabled配置、运行与监测身份 | 原件可追溯；选择后停单与非过滤边界明确 |

## 15. 新窗口实施提示词

> 使用目标模式，依据本规范完成P0—P3和S01—S30。固定已下载PCT的提交/许可，将最小内核适配到jev_select/stability；不导入RL环境。新增唯一enabled布尔开关，默认关闭；关闭不执行PCT，开启对任何已选定动作（含单候选）先监测、后提交。禁止PCT过滤/重排候选、提前提示或失稳换选。使用真实mass_kg和精确原位姿，封禁setting=2，落高不符/前缀失稳/数值错误独立分类。保存选择→监测→提交/终止及检查点：STABLE提交一次；UNSTABLE不放该箱、不计装入、终止订单；不可评价/ERROR按技术原因终止，不算坍塌。恢复不重选、不重复放置，开关和算法变更拒绝。完成真实内核构造反例、开关等价、停单、单候选、恢复及安装测试；只做最多两个任务开/关配对的受限8事件本地冒烟，旧记录事后分析标POSTHOC_ONLY。不读密钥、不调用真实Jev/DeepSeek、不运行全量订单或搜索，不改旧数据/物理准入/历史摘要。新产物进outputs，交付实际验收、指标和handoff，不能把预测静态失稳称真实坍塌。止于监测模块可用及选后停止链路，不进入经验效果或候选过滤。
