# Jev J4 业务属性约束、评价指标与对比消融实验设计

日期：2026-11-02。适用范围：当前 J4 v2 数据、Jev 原生 Choice、冻结经验检索，以及同箱候选离线分支研究。

本文汇总当前实现与后续研究设计，不启动模型调用、重新采集或新一轮仿真实验。设计中的实验数量、方法和预算不是新增调用授权。当前事实以源码及封存证据为准，早期研究设想不等于实际实现。

## 1. 当前研究问题与完成边界

目标是在物理可行的候选中，结合公开业务要求和历史经验，选择箱体及放置位置，兼顾订单完成、空间利用和业务合规。经验应保留“触发状态—实际动作—违规后果—替代方案—证据边界”，而非只重复规则。

| 部分 | 当前状态 | 结论边界 |

| J4 数据 v2 | 4来源、66件、33种去重商品、24个任务 | 变体不增加独立来源，非全量原始数据规模 |

## 3. 当前业务属性约束

### 3.1 正式数据中的规则

| 编号 | 规则/属性 | 可执行含义 | B1 | B2 |
| --- | --- | --- | --- | --- |
| BIZ-01 | 普通限载标签 | 累计顶部载荷不得超过标签上限 | 是 | 是 |
| BIZ-02 | 禁压标签 | `no_top_load=true`时，业务允许顶部载荷为0 | 是 | 是 |
| BIZ-03 | 强化例外 | 玻璃＋强化包装＋无禁压时使用强化常量，覆盖普通标签 | 是 | 是 |
| BIZ-04 | 食品/清洁品相容性 | 正式数据为禁止直接面接触 | 是 | 是 |
| BIZ-05 | 食品区域 | 食品底面须完全处于指定区域 | 否 | 是 |
| BIZ-06 | 清洁品区域 | 清洁品底面须完全处于指定区域 | 否 | 是 |
| BIZ-07 | 相对方位 | 食品位于清洁品指定方向，最小间距50 mm | 否 | 是 |

强化优先级0，禁压10，普通标签20；强化和禁压均仅覆盖普通标签。强化匹配条件明确排除禁压，因此不能用强化解除禁压。优先级和覆盖条件应共同解释，不能简单理解为“所有规则取最小值”或“强化总优先”。

区域L/R/F/B是矩形范围，不保证互斥。1200×1000 mm托盘上，L的x范围为[-600,300]，R为[-300,600]；F的y范围为[-500,250]，B为[-250,500]。因此区域规则不等于两个严格分离的半托盘；相对方向规则另外检查。当前四来源的B2包含食品在清洁品前方、左侧或右侧的配置，不把每个任务都概括为食品在右。

### 3.2 用户明确的新语义与尚存差异

用户明确食品和清洁品“不能接触”是不能一起放置。最新 `candidate_branch.py::segregation_feedback()` 将其解释为**同托盘不相容**：对每对已放食品箱/清洁品箱记录一个 `forbidden_co_pallet` 实例，替换旧面接触实例，其他规则保留。

| 项目 | 旧正式数据 | 最新离线分析 | 后续正式迁移要求 |
| --- | --- | --- | --- |
| 相容性 | 禁止直接面接触 | 禁止同托盘，按箱体对计数 | 新业务版本、解析/Schema、评价和策略输入一致 |
| 留出50 mm | 可能消除面接触和间距违规 | 不能消除同托盘冲突 | 不再作为混放修复证据 |
| 允许违规吗 | 业务`evaluate_only`，选择后评价 | 诊断分支允许违规并统计 | 明确业务为软评价还是硬拦截 |
| 多托盘 | 当前案例单托盘 | 未实现分托盘 | 若要求整单完成，设计分托盘或拆单 |

**此前“平移50 mm有效解决食品/清洁品接触要求”的业务结论已撤回。**旧协议结果保留，不按新规则重写历史成绩。

如果不可同托盘作为硬约束，而任务同时含两类货物、只允许一个托盘，则无法全部合规放完。不能把这一业务冲突误归为模型不会规划。新版本需先确定托盘分配及任务完成定义；不同托盘间是否适用相对方位规则也需明确，不能直接照搬旧两类同盘规则。新旧语义不混算收益。

### 3.3 业务限载与物理承载的区别

当前箱体自重范围2.04～10.81 kg，合成物理顶部承载范围4.09～492.96 kg。25/66件物理上不允许作为堆叠支撑，与适中档9/66件业务禁压不是同一集合。

对于每个受影响支撑箱i，计算原顶部载荷`L_i`、本次沿支撑链分配的增量`ΔL_i`、物理上限`P_i`及覆盖规则解析后的业务上限`B_i`：

```text
物理检查：允许作为支撑，且 L_i + ΔL_i ≤ P_i
业务检查：L_i + ΔL_i ≤ B_i
业务剩余余量：B_i − L_i
业务超限量：max(0, L_i + ΔL_i − B_i)
```

顶部载荷不包含该支撑箱自身重量，但新箱自重及其上方载荷会向下传递；多支撑情况下按实际分配计算，不默认全部载荷均匀或全部压在每只底箱上。业务禁压使`B_i=0`；物理不可堆叠直接排除支撑候选，即使业务标签大于0。

真实00100153案例：底箱原有上载6.38 kg，业务上限10.5 kg，仅余4.12 kg；新箱传入8.01 kg，累计14.39 kg，业务超载3.89 kg，尽管物理上限89.25 kg仍满足。直接支撑的强化玻璃箱可承载，也不能替代祖先底箱检查。

### 3.4 必须满足的物理候选条件

当前托盘1200×1000 mm、限高850 mm、总载重1000 kg。物理oracle检查：尺寸和位姿有效、箱体不越界、不重叠、总载重不超限；离地放置支撑面积至少70%、中心投影在支撑面内、直接支撑箱允许堆叠、整条支撑链不超物理载荷。

物理可行候选生成是共享基础，不是经验模块的收益。当前保留每箱最多16项、3箱缓冲联合最多48项；“物理池为空”表示当前候选生成/采样机制没有保留动作，不证明真实场景全局无解。

## 4. 评价指标体系及实现状态

### 4.1 指标总原则

1. 以完整订单、同来源同任务为比较单位，同时报告完成与违规；不能仅凭较少违规奖励少放箱。
2. 新增事件、不同实例、违规步数、实例步数和终态实例含义不同，分别记录。
3. 按规则、对象/对象对和物理单位分解；不把kg、mm和布尔冲突混加为无单位严重度。
4. 保留所有计划任务、接口故障、未运行及未检查项，不通过删除失败改善平均数。
5. 指标值、汇总接线和研究推断分开验收；有底层函数不代表已有正式五方法统计结果。

### 4.2 订单完成与空间指标

设订单计划箱数`N`、已放箱数`n`；计划总体积`V_order`、已放总体积`V_loaded`；固定托盘允许体积`V_container`。

| 指标 | 定义/方向 | 当前实现与解释 |
| --- | --- | --- |
| 件数装入比例 | `n/N`，越高越好 | `placed_item_ratio`；正式主收益指标 |
| 体积装入比例 | `V_loaded/V_order`，越高越好 | `placed_volume_ratio`；必须与件数并列 |
| 完整放完率 | 完成全部计划箱体的订单数/全部计划订单数 | `completed`聚合；运行终止不等于订单完成 |
| 全程合规完成率 | 全部放完且全程无违规的订单比例 | `clean_completed`；暂时违规后消失仍不合格 |
| 终态合规完成率 | 全部放完且终态无违规的订单比例 | `final_clean_completed`；不能替代全程指标 |
| 未放箱数/体积 | 计划总量减已放量 | 箱数可从计划/已放计算；体积可从输入和状态计算，需分析表显式导出 |
| 最大堆高 | 已放箱顶面最高z，mm | `max_height_mm`；仅在装载相当时比较 |
| 固定容器体积利用率 | `V_loaded/V_container` | `volume_utilization`；相同订单完整装完时为常数，不证明布局优化 |
| 包络利用率 | 已放体积/轴对齐占用包络体积 | `envelope_utilization`；空状态为null，需控制装载量与组成 |

“空间碎片化程度、连续可用底面”等属于研究设想，当前没有本文认可的统一正式指标。若引入，先定义公共可计算输入、单位、算法和版本，不能用主观观察直接填写收益。

### 4.3 业务轨迹与严重度指标

令第t次已提交放置后的违规身份集合为`I_t`，初始集合为`I_0`；身份包含规则类型、规则ID和对象/对象对。

| 指标 | 精确定义 | 当前状态 |
| --- | --- | --- |
| 终态违规实例 | `|I_T|` | `final_violation_instances`及分支`final_violations` |
| 新增违规事件 | `Σ |I_t − I_(t−1)|` | `new_violation_events`；消失后再次出现会新增一次 |
| 曾出现不同实例 | `|I_0 ∪ I_1 ∪ … ∪ I_T|` | `unique_violation_instances`；分支对应`ever_unique_violation_instances` |
| 违规步数 | `Σ 1[|I_t|>0]` | `violating_steps`；每步最多计1 |
| 违规实例步数 | `Σ |I_t|` | 离线分支`trajectory_violation_instance_steps`；衡量持续暴露，不是事件数 |
| 每百计划件新增事件 | `100 × 新增事件/N` | `new_violations_per_100_planned_items`；分母是计划件数，不是已放件数 |
| 逐规则数量 | 上述指标按规则拆分 | 轨迹`by_rule`、分支`by_rule`，字段结构不同，分析时显式映射 |
| 业务超载严重度 | 每只违规箱`max(0,L_i−B_i)`，kg | 状态及分支按规则/单位可计算；汇总前区分普通限载、强化和禁压 |
| 相对位置严重度 | 当前未满足最小间距的缺口，mm | 实例`severity`；不与kg相加 |
| 面接触/区域违规 | 对象对/对象实例数 | 不虚构kg严重度；区域当前没有通用连续严重度 |
| 不可同托盘 | 每食品箱/清洁品箱对计1；另可派生是否存在冲突 | 仅新分支评估；不能与旧面接触数量直接混算 |

建议表格同时给出“同托盘冲突对数”和“有冲突托盘比例”，前者反映成对暴露，后者反映托盘是否违反硬要求。当前案例单托盘的后者可从冲突对数派生；多托盘正式指标尚未实现。

可补充“每百已放件违规”等描述性归一化，但必须保留计划分母、绝对数量及装载完成指标，不用它代替主结果。

### 4.4 检查覆盖与早停解释

逐规则报告：计划可匹配实例、已放并可检查实例、已到但延期实例、未到货实例，以及`checked/deferred/not_applicable`状态。规则可能被覆盖或不适用，计划匹配数不等于实际生效数。

覆盖可由`planned_rule_coverage()`和状态`coverage`取得。未来箱体信息仅供离线审计，不进入策略或检索查询。未检查不记为合规；任务未放完时的0违规也不等于全程合规完成。

停止原因至少区分：全部放完、物理候选为空、接口/响应错误、调用预算终止、提交失败、等待恢复。接口失败不是空间决策差的充分证据；候选为空也不证明全局不可装。

### 4.6 统计汇总与源码接线差异

`evaluation.py`已实现订单及轨迹指标，也有`aggregate_v2()`的来源聚合、配对及bootstrap逻辑。但该旧入口主要组织`jev_choice`相对G0/H0的比较；当前`batch_j4.py`生成v3摘要时调用基础`aggregate()`并补充记忆统计，**不是自动输出D0/R0/M0所有配对分析**。

因此正式实验前还需单独实现/验收五方法分析脚本，统一读取冻结结果，并验证来源分组和分母，不通过改旧结果伪造汇总。重算分析不得触发模型调用。

统计协议：同任务先求方法差，再在独立来源组内折叠B1/B2和重复物理场景，最后来源等权汇总。B1/B2与三档变体不是独立样本。独立来源≥10时才按既有协议使用固定seed、2000次来源组bootstrap给配对95%区间；不足10组报告逐来源差异、样本量及描述统计，不伪造稳健置信区间。

当前4来源是已暴露开发集，单个分叉只有1来源。它们均不足以证明正式新来源总体收益。单次调用的来源bootstrap也不覆盖模型重复调用随机性。

## 5. 主对比实验设计

### 5.1 五方法主矩阵

| 方法 | 代码身份 | 决策依据 | 经验输入 | 主要用途 |
| --- | --- | --- | --- | --- |
| G0 | `shared_geometry` | 同物理池中几何优先 | 无 | 几何基线 |
| H0 | `shared_business_lexicographic` | 当前公开规则新增违规、动作后违规及几何 | 无 | 业务强基线，不可省略 |
| D0 | `jev_no_memory` | Jev原生Choice | 空数组 | 无经验模型基线 |
| R0 | `jev_raw_history` | 同一Jev原生Choice | 同训练池的原始历史片段 | 判断补充历史的作用 |
| M0 | `jev_memory_cards` | 同一Jev原生Choice | 通过准入的冻结经验卡 | 判断提炼检索流程作用 |

G0/H0能访问的正常公开信息与模型一致，但H0的离线/当前业务评分不作为专属答案提供给模型。R0/M0使用同一已终止训练轨迹池，不单独为M0挑优质教师答案；原主协议仅D0真实训练轨迹作为正式经验来源。

同状态下，D0/R0/M0请求去掉`state.memories`后须逐字节相同。模型、提示、可见事实、目标、显示种子、候选、错误策略、预算和采样设置保持一致。整单运行后状态可以自然分化；此时要求同样的候选生成机制，而非强行让不同状态拥有相同候选列表。

### 5.2 主要研究问题与允许推断

| 比较 | 回答的问题 | 不能直接推出 |
| --- | --- | --- |
| D0−G0 | 原生Jev相对几何的增量 | 经验有效 |
| D0−H0 | Jev相对业务启发式的表现 | 模型必然更优 |
| M0−D0 | 加入经验上下文的整体作用 | 收益必然来自长期资源策略 |
| R0−D0 | 原始历史上下文的作用 | 历史已被提炼成通用知识 |
| M0−R0 | 提炼检索流程相对原始历史的增量 | 单独的文本组织效果，因压缩、索引等也变化 |
| M0−H0 | 经验模型是否超过业务强基线 | 真实机器人收益或全局最优 |

若M0没有活跃卡或实际注入为空，应报告退化为空经验及`NOT_ESTABLISHED`，不能把该结果当作非空经验实验。

### 5.3 数据分区与原有矩阵

原规范的规划规模为：训练12组×B1/B2=24个D0 episode；校准4组×B1/B2×5方法=40 job；新来源20组×B1/B2×5方法=200 job。这是历史设计，不是当前已完成规模，也不保证适合新的不可同托盘语义。

正式执行前必须重审暴露、分组、可行性与语义版本；开发4来源不能充当20个未见来源。固定来源顺序与完整到货序列，不按模型表现补选。训练只用于提炼；校准只用于冻结参数；测试期间不改卡、不更新库、不换规则、不调阈值。

调用自然上限按任务箱数逐项求和，不把job数误当请求数。新语义或新增实验臂需新计划与明确预算；本文不恢复任何历史已耗尽或已停止批次。

## 6. 消融与机制实验设计

### 6.1 最小机制对照

| 实验 | 仅改变的主要因素 | 固定项 | 主要指标 | 状态与限制 |
| --- | --- | --- | --- | --- |
| M0 vs D0 | 是否注入经验 | 同状态基础请求、模型、候选机制 | 件数/体积、业务新增事件、全程合规 | 主矩阵设计，真实非空M0未完成 |
| R0 vs D0 | 是否补充原始历史 | 同训练池、公开信息、请求合同 | 装载、违规、实际注入覆盖 | 不将0命中当有历史干预 |
| M0 vs R0 | 经验提炼检索流程 | 来源池、检索实现、Top3及预算 | 主指标、长度、命中及角色 | 整体流程比较，不是纯表示消融 |
| M0 vs S0规则摘要 | 历史策略证据 vs 当前规则提醒 | 基础提示、补充位置、模型和候选 | 整单指标及行为变化 | S0现为校准设计，不能当正式已执行臂 |
| 匹配来源/长度的表示对照 | 文本组织方式 | 同证据范围、门控、近似注入长度、检索条件 | 同状态动作、整单指标、实际长度 | 新扩展，需单独冻结；不填充无意义文本凑等长 |

S0仅对当前公开要求确定性摘要，不额外加入人工资源策略。原规范限定校准前2来源组的B2任务作小规模提醒对照；若用于论文正式主张，应在首次正式请求前纳入测试矩阵与预算。

### 6.2 同箱候选排名分叉：当前用户关注的机制

研究问题：对于已选中的同一箱体A，实际第一名放置候选是否比同箱第二名更利于后续业务？

实验步骤：

1. 在训练/校准材料中预先确定来源与决策步，保存精确前置状态；不根据续跑结果选点。
2. 从保存的Jev原生概率中只保留箱体A的候选，按概率降序排列；保留原值及并列说明，不伪造严格第二名或成功概率。
3. 从同一前置状态强制第一名、第二名；若并列或预先登记可加入第三项。更换的是同箱放置动作，不是更换箱体。
4. 每分支重新生成候选，使用同一固定续接策略、到货顺序和终止规则。分叉后不能照搬旧Jev动作或旧概率。
5. 保存全过程，比较装入件数/体积、货物组成、各规则事件、严重度、实例步数及停止原因。
6. 如实交付改善、无改善或代价转移。当前分支不作为正式经验卡的独立真实来源，也不直接用于偏好训练。

最新实现使用固定G0几何续接；旧规范另有固定H0分支设计。二者是不同条件，不能混合结果或默认为用户实验已执行H0。若要研究续接策略敏感性，应事前冻结“候选×G0/H0”的交叉设计，每种策略内配对，再观察跨策略是否一致，不依结果临时换策略。

最新结果（00100153，D0000，同一清洁品箱9.8 kg）：

| 候选 | 原始概率 | 放置件数 | 终态实例 | 实例步数 | 业务超限 | 判断 |
| --- | --- | --- | --- | --- | --- | --- |
| C15，实际第一名 | 0.18 | 6/15 | 12 | 34 | 2.24 kg | 本地续接对照 |
| C36，并列项 | 0.05 | 3/15 | 3 | 3 | 2.24 kg | 少放箱，不是整体优化 |
| C39，并列项 | 0.05 | 6/15 | 7 | 22 | 3.89 kg | 总数下降但超载加重 |

全部物理早停；C39与C15的货物集合和已放体积也不同。结果为未发现全面支配替代，而非证明所有第二名都不好。共3条本地分支、0次新模型请求。真实历史Jev终态与本地续接对照不是同一策略，不用两者相减归因于首动作。

### 6.3 可选扩展消融，当前未执行

| 扩展 | 控制设计 | 可以研究什么 | 必须避免 |
| --- | --- | --- | --- |
| 无门控 vs 有适用性门控 | 同库、同检索、同预算，单独改变门控 | 适用性与负迁移 | 同时换库/改卡后归因为门控 |
| 观察证据卡 vs 分支证据卡 | 同训练来源池、表示预算、基础选择机制；披露额外仿真成本 | 分支验证/筛选流程整体作用 | 将模拟算成第二独立真实来源 |
| 原生Choice vs 外部重排序 | 同库同候选，保留原始回答及最终动作；配几何/业务排序基线 | 外部决策机制的贡献 | 混称原M0或Jev模型自身学习 |
| 经验规模检查点 | 固定来源顺序和冻结库检查点，统一未见评估集 | 规模与覆盖变化 | 测试期按成绩修卡，宣称已在线持续学习 |
| 宽松/适中/严格 | 同来源、几何、到达及方法，分别冻结标签版本 | 约束强度敏感性 | 当作新增独立样本或纯单参数消融 |
| B1 vs B2 | 同来源其他条件匹配，分层报告 | 区域/方位要求增加后的稳健性 | B2同时多加规则，不能分离单条规则作用 |
| 分别移除区域/方位等规则 | 新版本规则子集，逐次只去掉一类 | 单类业务约束贡献 | 与正式成绩混算，或移除用户必须遵守的规则作为部署方案 |

三档同时改变限载和禁压标签，不是纯限载消融。若要单独识别限载强度，另冻结禁压、包装及其他属性，仅改变限载；该变体尚未构建。硬语义和软语义比较属于任务定义变化，也不能简单称为同任务算法消融。

## 7. 判优规则与可接受结论

### 7.1 单案例分支判优

当前`outcome_dominates()`要求：放置件数不少、每条终态规则的数量和同单位严重度均不增加、至少一项终态指标或件数严格改善；若有过程实例步数和不同实例指标，也要求不增加。

当前函数尚未把已放体积、货物集合和规则检查覆盖全部纳入自动门槛，必须在报告中人工并列核对。因此“函数判为支配”也不自动代表整单货物等价的综合改善。若件数相同但体积/货物组成不同，应明确标注剩余差异，不临时设置总分掩盖代价转移。

### 7.2 正式来源级采纳门槛

沿用原J4设计，以M0−D0为主比较：

- 来源加权件数装入比例至少提高3个百分点，配对95%区间下界大于0。
- 来源加权新增违规事件差异的95%区间上界不大于0。
- 完整放完率和全程合规完成率点估计均不下降。
- 接口失败任务数不增加，且所有计划任务保留主分母。
- 并列报告体积、逐规则严重度、覆盖和成本；存在下降明确写为权衡。

这是原研究的工程采纳标准，不是对当前4来源小试的统计承诺。样本不足、空库或语义未统一时不能机械套门槛声称通过。只有M0对R0也有匹配的来源级收益并满足业务约束，才讨论提炼检索流程的增量；纯文本组织作用仍需匹配控制。

正式分析至少区分：`IMPROVEMENT_FOUND`、`TRADEOFF`、`NO_DOMINATING_ALTERNATIVE_FOUND`、`INCONCLUSIVE`、`NOT_RUN`、`NOT_ESTABLISHED`。这些是报告解释状态，不能替代现有各模块具体Schema字段。

### 8.1 必须冻结和保存的材料

### 8.2 建议实施优先级，不自动执行

1. **统一业务语义**：确定不可同托盘的硬/软要求、分托盘范围、区域/方位适用对象，再冻结新数据和规则版本；不覆盖v2。
2. **统一指标分析**：接通五方法来源配对、逐规则严重度、检查覆盖、装载体积/组成与失败分母，先用已有记录核验，不新调模型。
3. **固化同箱分支协议**：保留概率及并列、共享续接与自然终止；当前负结果完整保存，不为正收益重复扩大。
4. **完善经验证据表示与准入**：明确状态、机制、替代和限制；如果引入模拟证据，另开证据合同；开发代理语义核验不冒称独立审核。
5. **满足条件后再冻结正式对比及最小消融**：存在合格非空经验、合法数据和明确预算后，才开展M0/R0/D0及所需S0对照；后续扩展逐项独立登记。
