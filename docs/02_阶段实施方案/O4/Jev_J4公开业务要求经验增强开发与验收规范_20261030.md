## 1. 研究目标、成功定义和边界

研究问题：在业务要求、物理候选机制、实时可见信息和基础Jev模型相同的条件下，从训练订单轨迹中提炼的自然语言经验，能否改善新订单的装载表现与业务合规性？

J4必须完成三个目标：

1. **J4-A诊断与基线稳定**：分清接口失败、当前业务判断、选箱/选位和候选覆盖问题，交付逐步可查的订单记录。
2. **J4-B最小经验闭环**：训练订单结束后形成可追溯经验，冻结经验库，在新订单每步检索并供Jev选择，模型权重不变。
3. **J4-C经验增量验证**：用无经验、原始历史、经验卡及本地强基线对照，分别报告系统、装载、业务和成本结果。

工程验收与研究收益验收分开：完整负结果也可构成合格工程交付；没有显著收益时不得写“经验增强有效”。最终新测试是泛化证据的必要条件，不能用开发单例替代。

本轮生产决策路径不开发：隐藏规则学习、视觉识别、图像输入、AST生成、Jev权重训练、候选器优化、beam/未来订单搜索、卸箱回滚、测试期在线更新或真实机器人控制。经验仅影响现有物理候选内的选择。第10.2节开发分支仅用于独立诊断，不进入生产决策或经验教师数据。

## 3. 冻结任务与公平条件

| 项目 | J4第一版要求 |
|---|---|
| 模型 | Jev选择器固定`jev-1.14.0`，记录requested/served版本；不可用时明确失败，新模型另开协议 |
| 模态 | 文本原生Choice，外层仍只含`model/state/questions` |
| 缓冲 | 3箱，沿用`fill_then_plan`和原完整到货顺序，未到货箱不公开 |
| 动作 | 联合选箱选位，返回局部Cxx；空物理池环境停止，单候选自动提交 |
| 候选 | `e2_original_v1`，每箱≤16、联合≤48，yaw 0°/90°；不以业务或经验过滤候选 |
| 物理 | 原边界、碰撞、支撑、重心、stackable、物理承载检查全部保留 |
| 业务 | B1/B2公开规则、类别/标签、区域与相对关系均明确提供；违规可执行、独立记录并继续 |
| 特征 | 保留J3公开几何分、支撑、当前载荷和一步载荷变化；禁止候选业务答案、未来收益和参考布局 |
| 选择提示 | J4三个模型方法使用同一固定基础提示，仅历史补充区不同 |
| 失败策略 | 每决策最多一次Choice，无自动重试、修复、低置信度接管或本地代选 |
| 记忆使用 | 每订单固定同一冻结库，每步只读检索；验证/测试不写库、不跨订单积累聊天 |
| 生产默认 | 旧J3入口和配置保持原含义，J4必须显式启用 |

相同公共状态和种子必须生成相同候选内容、顺序、别名与编号；记忆不得参与候选生成、别名和显示顺序种子。不同方法分叉后各自继续，不强求整条轨迹的候选始终相同。

J4公共提示固定表达：完成尽可能多的订单装载、避免业务违规、保留可用空间；历史观察可能不适用，当前公开业务和物理条件优先。不得仅在经验方法中额外增加“优先区域”等人工策略。提示文件在第一次J4远程运行前冻结。

### 4.2 版本策略

新配置版本`jev_direct_choice_v3`；新业务实验协议`jev_j4_public_memory_v1`。v3数据对象使用`jev_*_v3`版本，执行与评价算法仍复用`physical_commit_v1`和`business_trajectory_v1`。升级的是协议及绑定能力，不是物理语义。

不能只修改`is_v2()`使任意后续版本命中；增加明确的协议识别与共享语义判断，并核对所有调用点。新方法枚举也须进入checkpoint、plan、metrics和恢复校验，不能只改CLI。

当前`experiment.py::source_manifest()`会递归冻结整个planner包的生产`.py/.json`，故新增模块即影响旧计划校验；提示`.txt`、ReMe vendor和外部依赖还需额外显式摘要。测试、缓存、凭证和运行产物排除。旧实验用其`code_snapshot/`，不得修改旧清单“适配”新源码。

除本包外，仅允许必要的`pyproject.toml`可选依赖/资源打包和文档导航改动。只读复用原E2、几何评分、物理oracle、buffer_state、reference评价及ReMe vendor，不改它们以制造J4收益。

### 4.3 最小配置与接口合同

v3配置保留现有物理/传输参数，至少增加以下字段；这是配置合同片段，不是可直接交给当前CLI的完整配置：

```json
{
  "version": "jev_direct_choice_v3",
  "experiment_protocol": "jev_j4_public_memory_v1",
  "memory_mode": "cards",
  "memory_backend": "cards_local_bm25",
  "retrieval_version": "bm25_public_query_v1",
  "memory_top_k": 3,
  "memory_item_max_utf8_bytes": 1600,
  "memory_total_max_utf8_bytes": 4800,
  "memory_update_policy": "frozen_per_experiment",
  "verification": "records"
}
```

`memory_mode`枚举为`none/raw_history/cards`，由D0/R0/M0固定映射，不由运行时随意覆盖；`memory_backend`与生成器来源独立登记。库摘要在prepare时写入计划，不在包内配置中硬编码某次库的绝对路径。D0也绑定空库身份；R0/M0绑定同一训练corpus及各自索引、快照。

适配层采用下列语义签名；数据对象须经封闭Schema验证，具体Python类型可使用既有Snapshot/dataclass模式：

| 所在模块 | 接口合同 |
|---|---|
| `memory_export.py` | `export_completed_episode(episode, training_manifest) -> EpisodeExport`；无网络、只读，错误来源/未结束时拒绝 |
| `memory_generation.py` | `generate_candidates(export, generator_config, ledger) -> GenerationResult`；只有显式remote_text才联网 |
| `memory_validation.py` | `validate_cards(cards, evidence_exports, training_manifest) -> ValidationReport`；未提供的来源和观察不能成为有效引证 |
| `memory_store.py` | `ingest(export)`幂等；`freeze_snapshot(output) -> MemorySnapshot`；`load_snapshot(path, expected_digest)`只读且校验摘要 |
| `memory_query.py` | `build_query(public_observation, public_policy, candidate_facts) -> Query`；不接收完整task或reference |
| `memory_retrieval.py` | `retrieve(query, snapshot, mode, limits) -> RetrievalResult`；结果含实际文本及本地命中/预算记录 |
| `context.py` | `ContextBuilder.build(..., memories=MemorySnapshot, retrieval=RetrievalResult)`；v3复核库/查询/文本一致性，v1/v2仍只接受原空记忆合同 |
| `memory_reme.py` | `probe()/ingest()/consolidate()/export_snapshot()`；只封装经核实的vendor入口，绝不以空实现返回成功 |

## 5. 方法矩阵与请求一致性

| 代码身份 | 报告简称 | 决策方式 | 额外上下文 |
|---|---|---|---|
| `shared_geometry` | G0 | 原同池几何最高分 | 无 |
| `shared_business_lexicographic` | H0 | 当前公开规则新增违规、动作后违规、几何分 | 无 |
| `jev_no_memory` | D0 | Jev直接选择 | 空数组 |
| `jev_raw_history` | R0 | 同一Jev直接选择 | 训练历史片段 |
| `jev_memory_cards` | M0 | 同一Jev直接选择 | 提炼并通过激活检查的经验卡 |

R0/M0基于完全相同的已终止训练轨迹池，不单独为M0采集优质答案。第一版正式经验来源只用D0训练轨迹；H0、人工方案和诊断评分不进入总结器，避免把强基线答案作为未申明的教师。

D0/R0/M0同状态请求去除`state.memories`后必须逐字节相同，模型、候选显示种子、公共规则、特征、目标、采样及错误策略全部相同。本地方法名、库ID、来源ID和检索分数不发送给模型。

`state.memories`统一为字符串数组：D0为空，R0为历史片段正文，M0为卡正文。正文可见历史观察的性质，但不额外告诉M0“专家经验”“最优动作”。所有溯源和验证字段留本地。

J4-D0是新协议下的无经验臂，不把历史J3请求直接改名为D0成绩。主比较M0−D0；M0−R0用于判断提炼组织是否优于原始历史，未超过R0时不能主张组织收益。

## 6. 经验生命周期与数据合同

### 6.1 白名单训练导出

只能在订单有终止状态、所有已提交动作的独立评价已落盘后执行`export_completed_episode()`。允许未完成或违规订单，保留负例；评价失败待恢复的订单不能提前导出。

总结器可见：当时已观察箱体/公共规则、实际提供的候选事实、实际选择位姿与箱体属性、提交结果、逐步业务反馈、终局装入件数/体积比例与停止原因。计划件数仅作为终局反馈可见，不提前暴露未来数量。

总结器不可见：`task.items`完整未来序列、未到货箱详情、reference_policy/私有AST、候选业务评分、Oracle答案、未执行分支收益、当前验证/测试轨迹。局部Hxxx可用于组织历史片段，必须标明仅属于该历史片段；卡正文不允许永久箱ID、局部Cxx或来源订单查表。

服务故障可保留账目，但从策略提炼输入中排除故障后的伪布局后果。若前缀有可用观察，明确反馈被服务故障截断，不给出“此布局导致订单失败”的结论。

### 6.2 卡结构

卡持久化为JSON；ReMe可使用等价Markdown/frontmatter索引，冻结时以JSON规范化正文和摘要为准。

| 字段 | 含义与校验 |
|---|---|
| `card_id/version/content_digest` | 内容身份及版本；正文变化生成新版本 |
| `status` | `candidate/active/retired/rejected`，不可覆盖旧正文 |
| `applicability` | 从公共状态可判断的适用条件，不依赖订单ID |
| `advice` | 自然语言选择建议，不含可执行AST或绝对Cxx答案 |
| `observed_evidence` | 已发生的观察，区分相关性与因果证据 |
| `limitations_counterexamples` | 失效条件、反例或尚未验证的范围，不得省略 |
| `evidence_refs` | 本地episode/decision/源码摘要与来源组；至少一条真实训练证据 |
| `evidence_level` | 第一版固定`observational`，不生成`optimal/causal_proven` |
| `created_after_episode` | 生成时间及已终止订单身份 |
| `parent_card_ids/generator_digest` | 合并父卡、生成模型/提示/请求身份 |
| `validation` | 结构、来源、冲突、正文泄漏检查及理由 |

正文输出统一英文，减少检索分词差异；当前公开业务中英描述对三个模型臂一致。正式库不预置人工“贴边”“先重后轻”等策略；离线测试卡必须标记`fixture_only`，远程计划拒绝携带。

### 6.3 生成与激活

拟议接口语义：`export_completed_episode()` → `generate_candidates()` → `validate_cards()` → `consolidate()` → `freeze_snapshot()`。接口名属于本包适配层，不假定ReMe存在同名方法。

每终止训练订单最多一次生成、最多2张候选卡；每4个训练订单最多一次合并。每次生成/合并最多一次格式修复，修复只反馈结构错误，不提供正确策略。成功、失败、修复、原始响应、usage和延迟全部记账。

`active`至少满足：Schema通过、证据均属训练来源且早于生成、引证可解析、无当前要求覆盖/泄漏、含限制或反例、同一建议有至少2个训练来源组的支持性观察（依第6.4节判定，不以两条引证存在代替支持成立）。单来源卡先保持candidate，可在后续训练合并后激活；支持性观察不等于因果证明。存在反例时限定适用范围，不能静默删除反例。

激活库最多64卡，超额时按支持来源组数降序、内容摘要升序确定性保留，其他转retired；该规则提前冻结，不按校准/测试收益挑卡。空库是允许结果，但M0退化为空经验时，研究收益必须记`NOT_ESTABLISHED`。

冻结快照包含卡正文、历史片段、状态、规范化检索文档、索引参数、生成器配置、证据摘要和内容清单；验证/测试过程只读。每次训练更新产生新快照，不就地改已发布库。

### 6.4 经验作用、引证与激活的可执行标准

卡增加本地`knowledge_role`：`rule_restatement/current_rule_application/sequential_resource_strategy`，分别表示规则复述、当前状态规则应用、跨步骤空间/区域/承载资源分配。该分类不发送给Jev、不参与候选评分；冻结时保存分类依据和判定者。第一版主M0库不激活纯规则复述卡，保留其候选记录及排除理由，避免把重复公开要求当成训练所得策略。分类有歧义时保留candidate，不能自动提升为长期策略。

以下仅为合同说明，不得直接作为正式卡预置：

- 规则复述：“食品必须在指定区域内。”
- 跨步策略：“受限箱与通用箱同时可选，且通用箱会占用受限箱当前唯一可用区域位置时，比较保留该位置的动作；若支撑或剩余尺寸不适用则放弃该建议。”后者必须由真实训练观察产生，而不是人工写入库。

每卡正文必须明确适用情境、比较候选时要注意的资源或取舍、限制/失效条件；“合理利用空间”等无法影响具体比较的泛化句保持candidate。建议不能覆盖当前规则优先级，也不能承诺未知到货的尺寸或收益。

每条`observed_evidence`增加结构化事实引证：来源组、episode/decision、证据字段路径、该时刻属性/位姿/已发生反馈、观察结论及支持范围。至少两个不同训练来源组均能核对卡声明的适用事实和所述结果，才计入支持数；同源B1/B2及重复片段只计一个来源。未执行动作、未观察箱体和没有记录的未来收益不能作支持；“先做A、随后结果B”只说明观察关联，不足以证明A导致B。

自动验收只证明字段、来源、数值与记录一致。开放式建议是否被事实支持另存`semantic_review`（判定者、版本、理由和结论），不能以Schema PASS冒充语义正确。第一版允许训练阶段人工只读审核并接受/拒绝/退回candidate，不允许直接重写卡、补策略、删反例或按校准/测试成绩选卡；保留全部审核账目并在报告披露人工介入。若另启用文本审核器，必须事前冻结其配置、预算与账目；未启用时不隐式调用。

合并只处理适用范围与建议相容的卡，保留父卡、支持和反例。冲突卡记录`conflict_group_id`；能用公共事实划分适用范围时形成新候选版本并重新审核，不能划分时均不进入active。不得根据测试收益选择冲突中的胜者。训练来源扫描中发现的反例必须保留；没有发现反例只表示本训练语料未观察到，不表示策略普遍成立。

### 6.5 总结输入预算与确定性导出

先冻结文本后端的上下文上限、单请求输入预算、输出预算和安全余量；不能把整单含全部候选的导出默认视为一定可装入。完整白名单证据保留在本地，总结请求使用确定性的事件窗口：每个已提交决策保留所选动作、当时可见属性、必要的资源事实、真实反馈及终局结果，字段/精度/窗口选择顺序写入版本合同。候选事实需要压缩时只用预注册的公开事实投影，不注入候选业务评分、不人工挑选成功片段。

第一版仍为每训练订单最多一次生成，窗口在本地构造，不额外逐窗调用LLM；合并次数和总计60次文本调用自然上限保持第6.3/9.2节合同。若确定性投影仍无法满足预算，记录`GENERATION_INPUT_TOO_LARGE`及未覆盖事件，不截半条事实、不偷偷增加调用。需要分层多次总结时须先修订协议与调用上限，不在正式运行中临时扩展。生成结果只可引用实际送入该请求的证据，不能引用虽在本地但总结器未看到的完整导出。

## 7. 查询、检索、上下文预算和绑定

### 7.1 固定检索

第一版使用BM25，`k1=1.2`、`b=0.75`，关闭embedding、图展开、后台自动更新和额外查询模型。`memory_query.py`统一从当前布局高度/可用箱尺寸质量/支撑与载荷事实、公开类别与业务要求、候选公共特征产生中性查询。

固定小写英文词元及数值单位规范，记录tokenizer版本、完整查询和query_digest。不得用方法排名、未来箱、私有规则或旧测试成绩构造查询。

R0/M0索引内容不同，但检索实现、词元规则、参数、Top3和预算相同；只取正分条目，同分按内容摘要升序。索引在计划冻结前建立，不因当前测试运行改变。无命中即空数组，记录`NO_MATCH`，不得人工补卡或改用H0答案。

检索前仅允许从当前公开状态计算的适用性门控：采用冻结的有限字段与比较算子，作为本地记忆检索元数据，不是模型生成AST或候选业务成本。所有门控字段须来自`build_query()`白名单；不允许完整task、未来到货或私有评价。R0片段适用字段由相同公共字段投影生成，M0条件须有证据并审核；两臂共享门控执行语义，文档内容导致的差异如实保留。

条件取值缺失或无法确定时排除该条并记`APPLICABILITY_UNKNOWN`，明确不满足时记`NOT_APPLICABLE`。第一版门控不能判断的开放式文字限制保留在正文交给Jev，不将它标为已自动验证。剩余条目再走原定BM25。逐步保存门控依据、排除项、正分排序及实际注入，统计Top3来源覆盖、卡片集中度和适用性抽样审计结果。命中率不等于适用率，不能只用“检索成功”证明经验被正确使用。

### 7.2 可执行预算

最多3条补充文本；每条UTF-8正文≤1600字节，`canonical(state.memories)`整体≤4800 UTF-8字节，正文中须保留限制/反馈。卡整体装入或跳过，不截掉反例；历史片段按完整事件边界预构建，超限的单事件片段排除并登记，禁止截半句后改变事实。

该字节预算不声称等于1200 token。真实请求token按服务usage报告，全文仍受冻结请求字节和服务上下文约束。完整物理池与公共事实优先，不为容纳记忆静默删候选；超过上限则记录`MEMORY_CONTEXT_TOO_LARGE`并停止该job，不能偷偷缩短D0输入。

原始历史片段按“一次真实决策事件”预构建，不直接塞入完整请求。固定投影至少包含：当时已可见且与所选动作相关的箱体属性、所选箱体/位姿、公开业务要求引用及相关资源事实、真实新增反馈、终局件数/体积比例/停止原因。公共候选只保留预注册的几何/支撑/载荷摘要及实际动作，不附未执行动作的伪结果；被省略字段在清单中说明。R0不写建议和概括结论，投影对所有事件执行，不按成绩筛选。

历史片段须自包含，不能只留一个在当前请求中无定义的历史规则或对象ID。必要语义无法在1600字节内完整表达则排除并记原因，不删掉负反馈求入选。正式前在训练库预检可用片段率、排除率和检索覆盖；R0大量无法注入时先在校准阶段修订统一预算/投影，再冻结正式协议，不能测试结束后调整。

报告R0/M0实际条数、字节/token、命中来源和排除比例。相同预算上限不代表信息量或检索难度相同；M0−R0主比较评估整个提炼与检索流程，若要把收益单独归因于“文本组织”，还需第12.3节的匹配控制。

### 7.3 摘要和恢复

v3本地绑定至少增加：`memory_snapshot_digest`、`corpus_digest`、`query_digest`、`retrieval_digest`、`injected_text_digest`、`memory_mode`、`retrieval_version`，继续绑定状态、候选、映射、公共规则、配置、提示及实验身份。

每个decision持久化命中条目、分数、排除原因、实际注入文本与预算；checkpoint固定订单的库摘要。改变卡、索引、查询、正文或库版本后，旧回答不得复用；恢复必须拒绝不一致。

现有RESERVED→原始回答→COMMITTED→评价顺序继续保留。未知发送不自动重发；已提交但评价失败只补评价。不得在恢复中自动生成新卡或重新检索一个已保存决策。正常新决策才查询冻结库。

## 8. 文本生成后端与ReMe集成

**Jev原生Choice路径不是经验文本总结器。** `typesafe_api_key.md`只用于既有Jev调用；不假定该凭证也可调用文本生成接口。开发者不得硬编造一个生成模型或用离线字符串替身冒充真实LLM经验。

总结后端提供显式`offline_fixture/remote_text`模式。`remote_text`计划必须冻结provider、endpoint、精确模型、采样、最大输出、提示、凭证环境变量名及调用预算；没有可用文本后端时，先交付导出/存储/检索工程，生成标记`NOT_RUN`，不能宣称J4-B研究链路完成。

ReMe适配按两级交付：

- B1：本包冻结卡库＋确定性BM25，方法标记`cards_local_bm25`，不称为ReMe收益。
- B2：核实本地`ReMe-main/reme/reme.py::ReMe`、文件检索及`reme/steps/evolve/auto_memory.py`的实际调用合同，交付最小能力探测、真实调用账目、导入导出和冻结快照；方法标记实际`memory_backend`。

主实验使用同一冻结正文和规范BM25；ReMe可承担真实提炼/维护及索引构建，运行时不得隐式启用额外检索增强。若vendor检索无法满足本规范，保留本包BM25并如实报告ReMe承担的部分，不声称端到端ReMe检索。若不能接通ReMe，B1仍可验收，B2标记未完成。

依赖使用J4可选依赖组或独立环境，锁版本；不为复用vendor将其测试/源码打包进planner wheel。冻结vendor生产源码树摘要及工作区，关闭不受账目管理的后台任务、embedding、auto_dream等额外模型调用。

## 10. J4-A诊断与订单过程产物

### 10.1 必须输出的诊断

每步记录物理采样池/TopK/各箱候选数、实际选择、同状态几何选择、选箱差异、姿态差异、支撑与载荷、公开业务新增事件及当前违规。业务成本由离线诊断器读保存事实计算，只用于分析，不回填模型输入。

### 10.2 小规模长期策略分支诊断

在训练/校准来源上最多预选4个状态，按来源组/决策顺序确定性取样，优先包含受限区域占用、承载资源消耗或空间阻塞；不得从正式测试结果挑案例。预先写明实际动作、一个物理可行替代动作及选择依据，不以试跑终局最好者作为替代动作。替代动作不回填正式经验输入或主方法。

各分支从同一已保存状态开始，强制执行各自首动作，后续统一使用固定H0及原候选/到货机制，不调用Jev；分支执行器可读取完整历史订单以驱动到货，但续接策略每步只见正常公共状态。记录首步及后续候选、件数/体积比例、违规、停止原因和分支源码摘要。此为明确标记的局部反事实仿真实验，不是断网回放或正式方法成绩，也不替代真实经验臂实验。

第一版证据仅表明“在该状态、该替代动作与H0续接策略下”的结果差异，不证明全局最优或Jev续接也会改善。分支结果不进入第一版总结器/卡激活支持数，保持经验只来自D0实际轨迹；若以后纳入，另开教师数据协议。缺少精确状态、物理接口或可用案例时标`NOT_RUN/NOT_APPLICABLE`；仍可做主实验，但不得以案例文字宣称长期机制得到验证。

### 10.3 过程查看

新增包内离线构建器（优先复用`jev_select/viewer/`，不在报告目录新建平行生产实现），生成`outputs/JEV_J4_PROCESS_<ID>/index.html`单文件页面，只读取保存事件。展示到货/缓冲、当前候选、选择箱体和位置、实际提交、注入经验、逐步业务事件、最终停止原因；支持逐步前后切换及方法切换。

经验引用与正文分开显示，注明历史观察；界面不显示密钥。未到货箱不提前展示，轨迹停止后不补放箱体；已保存源文件摘要写入`source_hashes.json`。页面是过程查看，不等于重新执行或独立规划验证。

## 11. CLI与产物合同

以下为**拟实现接口**，目前不能直接运行。命令名称可在首次J4远程计划前调整一次，必须同步更新README和本文，语义不得省略。

```text

python -m semantic_pallet_planner.jev_select preflight-j4 --plan <计划> --api-key-file <凭证路径>

python -m semantic_pallet_planner.jev_select export-memory --experiment <已结束训练实验> --output <新导出>
python -m semantic_pallet_planner.jev_select build-memory --input <训练导出> --mode offline|remote --output <新库>
python -m semantic_pallet_planner.jev_select validate-memory --memory <库> --training-manifest <清单>
python -m semantic_pallet_planner.jev_select freeze-memory --memory <库> --output <只读快照>
python -m semantic_pallet_planner.jev_select inspect-j4 --experiment <实验> --output <新报告>
```

`prepare-j4`至少接收数据/来源清单、methods、memory快照、配置、全局及每job Choice预算、文本生成预算、显示seed和`verification=records|sampled|full`。调用预算用显式正整数，缺省不允许远程运行；不能复用其他campaign未说明的unlimited授权。

`preflight-j4`零网络：校验版本、来源分组、经验依赖、模型配置、首步请求体、自然调用上限、凭证可解析与输出目录。凭证只读，不能冻结入计划。生成后端另行预检，不误用TypeSafe密钥。

默认`verification=records`：核对Schema、计划/源码/库摘要、请求映射、回答、动作/位置/检查点、分母和账目；不强制末尾全量轨迹重执行。小规模恢复和关键v3路径在集成测试覆盖。sampled/full须在计划中显式选择，报告其真正执行范围，不把records称为完整回放。历史J3免回放状态不改。

## 12. 指标、收益判据与报告限制

### 12.1 必报指标

- 系统：计划/完成记录/未运行/失败job数，HTTP、响应无效、未知发送、单候选自动执行、有效模型提交分别统计。
- 装载：完整放完率、全程合规完成率、逐任务件数和体积装入比例、未放及未到货数量。
- 业务：新增事件、唯一实例、持续违规步数、最终违规、每规则匹配/已检查/延期/未观察覆盖；不同物理单位不求混合严重度总和。
- 空间：最大高度、包络利用率；少放箱形成的低高度不解读为改善。完整订单的固定托盘体积利用率不能作为布局改善证据。
- 经验：命中率、适用性门控/未知/预算排除、注入条数与字节/token、Top3来源覆盖及卡片集中度、三类knowledge_role占比、活跃/候选/退役卡数、生成失败/修复、人工/自动审核情况、库大小及每步检索时长。
- 成本：Choice与总结/合并/修复分别计请求、输入/输出token、延迟和费用；未知usage保持null，历史参考单价与当期核实单价分列，不称参考估算为实际账单。

配对先对同任务求差，再折叠同来源B1/B2与重复物理场景，按来源组报告均值与bootstrap区间（固定seed，2000次）；样本不足10组只报告差异和来源数。全部失败保留主分母，无接口失败子集仅作描述。测试一次调用的区间不代表模型重复调用的不确定性。

### 12.2 预注册采纳门槛

主比较M0−D0，以平均件数装入比例为首要收益指标，业务新增事件为约束指标。第一版候选采纳要求：来源加权件数装入比例提高至少3个百分点、配对95%区间下界>0；来源加权新增事件差异95%区间上界≤0；完整放完率与全程合规完成率点估计均不下降；接口失败任务数不增加。

件数为首要指标，但体积装入比例必须并列报告；件数提高而体积下降时明确标记权衡，不概括为所有装载指标都改善。业务事件按规则类型及检查覆盖分列，接触/相对位置的成对计数不能解释为与单箱限载相同的严重度。少放、少检查或提前停止造成的低违规不能单独认定为合规策略提升。

“接口失败任务数不增加”属于系统工程采纳条件，不是模型策略因果判据。全部计划任务保留主分母，另列双方均无接口故障的配对子集用于描述；不能以子集替换主结果。若策略指标改善但服务故障使采纳失败，分别报告策略观察和系统未达标，不把所有差异归于经验。

这是本轮工程采纳规则，不是统计功效承诺；20个来源可能无法满足，应如实报告`INCONCLUSIVE`或未达到，不能降低门槛重签测试。只改善业务、装入未达门槛时报告业务收益或权衡，不称综合采纳。H0/G0结果并列，M0超过D0不自动意味着超过强基线。

只有M0对R0也显示配对收益、并满足相同业务约束时，才讨论“经验提炼检索流程优于原始历史”；组织形式的独立收益另受第12.3节匹配控制限制，否则只能讨论经验上下文整体作用。上述规则不代替多指标完整报告，也不证明通用最优或真实机器人收益。

### 12.3 作用机制控制与允许的结论

在校准阶段增加小规模`S0`固定规则摘要提醒对照。固定采用校准清单按来源组排序的前2组B2任务，仅新增2个S0 job，D0/M0复用相同最终协议的已有校准结果；协议改变时旧结果不混用。调用自然上限为该2任务箱数之和，单独计入校准计划，不计入正式200-job或文本生成60次上限。摘要来源为当前公开业务要求的确定性改写，不使用训练经验、不增加人工空间策略；与D0共用基础提示、候选及错误策略，仅在相同补充区注入摘要。任务清单、摘要、方法身份、预算在该对照首次请求前冻结；S0仅作校准诊断，不自动增加正式五方法矩阵，也不能用校准结果声称正式新来源收益。

若M0与S0表现相近，只能说明可能主要是规则提醒或当前业务应用作用，不能声称经验改善长期规划。S0弱于M0同样不能单独证明长期机制，还须结合卡片内容、实际使用案例和第10.2节证据。若要在论文正式比较经验与规则提醒，须在首次正式请求前将S0纳入预注册测试矩阵及调用预算。

M0−R0同时改变文本压缩、文档划分、适用条件及索引内容，严格表述为“提炼检索流程相对原始历史的增量”。要单独主张组织形式有效，可在校准阶段预注册少量同状态、匹配证据来源且近似等注入长度的比较；记录实际长度，不以补无意义文本强行等长。该诊断不按效果选正式卡、不替代整单正式结果。未执行匹配控制时限制结论，不额外扩展正式付费矩阵。
