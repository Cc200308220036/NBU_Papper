## 1. 已确认的开发方向

用户确认：Jev 的输入继续使用公共状态、商品属性、候选特征、业务要求及预留经验字段；**输出直接是候选序号，不再生成 AST、约束程序、坐标或解释文本。**

本轮目标是建立可独立运行、可审计、可离线回放的候选选择链。后续再由 LLM 在订单结束后提炼和验证策略经验，将相关经验注入同一个决策接口。本轮不开发完整 ReMe、LLM 订单反思、参数训练或自主代码修改。

### 1.1 职责划分

| 组件 | 负责什么 | 本轮明确不负责什么 |
|---|---|---|
| 环境 | 接收真实到货、维护缓冲和已放箱体 | 将未到货物品交给选择器 |
| 几何候选器 | 按当前状态生成坐标与0°/90°姿态，物理过滤 | 按隐藏业务答案挑选候选 |
| 公共业务检查器 | 从公开要求确定性检查候选、提交前复查 | 用私有参考答案替方法纠错 |
| Jev | 在给定候选之间选择一个序号 | AST生成、连续坐标搜索、精确载荷运算 |
| 提交器 | 将序号恢复为原候选，验证绑定并更新状态 | 接受模型修改的位姿或商品属性 |
| 独立评价器 | 提交后检查整单与违规、解释失败 | 参与在线候选排序 |
| 后续LLM经验模块 | 从轨迹提出并验证可迁移策略经验 | 修改当前订单硬约束或直接更新Jev权重 |

### 1.2 “不做 AST 生成”的准确含义

新远程链没有 AST 生成请求，也不接受 `policy_ast` 模型输出。旧工程的内部规则表示可以继续用于公共业务检查与原 `commit()` 兼容，但它由公开规则本地确定，属于基础设施，不作为 Jev 的研究输出。

首版公共业务规则来源只允许两种显式途径：

1. 当前可支持的公开作业单，由本地 Public Parser 确定性解析；
2. 任务输入中另行声明、对各方法同样公开的规则配置。不能把现有 `task.reference_policy` 直接改名当作该配置。

第一种作为本轮默认。为兼容现有提交绑定，可每步本地编译，或复用语义相同的政策后重新构造当前请求对应的本地响应；不能复用过期状态绑定。解析不支持时在调用 Jev 前明确失败，不转而调用 LLM 生成 AST。

这里不承诺删除整个仓库中的 AST 代码；删除它既非本轮目标，也会影响历史实验。主张是“**Jev直接选择动作，约束由程序执行**”。

## 2. 当前代码与改动边界

### 2.1 当前调用链

`o4/extensions/e5/episode.py` 当前先执行 `compiler.compile()`，取得 AST；再调用 `choose()`；随后通过 E2 `action_for()`、`commit()` 提交，最后进行参考评价。

Jev 的逻辑接点位于**生成和筛选候选之后、构造提交动作之前**。不是把 `RemoteCompiler` 的模型名换成 Jev。

| 已有文件/函数 | 当前行为 | 本轮使用方式 |

## 3. 首版动作空间与对照规则

### 3.1 固定的公共任务条件

- 默认缓冲容量3，另保留容量1的选位实验；箱体直立，yaw仅0°/90°。
- 沿用现有到货机制 `fill_then_plan`；WAIT/EOS由环境决定，不交给Jev。
- 每个已到货待码箱最多16个物理候选，联合最多48项。坐标与候选保留规则首版使用原E2版本，不能自动启用B0或layout_v2。
- 每个候选表示完整动作：`pick_item_id + pose + oriented_size_mm`，一个选择同时决定选箱与选位。
- 原始候选及物理元数据只读保存；显示序号只用于模型交互。

### 3.2 默认候选范围：业务可行全集

新直接选择实验的默认 `selectable_pool` 为 `hard_business_feasible`：在原E2返回的联合物理Top-K中，保留**公共业务检查器允许的全部候选**。

不只提供各箱 `group.selected`，否则位置已被程序选好；也不默默继承 `eligible` 中的heavy_low/heavy_center软预算，以免可行空间先被旧策略过度限制。重箱低位/居中若属于公开软要求，保留在目标说明及特征中；首版不将其作为隐藏硬过滤。

这是相对旧E5“选择范围”的显式变化。因此必须同时提供同一范围内的新对照：`shared_geometry` 与 `shared_constrained_first`。旧E5结果只列为历史参考，不能直接把新旧分差全部归因于Jev。

可额外配置 `legacy_soft_eligible`，严格保留旧0.05/0.25软预算；它是单独的动作空间消融，各方法一同切换，另有配置摘要。不得将两种模式混为同一实验。

物理可行但业务未过滤的 `physical_only` 不是首版开发范围。默认模式中业务违规为0主要来自确定性屏障，模型研究目标是避免后续受阻、提高完整合规装入；不得据此声称Jev独立学会了规则检查。

### 3.3 零个、一个和多个候选

| 数量 | 行为 | 账目 |
|---|---|---|
| 0个物理候选 | `STOP_NO_PHYSICAL_CANDIDATE` | 不调用模型 |
| 有物理项但业务可行项为0 | `STOP_NO_BUSINESS_CANDIDATE` | 不调用模型；不添加任意拒放选项 |
| 恰好1项 | 按统一规则自动提交 | `SINGLETON_BYPASS`，不是模型成功 |
| 至少2项 | 一个Choice选择一个联合候选 | 真实或离线模型决策 |

当前允许不等于整个未来订单必然可行；相对位置等deferred关系仍按现有语义在后续状态复查。终止不证明连续几何全局无解。

## 4. 新代码接口契约

下列是设计签名；实际已实现模块可导入，精确参数以jev_select代码及README为准。类型可以使用dataclass或TypedDict，但公开字段与错误语义必须落入版本化Schema。

```python
class CandidateProvider:
    def build(self, state: dict, observation: dict,
              generator_config: dict) -> "CandidateBundle": ...

class PublicBusinessGuard:
    def resolve(self, observation: dict) -> "PublicPolicyContext": ...
    def evaluate(self, observation: dict, policy: "PublicPolicyContext",
                 candidates: list[dict]) -> "BusinessEvaluation": ...

class ContextBuilder:
    def build(self, observation: dict, bundle: "CandidateBundle",
              public_policy: "PublicPolicyContext",
              memories: "MemorySnapshot") -> "DecisionContext": ...

class CandidateSelector:
    def select(self, context: "DecisionContext", *,
               decision_id: str) -> "SelectionResult": ...

class JevTransport:
    def build_body(self, context: "DecisionContext") -> dict: ...
    def complete(self, body: dict) -> "TransportResult": ...

def run_episode(public_environment, selector: CandidateSelector,
                config: dict, *, resume=None, on_checkpoint=None) -> dict: ...

def replay_experiment(experiment_root, *, network_allowed=False) -> dict: ...
```

`CandidateProvider`不接收AST或私有任务。公共检查器只接受当前公共观测，不读取 `reference_policy`。环境可以内部持有到货流，但selector/context接口不接收完整任务对象。私有参考评价仅在提交之后调用。

### 4.1 CandidateBundle

至少包含：

- 完整物理候选、分箱生成计数、候选器版本；
- 业务检查结果、配置指定的可选子集；
- 本地 `C01…C48 → 原候选` 映射；
- 物理池、可选子集与映射的摘要。

为保证职责明确，可将业务结果附加到provider输出形成的新bundle，而非在provider内部执行业务解析。不得修改原候选位姿后继续使用旧摘要。

### 4.2 DecisionContext 与本地绑定

区分两个对象：

1. `model_state`：真正发送的白名单事实与经验；
2. `local_binding`：本地用于审计和恢复的身份、映射和摘要，不要求Jev回显。

`local_binding`至少包含：`decision_id`、`job_id`、`event_index`、原公共观测的四项绑定、`candidate_set_digest`、`selectable_pool_digest`、`display_mapping_digest`、`memory_digest`、`prompt_version`、`feature_version`、`model_config_digest`、最终`request_body_digest`。

`SelectionResult`至少包含：

```text
status                       # selected / singleton / provider_failure / ...
selected_display_id          # Cxx；仅有效选择或singleton有值
selected_candidate_id        # 由本地映射恢复，不由模型生成
source                       # jev / local_baseline / test_double / singleton
requested_model / served_model
probabilities / confidence   # 原始模型元数据；singleton不伪造概率
attempt_ids / usage / latency_s
local_binding_digest / raw_response_digest
```

失败时选择字段为空。Jev返回的唯一动作语义是候选序号；完整HTTP响应中的概率、置信度和usage作为测量元数据保留，不是解释或AST。

## 5. Jev输入设计

### 5.1 白名单内容

| 输入部分 | 具体字段 | 来源与限制 |
|---|---|---|
| 托盘 | 尺寸、载荷上限、坐标约定、公开区域 | 当前公共观测 |
| 已放箱 | 位姿、尺寸、质量、类别、禁压/限载/加固属性 | 仅已到货事实 |
| 待码箱 | 尺寸、质量、准确属性、槽位、到货顺序 | 最多3箱；无虚构托盘位姿 |
| 当前业务说明 | 原作业单及确定性同义英文说明 | 不改变阈值、范围或优先级 |
| 决策目标 | 完整合规装入优先，再比较已声明的布局目标 | 模板与优先级冻结 |
| 候选 | 显示编号、选箱、位姿、方向尺寸及可计算特征 | 完整联合动作 |
| 经验 | 当前决策前已激活的相关经验 | 首版固定为空；预留接口 |

禁止包含：私有参考AST、Oracle候选或允许集合、完整未来订单、未到货箱的属性/数量/序列、任务划分、来源订单键、当前订单结束后才形成的经验、提交后reference诊断。

物理候选检查得到的支撑、累计载荷等可公开事实可以使用；不可直接发送带有上述私有字段的整个 `task`、`event`、`generation` 或历史原始日志。物品用本次公开别名关联，来源标识只留本地日志。

### 5.2 特征分层与避免夸大

首版 `features_basic_v1` 包含：箱体尺寸/质量、姿态与占地、底面高度、支撑比例、支撑箱属性、几何分及其已有分量、业务检查后的明确状态。可确定性计算并提供重箱高度/距中心特征，避免让模型自行做精确算术。

`features_layout_v1` 是单独配置的增强实验：复用 `quality.measure()` 的侧向接触、对齐接触、狭长空白比例和自由区段特征，并记录新增计算耗时。所有模型/本地对照获得同一版本特征。

现有 `remaining_capacity_prediction` 与 `business_support_quality` 为NOT_IMPLEMENTED；首版不伪造剩余可容纳数量、整单成功率、真实稳定性或业务可用支撑预测。原始数值可附单位，必要时加入预声明的语义描述；不能根据结果临时改变分箱阈值。

### 5.3 语言和编号

官方说明英语为主要训练语言。因此首版用英文固定问题及英文键名；公共中文业务要求保留原文，可配程序生成的等价英文模板，不调用LLM逐步翻译。对应对照方法使用相同事实和目标语言；中文输入效果可另立消融。[S3][S4]

为减少第一项偏好，默认将可选原候选按固定姿态键建立规范集合，再按冻结seed、任务公开身份和decision_index产生显示排列，依次分配C01等序号。内部候选指纹不作为选项语义。固定状态比较中各模型使用完全相同的排列；跨轨迹状态分叉后按各自状态生成。

标签仅在当前决策有效。经验内容不能包含Cxx或具体来源答案。顺序鲁棒性检查保持物理动作不变，只改变显示排列，按实际动作比较而非标签比较。

## 6. 官方API指导

### 6.1 核实结果与版本

官方文档核实日期：2026-10-29。使用原生HTTP：

```text
POST https://api.typesafe.ai/v1/systemone
Authorization: Bearer <TYPESAFE_API_KEY>
Content-Type: application/json
```

主请求是 `model`、`state`、`questions`。一个`Choice`问题用 `type="choice"`、`instructions`与`criteria`定义，criteria键是选项名，值可包含选项描述。官方支持最多255选项，足以容纳48项联合池。[S1][S2]

模型配置首版固定 `jev-1.14.0`，正式实验不使用会漂移的 `jev-latest`。按核实时文档，默认上下文为每请求64k、每问题32k；本方案只有一个Choice，state加该问题需满足32k。Jev公开版本为文本输入，不启用图像或长上下文扩展。[S3]

### 6.2 请求和响应示例

### 6.3 HTTP实现选择

生产首版在 `jev_select/transport.py` 中使用标准库 `urllib.request`，保持与原工程相近的显式一次请求模式；开发者实现Bearer认证、超时、HTTPS校验、拒绝重定向、响应大小限制和错误分类。密钥只在发送时从环境读取，不能进入请求体、原始响应日志或manifest。

官方Python SDK可作为对照参考：`from typesafe_sdk import TypeSafeClient, Choice`，通过 `client.system_one(state=..., questions=...)` 使用；但首版不依赖SDK，避免其默认自动重试绕过实验账目。[S5][S7]

### 6.4 响应验证与置信度

验证：HTTP成功、JSON结构正确、服务模型与固定配置一致、`answers.next_action.type==choice`、choice属于本次criteria、概率键与可选序号一致、各概率有限且处于[0,1]、概率和在冻结容差内、confidence有限且处于[0,1]。choice应属于最大概率项，允许数值容差下并列。示例容差可设`1e-5`，须写入版本配置。

记录原始值，不自行改成更好看的分布。confidence是分布派生的确定程度，不是整单成功概率，也不是安全证明。[S6]

首版 `confidence_policy=record_only`：有效回答照常提交，不因低置信度让LLM或搜索代选。这样可测Jev本身。低置信度接管作为另一个未来方法，不纳入首版结果。

畸形回答不要求“生成式格式修复”。记录`INVALID_RESPONSE`，本任务停止并保留分母；有效但选得不好的回答同样不能触发重问或偷偷改选。

### 6.5 官方价格与使用边界

核实时官方定价为每百万输入token 0.042美元，输出token免费；这只是有日期的参考。冻结单价来源，按实际usage计算估算费用；usage缺失记null，不能记0。价格和低延迟不证明Jev模型尺寸小、能本地部署或擅长三维长期规划。[S3]

官方不提供客户数据微调/LoRA；经验通过state进入，不宣称参数进化。1.13的官方限制页涉及算术、间接推理、冗长输入和选项顺序，仅能作为新版测试设计线索，不能直接当作1.14已经测得的错误率。[S3][S8]

## 7. 新状态机与提交流程

首版每个真实放置决策只在根状态调用一次Jev，不在beam节点调用。流程固定：

1. 环境执行WAIT/接收到货/EOS，维护原守恒条件。
2. 从当前状态建立原公共observation；本地解析公开业务要求。
3. 几何provider对已到货箱逐个生成物理Top-K，公共guard筛出本次允许集合。
4. 按3.3节处理空集和singleton；其他情况建立显示映射、上下文和请求体。
5. 先保存decision与请求，再预占HTTP尝试账目，执行一次远程请求。
6. 保存原始响应、served_model、usage、延迟；验证并映射Cxx。
7. 重建当前观测、可选集合与映射摘要，确认无过期状态/记忆变化；构造原action。
8. 使用公共本地政策响应、完整物理候选和原 `commit()` 复查后提交。
9. 提交后才调用私有reference评价、更新订单指标、保存事件和检查点。

不允许先让原 `choose()` 选一次、再用它覆盖Jev结果。可以只读计算基线选择用于独立分析，但这项额外计算不得伪装成Jev免费获得的推理。

提交失败时原提议、错误原因及未改变状态全部保留。主方法不自动切换候选。当前业务合法不代表未来不会受阻；后续无候选属于策略/候选/任务可行性问题，交给诊断而非语言修复。

## 8. 账目、缓存、恢复与回放

### 8.1 独立调用账目

不直接复用旧 `e5/backends.py::Ledger`：它的恢复解析、最多一次修复和状态转换依赖AST响应。可以借鉴原子写与锁机制，但新账目必须围绕selection，而不是compilation。

每条HTTP尝试保存：全局attempt_id、job_id、decision_id、body_digest、状态、发送前时间、响应结束时间、HTTP状态、原始payload、usage、served_model、错误与retry身份。全局和逐任务预算均在网络前检查，失败尝试也不从账目删除。

首版生产默认每个决策最多1次HTTP尝试，`max_retries=0`。429/529按官方错误分类记录；首版不自动重试。若后续允许退避重试，必须独立配置、每次预占预算并保存等待成本；不能启用未记账的SDK默认重试。[S7]

超时或进程在发送后退出，不能确定供应商是否已处理：标记`UNKNOWN_IN_FLIGHT`，不在恢复时自动重发。它与收到完整错误响应不同，不承诺付费exactly-once。

### 8.2 缓存规则

- 几何与业务计算可复用现有精确输入缓存；命中和耗时单列。
- 禁止跨新决策复用旧模型回答并算成新调用；首版无模型回答缓存。
- 相同实验、相同decision的恢复可以消费已保存有效响应，必须核对全部摘要；它不是独立重复模型实验。
- 不把 `JevSelector.select()` 放进原 `choose()` 的 `lru_cache`。
- 同一决策开始后冻结记忆快照；重建上下文时如变化必须拒绝恢复。

### 8.3 无网络回放

原E5回放会重新执行确定性 `choose()`，不适用于远程直接选择。新回放需：重建公共观测与候选、重算业务mask和特征、核对显示映射与请求体、重新解析保存响应，再重放同一候选提交与独立评价。

回放不得访问密钥、不得调用API，也不要求活模型再次选择相同结果。恢复也不能因回放而重复放箱。对原响应、映射、记忆、usage、预算或汇总的篡改，不能仅靠重签文件清单就通过，必须核对派生关系。

## 10. 预留经验接口

首版 `MemorySnapshot`只提供空列表、固定版本及空内容摘要；模型请求明确 `memories=[]`。记录字段从第一天进入上下文摘要，避免后续接入记忆时无法追溯。

未来可扩展为：

```python
class MemoryProvider:
    def retrieve(self, public_context: dict, *, snapshot_id: str) -> "MemorySnapshot": ...
```

经验内容包含适用条件、策略建议、禁用条件、验证状态和版本；证据来源指针留本地，不能把源订单答案或当前未来序列交给Jev。LLM订单回顾与记忆激活发生在相应反馈形成之后，首版不实现。

记忆不作为新的业务规则，不修改公开限载、禁接触或区域要求；它只影响既定候选范围内的选择。后续验证先给Jev与LLM同一冻结记忆，再研究自动提炼。

`--config`省略时加载包内 `configs/jev_direct_v1.json`，显式传参时记录外部文件摘要与完整配置快照。`--offline`与`--remote`互斥且必须显式选择；只有remote路径读取真实密钥。prepare/validate/replay均0网络调用，不依赖旧240条矩阵验收，不重跑历史实验。新运行目录拒绝覆盖；resume只恢复同一计划及参数。

固定决策题须由新链公共状态导出，并含至少两个可选动作；不能直接消费1C旧答案作为Jev真值。题目固定的作用是检查接口、同状态动作差异和选项顺序，不默认具有唯一最优动作。

## 12. 评测与成本

### 12.1 首轮方法

先实现 `shared_geometry`（共享可选池内几何最高分）和 `shared_constrained_first`（按同池逐箱可行数、质量、到货次序选箱，再取同池内几何最高位置），以及 `jev_choice`。

后续加入 `llm_direct` 时使用相同候选、上下文事实、目标、编号排列与记忆。旧LLM AST+Executor可以列作架构参考，但不能当作同任务的直接选择对照。完整新共享池搜索作为另一个独立实现，不直接假定旧 `buffer_search`使用了相同候选子集。

第一版不把Jev嵌进beam搜索；如后续增加 `jev_ranked_search`，单列模型调用与额外模拟预算。

### 12.2 必须记录的指标

- 完整合规完成率；全部计划订单分母与来源数。
- 已放件数/订单件数、已放体积/订单总体积；失败与矛盾构造单列。
- 每步和最终参考业务违规、物理检查失败、终止原因。
- 可选项数量、空集、singleton、真实模型选择步数；显示顺序敏感性。
- 首次有效响应率、服务失败、预算停止、UNKNOWN_IN_FLIGHT；无AST准确率。
- 模型请求延迟P50/P95、单步端到端延迟、几何/特征耗时、订单墙钟时间。
- 输入token、输出token、按冻结单价估算的模型费用；离线替身费用与真实调用均为0。
- 后续记忆维护成本单列，不能只报Jev在线费用。

同一订单全部放完且托盘规定体积相同时，体积利用率相同；完整成功订单可另比较垛高。不得把提前停单造成的低违规/低费用当成性能提升。按来源订单聚合，配置、步骤与方法记录不是独立来源。

首版无性能通过的预设结论。协议工程PASS不代表Jev优于LLM或启发式，实际吞吐量与真实机器人执行尚未验证。

## 13. 开发顺序与验收门槛

| 阶段 | 具体交付 | 通过条件 |
|---|---|---|
| J0 接口与数据冻结 | 新Schema、配置、构造任务、公开guard、provider | 0网络；16/48边界、来源/未来隔离、无模型AST生成 |
| J1 离线选择闭环 | 测试替身、选择映射、提交、账目与回放 | 原生请求体真实走编码路径；失败、恢复与篡改案例通过 |
| J2 真实小冒烟 | 至少一个存在多候选的构造订单；显式有限预算 | 保存真实Choice响应与served_model；回放0网络；结果可失败但不可伪装成功 |
| J3 开发订单对照 | 恢复/导入来源快照，冻结方法与输入 | 同候选同信息，任务分母齐全，成本与结果分开，不按Jev表现挑订单 |
| J4 记忆扩展 | 同一冻结经验供模型对照 | 本轮后置，另立经验提炼/验证协议 |

不得以模型是否提升作为J0/J1工程验收条件；不得为了获得正收益继续修改已冻结的J3测试配置。真实API执行须有用户授权；本次J2已有实际运行及不限预算授权，已执行。J3真实对照另行安排。

### 13.1 必须的针对性测试

1. Jev返回Cxx后确实提交对应箱体和位置，不被旧choose覆盖。
2. 多箱联合选择可改变选箱和选位；不能只让模型选择group.selected。
3. 公共检查器不能读取reference_policy；禁压、间接累计载荷、禁接触、区域及相对关系沿用原定义。
4. 当前合法但未来受阻的轨迹如实记未完成；不改写为编译错误。
5. 未到货箱改变时，当前公共上下文、候选和请求完全不变。
6. 0/1/2/48项边界：空集与singleton不联网，超过48拒绝。
7. 非法候选序号、错误模型版本、错概率键、NaN、概率和错误、错误类型分别拒绝。
8. 乱序映射可恢复原动作；重复序号、过期状态/候选/记忆摘要拒绝。
9. 缺少密钥、超时、429/529、非JSON、预算耗尽不会静默回退或反复请求。
10. 原始服务回答已保存后恢复不重复调用；已提交后恢复不重复放箱；未知in-flight不重发。
11. 无密钥、禁网络条件下可回放；篡改响应、映射、汇总或预算并重签清单仍被拒绝。
12. 构造正例和不可行负例分开；整单指标不能把singleton算成模型正确率。
13. 离线替身永不进入remote分支，其响应仅证明协议，不证明模型能力。
14. 同池本地基线与Jev均不读取旧soft-selected答案；legacy_soft模式另存配置。
15. 新生产代码、测试替身、配置和Schema全部归属 `jev_select/`；包内测试可单独发现，安装后的资源路径不依赖cwd，构建产物不携带测试代码；旧目录无平行Jev实现。

不要求重跑旧E5 240条或旧D矩阵。新增测试与受影响的定向回归先完成；必要的全套回归须报告缺失快照导致的不可运行范围，不能伪造通过。

## 14. 完成定义与开发者交付清单

本轮实现完成时应交付：`jev_select/`内的新代码/配置/Schema/测试与README、统一模块入口的实际CLI帮助、新旧职责说明、离线构造闭环及无网络回放记录、失败/恢复测试、源文件摘要、缺失数据检查、真实调用手册与最大预算计算方式。

以下仍可能是NOT_RUN：真实Jev选择质量、独立未见订单泛化、相对LLM的质量/速度收益、经验增量和真实机器人执行。不能因类型合法或只输出候选编号，就写成安全、全局最优或已学会长期规划。

**最终架构：公共状态与属性＋几何/业务可行候选＋经验上下文 → Jev直接选候选序号 → 本地绑定恢复及检查 → 仿真提交 → 独立订单评价。**
