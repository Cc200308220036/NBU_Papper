## 2. 保留的语义、输入与规划预算

### 2.1 五类规则全部沿用已有含义

| 规则 | 本轮执行定义 |
|---|---|
| `max_top_load` | 累计直接/间接顶部载荷不超过常数或对象标签限值；旧载荷规则族覆盖关系保留 |
| `no_top_load` | 顶部累计载荷不超过0kg及既有载荷容差；保留与零限载的白名单等价 |
| `forbidden_contact` | 禁止指定对象集合直接正面积面接触；不把角点/边接触擅自扩大为违规 |
| `inside_region` | 整个已定向底面落在公共矩形内，不仅中心在内 |
| `relative_position` | 所有匹配且不同对象的有序对满足指定轴AABB分离及间距；排除自身，待放端点deferred，后放箱到来重新核验 |

区域/关系规则合取、`overrides=[]`；例外由选择器显式排除或载荷族内合法覆盖表达。矛盾规则可以是合法AST，不能删规则或放宽间距。EOS无适用对记录N/A；EOS仍有未放对象不能记整单完成。

坐标、mm/kg、空间容差`1e-6mm`、精确JSON十进制关系比较、载荷容差、字段枚举/类型、32规则/选择器深度4沿用E2。空间容差不得混用为质量容差。原始AST、等价语义和候选集合分别保存。

### 2.2 公共输入与独立评价边界

Parser/Text/Image得到相同指令、准确属性、公共区域、坐标与已到货状态；只有已码箱有托盘pose，待码箱有缓冲槽位但无托盘pose。Image额外收到同事实生成的实际PNG。Text也获得准确事实，不刻意缺字段制造图像优势。

参考AST、参考允许集合、目标终局布局、未来箱属性和未来到货列表都不能进入编译器、主方法候选生成或排序。Oracle是明确标记的特权对照，不是Parser/模型失败后的兜底。

独立参考只在本方法提议/提交后评分。合法但语义错误的模型AST按其原义执行并计错，不由参考AST纠正、剪候选或阻止业务错误提交。物理安全检查始终独立执行，任何方法都不能放宽物理限制。

### 3.2 后端接口必须明确返回实际编译请求

建议接口语义为：

```text
compile(source_request, job_context)
    -> {compiled_request, response, compilation_record, status}
```

- `source_request`为无附件的当前公共状态；`compiled_request`为实际发送模型、包含真实图片附件及最终摘要的请求。
- Image附件会改变观测摘要。后续动作、提交与审计必须使用同一个`compiled_request`及模型原始响应；不得拿无图请求校验有图响应，也不能重写模型返回摘要。
- 提交前从真实状态重建含相同附件的请求，验证其仍对应当前状态、指令和候选。槽位/EOS/候选顺序变化后，旧响应和动作失效。
- 格式/绑定无效允许至多一次定位修复；语义合法但错方向、错对象、漏规则不能触发“修成参考答案”。最终编译失败即该episode明确失败，禁止按空AST继续。
- 相同状态的重复调用也要计真实尝试；本轮不新增模型缓存，不把上一个状态回答换摘要后复用。

### 3.3 全局账目与恢复是实质开发项

现有`E2 RemoteCompiler`构造时会初始化账目，编译ID也从局部计数开始。不能让多个episode共用一个输出根目录并互相清空账目，不能为每个episode重新获得整份API预算。

E5必须提供全实验/分片统一预算，或者预先划分并冻结不重叠的子预算；全局编译ID至少含`job_id＋decision_id`，attempt唯一且可追溯。一次HTTP尝试在发送前登记并占预算，失败、超时和修复均计数。进程中断时in-flight尝试标为未知/未确认，不退款、不无证据自动重发。恢复读取已有账目，防止预算重置、重复提交和覆盖输出。

离线恢复重用保存响应复现历史前缀；如果继续真实运行，仅对未完成的新决策发起新尝试。不能把“用保存AST离线重算”统计成新增真实模型episode或新增API证据。

## 5. 单箱、缓冲和错误AST的闭环行为

- 单箱容量1按原到货顺序执行；buffer容量3按已有守恒和WAIT规则接收。队首阻塞时FIFO可失败，启发式/搜索可以选其他已到货箱，但不能读取未来箱。
- WAIT只在未EOS且缓冲未满时接收下一箱或EOS，不调用模型、不修改业务约束。缓冲满或EOS后必须决策、提交或明确停止，不能无限等待。
- 每次决策至多提交1箱；每次PLACE减少一个pending并增加一个placed，已到货=已码∪待码，集合互斥；所有真实提交通过独立物理检查。
- 每次新状态重新编译当前指令和公共事实；实际成功PLACE后才推进码放状态，不能直接按参考终局摆放。
- 正确AST的实际提交参考业务违规必须为0；模型合法错误AST可能引起业务违规，应记录原始错误、实际动作和违规链。参考不得代为补答案。
- 终止时无论EOS是否已到，都用原始截取的N_i作为完成率、件数和体积分母，保存pending/unarrived；不能把尚未到货箱从分母删除。

搜索的“无可行动作”不是连续问题无解。全局可行性只有独立证书能支持；其他来源订单只报告当前候选与方法限制。

### 6.2 真实在线阶段（开发完成、计划封存后由用户执行）

本轮沿用原E5真实矩阵规模，去除四方向语义：

| 子矩阵 | 任务/来源/规划器 | 主episode | 远程编译episode |
|---|---|---:|---:|
| SINGLE | 24任务×Parser/Text/Image/Oracle×single | 96 | Text24＋Image24＝48 |
| BUFFER | 24任务×Text/Oracle×FIFO/heuristic/search | 144 | Text72 |
| 合计 | 不重复运行single中的Text/Oracle作为容量基线 | **240** | **120** |

BUFFER首版不要求Image，不支持“图像对缓冲也有增量”的主张。如后续需要，另冻结同任务/同规划器Image配对，而不是把single结果外推。

在线冒烟前缀固定为来源排序索引0的C0、索引1的C1两个任务（至少涉及两个来源和两种配置）；这两个任务先列入计划执行顺序，其余22任务按source key/config排序。可先执行这个前缀：single8＋buffer12＝20个job。这20个job属于上述240分母，验证成功后继续余下220；不另加一遍同题、不得看结果后换前缀任务。冒烟用于检查连续响应/绑定/提交/账目，不要求模型或订单满分。

本轮不强制再次单独付费执行E1/E2固定题。E5使用同一E2语义和已验收模型编译协议；新增在线后端的编码、修复和故障路径先由离线假HTTP测试验证，再由在线冒烟前缀验证。

### 6.3 API预算的计算规则

所有真实状态编译和修复都由统一账目计数；搜索节点和WAIT不调用API。每个episode至多N_i次成功PLACE和1次终止决策，因此基础编译上界为`N_i+1`，最多一次格式/绑定修复后尝试上界为`2×(N_i+1)`。最终无pending的完成审计不额外调用模型；编译最终失败、物理提交失败不循环重试。

记`S=Σ24任务(N_i+1)`，模型/超时/预算配置冻结后：

- SINGLE远程上界：Text `2S`＋Image `2S`＝`4S`。
- BUFFER远程上界：Text三规划器 `6S`。
- 完整240主episode远程尝试上界：`10S`，若全部N_i=12则不超过3120次；实际以冻结N_i逐任务计算，不能把3120当必须消耗次数。
- 上述2个前缀任务冒烟预算上界：`10×Σ前缀任务(N_i+1)`，最多260；它是总预算的一部分，继续运行时累计，不重新归零。

准备阶段输出每job上限、总上限、已用/剩余与分片分配；`--remote`和显式预算必须由用户给出，预算不足保留计划任务并标PARTIAL/NOT_RUN。不得在任务间自动挪用未授权额外预算，HTTP失败也占尝试；未知费用为null，不从token量臆算费用。

## 7. 指标与停止归因

### 7.1 规则与闭环分开报告

规则层：首答/最终有效率、原始AST一致、白名单语义一致、适用对象、区域引用、主客体/方向/gap、载荷阈值、条件/例外/覆盖，以及指定候选上的允许集合一致、false_allow/false_reject。不适用字段为null/N/A并报告分母，不能一律记正确。多规则无法唯一匹配时保留不可比较，不能按rule_id猜测业务对应。

闭环层：全部计划任务的完成率、无违规完成率、件数/体积放置比例、物理违规、业务违规步及实例、终止原因、到货/未到货/待码数量、候选漏斗、搜索耗时与预算截断。首答与修复分开；零提交的违规率为N/A，不能写“零提交所以100%安全完成”。

来源配置C0/C1、四规划器、四编译来源分别汇总；同来源重复/业务变体不增加独立样本数。在线轨迹分叉后比较整单指标，不能把不同状态的逐步候选差异直接归因于编译能力；若需同状态编译比较，单列共同观测诊断，不混入主在线分母。

### 7.2 失败原因至少包含以下层次

| 层次 | 必须记录的区别 |
|---|---|
| 协议/API | provider error、格式/绑定无效、修复失败、预算耗尽、未执行、未知in-flight |
| 语义 | 合法AST漏规则/错对象/错方向/错阈值，与格式错误分开 |
| 物理 | 公共物理采样无候选、独立物理提交拒绝 |
| 候选覆盖 | 完整公开采样池中有本方法合法候选、Top-K中没有；单独标Top-K覆盖不足 |
| 当前业务 | 本方法Top-K无合法候选，参考同一池是否有合法候选；参考只用于事后归因 |
| 缓冲/搜索 | FIFO队首受阻、未观察未来、后继预算截断、当前搜索无路径；不能笼统叫全局无解 |
| 独立无解证据 | 仅构造证明/充分穷举证明的限定范围使用`proven_infeasible` |

Top-K有截断不等于导致失败；应记录“截断发生”与“已证覆盖不足”两项。公开采样池不是连续空间穷举，池内无解仍不能宣布全局无解。统计模型错误时可比较AST及同状态候选；不能用参考路径替主方法继续运行。

## 8. 必测故障与预期行为

| 故障 | 预期 | 证据 |
|---|---|---|
| 区域边界、指令、能力、坐标、标签/渲染约定变化后复用旧响应 | 拒绝过期响应 | 当前请求/旧响应、字段诊断 |
| Image附件字节或facts改变，或将有图响应提交到无图请求 | 摘要/绑定/独立图像校验拒绝 | 原始附件摘要及实际提交结果 |
| yaw、候选ID/顺序、待码槽位/容量/EOS改变后复用旧动作 | 拒绝 | 候选集/请求摘要与动作 |
| 未知对象/区域、布尔/字符串数值、NaN/Infinity、跨族覆盖 | 拒绝 | 字段路径与原因 |
| allowed_yaw、180/270、侧面标签、roll/pitch | 超当前能力明确拒绝 | 不能忽略要求后继续空规则 |
| 只改未到货未来箱 | 当前请求、候选与决策相同 | 对照实际驱动首个决策及trace |
| 搜索克隆被篡改、预算超限 | 检出且真实状态不变 | before/after、实际后继计数 |
| 合法错误AST（漏关系、反方向或漏限载） | 不修语义；能形成实际业务错误并由参考检出 | 至少2条不同类型完整实际轨迹 |
| 网络错误或格式修复仍失败 | 保留失败、无Parser/Oracle回退 | 假HTTP原始请求/返回与attempt账目 |
| 全局预算不足或多任务恢复 | 上限不变、未执行保留、无重复扣用/免费重试 | 跨至少2任务、1次恢复的账目 |
| 模型编译ID碰撞/相同输出目录 | 拒绝或从设计上保证唯一，不能覆盖旧响应 | job/decision/attempt唯一性检查 |
| 进程在发送前后、提交前后中断 | 不重复提交，不丢失已占预算和失败分母 | 检查点与已保存响应恢复对照 |
| 保存事件、模型回答、参考指标或图片篡改 | 只读复算检出 | 用独立副本注入，原件不动 |

不要求空四方向集合等E3专属故障；本轮应拒绝整个未支持的`allowed_yaw`规则。测试数量不是覆盖标准，以上每行需明确子项清单、实际输入、期望、结果和产物路径。
