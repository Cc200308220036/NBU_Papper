## 3. 全阶段共用的语义与协议

### 3.1 坐标、单位与容差

- 继承现有托盘坐标：原点为托盘底面中心，x/y水平，z向上；箱体pose的x_mm/y_mm为底面中心，z_base_mm为底面高度。
- 本文固定+x为右、-x为左；+y为后、-y为前。图像必须标注轴与前后方向，不按相机屏幕左右解释业务。
- 长度mm，质量kg，角度degree。空间比较容差`spatial_eps_mm=1e-6`，角度只接受离散整数枚举，不用角度容差接受89.9°或360°。载荷容差沿用原业务定义，与空间容差分开记录。
- 所有箱体本地顶面为+z，业务标签固定在该面；roll/pitch固定为0或由契约规定不出现，不生成翻转/倾斜候选。
- E3以后yaw绕+z，从+x朝+y逆时针为正。尺寸按yaw mod 180计算；allowed_yaw使用完整yaw，不能按mod 180合并状态。四种yaw下顶面法向均为世界+z。
- 输入拒绝NaN/Infinity、布尔值冒充数值、未知ID、未声明能力、非法区域、非法角度。所有容差与能力进入冻结配置；更改后建立新版本。

### 3.2 公共输入与版本

新增独立能力版本（建议`o4_e1_v1`至`o4_e3_v1`），不要覆盖`o4_request_v1`、既有buffer协议、remote_v2和研究冻结入口。新增schema、响应契约和摘要规则必须同步生效，未实现的规则不能被schema接受后静默忽略。

| 公共字段 | 语义/校验 | 必须绑定的变化 |
|---|---|---|
| capability_version、coordinate_convention | 已启用规则、轴方向、yaw定义 | 能力或坐标变化使旧响应失效 |
| regions | region_id及x_min/x_max/y_min/y_max，轴对齐、正面积、在托盘内 | 区域名称/边界变化进入观测摘要及扩展状态摘要 |
| placement_convention | 固定直立、标签位于本地pos_z顶面；各方法公开相同前提 | 约定或标签渲染版本变化使旧响应失效；不新增任意标签面选择 |
| placed_objects、available_objects | 既有准确事实；只有已码箱有托盘位姿 | 完整yaw、已码/待码集合变化使旧响应失效 |
| instruction_text | 完整要求、范围、关系、目标方向及明确例外 | 指令摘要变化使旧响应失效 |
| images及渲染版本 | 同事实生成的区域图、箱面卡片和场景PNG | 图像字节/事实摘要按附件协议绑定 |

新增公共区域及固定顶面标签事实给所有方法；参考AST、按本题规则展开的目标对象集合、允许候选标签和参考动作不能进入主方法输入。缓冲箱仅有真实暂存槽位，不编造已有码放pose；未来箱、参考终局布局不可见。

摘要层次需明确：物理摘要覆盖物体与容器；扩展公共状态摘要还覆盖区域、固定放置约定、能力及坐标定义；请求绑定覆盖指令、图像和全观测。候选摘要覆盖完整yaw与候选生成版本。不能通过替换返回摘要来接受旧响应。

### 3.3 AST、条件与组合

新增规则沿用现有selector表达能力（对象ID、公开属性、and/or/not、数值比较），完整公开合法类别、字段、类型、深度和规则数限制。建议在阶段开发时固定新规则数上限32、selector深度上限4，并对超限给字段路径诊断。业务AST生成失败不能当作空规则继续执行。

| 新规则 | 必需业务参数（语义接口，非已经实现的JSON契约） |
|---|---|
| inside_region | target selector、region_id |
| relative_position | subject selector、reference selector、relation枚举、min_gap_mm |
| allowed_yaw | target selector、非空离散角度集合 |

不提供label_facing_outward或label_facing_up规则；标签朝上由固定姿态与数据约定保证，不要求模型重复生成。若出现翻转、非顶面标签或侧面朝外要求，按超出本轮能力明确拒绝，不能忽略后继续运行。

具体JSON字段在E0/对应阶段实现前写入封闭schema并冻结，样例与校验器一致。rule_id、priority和overrides的处理不能复用旧实现而不检查规则族：

- 原三约束的语义和原有合法覆盖关系保留；载荷覆盖只在载荷规则族内解析。
- 新空间/朝向规则之间默认合取；同一对象的多个区域、多个角度集合取同时满足条件，不按规则顺序覆盖。
- 首版新规则`overrides`必须为空；例外用selector显式排除后另写规则。跨规则族覆盖及新规则非空overrides必须拒绝，不默许旧载荷解析器处理。
- 明确矛盾属于合法但不可满足的业务要求，不能删规则或放宽条件。结构错误、引用错误属于协议失败，与不可满足区分。
- 对所有已码对象和试提交对象重新检查；待码对象不凭空拥有几何。集合尚无已码关系端点时记录`deferred`，当前不形成违规，但不能计为整单关系已满足；EOS仍有未放对象必须按未完成计分。

## 4. E1：公共区域与inside_region

### 4.1 目标及执行定义

区域首版仅支持公共轴对齐矩形，不含高度区间、多边形、软偏好或自动从图像识别区域。对已定向箱体，令底面范围为`[bx0,bx1] × [by0,by1]`，区域为`[rx0,rx1] × [ry0,ry1]`，满足：

```text
bx0 >= rx0 - eps 且 bx1 <= rx1 + eps
by0 >= ry0 - eps 且 by1 <= ry1 + eps
```

仅中心在区域内不够。此约束限制xy投影，不隐含“必须落地”；叠放只要投影在区域内且物理/其他业务允许即可。多个适用区域是交集；集合为空不产生规则实例，但须报告空适用集合。region_id指公共事实ID，不接受模型自行创造区域坐标作为参考替代。

### 4.2 必须新增

1. 区域公共数据、schema校验、准确坐标渲染与文本字段；区域事实不包含本题答案标记。
2. 规则Parser、模型契约、运行执行器及独立参考解释器。
3. 公共区域边界候选：对每个公共区域，无条件尝试底面贴边/居中位置，与原极值点/支撑层候选合并。不能只为参考AST目标生成区域内候选；所有方法共享候选与Top-K预算。
4. 检查已码目标是否越界、逐候选越界量与方向、无解终止原因；旧状态违规不能因新增动作未加重而被掩盖。

### 4.3 E1验收门槛

- E1-A：四边、四角、恰贴边、容差内/外、中心在内但角越界、箱体过大、非法区域引用均符合独立期望。
- E1-B：同状态仅改区域或业务目标时，至少4对预先指定机会题改变允许集合，其中至少2对改变确定性动作。
- E1-C：至少2例证明原候选未覆盖区域而扩展候选覆盖；至少2例区域不可容纳/与物理冲突仍明确无解。构造存在性由人工解析坐标或独立小范围穷举证明。
- E1-D：与禁压、限载、禁接触及属性例外组合正确；不能为满足区域提交物理违规动作。
- E1-E：单箱及三种缓冲规划器均完成阶段实验、事件守恒与失效绑定检查。

## 5. E2：有向相对位置

### 5.1 冻结语义

首版采用包围盒在指定轴上完全分离，**不采用中心大小比较**。设A为subject，B为reference，gap为非负mm：

| relation | 判断 |
|---|---|
| left_of | A.x_max + gap <= B.x_min + eps |
| right_of | A.x_min >= B.x_max + gap - eps |
| front_of | A.y_max + gap <= B.y_min + eps |
| behind | A.y_min >= B.y_max + gap - eps |

gap=0允许边界接触；这不代表满足独立的禁止接触规则。默认gap必须在契约中明确（首版0）。关系不含z排序，也不要求另一水平轴重叠。集合语义为所有已码有序对`A∈subject, B∈reference, A≠B`均满足；相同对象不与自己比较。选择器重叠可能使不同对象同时承担两个角色并产生矛盾，按合取处理，不自动改为“存在一对满足”。

left_of(A,B)可在评价表示中与right_of(B,A)归一，但目标集合、gap和条件必须相同；不能仅因当前候选恰好一致就判规则等价。前后同理。

### 5.2 必须新增与验收

- E2-A：有向关系AST、集合展开、间距、逐有序对违规、条件对象和方向分别计分；错方向、交换主客体、中心满足但包围盒重叠必须判错。
- E2-B：两种到货顺序各有正反例；A先到与B先到不改变最终业务含义。另一端尚未放置时记录deferred；后放箱出现后重新核验双方。
- E2-C：至少4对改变允许集合、其中至少2对改变动作；至少2例几何可行但关系无解，且不能用参考关系替主方法剪候选。
- E2-D：关系候选补点仅由公共已码箱边界、公开配置间距格点形成，所有方法共用；不读取正确关系/参考gap来为某方法生成答案候选。若离散候选遗漏合法位置，明确记候选覆盖不足。
- E2-E：包括E1与原三约束的混合任务；至少2个构造案例中，容量3搜索能复现独立已知的合法选箱/选位路径，同时保留至少2个无收益/无解案例。此项验证功能，不要求自然订单上搜索平均更优。

## 6. E3：四方向allowed_yaw

### 6.1 定义与全链路变更

yaw集合是`{0,90,180,270}`的非空子集。初始尺寸L/W/H：0/180定向尺寸为L/W/H，90/270为W/L/H；高度不变。多条适用规则角度取交集；无适用规则时使用该阶段配置的公共朝向集合。非法角度拒绝，不静默取模；360°不能冒充0°通过协议。

必须同时升级新版本中的观测、候选枚举、定向尺寸计算、去重、候选指纹、分层Top-K、状态hash、动作绑定、物理检查、状态提交、缓冲克隆/搜索、恢复和图像箱面变换。原有生成器使用“yaw==0否则交换长宽”，独立物理检查仅接受0/90，不能只改配置列表。

候选去重键至少包含对象、位置和完整yaw；0/180以及90/270即便几何相同仍是不同动作，因为allowed_yaw可明确只允许其中一个角度。所有方法共用四方向生成器；比较旧/新动作空间收益时固定编译来源，不同时更换模型和规划器。标签位于顶面，因此不以这些水平角度区别标签是否朝上。

### 6.2 验收门槛

- E3-A：非正方形箱在四角度下尺寸正确；正方形箱几何相同但四种yaw仍可区分。45、-90、360、字符串及布尔角度拒绝。
- E3-B：所有非空允许集合（共15种）至少各1个金标准，另覆盖集合交集为空、未命中目标、已码箱朝向违反规则、错误尺寸与正确yaw组合。
- E3-C：至少4对允许集合变化、至少2对动作变化；至少2例只允许180或270，实际成功提交该yaw，不能由0/90动作冒充。
- E3-D：同位置0→180仅改变yaw时，状态hash、候选摘要及动作绑定变化；篡改角度/尺寸可检测，恢复能保留方向。
- E3-E：已码载荷、接触、区域、关系的独立检查保持正确；三种缓冲规划器搜索克隆与提交均支持四方向。

## 7. 标签顶面朝上固定前提与E4取消

不开展任意标签面、朝指定托盘外侧方向、标签可视性、遮挡或可读性优化，不设置E4专属AST、评分和真实API矩阵。标签朝上不表示堆叠后仍无遮挡可见，也不因此禁止在箱体上堆放；是否允许承压继续由原禁压/限载等规则决定。

只需在公共基础与现有验收中核对：新数据标签面恒为本地pos_z；箱体直立且只绕z旋转；公共文本、facts和PNG一致；非零roll/pitch或非顶面标签不被静默接受。这是固定输入/动作空间一致性检查，不建设独立标签方向规划模块。

现有A5图像代码采用侧面pos_x标签，是旧版仿真设定，不能声称已符合新约定。后续E开发新增顶面标签事实与渲染版本，并按新版本生成实际使用的E图像；旧A5代码、旧PNG和封存实验保持不变，不能直接复用侧面标签PNG并把文字改为朝上。

后续机器人接入沿用顶面朝上前提：上游提供符合约定的箱体，抓取和放置保持直立；具体机器人动作与姿态验证属于接入阶段，当前文档不代表机器人实验已经实现或通过。

### 8.1 候选与缓冲预算

沿用每箱Top-K≤16、容量3首层联合候选≤48、深度≤3、束宽≤8、每轮后继评价≤256。四方向不得静默扩大Top-K/搜索预算。建议E3按无向足迹分组，每个组保留其物理可行的完整yaw成员，在16个上限内选择完整组；确定性同分策略和截断原因在E3前冻结。

空间补点与全方向枚举成本单独记录，不冒充被256后继预算限制。若某区域/姿态合法点在Top-K外，只能报告候选覆盖不足，不能说原问题无解。若保留分组方案改变旧版候选分布，必须在同一新生成器下比较编译方法，并另做固定编译来源的生成器对照。

### 10.2 指标分层

必须报告原始AST一致、白名单等价语义一致、适用对象、关系主客体/方向、区域引用、gap、角度集合、条件/例外/优先级、候选允许集合、false_allow/false_reject。标签顶面朝上只作固定前提一致性检查，不报告模型标签方向理解得分。限值不适用的新规则不得填“限值正确”；多规则无法唯一对应时保留不可比较及分母，不能推测匹配。

闭环记录完成率、无违规完成率、件数/体积比例、违规步/实例、终止原因、候选数与覆盖、生成/搜索耗时及截断；有API时另报首答/最终有效率、修复、真实尝试、usage、延迟和未知费用null。几何相同而方向正确的收益可独立报告，不把它包装成体积利用率提升。

失败归因至少分：协议无效、合法AST语义错、物理无候选、Top-K覆盖不足、当前方法业务无可行动作、参考业务无候选、搜索预算截断、到货/队首受阻、API/预算未执行。只有构造证明或独立充分搜索才可声称该范围无解，不能把Oracle同候选集无动作当连续空间无解。

### 10.3 必测故障表

更改区域边界、顶面标签约定/渲染版本、能力版本、坐标约定、yaw、候选顺序/身份、待码槽位/容量/EOS后提交旧响应；注入未知对象/区域、错字段类型、空角度集合、新规则跨族覆盖、非顶面标签/翻转姿态；仅修改隐藏未来订单保持当前输入；篡改搜索克隆或恢复事件；模拟网络错误、格式修复仍失败、预算用尽。期望分别为拒绝/不变/明确失败，不能静默修正后通过。

新增runner需要具备数据构建/校验、计划冻结、固定题、在线单箱/缓冲、离线验收、结果复算能力。真实开关、预算和输出拒绝覆盖继承D要求；模型能力、图像实际发送和一次修复需离线故障测试。此处不提供尚未实现的命令：开发交付必须新增运行手册，附实际`--help`、每个阶段离线最小命令、正式实验命令、配置/预算及产物阅读方式。

**E工程完成**：E0、E1、E2、E3、E5必跑离线实验完成，EA-01—EA-10及E1—E3门槛逐项通过，E4明确记OUT_OF_SCOPE，单箱与最多3箱缓冲均交付，旧件保护成立，并提供可审查的真实运行计划和命令。仅E1通过则只写E1完成。

**E真实验证完成**：相应版本的真实冒烟、固定题和在线计划执行完，所有失败/未执行如实进入结果与状态；模型低准确率不能被包装为工程故障而删去。泛化或视觉增量仍分别依据独立研究实验，不能由工程完成推导。
