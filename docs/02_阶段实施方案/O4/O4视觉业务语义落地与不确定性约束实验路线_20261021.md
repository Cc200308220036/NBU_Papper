# O4：理想感知仿真下的业务语义理解与约束码垛路线

2026-10-21，依据用户明确的理想仿真范围修订。沿用原路径以保留链接；文件名中的“不确定性”不再代表当前研究内容。本文保留研究方案；A/B离线核心已有开发结果，当前状态见第7节。冻结V2未改，真实API未调用。

开发执行入口：[O4阶段任务实现与验收规范](O4阶段任务实现与验收规范_20261021.md)，细化首轮属性、规则语义、模块/AST接口、数据配额及逐阶段验收。按用户决定暂缓O3补充验证，优先开发O4；O3独立泛化仍未验证，不作为O4前置条件。本文保留研究路线，具体首轮实现范围以该规范为准。

场景修订：首轮取消抽象A/B业务分组，改用具体货物类别、包装加固事实、禁压与逐箱限载标签以及明确作业单。重点实现“哪些箱不能承压、每箱能承多少、哪些货物在本订单中不得接触、包装例外适用于谁”。类别不自动触发规则，加固不自动增加物理承载；规则与例外由完整业务说明明确给出。

## 1. 实验前提

**感知结果准确，相关信息完整且确定。** 检测、定位、跟踪、标签读取、符号识别、标签与箱体/箱面的关联均视为上游已正确完成。由仿真直接提供准确观测，不开发或评测这些感知模块。

当前及已到货箱体的尺寸、质量、位姿、实例ID、包装图像、标签信息、必要物理参数以及完整业务说明均可获得。坐标系、单位、业务含义和优先级预先明确，不设置歧义、来源冲突、遮挡、未知属性、置信度、补拍或主动观察。保留单箱基线，新增O4-F最多3箱待码缓冲及联合选箱选位，不读取未来到货信息；待码箱仅有准确暂存槽位，不虚构托盘位姿。真实图像采集和OCR开发不是本阶段前置条件。

**输入确定不代表语义编译必然正确。** 需要验证模型能否理解业务指代、适用对象、条件、关系、例外与优先级，并生成正确约束；不能将正确AST直接给主方法，再把执行成功计作理解成功。

研究问题：在准确场景与完整业务信息下，如何将对象属性和组合业务要求转为可核验、可执行的码垛约束？

## 2. 总体链路与职责

```text
理想仿真场景图 + 准确对象/标签观测 + 完整业务说明
  → 理解业务指代、对象集合、条件、关系、例外与优先级
  → 生成对象级/关系级的确定性约束AST
  → 校验对象引用、单位、语法、规则覆盖与可表达范围
  → 物理候选生成 + 业务约束核验 + 固定布局排序
  → 仿真提交动作、更新状态、处理下一箱
  → 独立核验约束、候选、动作与完整订单
```

VLM负责业务语义理解与约束编译。对象ID、标签文字及所属对象/箱面由仿真准确提供；模型处理的是业务说明中的对象指代与关系，不承担视觉跟踪或标签辨读。

程序负责累计载荷、接触/区域关系、碰撞与支撑核验、坐标与允许朝向选择。执行仅指仿真状态提交，不表示已接通机器人运动控制。

准确属性可以作为公共输入。如果图像信息已经被准确观测完整表达，需要用去图像对照验证视觉模态的额外作用，不能预先宣称VLM或视觉输入不可替代。

## 3. 信息公开与答案隔离

| 层次 | 示例 | 使用范围 |
|---|---|---|
| 准确观测事实 | 某玻璃杯外箱、质量4 kg、包装已加固、限载标签5 kg、标签位于+x面 | 各方法统一公开，属性为准确提供的仿真事实 |
| 业务要求 | 本订单已加固且无禁压标记的玻璃制品箱改按2 kg业务限载；指定货物放在公共标记区域（后续扩展） | 各方法统一公开，表达明确 |
| 编译参考答案 | 完整正确AST、按业务条件展开的适用对象集合 | 独立评价及明确标注的Oracle对照 |
| 决策参考结果 | Oracle允许候选集合、参考动作与违规判定 | 评价及Oracle对照 |

公开准确标签属性符合本轮前提，不属于泄漏。若评测业务编译，却直接公开已经按该业务计算好的禁放列表、正确AST或最终可行动作，则绕过了研究问题。字段来源和评价目标必须逐项对应。

物理承载参数与标签表达的业务限载分开，前者由仿真明确给出，不从外观估计材料性能。遗漏规则、无效单位或非法AST计为编译失败，不能默认为无限承载；不因此引入信息不确定性实验。

## 4. 约束与任务设计

| 顺序 | 开发内容 | 验证重点 |
|---|---|---|
| 1 | no_top_load、max_top_load、forbidden_contact | 对象限载与关系规则的可执行语义 |
| 2 | 属性筛选、对象集合、条件、例外与明确优先级 | 相同准确事实在不同业务要求下生成不同约束 |
| 3 | inside_region与相对位置要求 | 空间业务关系如何限制候选 |
| 4 | allowed_yaw与label_facing_outward | 已知箱面和位姿下的方向变换 |

首轮示例作业单：“普通箱按各自标签的累计顶部限载执行；带禁压标记的箱体禁止顶部加载。已加固且无禁压标记的玻璃制品外箱改按订单指定2 kg限载，替代其标签业务限载。食品和清洁用品允许同托盘，但不得直接面接触。”模型应识别具体类别、标签与加固条件的适用对象，生成可核验规则；加固但禁压的箱仍禁压，加固的小家电箱不适用玻璃制品例外。

上述是明确设定的仿真订单要求，不代表行业通用规则；禁止直接接触不能等同于已实现食品卫生隔离或危险品合规。首轮围绕禁压、累计限载、明确接触限制及包装例外开展验证；重箱低位/居中复用固定软目标，区域/标签朝外后续单独开发。普通类别不能自动推导禁压或真实承载，新增类别和包装信息均通过O4独立侧表派生并标记仿真来源，不改写V1。具体六种包装画像及验收见实现规范第3、7、9节。

现有V2 schema不足以表达完整范围，需新增独立O4 schema/evaluator，不向旧schema添加未经校验字段。关系约束同时覆盖当前与已放置箱体，不因到货先后改变含义。

朝外约束采用仿真准确给定的箱面、姿态和托盘坐标系，不增加相机标定课题。现有生成器按yaw==0/其他方向交换长宽，不能简单加入180/270；新版本需正确处理0/180和90/270，并保留几何相同但标签朝向不同的候选。所有方法共用新生成器。若所有候选始终直立，“此面向上”不会扩大动作能力，不能单独算作放置改进。

## 5. 仿真数据与对照

复用现有订单几何与到货流，确定性生成货物类别、包装加固、禁压/限载标签、场景图和业务说明，保存种子、准确观测与独立参考规则。覆盖同类不同标签、同标签不同类别、加固但禁压、加固但非目标类别，不能把每类货物绑定成一套固定答案。开发覆盖基本规则和组合，独立测试预留未见表达、属性组合、规则组合及订单。按基础订单、生成模板和反事实变体分组划分，避免同源样本跨集合。

| 方法 | 作用 |
|---|---|
| 准确观测＋规则编译器＋Planner | 强确定性基线，支持预先声明的语法和组合规则 |
| 准确观测＋LLM＋Planner | 判断文本语义编译是否已经足够 |
| 场景图＋相同准确观测＋VLM＋Planner | 主候选方法，检验组合语义及图像增量 |
| Oracle AST＋相同Planner | 隔离业务语义编译损失，属于特权参考 |

所有方法共享业务信息、物理候选和布局策略。首轮可固定relaxed_geometry以隔离语义变量，不声称它全面最优。不能故意遗漏文本基线的已知事实来制造视觉优势；VLM去图像时保持准确观测和说明一致。如果文本方案同样好，应将贡献归于业务语义编译，不能归于视觉感知。

## 6. 配对实验与审计

1. 几何/质量不变，改变准确标签属性，检验规则是否随相关事实变化。
2. 观测事实不变，改变完整业务条件和适用范围，检验约束和允许候选是否相应变化。
3. 语义不变，改写明确业务说明、重排对象ID或规则顺序，检验不变性，不引入歧义。
4. 基本规则已见、组合未见，比较规则编译器、LLM与VLM的组合泛化。
5. 保持事实与说明一致，进行去图像对照，区分语义模块收益与视觉增量。

约束变化不一定改变最终动作，先比较规则语义与允许候选，再解释动作和整单结果。Oracle也不可行的案例归为候选或规划限制。

允许公开准确观测，禁止参考AST、答案编码和参考动作进入主方法请求。现有O3的public_relations或评分如果已替方法完成待测业务推理，需要拆分为公共几何关系和各方法编译的业务关系。物理候选不能按参考业务答案预先剪枝，评价器不能替主方法筛掉违规动作。

## 7. 开发顺序与验收

| 阶段 | 工作 | 验收产出 |
|---|---|---|
| O4-A | 理想观测协议、业务定义、仿真样本与独立参考规则 | 字段来源表、划分清单、准确观测一致性检查、答案隔离审计 |
| O4-B | 组合约束schema、编译adapter、规则基线及独立评价器 | 可检查AST；对象集合/条件/关系案例；非法输出处理与边界核验 |
| O4-C | 接入相同Planner，完成离线配对实验 | 规则及允许候选差异、动作变化、完整轨迹；区分编译错误与规划无解 |
| O4-F（C后、D前） | 最多3箱待码、到货事件、多箱候选、有界联合搜索 | 容量/守恒/无未来泄漏、跨业务构造案例、单箱/FIFO/启发式/搜索对照及逐事件回放；具体门槛见实现规范 |
| O4-D | 用户执行真实API对照 | 请求响应、API账目、未见组合测试、图像消融与完整订单结果 |

区域/朝向按候选器能力逐项接入，不与首轮全部捆绑。不开发标签识别或置信度评测。重点检查条件例外、累计载荷、双向到货关系及非法输出处理。

编译指标：有效AST率、规则语义正确率、适用对象集合正确率、条件/例外/优先级正确率。闭环指标：Oracle允许候选集合差异、业务违规、物理违规、完成率、无违规完成率、件数/体积比例，以及API/token/延迟和有依据的费用。失败和未完成任务保留在计划分母。

## 8. 论文主张边界

候选贡献聚焦：理想感知下，将对象属性与组合业务要求落地为可验证约束，并通过统一规划器分析语义理解对码垛结果的影响。结论限于理想仿真，不主张真实视觉识别、遮挡鲁棒性或不确定性处理能力。

OPA-Pack已有属性识别、易碎与不兼容研究，SayCan已有语义与可执行能力结合的先例。理想环境能隔离研究问题，本身不是创新；具体组合语义机制、强基线差异与未见组合泛化需要实验证明。若简单规则足够，应如实报告，不能预设VLM增益或以增加约束数量代替贡献证据。
