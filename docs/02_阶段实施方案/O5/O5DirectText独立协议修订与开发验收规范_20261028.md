# O5 Direct-Text 独立协议修订与开发验收规范

日期：2026-10-28。研究协议 `o5_direct_text_v1`；公共请求 `o5_direct_text_request_v1`；远程计划 `o5_direct_text_plan_v1`；provider profile `o5_direct_text_provider_profile_v1`。本修订依据本轮用户明确授权，在后续新实验使用纯文本候选选择。开发顺序为先冻结本文件，再实现、离线验收、准备新计划和本地手册。

## 1. 目标、权限和历史边界

交付可独立复核的 Direct-Text 工程及用户在 pallet_vlm 执行的文本预检、开发集前八单 G0/D0 Pilot 命令。本轮真实 API 调用必须为零；真实预检和 Pilot 留待用户显式运行。本轮不进入 S3，不实现经验生成、ReMe 检索、R0/M0、训练采集或正式测试集实验。

本文件只替换新文本协议的图像模态及识图前置条件。旧总规范、S2图文规范、金额修订、历史计划、账本和失败证据保留原含义；旧01号真实图文预检仍为 HOLD。文本通过不能证明识图能力，旧失败不能重判为文本通过。旧入口默认图文；文本入口独立命名。活动源码变化导致旧计划漂移拒绝，须用其封存源码环境解释历史，不能删除漂移校验。

## 3. 公共输入与输出

每次新上下文只输入白名单 JSON：版本、request_id/state_hash、容器、当前唯一箱体、已放箱体、当前候选、单位/坐标约定、固定目标和输出契约。候选后端仍是原A/E2、单箱缓冲1、Top-K≤16，按既有固定种子排列并重绑Cxx。候选池及排列规则不随模态改变。

- 容器：1200×1000×850 mm、载荷1000 kg及容器底面中心坐标系。
- 当前箱：请求局部item_id、长宽高mm、质量kg、stackable、物理顶部承载kg（模拟100kg）。不包含未来箱、总到货数量或顺序表。
- 已放箱：同上，并含pose（中心x/y、底面z、yaw）、朝向尺寸和当前承载kg。
- 候选：编号、pose、朝向尺寸、公开支撑箱ID/支撑率/重心裕量。内部候选ID、几何评分、排名和保留原因只存私有映射，不入模型请求。
- 单位：长度mm、质量/承载kg、yaw为度；原点在容器底面中心，x沿length、y沿width、z向上。pose x/y是箱体平面中心，z是箱底；yaw只允许0/90。
- 固定目标：在物理限制内最大化完整订单装载比例。输出仅 `request_id,state_hash,action,candidate_id`；PLACE必须选已有Cxx，STOP必须为null。不接受新坐标、箱体属性覆盖、代码或额外字段。

state_hash覆盖全部公共输入（排除两个绑定字段）；request_id由私有nonce哈希产生。维持严格JSON、重复键拒绝、过期绑定拒绝及未知候选拒绝。公共白名单递归闭合，不泄漏split、来源、隐藏答案、未来属性、AST、业务指令、经验或搜索权限。模型仅作候选选择，不要求预检唯一“正确”候选。PLACE提交前独立oracle核验，通过后才apply_candidate。STOP及失败保留完整订单分母。

## 4. 实施任务与输入输出

|阶段|输入|输出与完成条件|
|---|---|---|
|T0 现状审计|活动源码/已有文档/证据|初始状态、哈希和保护范围；不改数据|
|T1 文档先行|本轮授权|本独立协议及可执行验收矩阵|
|T2 请求适配|真实公共物理状态/原候选|独立文本schema、build/envelope/parse路径；无render调用、图片文件或image_url要求|
|T3 全链路适配|新profile/计划/旧runtime|长度预算、封存、预检、记账、恢复、verify/report及独立运行入口；版本不混用|
|T4 离线验收|可控wire与冻结开发状态|测试结果、故障证据、真实API=0，替身明确标记|
|T5 交付|通过后的活动源码|精确绑定预检计划、pallet_vlm手册、阶段验收记录|

文本profile沿用DeepSeek Flash endpoint/model/account/credential_env、thinking disabled及JSON选项，金额unlimited。文本输入保守上界为全部消息文本UTF-8字节数加512 framing余量；不再收取或要求图片token估计。512为工程余量，真实usage逐次验证，不能宣称精确tokenizer。输入≤12000、输出≤256、每决策原始一次+格式修复最多一次，服务重试0。超长直接拒绝并保留原因，不截断物理状态或候选，不静默回退几何。未知价格/费用为null/UNKNOWN，已知小计独列；零请求费用零与未知费用有别。

## 5. 文本预检与Pilot计划

预检使用冻结开发第1单第一箱及按原G0推进一步后的真实已放状态，各建立一个完整JSON请求；固定两个状态，各最多两次（总≤4），覆盖空布局和非空布局，不用颜色/形状探针。每个状态只验证输出格式/绑定/候选或STOP合法性及选中候选物理合法性，不预设最优选择、不要求模型解释。预检不是整单性能样本。

计划封存数据manifest、完整前八单私有任务、源码快照/摘要、依赖、物理配置、协议文档、模型配置、公开请求及私有映射。实际请求复核必须重建状态和候选，不能只信保存的hash。预检通过指真实保存响应完成全部文本任务并通过独立验证，任何失败不能跳过或换题。离线替身不能生成可供用户Pilot使用的真实预检凭据。

只有真实文本预检PASS后，才能准备并手动启动前八单 G0/D0 Pilot：16条作业、145箱完整分母、D0≤290次尝试、G0=0。新Pilot绑定同一protocol/profile/data/source/campaign，拒绝旧图文预检。完整订单指标、合法率整数分母、物理违规0、trace100%、最终合法率≥98%和难度判定沿用S2。完成运行不自动代表D0封存，不自动进入S3。

## 6. 错误、记账与恢复

复用已有共享campaign逐attempt先预留、sent、receipt持久化、结算状态机与单写锁。每次调用保存实际body及digest、request/state绑定、usage、provider ID、延迟、错误、费用未知状态与真实/替身标签；文本image摘要为空数组只作记账字段，实际body不能含图片字段。

非法JSON/重复键/闭合schema/过期绑定/未知候选最多一次仅反馈错误码的修复；不得修改候选、目标或给正确答案。服务失败无修复/重发，UNKNOWN_IN_FLIGHT停止campaign并禁止重发。401/403/404/429、重定向、模型漂移、usage超界和连续两次5xx停止规则保留。receipt已存可复用；sent无receipt保持未知；缺账本、映射、检查点、改body/响应/源码必须拒绝。verify/report零网络，不构造远程client。
