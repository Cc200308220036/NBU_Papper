# O5 S2 金额预算可选修订

日期：2026-10-28。修订：S2-AMOUNT-v2。

依据本轮用户指令：“目前不需要给API做预算限制，先以完成任务为前提”，并明确要求完成金额预算可选改进。本修订只调整金额准入，不授权本轮发送真实API，也不改变模型选择、数据隔离、物理环境或实验门槛。

## 1. 模式与旧版兼容

新版 `o5_s2_provider_profile_v2` 增加显式 `amount_policy`：

- `unlimited`：新版模板默认，不设置金额硬上限。价格、币种、计价证据、金额上限可以为null或省略。缺这些值不进入运行阻塞清单；有完整价格时仍估算费用。
- `capped`：继续要求完整计价与预检/pilot/合计金额，执行发送前预留和所有金额上限检查。缺项不能自动改成unlimited。

旧 `o5_s2_provider_profile_v1` 永远解释为capped，原字段和摘要保持不变，不自动迁移或清空旧额度。v2必须明确写amount_policy，不能因缺少该字段而推测无限额。旧配置/计划/账本原件不覆写。

可选价格字段由校验器补为null（quantum省略时使用模板精度），金额上限缺失补为null。provider、HTTPS接口、模型、账户、凭据变量、seed能力及图文token上界仍是运行要求；请求数、输入12000/输出256上限不取消。

## 2. 费用记录

有完整计价依据才生成费用估算；缺价格/币种或计费覆盖范围时，`maximum_amount`、`reserved_amount`、`accounted_amount`为null，`cost_basis=UNKNOWN`。不将未知费用改为0或虚构币种。

unlimited汇总包括各阶段/总计、known_subtotal和unknown_attempts。只要某组存在费用未知请求，该组总额就是null；已知部分另列，不能将其当完整费用。零请求组可为0，这是无请求，不是把未知费用记零。

usage原件、provider请求ID、耗时、错误、真实/替身标识继续记录。输入/输出usage超冻结token上界仍停止，与是否有价格无关。无金额限制不表示token或服务异常可以忽略。

v2 profile使用 `o5_s2_attempt_ledger_v2`；v1仍使用原账本版本。profile与campaign身份继续绑定，不能在同一旧账本中修改金额模式后续跑。

## 3. 授权

unlimited使用 `o5_s2_operator_authorization_v2`，明确 `amount_policy=unlimited`；currency/stage_amount/total_amount可省略或为null。金额字段如给非null值则拒绝，避免把“无限额”授权误读为有额度保障。币种若填写，须与profile一致。

必须保留具体plan/profile摘要、账户标识、绝对campaign路径、stage及实际用户指令出处。旧v1授权只允许capped；v2 capped授权仍必须填写完整金额和币种。填充null字段不等于绕过计划/账户/阶段校验。

## 4. 不变条件与阶段状态

预检当前固定探针矩阵最多4次请求（配置上限≤8），pilot仍为前8个开发来源、D0≤290次尝试；每决策一次请求加最多一次格式修复。G0无模型调用。未知请求仍停止整个campaign且不得重发；认证/限流/模型漂移/连续服务错误等停止规则保留。

unlimited只消除金额缺项。无真实provider、图文能力证据或具体运行计划时，不得宣称S2-B/C通过，也不自动运行训练/测试集、R0/M0或进入S3。

新计划保存本修订副本和摘要。此前规范和手册中“无金额/价格即COST_NOT_FROZEN不可运行”的条款，此后只适用于capped；旧阶段报告仍反映当时协议，不回写历史结论。源码和协议变更后使用新计划目录，旧冻结计划按漂移规则拒绝恢复。
