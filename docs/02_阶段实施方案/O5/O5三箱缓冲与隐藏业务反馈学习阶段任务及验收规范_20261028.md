# O5 三箱缓冲与隐藏业务反馈学习：阶段任务及验收规范

日期：2026-10-28。后续研究协议：`o5_buffer3_hidden_business_v1`，简称 **HB3**。阶段使用 `HB-S0`—`HB-S7`，与既有 O5 单箱 S0—S2 区分。

**状态：后续阶段计划，尚未实现或运行 HB3 实验。** 本轮仅更新阶段任务和文档导航，不修改代码、数据、旧计划或历史结果，不发送 API，不启动经验生成。经验沉淀的具体方案，在 HB-S4 开始时结合实际训练轨迹另行讨论和冻结，本文件不提前指定实现。

## 1. 本次明确的论文实验

研究问题：在相同三箱缓冲、物理候选、基础模型及实时公开信息下，从已结束训练订单的轨迹与外部业务评价反馈中形成的经验，能否迁移到未接触订单，提高完整订单完成情况并降低业务违规？

本次用户明确：

1. 基线 LLM 直接读取取料区、码垛区及候选，以三箱缓冲方式联合选择取哪箱、放哪里。
2. 业务规则由外部人为预先设计，由独立评价环节统计违规；模型运行过程中看不到业务规则定义。
3. **规则定义不直接公开，但允许模型通过历史反馈间接学习。** 学到的经验可以表达推测出的业务规律，不能因此把“有经验”错误认定为泄漏；必须核实其来源确实是允许的历史轨迹与反馈。
4. **经验中的“原因”首先是有轨迹依据的假设，不能把模型解释直接当作因果证明。**
5. 经验生成、表示、检索和更新的详细方案，留待对应阶段讨论。本文件只固定其权限、输入输出边界和验收责任。

主实验为两臂：

|方法标识|在线输入与权限|跨订单状态|研究角色|
|---|---|---|---|
|`D0-HB3`|相同公开状态、三箱物理候选、统一任务目标及输出契约|无历史反馈、无经验、无跨订单聊天记忆|直接选择基线|
|`M0-HB3`|与D0-HB3相同，增加来自训练历史的允许经验上下文|使用已冻结经验快照；正式测试期间只读|反馈支持的经验方法|

两臂使用同一模型、provider选项、采样参数、物理规则、候选后端、缓冲事件机制、输出和修复策略。首版沿用 Direct-Text 纯文本模态，不恢复图片或识图前置条件。基础目标提示相同，可以说明完成整单及改善外部评价的任务，但不得解释具体业务规则或给出人工选择策略。

无经验基线并不知道任意隐藏的人为偏好；其违规不能直接归因为推理错误。M0-HB3相对D0-HB3的差异首先衡量“历史反馈与经验方法整体”的作用。若要进一步论证经验提炼优于直接增加历史上下文，再于HB-S4讨论是否加入原始历史对照；不在本文件中把该对照擅自升级为必跑主实验。

## 3. 不变边界与新输入输出

### 3.1 三箱缓冲和动作

- 容量固定3：只包含真实已到货且尚未放置的箱体；不提前公开未到货箱、余下订单长度、参考终局布局或未来顺序。
- 沿用已审计的补货机制：环境按原顺序接收，补满缓冲或收到EOS后决策；提交一箱后补货、重新构造请求。EOS来自到货环境，不由模型猜测订单总数。
- 一个箱体无物理候选时，只要其他缓冲箱仍有候选，就不能把该箱的空池当作整个订单空池。全部缓冲箱联合物理池为空才按冻结原因停止；到货、尾单和EOS边界由HB-S1明确覆盖。
- 每箱使用同版本公共几何后端，Top-K≤16，三箱联合≤48。未码箱不充当已放支撑；不把整个联合池裁回16以静默改变研究条件。
- 主模型每次只选一个现有候选或STOP；候选唯一映射到待码箱、槽位、位姿及朝向。不输出任意坐标、不跳过/删除箱体、不卸箱、不重排已提交箱体。
- 不启用业务过滤、beam、后继搜索或未来箱模拟为模型提供优势。复用O4缓冲状态机制时必须隔离其业务编译、业务软评分和搜索路径。

### 3.2 公共请求和响应

公共文本只包含：版本、请求/状态/候选集合绑定、容器与单位坐标、已放箱物理状态、最多三箱的公开属性/槽位、每箱物理候选及统一目标/输出契约。属性按同一公开schema提供，不因隐藏规则或方法身份变化；具体业务相关属性白名单由HB-S0审计后冻结。

公开属性可以支持从历史反馈学习，但不得直接附加评价规则正文、阈值、规则选择器、参考AST、允许集合、候选业务合规标记、推荐动作、内部几何评分、来源/split或隐藏订单信息。业务阈值不能伪装成“物理属性”进入公共输入。例如，固定物理承载与隐藏的业务限载必须使用不同字段和代码路径。

候选显示排列采用不读取业务规则的确定性方法；同一公开状态生成同一物理池与显示映射。具体绑定schema在HB-S1版本化实现，至少覆盖缓冲全部箱体及槽位、已放状态、候选池；响应仅选择当前编号或STOP，候选到箱体的绑定由程序核对，提交前执行独立物理检查。

不把隐藏规则摘要用作可观察标识影响排序或提示；评价器私有版本摘要只进入评估侧manifest。改变私有规则时，固定公开状态下的模型请求、物理候选和显示映射应保持一致。

### 3.3 物理安全与隐藏业务评价

物理规则公开且所有方法相同，沿用冻结容器、直立yaw0/90°、边界、不重叠、支撑、重心和传播承重检查。物理不合法提议不能提交；物理合法但违反隐藏业务规则的动作应如实提交并记错，不能调用参考规则纠正或回退。

业务规则由外部设计者先于新实验冻结，训练/开发/正式测试使用同一版本，研究的是在固定隐藏评价目标下跨订单迁移。规则可以用私有程序或参考AST执行，但不能成为模型动作路径的一部分。若人工评分，应冻结判定说明、记录评分依据，并尽量对方法身份盲评；不能按模型输赢临时修改判定。

物理违法与业务违规分别记账，不使用公开物理检查全部阻止的事件来证明模型降低了隐藏业务违规。业务评价只读已发生轨迹与评估侧完整订单，不影响该订单继续动作、候选、修复提示或停止判断；除物理/协议故障外，不因业务违规提前截断订单。

## 4. 业务指标和反馈的分层

### 4.1 外部评价指标：HB-S0必须先冻结

不能用单一低违规率判断有效。每个计划完整订单均保留在分母，STOP、空池、格式/服务失败、预算中断、未执行均有明确状态。

|指标|定义或必须冻结的口径|解释边界|
|---|---|---|
|完整订单完成率|全部原始计划箱均实际提交的订单数/全部计划订单数|提前停止不算完成|
|完整且业务零违规完成率|全部计划箱物理合法提交，且全轨迹及终态按预定规则无业务违规的订单数/全部计划订单数|核心成功指标；不能只检查最后一帧|
|订单业务违规情况|有实际已观察业务违规的订单数、各终态类别及其计划分母；另列“完成但违规”“未完成且观察到违规”等|失败/无提交/未执行不能默认为零违规成功；仅观察到的违规占比不能单独支持收益|
|业务违规负担|逐规则类型的事件/对象/对象对计数及相应适用分母；每个指标冻结计数单位、去重键、容差和宏/微平均|累计持续违规不能随回放帧数任意重复；最终布局违规和逐步违规分开|
|适用性与覆盖|适用、已评价、待关联对象到达、未装对象导致未评价、真正N/A分别计数|未放对象或关系未完成，不得直接当成满足规则；零分母为null/N/A|
|装载情况|原始整单件数比例、体积比例、完整分母、终态余箱与未到货箱数量|防止少放箱换取表面低违规|
|安全/协议/资源|物理拒绝及实际物理违规、绑定和响应合法率、尝试/修复、usage、费用未知项和端到端时间|不把工程通过当作业务收益|

HB-S0须对每个业务规则族给出独立可手算正例/反例、实际评价时点、终态重算方式、违规归属与分母。业务关系若有尚未放置的端点，只能记为未评价/待完成，不得提前泄漏该端点给模型或记为零违规整单完成。

研究成功必须同时检验完整完成与业务违规，且装载比例不能发生超过预声明容差的退化。具体主检验、业务违规主口径、最低实用效应及区间判据，由HB-S0形成封闭的统计计划后才能执行新Pilot；不得机械继承旧“VR提高3个百分点”等单箱物理门槛，也不得在看到M0结果后调整成功标准。若全部未完成、适用机会过少或出现指标地板/天花板，报告诊断和结论局限，不以综合加权分掩盖。

### 4.2 评价器内部记录与学习反馈不是同一份载荷

外部评价器可持有完整规则、适用对象及详细违规依据；这些属于评估私有信息。HB-S0/1先实现完整、可追溯的内部评价结果，并预留一个独立的学习反馈投影接口。**接口预留不等于授权把内部评价记录全部交给模型。**

HB-S4再讨论并冻结学习反馈粒度：整单汇总、匿名规则编号/分项、涉及对象或事件定位等是否允许；不同选项会改变模型获得的信息量，必须明确记录。规则定义、参考动作、私有阈值和未来箱原始明细不能直接放入生成请求；字段名称或解释文字若等价于给出完整规则，也必须纳入信息公开审计，不能仅因没有AST就声称规则未公开。

本协议允许从反馈与公开轨迹中推断关系、阈值和业务规律。经验中出现推测出的规则并不自动构成违规；必须有训练证据链，不能来自读取评价器配置、人工填写或隐藏答案注入。正式测试订单的反馈对模型和经验库保持封闭，只用于外部评分。

### HB-S0：协议、隐藏规则、指标和来源冻结

开发内容：

1. 保存活动源码与未提交状态，建立HB3变更范围；旧单箱/O4默认与历史证据保护。
2. 外部制定固定业务规则集，审计规则间冲突、物理约束关系和属性来源；保留冲突或不可判断任务的证据，不按模型结果筛选规则或订单。
3. 将私有规则、评估完整订单、模型公共投影分开；冻结公开属性、基础目标和三箱动作权限。
4. 审计DATA03物理订单和来源划分的可复用性。原train60/dev20/ID40/OOD20作为现有冻结来源基础，不重抽样；新属性、规则关联和评估任务使用独立派生版本与manifest，保留原件。当前已暴露开发来源不能改称未接触订单。
5. 明确规则版本在训练/开发/测试保持一致；“未接触”指来源订单未用于该方法开发、历史或经验，不代表隐藏规则也全新。
6. 冻结第4节所有指标、去重与失败口径、统计单位、主检验、效应门槛、开发/Pilot/测试任务数及重复数。评估依据为独立来源，重复和政策变体不扩充来源数；样本量不自动构成功效认证。

验收：独立正反例覆盖每个规则族和未装对象边界；公开字段没有规则定义/阈值；固定公共状态扰动隐藏规则不改变候选/请求；源级划分与曝光账本通过；计分与实验计划无关键空白。学习反馈的细节可以明确记为HB-S4待讨论，不因此阻塞D0离线实现，但禁止提前开放给模型。

### HB-S1：三箱直接选择与离线验收

开发内容：新增独立HB3入口及schema，适配真实缓冲、每箱候选/联合映射、公共属性、文本长度上界、PLACE/STOP、物理提交及内部事后业务评价；复用经审计的HTTP/全局attempt账本、锁、断点恢复和源码绑定，禁止复用旧业务选择策略。

首版沿用现有DeepSeek Flash与本地环境、纯文本、每决策最多一次格式修复、服务重试0、输出≤256和unlimited金额政策，未知费用记null/UNKNOWN。输入12000作为现有工程起点；必须测量联合48候选和长布局的实际文本长度。若无法覆盖，先明确发布长度/编码契约修订再封存计划，不能截掉某箱候选、漏状态、静默提高上限或把旧单箱290次限制直接搬给新任务矩阵。具体请求次数按新订单箱数、方法和修复上限计算。

验收至少覆盖：

- 初始补货、满缓冲、独立槽位、改序后留槽、提交后补货、EOS及尾单1/2箱、已到货=已放+待码守恒、失败不删箱。
- 三箱中某箱空池、另外箱可放时仍可选择；联合空池不调用模型；仅未到货箱变化不影响当前请求/动作。
- 候选不跨箱错绑，改槽位/状态/映射、未知候选、过期响应、额外坐标、重复JSON键及非法STOP严格处理。
- 公共输入和最终provider body仅含允许信息，无图片字段、隐藏规则/AST/评分泄漏；隐藏业务规则不参与候选生成/排序、物理提交或错误修复。
- 物理拒绝不提交，物理合法的业务违规实例确实被提交并记错；相同轨迹的业务计分不因方法身份变化。
- 超长拒绝、服务失败无重试、未知在途不重发、reserved/sent/receipt中断、缺账本/映射、并发锁及计划漂移；替身标记不能作为真实预检证据。
- 逐单报告包含完整分母、业务适用性/覆盖、终止原因、物理/协议/成本；只读报告不发API。测试覆盖真实风险，不为文档变动增加形式测试。

输出：实现差异、离线验收记录、真实预检及八单Pilot具体计划、用户本地运行手册。此阶段所有真实API为0。

### HB-S2：真实预检、八单Pilot和基线封存

开发目标：确认新协议在真实模型上可运行，业务计分有实际适用机会，三箱决策和全订单分母可信；不要求D0-HB3知道隐藏规则、业务零违规或装完全部订单。

任务顺序：先零网络封存精确源码/模型/物理/规则私有版本/数据/计分/调用上限；使用开发公共状态进行真实文本预检，包含多箱、非空布局和尾单边界；预检通过后按新计划运行开发集前8来源D0-HB3。物理G0/缓冲FIFO等仅在提前声明时作为辅助诊断，不自动扩充必跑模型矩阵，也不允许其读取隐藏规则形成特权主对照。

验收：所有计划任务有终态或未执行原因；每个决策≤2次尝试、提交与响应100%可追溯、实际物理违规0；最终协议合法率≥98%，列原始整数，分母为非空候选且已经开始至少一次实际远程请求的决策，服务/最终格式失败记入分母，分母0不能通过。输入usage超界、未知调用、泄漏或漂移分别记录并按冻结规则停止。

另行判断任务难度：报告装载比例、完整完成率、业务适用机会/违规分布和空候选原因。低完成率不自动失败；缺乏业务适用机会、全体早停或无法解释的瓶颈不能自动放行大规模采集。无需证明连续空间全局可装，也不要求先解决旧单箱Pilot的全部空候选问题。

只有新协议工程和任务适用性均达到预声明要求，才封存 `D0-HB3` 的提示、模型、候选、缓冲时序、错误处理、评价接口、源码和依赖。工程通过但难度仍未知记HOLD_DIFFICULTY；不得为进入下一阶段修改数据或门槛。是否要求额外全量复算应在具体计划明确，不把重复旧实验或重复付费调用作为默认收尾任务。

### HB-S3：训练轨迹与外部评价采集

开发目标：为后续经验讨论提供真实训练证据，不提前决定如何总结这些证据。

开发内容：按已冻结D0-HB3，仅采集经验训练来源；每订单结束后生成独立业务评价记录，保存成功、部分装载、业务违规、主动STOP、空池和服务失败。建立episode/step/attempt/评价引用及内容摘要，区分业务失败和技术失败。

验收：训练来源与开发/测试隔离；全部计划来源和失败保留；没有开发Pilot或测试轨迹混入经验训练包；评估私有规则不进入选择器；没有在订单执行中反馈当前业务违规来指导下一步。尚未到货的原始箱清单和隐藏参考动作不得因“订单结束”被自动开放给经验生成器。

交付训练轨迹包、内部评价包及清晰字段字典，供HB-S4讨论。该阶段不自动启动总结、ReMe写入或生成经验卡。真实采集由阶段具体运行计划界定，不沿用旧单箱授权或请求额度。

### HB-S4：先讨论经验方案，再开发与验收

**进入本阶段时再与用户讨论具体方案；现在不预定卡片结构、ReMe接口、BM25/向量检索、提示、卡数、合并周期或生成模型。旧总规范中的相关参数不自动继承。**

届时需要确定并形成可审查方案：允许给学习器的历史反馈粒度；轨迹如何与反馈对齐；经验内容和来源；模型解释的证据要求；保留反例/冲突、版本和淘汰的办法；在线如何读取；是否需要原始历史消融；生成/修复/更新的请求上限、快照和资源记录。冻结后才实施相应功能与真实生成计划。

无论选择何种实现，都必须达到以下验收：

1. 输入仅来自已结束训练订单的允许公开轨迹和已冻结反馈投影；无私有规则配置、测试结果或人工策略注入。
2. 每条经验可定位到真实episode/step及反馈，推断出的规律与观测事实分开，原因标记为“假设/关联证据”，不附虚构的反事实或因果保证。
3. 服务故障不能总结成摆放规律；一次成功或失败不能宣称普遍最优；经验有无证据、冲突和适用不确定性可查。
4. 测试替身/手工金标准只作工程夹具，不能流入正式经验库；开发者可设计结构与通用提示，不能手写业务选择策略充当学习产物。
5. 经验快照可重建、生成/修复有记账，M0-HB3可读取；与D0-HB3差异只来自已声明的经验上下文，不增加候选、搜索或在线业务纠错权限。
6. 在线读取规则及内容预算冻结，正式测试只读；测试订单反馈不得进入本单后续步骤或后续测试订单的经验。

完成标准是“已讨论方案得到实现并通过工程验收”，不是预先宣称经验已经有效。不能因HOLD或生成失败而用人工正确策略补齐。

### HB-S5：开发集配对比较与有限修订

开发内容：在冻结开发来源上，以相同任务/规则/模型/缓冲/候选分别运行D0-HB3和M0-HB3，各自真实推进，不要求分叉后候选逐条相同。Pilot记录若复用，必须证明新旧方法契约、源码和评价等价，不能静默拼接。开发反馈不得自动加入正式训练经验；本协议采用训练集构建经验、开发集选择方案、测试集只读的迁移设计。

验收：全部配对订单、失败和重复进入表格；同时报告完成、零违规完整完成、业务违规/适用覆盖、CR/VR、成本；按HB-S0冻结的双目标与退化容差判断。只减少已放箱或业务适用机会导致的低违规不能判PASS。经验方案修订次数和规则在首次比较前声明；修订说明假设与差异，保留全部版本和退步，不无限试到赢。

通过后才能提交HB-S6最终冻结；无收益为NO_GAIN，区间或样本不足为INCONCLUSIVE，泄漏/缺任务为INVALID_OR_PARTIAL。方法工程可用不等于研究扩测准入通过。

### HB-S6：冻结经验的未接触订单测试

开发内容：冻结唯一最终方法、D0-HB3基线、训练证据及经验快照、反馈/规则版本、公共属性、数据分割、统计脚本与任务矩阵。只使用已审计的未接触来源；同一隐藏规则版本下比较两方法。先冻结样本与重复数、效应阈值及统计方案，后执行，不访问测试成绩调参。

验收：来源隔离和经验只读；正式测试反馈只进入外部结果文件，模型与检索器无读取权限；每方法全部计划分母/失败/费用完整，配对单位为来源，重复不冒充新样本；样本不足或区间宽如实报告。不得根据测试订单写新经验、改规则、换最终快照或补跑直到显著。需要研究跨规则迁移或测试期间连续适应时另立实验，不并入本主结果。

### HB-S7：论文结论与可复核交付

交付：新版协议和历史差异表、全部方法和阶段状态、来源/规则/经验/源码摘要、主次指标与配对区间、成本、代表成功与退步轨迹及不确定经验案例。

验收：明确区分工程通过、开发扩测准入和正式性能结论；达到预声明门槛才支持“固定隐藏业务目标下，反馈支持的经验方法对未接触订单有效”。未做原始历史对照时，不单独归因于经验压缩/提炼算法；未做因果干预，不把原因假设写成因果机制已证明；同规则跨订单不外推为新规则、真实工业或任意订单泛化。无收益、证据不足和失败也必须完整交付。

## 6. 阶段交付和停止状态

每个阶段交付一份阶段记录：目标、代码/文档变更、输入版本与摘要、通过项、失败/未验证项、真实API及替身调用数、费用已知/未知项、下一阶段条件。新文件和输出拒绝覆盖；保留原默认A、旧O4/E2、旧O5图文/单箱协议及证据。

阶段状态至少包括：`PLANNED`、`PASS_OFFLINE`、`READY_FOR_USER_RUN`、`PASS_STAGE`、`HOLD_ENGINEERING`、`HOLD_DIFFICULTY`、`DESIGN_PENDING`、`NO_GAIN`、`INCONCLUSIVE`、`INVALID_OR_PARTIAL`。不得将阶段计划表的存在写成实现完成，也不得因某阶段通过而自动执行后续远程调用。

当前下一项具体开发任务是 **HB-S0：冻结隐藏业务评价、指标和数据/信息权限**，随后为HB-S1三箱直接选择离线工程。HB-S4经验方案明确保留为后续讨论事项；本次没有提前开发该方案。
