# O5 直接 VLM 基线与自然语言经验沉淀开发及验收规范

日期：2026-10-27。协议建议版本：`o5_direct_memory_v1`。

**状态：开发方案，尚未实现、尚未运行新实验。** 本文件收敛论文的任务、基线、经验形式、数据、工程接口、实验顺序和验收标准。表中的数量和阈值是新协议的预设参数，不是已有实验成绩，也不代表统计功效已经得到认证。

## 1. 研究目标与本轮边界

研究问题：在候选生成、物理环境、可见信息和基础模型均相同的情况下，从已完成订单的成功与失败轨迹中沉淀、检索**自然语言经验卡**，能否改善 VLM 对后续候选的选择，并提高完整订单的装载表现？

用户确认的两个定义：

1. 直接 VLM 基线不提供人工策略、经验、正确 AST 和业务指令；仍提供完成任务必需的当前公共状态、当前到货箱、候选、统一任务目标和输出协议。
2. 经验表达“什么状态下，怎样选择候选，更有利于后续装载”，采用自然语言经验卡。

因此，本轮主线为：

```text
D0：当前公共状态 + 当前箱 + 当前候选 → VLM → 候选编号 → 物理提交
M0：相同实时信息 + 检索出的自然语言经验卡 → 同一 VLM → 候选编号 → 相同物理提交
经验更新：已结束订单的轨迹与整单反馈 → ReMe 适配器 → 新版经验库
```

本轮不开发 AST 生成、AST 编译、业务指令解析或新的候选排名器。经验不是 AST，也不需要被转换成可执行规则。模型权重保持不变，学习发生在外部经验库。最终收益必须在独立推进的整单轨迹中测量。

交付分三项报告：**工程能否可靠运行；经验是否带来可测收益；是否具备后续应用资格。** 工程通过不代表性能通过，性能通过也不自动替换生产默认方案。

## 3. 冻结任务：单箱到货、候选选择、整单闭环

### 3.1 第一版统一环境

|项目|第一版决定|
|---|---|
|任务|按原顺序逐箱到货，在固定托盘内尽可能完成整单装载|
|主数据|原始完整的 14–20 箱订单；不得把前 12 箱冒充原始整单|
|到货可见性|只公开当前箱及已放状态；后续箱尺寸、质量、数量、序列和参考结果均不公开|
|缓冲与动作|容量 1；只能放当前箱，或主动 STOP；不跳箱、不换箱、不卸箱、不重新规划已提交动作|
|候选后端|原 A/E2 公共几何后端，单箱 Top-K≤16，所有方法相同版本与配置|
|候选顺序|对物理候选采用固定种子排列，重新绑定显示编号；不按 G 分向模型展示排序|
|规划权限|不使用 beam、深度搜索、模拟未来箱、Oracle 答案或候选的整单预演收益|
|容器|沿用物理配置：1200×1000×850 mm、最大载荷 1000 kg；源码核实后封存精确配置|
|物理|直立、yaw 0/90°；边界、不重叠、支撑率、重心投影、可堆叠、传播承重等沿用原检查|
|物理属性|第一版固定全部箱可堆叠、单箱顶部物理承载 100 kg；明确为模拟假设，向所有方法公开|
|业务语义|不输入业务指令，不生成或使用类别、区域、易碎业务政策、标签规则或正确 AST|
|模型输入模态|主实验固定图文：规范化公共几何 JSON + 当前布局图 + 当前候选图；两模型臂相同图像|
|生产默认|原 A 保持默认，O5 以新入口显式运行|

旧 16/48/3/8/256 预算仍属于封存 O4 搜索协议。本轮直接选择只使用同一候选后端的单箱 16 上限，48/3/8/256 不参与 O5 决策，不能在 M0 中偷偷启用搜索，也不修改旧配置。

候选生成本身含有几何先验，这是统一环境的一部分。论文应写“在固定物理候选池上直接选择”，不能写“无任何几何先验”。原始 G 分、排序、优选标志及保留原因不输入 VLM；候选尺寸、位姿、支撑等直接公共事实可以输入。

图像必须只渲染当前公共内容，不出现未来箱、参考布局、推荐箭头或方法成绩。必须验证请求实际携带图片且模型实际支持该接口。仅调用多模态模型的文本端时，应命名 Direct-Text，并冻结为另一协议，不能静默替代图文主实验。

### 3.2 公共请求和输出契约

新增 `DecisionRequestV1` 白名单：协议版本、`request_id`、`state_hash`、容器物理参数、已放箱几何与质量/物理属性、当前箱、当前候选及显示编号、图片引用和固定目标/格式说明。`request_id/state_hash` 仅用于协议绑定，不作为经验检索特征。

候选标识采用当前请求局部编号，展示映射对全部方法使用同一生成规则。模型只返回：

```json
{"request_id":"...","state_hash":"...","action":"PLACE","candidate_id":"C03"}
```

STOP 输出保留前两项，`action="STOP"`、`candidate_id=null`。不接收自由坐标、代码、AST 或由模型覆写的箱体属性。

- 空候选池：环境直接停止，不调用模型，原因 `NO_PHYSICAL_CANDIDATE`。
- 非空时 STOP：记为模型主动终止；未完成的箱全部保留在整单分母。
- 最多一次格式修复，只反馈格式/绑定错误，不提示正确候选，不提供新经验、不重新采样候选。
- 两次均非法、过期、未知候选或服务失败：保存现场并终止该订单，原因分列；不改用几何候选兜底。
- 选定候选再次独立物理核验，通过才提交。拒绝提议与实际违规分别统计。
- 每个决策使用新请求上下文。D0 不保留跨订单聊天、隐式摘要或服务端会话记忆。

不同方法第一步之后可能走到不同状态，不能要求其全程候选逐条相同。公平要求是**相同公共状态生成相同物理池**，并且后端、上限、物理检查和可见信息一致。

## 4. 方法矩阵与可支持的论文结论

|编号|方法|额外上下文|角色|
|---|---|---|---|
|G0|Geometry-Greedy|无模型、无经验；沿用冻结原几何分与确定性 tie-break|必须保留的强几何参照|
|D0|Direct-VLM|无人工策略、经验、AST、业务指令|论文核心基线|
|R0|VLM + Raw History|同一训练轨迹池中检索的原始历史片段，包含当时状态/动作及已结束订单反馈|区分增加历史上下文与经验组织收益|
|M0|VLM + ReMe Cards|同一训练轨迹池沉淀的自然语言经验卡|论文主方法|

D0/R0/M0 冻结同一 provider、精确模型名/可用版本、采样参数、最大输出、图像处理、基础提示、修复规则和传输错误策略。精确模型在预检时选择已可用接口，不凭本文件假定某个远程版本存在。若服务不能固定模型快照，记录时间与返回元数据并说明局限。

R0 与 M0 的训练历史完全相同；固定相同的附加上下文上限 1200 tokens，最多取 3 个片段/卡，超过则按确定性规则截断。分词器、估算误差及截断位置入日志。D0 不填充虚假经验凑长度；额外输入成本如实报告。

R0/M0 使用同一公共查询构造器及同版本 BM25 检索器，只改变索引内容为原始历史或经验卡。无命中时使用空附加上下文并记日志，不人工补卡。除经验上下文区块外，两者与 D0 的目标和输出约束完全一致，不加入“推荐候选”或另一个模型的动作建议。

M0 对 D0 的改善可支持“外部经验有效”；只有 R0 对照也完成，且 M0 相对 R0 的差异有证据，才讨论“经验提炼与组织比直接加入历史更有效”。只接入普通 JSON 检索而未真正调用本地 ReMe 时，方法必须如实命名，不能标为 ReMe。

本轮不把 Oracle AST、人工策略、业务解析器当作主对照。可选 Random-Valid 仅用于离线调试，不扩充付费主矩阵。

## 5. 经验生产、检索与更新

### 5.1 第一版经验来源

先用 D0 在经验训练集独立运行，保留成功、部分装载、早停、格式失败和服务失败。只有订单终止后，才允许生成历史记录与经验。记忆训练是交互数据收集，不更新 VLM 参数。

总结器可读取：已发生的公共状态、已提供候选、实际选择、执行结果和订单结束反馈。反馈包含计划/实装件数、体积比例、完成标志、停止原因。未到货箱的详细几何、隐藏参考布局、Oracle 最佳动作、旧 AST 和人工改写策略不进入总结器；未来原始订单明细仅供环境计算分母。

服务故障不得总结成摆放策略；一次成功也不能证明某一步选择具有因果最优性。经验可包含适用性有限的建议、失败警示和反例，不得捏造未执行动作的效果。

### 5.2 经验卡结构

正文为自然语言，元数据只承担溯源、版本与检索职责，不进入硬规则执行器：

```text
card_id / version / status: candidate|active|retired
适用状态：从历史公共状态中归纳的布局与当前箱特征。
选择建议：对候选之间相对关系的自然语言建议。
观察依据：历史轨迹中实际出现的结果，明确相关性与证据局限。
失效条件或反例：不适用的状态，或尚未验证的情形。
evidence_episode_ids / evidence_step_ids / source_cluster_ids
created_after_episode / parent_card_ids / generator_digest
```

上面是格式定义，不能预填“优先贴边”等人工策略再作为已学经验。第一份策略正文必须来自本轮真实训练轨迹；离线测试使用明显标记的协议测试文本，不能流入正式经验库。

审计字段中的来源 ID 不发送给选择器。正文禁止出现来源订单编号、split、真实候选永久 ID、隐藏答案、未来原始箱清单或按特定 case 指定动作的查表规则。自然语言中可以使用公共物理量或相对关系，但需能追溯到训练轨迹。

### 5.3 ReMe 适配器

新增适配层至少提供以下语义接口，实际函数签名在开发时以本地版本核实，不假定 vendor 已提供同名方法：

|接口语义|要求|
|---|---|
|`ingest(completed_episode)`|只接受已终止订单，幂等、保留正负反馈及原始证据|
|`consolidate()`|经 ReMe 的真实记忆整理路径生成/合并卡，保留父子关系与反例|
|`retrieve(public_query, snapshot)`|固定快照、只读检索，返回可溯源的卡及分值|
|`freeze()`|封存正文、索引、配置、版本与内容哈希|
|`snapshot()/restore()`|支持离线复核；恢复不触发隐式模型调用|

第一版使用本地 BM25 检索，关闭 embedding 和后台自动任务。查询由冻结程序将当前布局、当前箱和候选公共几何特征转成中性描述；不读取未来箱、历史测试成绩或方法排名。查询构造不调用额外 VLM。

每订单最多一次经验生成，每 4 个训练订单最多一次合并；训练 60 单最多 60 次生成、15 次合并，每次至多一次格式修复。经验库最多 200 张 active 卡；容量控制、去重与替换按冻结的确定性规则执行，保留 retired 原件。检索最多 3 卡且不超过 1200 tokens。

运行 manifest 必须记录 ReMe 源码树/commit 摘要、调用入口、依赖、提示、总结模型、工作区路径、索引参数、是否启用后台更新。若实际版本无法实现上述能力，先报告接口差异并冻结最小适配方案；不安装一个不同版本后沿用旧版本名，不调用未记账的后台 LLM。

### 5.4 两种评测严格分开

**冻结经验迁移，第一阶段主实验：**训练经验库冻结后，在测试期间禁止写入、合并、检索评分调参和摘要更新。R0/M0 共用同一训练历史，测试订单不能进入经验库。三次测试重复共用该冻结库；它们测量调用波动，不等于三次独立训练。

**连续适应，第二阶段可选：**另选未参与主测试的来源组成预定顺序的流。每单先选择和计分，结束后才把本单反馈写入相应历史/经验库，影响下一单。D0 无跨单记忆；R0 可增加原始历史，M0 可生成/合并卡。两者更新权限和预算预先固定，各自轨迹差异属于在线方法总效果。不得回头重跑、改写已评分订单，也不得把连续流结果并入冻结主实验。

### 6.2 必须完成的数据整改

1. 新建独立 `DATA_O5_DIRECT_MEMORY_*`，从原始完整订单派生，保留全部到货箱与原顺序。主协议只选 14–20 箱，不截断为 12 箱，不把旧政策变体复制成新订单。
2. 审计已有 dataset、所有相关 plan/run/private manifest、预留协议和可视化使用过的来源。建立 `source_exposure_ledger.json`，标记 `EXPOSED/RESERVED/UNKNOWN/ELIGIBLE` 及证据路径。未知来源状态不能自动视为干净测试集。
3. 按原始订单及来源别名聚类；跨划分检查完整有序几何/质量指纹，并检查旧前缀、窗口、相同箱多重集、平面旋转等近重复。相同订单的不同窗口、同源变体和同构派生必须放同一簇；不把共同商品尺寸误判为整单重复。
4. 固定模拟物理属性。BED-BPP 的尺寸、质量、到货顺序可继承；可堆叠、物理顶部承载等须明确是模拟配置。旧业务标签及其 AST 不流入输入、查询、经验和计分。
5. 保存全订单 evaluator 数据与逐步 public 投影，单独设置测试读取权限；最终分母只由 evaluator 读取。模型看不到还未到货的箱及订单长度。
6. 保存抽样种子、排除理由、未抽中清单摘要、分层分布和哈希。不得用 D0/M0 成败、G0 是否完成或候选 Oracle 结果选择正式订单。
7. 如剔除总量明显超限任务，应在模型运行前依据必要条件统一处理并报告；压力任务可单独保留，不能混入“可完成订单”结论。

### 6.3 建议首轮规模与划分

|集合|独立来源目标数|用途|
|---|---:|---|
|经验训练|60|D0 采集轨迹，R0/M0 共用训练历史|
|开发|20|前 8 单做 baseline pilot；其后做经验方案与完整链路开发验证|
|冻结 ID 测试|40|主要统计比较，来源隔离、分布与训练相近|
|冻结 geometry-OOD 测试|20|形状/组合分布迁移，预注册的次要探索比较|
|连续适应扩展|另 20|另行冻结、另行记账，不占用主测试样本|

主阶段共 140 来源，可选连续流后为 160。**这些是目标配额，不是已经构建的数据集。** 来源审计后不足时输出 BLOCKED_DATA，先在计划中调整规模或新采数据，不能暗中复用旧留出、补同源变体或按结果重抽。

ID/OOD 根据订单长度、总体积占用比、长宽比、尺寸离散度等外生特征设计。OOD 的特征、阈值及分配算法须先于模型结果冻结；无法形成有明确分布差异且足量的 OOD 时，删除该比较并缩减预算，不把随机剩余集叫 OOD。未见来源迁移与形状分布迁移分别报告。

### 6.4 难度与整单目标的适配

物理任务去掉业务约束后可能比旧 E5 容易，旧失败率不能用来估计新数据难度。开发 pilot 同时运行 G0/D0，报告完成率、终态体积比例、候选数量和停止原因。

- 若开发 8 单中两方法都完成至少 7 单且平均体积比例均≥98%，标记 `CEILING_RISK`；先核查样本分布，不扩大付费矩阵。
- 若完成率接近 0，仍先区分物理不可行、候选覆盖、任务长度和模型接口失败；不直接归因于 VLM 或经验无效。
- 如必须改为更长完整订单或不同固定容器，建立新数据与协议版本、保留原 pilot 结果，在接触测试成绩前重新冻结；不得挑选“模型曾输”的订单作为正式集。
- 第一版不要求主数据必须每单已知可完成；主要比较是同任务下的实际装载比例，完整完成率另报。没有穷举证明时不声称所有订单都存在可行解。
- 旧 12 箱窗口仅可作工程补充，名称须为“完整派生子任务”，不能与原始整单成绩混报。

## 7. 评价指标与统计方案

所有指标在订单完成、STOP 或失败终止后计算。不能只对模型成功返回或候选非空的决策计分。

### 7.1 结果与成本

对计划订单 i：计划箱数 `N_i`、全部箱总体积 `V_i`、独立物理检查通过并实际提交的集合 `P_i`。

|指标|定义与用途|
|---|---|
|主指标：整单体积完成比例|`VR_i = sum(volume(j), j∈P_i) / V_i`，主表对订单宏平均；分母是订单全部箱体积|
|整单无违规完成率|所有计划箱均合法提交且订单无实际物理违规的订单比例；不是解析成功率|
|件数完成比例|`CR_i=|P_i|/N_i`，报告宏平均及总实装/总计划箱数|
|托盘空间利用率|实装体积/容器容积，单独列出，不与 VR 混称|
|停止与失败|空候选、主动 STOP、非法输出、绑定错误、物理拒绝、服务错误、预算中断分别计数|
|安全|提议违规与实际提交违规分开；实际物理违规必须为 0，不能据此宣称模型自己学会了物理约束|
|成本|每计划订单/每决策 API 尝试、输入/输出/图像 tokens、修复次数、实际费用、端到端 median/p95|
|记忆成本|生成/合并/检索时间与 tokens、active/retired 卡数、字节、命中率、卡证据覆盖|
|连续学习|按预定订单顺序报告累计/固定窗口 VR 和完成率；不得仅挑最好窗口|

本轮无业务指令/业务 AST，因此旧业务违规率、AST exact-match、AST 语义一致率不作主指标。环境物理规则仍明确、固定、公开。

### 7.2 主要假设及性能判定

主要假设为 ID 测试上 `M0 − D0` 的订单宏平均 VR 提高。选择 VR 而非仅完成率作为主指标，是因为完整订单仍可能部分装载；完整完成率为关键次指标，不能被平均收益掩盖。

预设实用门槛：

1. 平均 VR 增益≥3 个百分点，来源聚类配对 bootstrap 95% 区间下界>0。
2. 完整完成率差的 95% 区间下界≥−5 个百分点；件数比例差的区间下界≥−1 个百分点。
3. 实际提交物理违规为 0；全部计划分母、退步来源和失败现场完整。
4. M0 每计划订单端到端 median≤D0 的 2 倍、p95≤3 倍；加上训练/记忆成本后另报总费用及按测试订单摊销成本，不只报告在线选择费用。

上述阈值是本轮建议的研究准入参数；如需依据 pilot 和费用限制修订，必须在正式测试前发布新的冻结计划，保留旧参数和理由。不能看测试结果后修改门槛。

统计单位是独立来源簇。D0/R0/M0 测试各 3 次独立调用重复，先按来源对重复取平均再配对；不能把 40×3 当 120 个独立来源。G0 确定性仅跑一次。bootstrap 固定 10000 次和种子，保留源级配对表与置信区间计算输入；未支持 provider seed 时记录“不可控”，不要伪称精确种子复现。

ID 的 M0/D0 是唯一主检验。M0/R0、G0 比较和 OOD 为预声明次要/探索结果；如进行多项确认性推断，须另行预注册校正方案。40 来源、三次调用不自动构成功效认证；默认 `power_certified=false`。可用开发集估计方差和最小可检测差异，若预算不足以支持精度则如实报告。

结果状态分为 `PASS / NO_GAIN / INCONCLUSIVE / INVALID_OR_PARTIAL`。均值变好但区间跨 0，属于证据不足；技术失败或缺任务不能包装成无收益。缺失/预算中断仍在计划表中，报告已执行比例与保守界，不能从分母删除后声称正式通过。

固定经验库仅支持“该库下的迁移”结论。若要声称经验构建过程跨训练随机性稳定，须增加独立轨迹采集与经验库构建重复，另行记账；本轮三次测试重复不支持该外推。

缓存只可加速确定性候选/渲染，键含全状态及版本。正式模型请求不命中旧响应缓存；测试重复必须是独立请求。密钥不写入请求快照、配置、报告或错误堆栈。

G0 不调用模型。pilot 的 D0 若与最终开发计划数据、源码、模型、提示、参数和请求条件完全一致，可记为开发表中已有记录，减少新调用；必须列复用证据，不重复算作两次独立重复。否则保留为早期 pilot，新版本另记，不伪称复用。

正式测试 60 源对应 540 条模型订单记录，加 G0 的 60 条确定性记录，共 600 条；独立来源仍为 60。ID 40 源与 OOD 20 源分开计分。可选连续流另立最多 2400 次选择尝试及 50 次 M0 更新尝试，不包含在上述主阶段总额。

费用冻结必须填明模型单价/计费口径、每请求输入上限、图像计费、选择输出上限 256 tokens、总结输出上限 1024 tokens，以及各阶段**币种金额上限**。输入建议上限 12000 tokens，含附加上下文与图像折算；实际接口预检确认后写入计划。超长请求应在发送前拒绝并记账，不能自动删字段或换更贵模型。

请求次数上限不能替代金额上限。没有核实单价、图片 token 和输入规模前，只能输出 `COST_NOT_FROZEN`，不能启动大批调用。费用按包含全部失败/修复/总结的实付成本报告，供应商计费不可得时明确标为估算。

遇到数据隔离失败、泄漏、候选不一致、经验冻结失效、协议漂移、未知付费请求、总预算达到上限时立即停止受影响阶段并保留现场。单个普通订单失败按计划记分继续其余任务；系统性故障不得通过反复重跑完整批次掩盖。测试已启动后发现实现错误，该版本标为无效，保留全部原件，不修后覆盖旧结果。

## 13. 当前风险与排查顺序

|现象|先核查什么|不应直接采用的解释|
|---|---|---|
|D0 很差|图像实际传输、候选编号、坐标、输出协议、任务是否完整、接口故障|“一定需要经验”|
|D0/G0 接近满分|数据难度与候选后端先验、是否隐藏用了 G 排序|“没有改进空间，所以扩大 API 找收益”|
|M0 无收益|卡证据质量、检索命中、长度截断、过度泛化、任务分布|先加人工策略或放宽 M0 搜索权限|
|M0 赢但 R0 也赢|两者历史一致性、等长上下文、区间|“ReMe 特有机制已被证明”|
|开发赢、测试输|来源差异、过拟合、训练库单次随机性|重新选择测试源或重写旧验收门槛|
|两方法都 STOP|公共候选空还是主动终止、后端覆盖与物理限制|“全局无解”|
|平均赢但个别单退步|共同分歧状态、候选与卡、后续真实轨迹|从不同终态推断某一步的唯一因果|
