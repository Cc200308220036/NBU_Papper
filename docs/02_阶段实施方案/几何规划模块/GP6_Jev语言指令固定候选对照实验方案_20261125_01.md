# GP6 Jev 语言指令固定候选对照实验

日期 2026-11-25（Asia/Shanghai）。状态 `DESIGN_ONLY`。首轮只准备并验证单步对照。真实发送待用户单独授权。

## 1. 研究问题

同一个可观察状态和同一份合法候选，Jev 会不会随语言规则从左边改选到右边？先测一条容易判断、方向可以反转的几何规则。如果有清楚的方向响应，再测多条规则的优先顺序和动态业务条件。

上一次强制文字整单运行中，首箱仍居中，8 次选择均至少违反一条文字规则。最终装入量由 4/19 变为 8/19。整单轨迹分化后，候选也随之改变，因此装入量无法直接衡量语言指令的作用。[强制文字实跑报告](../../03_阶段产出分析/几何规划模块/几何候选器GP6_EMS强制顺序文字真实运行_20261123_01.md)

## 2. 固定状态与首轮实验

用关闭包装承载上限的原 EMS＋Jev G01。读取 `GEOM_CANDIDATES_GP6_TOP_LOAD_DISABLED_RUN_20261122_01/jobs/G01/checkpoint.json` 中保存的请求上下文。三份状态都来自同一个已暴露订单。

| 状态 | 已放箱数 | 完整候选数 | 贴最小 X 边 | 贴最大 X 边 |
|---|---:|---:|---:|---:|
| G01_D0000 | 0 | 30 | 12 | 12 |
| G01_D0001 | 1 | 36 | 4 | 4 |
| G01_D0002 | 2 | 30 | 6 | 6 |

用请求里的 `x_mm`、朝向后 X 向尺寸及托盘边界核对贴边资格。当前托盘 X 边界为 −600 mm 和 +600 mm。箱体的 X 向最小边和最大边分别由中心 X 减去、加上朝向后 X 向尺寸的一半得到。核对时可用 1e-6 mm 处理舍入误差，该值仅用于本实验的贴边判断。逐状态保存左右标签以及两侧均不贴或同时贴两侧的标签。首轮的左右集合必须非空且互斥。遇到与上表不符的状态先记录差异，不根据模型结果换样本。

每份状态测三种条件。原始组使用当时的 `questions.next_action.instructions`。左侧组和右侧组在同一基础指令后分别追加下列一句。两条实验指令只替换方向和对应边界。

| 条件 | 追加文字 |
|---|---|
| 左侧 | `For this decision, you must choose an offered action whose box touches the left pallet edge (minimum X). Return exactly one of the provided Cxx labels.` |
| 右侧 | `For this decision, you must choose an offered action whose box touches the right pallet edge (maximum X). Return exactly one of the provided Cxx labels.` |

每个状态重复 2 轮，每轮三个条件各一次，共 `3 × 3 × 2 = 18` 个预定请求槽位。按下表预先固定发送顺序，第二轮反转第一轮顺序。条件间使用独立请求，不把其他响应放进上下文。

| 决策状态 | 第 1 轮 | 第 2 轮 |
|---|---|---|
| G01_D0000 | 原始 → 左 → 右 | 右 → 左 → 原始 |
| G01_D0001 | 左 → 右 → 原始 | 原始 → 右 → 左 |
| G01_D0002 | 右 → 原始 → 左 | 左 → 原始 → 右 |

同一状态内使用原 `jev-1.14.0`、公开状态、所有候选、可见展示顺序及原 `Cxx` 映射。传输序列化后校验三个正文只在 `questions.next_action.instructions` 有差异。程序只在收到结果后将原始选择与左右集合比对。候选完整交给 Jev，保持原选择；单步诊断到保存结果为止，不放置箱体，也不生成下一状态。

## 3. 实现与最小验收

- 新增独立的单步实验入口和输出包。沿用 `jev_select/transport.py` 中的 `JevTransport`、`jev_select/selector.py` 中的 `parse_response` 及现有请求计量能力。开发端按实际接口核对绑定，保留基础上下文与实际发送正文各自的身份；如果生产账本与订单执行耦合，使用有显式版本的新实验账本，仍完整记录预留、发送、响应、选择和未知发送状态。
- 准备和测试使用已有归档及替身响应。验收包括来源摘要、候选与映射一致、每个状态仅文字不同、方向判定正确、完整 18 槽位、预算和停止行为。筛掉候选、改序或收到响应后改选的实现不通过。
- 受控实验只使用当时可观察的状态和候选。期望标签、历史选择与响应、订单后缀、监测诊断只进入本地核对。沿用既有密钥加载，归档不包含密钥或认证头。
- 如获授权，使用新计划、新账本、新输出目录单次启动，总发送保留上限 18。沿用既有模型及 TypeSafe 端点 `https://api.typesafe.ai/v1/systemone`。无隐式重试、补跑或追加矩阵。技术失败保留实际状态，发送结果不明则保留 `UNKNOWN_SEND` 并停止后续发送，剩余槽位标为 `NOT_RUN`。
- 证据包括源状态和候选摘要、计划与执行清单、实际请求正文摘要及指令、原始响应和选择、槽位状态、统计表及简短中文报告。准备阶段真实调用为 0，结束后交回独立质检。

## 4. 判定和后续

逐槽记录实际 `Cxx`、几何动作、落在左／右／其他、响应状态和可得的原生概率。结果至少报三项：

1. **左、右组各自的规则遵守率。** 列出命中数、有效响应数和预定数，同时保留技术失败与未运行分母。原始组只报实际落点分布。
2. **成对反转。** 每个状态、每轮都有一对左／右指令。只有左指令得到左侧动作、右指令得到右侧动作，才计一次符合预期的反转。两次只换了候选标签但没有按要求换边，单列。完整计划有 6 对，逐状态展示两轮结果。
3. **可选的概率变化。** 服务若返回完整的原生候选概率，分别加总左、右集合的原生概率，比较指令切换前后的变化。保留服务精度，不补造或重新归一化。概率变化和最终选择分开报告。

单个完整配对的正向反转支持该次、该状态下有方向响应；同一状态两轮均反转说明在该状态内可重复。三份状态同属一个订单，结论只覆盖本试点。若没有反转，报告本试点未观察到指定方向的选择反转；失败或未运行不能算模型不遵守。

后续单独设计和授权。若单条规则在多个固定状态可重复引导换边，第二阶段用“先最低，同高再贴边”测试优先顺序，选取两条规则确实给出不同选择的状态。第三阶段测试动态业务条件，例如“有急单箱且有合法落点时优先急单箱”，同时覆盖条件成立和不成立的状态。若单条指令未产生可重复响应，下一轮可独立比较是否增加显式、真实的候选贴边属性，同一呈现条件内继续只替换语言，并保留完整候选。整单装入量和稳定性收益后续另测。
