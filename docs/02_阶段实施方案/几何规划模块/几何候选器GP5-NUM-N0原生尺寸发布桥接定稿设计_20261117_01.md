## 2. 唯一选择：最终原候选池到发布池的桥接

选定 **发布桥接**，不新增数值profile。唯一允许转换位置是 `candidate_backends.build_geometry_bundle` 内：各后端既有生成、原物理准入、压缩及最终排序全部完成后，`audit.final_candidates_digest`和bundle physical/selectable池生成前。新增纯桥接模块拟为 `jev_select/geometry_native_shape_bridge.py`，协议 `geometry_runtime_native_shape_bridge_v2`。两个后端在独立新v17运行协议中都经过同一桥接；E2已具有正确原生类型时尺寸映射为空操作，但仍使用新发布身份。

原始池R是原后端本次返回的有序完整最终池，发布池P是R逐项一对一副本。仅允许修改 `oriented_size_mm[0:3]` 的原生类型，使其为当前已到货箱dimensions按yaw排列的原叶子深拷贝；此外只赋新的candidate_id/fingerprint。保留pose三坐标的类型/位模式及yaw，保留尺寸数值、箱ID、顺序、数量、support/load/resulting_geometry/score/EMS及所有其他字段。不得改dimensions、container、mass、capacity、载荷/支撑边，不能将pose或数据源一起规范化。

理由：缺口发生在原evaluate_pose的可见尺寸输出到提交保存之间。新核心 `_generation_core` 在原物理调用前将l/w转binary64，height来自原item；原 `evaluation.state.apply_candidate`直接复制候选定向尺寸。发布时恢复源类型可使后续原 `_item` 保持严格检查；无需改变当前公开快照的含义。更换profile会同时改变几何数值解释，无法单独解决“提交保存了部分float”这一输出类型缺口，故不采纳。

不选提交后修复：那会令SELECTED/监测/提交动作不同，且掩盖历史不一致。不选快照入口修复：那会重写已存状态、绕过same_native。不在压缩前桥接：原排序/覆盖选择已经冻结，不让新发布身份影响压缩。

桥接对任一R成员校验失败，**整个决策技术ERROR**，保存原池与失败索引，无部分P、无过滤/重排/补候选/另选、无后端回退。R为空时仅在原status=OK_EMPTY且输入准入有效时发布空P，原ERROR不转空池。两后端在同一公开前缀用同一双快照准入；轨迹分化后的快照不要求相同。

## 3. 严格数值、类型及可表示性

定义两个不同判据，不能混用：

- `same_native(a,b)`：现有函数原样保留，类型完全相同；float按IEEE binary64大端8字节完全相同。用于快照、未转换字段、配置、已有记录及恢复身份。
- `E(a,b)`：只用于桥接三条尺寸轴的证明。先要求type恰为int或float、拒绝bool及外部标量，再要求有限、尺寸>0；int的精确有理值为n/1，float的精确有理值为as_integer_ratio()。两有理数分子/分母约分后完全相等才为真。没有epsilon、round或近整数判断。该证明不替代same_native。

令源尺寸D=[L,W,H]，yaw严格int 0或90，唯一目标T分别为[L,W,H]或[W,L,H]。每轴要求E(R.size[i],T[i])；T直接复制源叶子，不从R执行int()/float()猜测。源float的目标类型与位模式不变；源int恢复int。float与float数值相等时仍要求位模式相同（尺寸正数无符号零例外）。证明保留两侧类型、整数十进制文本/float位模式及精确比值。

每个原生int进入既有binary64物理边界前必须有限且精确可表示：转换后int值仍等于原int。它不是“绝对值小于2^53”的粗略截断；2^53+2可表示，2^53+1不可表示。任一桥接前需要的原生字段不满足既有门就先拒绝，不能只比较两个已经被舍入的float。float输入只能是已有有限binary64值；不从float推测原JSON词素，原任务字节SHA与native快照SHA分别保存。

| 手工例（mm） | 源D及类型 | yaw | 示意R定向尺寸 | 唯一发布T及类型 | 结论 |
|---|---|---:|---|---|---|
| I0 | [100,80,60]，III | 0 | [100.0,80.0,60]，FFI | [100,80,60]，III | 三轴精确相等，恢复前两轴类型 |
| I90 | 同上 | 90 | [80.0,100.0,60]，FFI | [80,100,60]，III | 仅按yaw交换L/W，不交换H |
| F0 | [100.0,80.5,60.25]，FFF | 0 | [100.0,80.5,60.25] | 原叶子FFF | 完全不变 |
| F90 | 同上 | 90 | [80.5,100.0,60.25] | [80.5,100.0,60.25]，FFF | 完全不变 |
| M0 | [100,80.0,60]，IFI | 0 | [100.0,80.0,60]，FFI | [100,80.0,60]，IFI | float宽度保留，不统一取整 |
| M90 | 同上 | 90 | [80.0,100.0,60]，FFI | [80.0,100,60]，FII | 来源轴身份随yaw对应 |

以上R是**手工指定接口例**，不是本轮生成器输出或可达性证据。I/F表示严格int/float；数组中1与1.0不是原生同一值。

`0.1`两侧同一binary64时，E使用3602879701896397/36028797018963968，接受并原样保留该float位模式；它不等于数学1/10。新几何仍按原profile把repr(0.1)解释为精确十进制0.1，两种用途分开，不能拿profile十进制值替换桥接证明。raw=0.30000000000000004、源=0.3时比值不同，拒绝；raw=99.99999999999999、源int100同样拒绝，不取整。

| 异常/边界 | 规定 |
|---|---|
| 源int9007199254740993，raw float9007199254740992.0 | 来源不精确可表示，先拒绝；不得将来源int改成舍入后的float |
| 源int9007199254740994 | 可表示性检查可通过，但后续原物理/精确前缀/派生行为一致性仍可能拒绝；不承诺产生候选 |
| 非有限float、溢出、bool、Decimal/Fraction/numpy标量、维度<=0 | 技术拒绝；不转成float接受 |
| 源数字文本1e-400解码为非零下溢 | 保留既有解码拒绝；若来源早已丢失词素，只能检查当前值，不能声称从0识别出了历史下溢；0尺寸因不正而拒绝 |
| 正subnormal | 不因微小而改0；只通过既有有限/往返与后续原准入者才可能继续；任何非零→0转换拒绝 |
| -0.0尺寸 | 非正，拒绝；无“负零尺寸等价”特例 |
| pose的-0.0/+0.0、质量/容量等非尺寸字段 | 完全不在桥接允许集。保留原位模式；任何跨副本/恢复的位模式漂移拒绝，即使数值均0 |
| yaw=True/0.0/180、错误轴顺序、错箱ID、源尺寸缺失 | 拒绝，禁止从候选反推源D或读取未来task补字段 |
| 2.0004变2.0、0.30000000000000004变0.3、H被改写、pose量化/吸附 | 拒绝；原1e-6等容差只留在原物理内部，不用于桥接相等 |

## 4. 不以数值相等冒充计算行为相同

类型变化可能改变乘法、求和及派生指标的舍入，尤其大整数。仅E为真不够声称所有公共行为相同。桥接验证器必须在当前公开前缀的独立副本上复用原 `check_candidate` 分别检查R与P，二者都须原样通过；复用原 `evaluation.state.apply_candidate` 和 `packaging_runtime.layout_facts` 作只读影子转移核对，不调用commit_physical、buffer.place、monitor或内核，也不移真实缓冲。

对影子after，除新箱oriented_size三轴预期类型差异以外，before/after的原静态叶子、pose、支撑边/载荷及其他结果必须same_native完全相同。另核对原函数计算的件数/体积/质量累加、几何包络/垛高及F0已有派生量：类型不变的量要求same_native；单纯尺寸类型派生的整数/float结果允许E，但必须证明后续binary64转换位模式相同；无法形成证明、出现进位/舍入差或非有限即整体ERROR。不用保存的生成器私有result_state/load_increments代替独立转移。此检查是接口一致性防护，不另造物理模拟器。

影子转移仅使用已到货当前项与已放前缀，是原公共物理事实核对，不评估选后稳定性或未来箱体，不形成放置/监测记录。它最多对原最终48候选各核对两份副本，实际次数与时延单独记为publication验证，不能计为commit、PCT或solver次数。原原子性、预算和失败类别保留；验证自身资源/存储失败同样停止，不追加候选预算。

F0仍从P通过原公共事实投影产生。拟实施时须保证原public_facts用于验证的纯投影可在已校验原候选与发布候选上比较，允许差异仅为candidate标识映射及oriented_size相应原生类型；criteria其余字段、排序输入、得分与可选性完全不变。需要抽取纯投影时，只抽函数复用、不改变计算；如发现无法做到此限制，停止实施交QA，不删检查。已读实际实现：public_facts先按pose x/y/z/yaw及箱别名排序，再按原display_order_seed/request_id/state_hash洗牌；local_first取最小Cxx，local_geometry的baseline_label按geometry_score、pose及pick_object取最小键，均不读candidate_id/fingerprint。因此保持池顺序、这些字段和原种子，就不因新ID改变展示或两个方法的动作；纯投影/配对回归必须验证该事实，不改本地策略或引入另一套tie-break。需抽取的私有纯投影只由已校验R/P和当前observation进入，不提供绕过bundle身份检查的公开开关。F0核对复用同份影子after，publication阶段每决策最多96次apply_candidate影子调用；正式F0原有计算另记，不混入实际提交。

## 5. 双快照及确定性身份链

保持 `geometry_runtime_state_snapshot_v1`、`geometry_runtime_public_input_v1`、`geometry_runtime_shortest_decimal_v1`、`geometry_runtime_snapshot_adapter_v1`、`geometry_runtime_cpython_json_v1`及捕获/校验函数v1原封不动。新v17首次输入只能是满足原 `_item` 的新初始状态/后续正确提交状态；历史已坏前缀依旧拒绝，绝不在capture中修复。

B_native保存当前公开state+observation，连续量保留int/float类型、float位模式、数组顺序；B_geometry是按原profile由同一B_native唯一导出的规范字节。两后端同前缀共用同一对字节；common binding保留原字节SHA、effective/geometry/observation摘要、source/physical/environment/data/task/monitor身份。共同输入绑定合同v1可复用内容，但新config/source摘要必然不同；不能复用旧绑定值。原任务raw_sha256、normalized_digest、runtime_digest继续分层，桥接不读取task或改变适配器输入。

当前后端返回的是Python对象；包装层仅在此处用冻结序列化器捕获一次R及generation返回值为新原始字节，校验类型/float位模式往返，之后不重序列化代替这些保存字节。它们不是任务原词素，也不是历史运行原件。R的完整原返回值、generation audit、原candidate ID/fingerprint、原raw action key及逐项顺序以原字节blob保存。新后端raw action key沿用核心八元组[item_id,l,w,h,yaw,x,y,z]及原十进制规范；从原audit按fingerprint定位，禁止从float重新猜精确原key。E2公开接口无该raw key时写null并明确 `NOT_AVAILABLE_OLD_E2_INTERFACE`，不能伪造旧内部key。

P的publication_action_key为同样八元组：item_id及yaw来自R，尺寸来自T、pose来自R，连续量用原profile的numeric_text唯一导出。key表达动作数值，不承诺包含类型；类型身份由native尺寸签名/原字节另绑。新后端还必须证明publication key与原raw key逐值完全一致；E2从R与T各导出发布键并核对，不声称该键就是不可得的旧内部key。

为避免摘要循环，严格按下列顺序构造，不允许把尚未算出的总audit摘要放回候选：

1. `raw_pool_sha256`及原generation字节SHA；保存R，不覆盖generation.candidates。
2. 每个ordinal的proof_core：version、backend、common/backend binding digest、raw pool SHA、raw candidate digest/ID/fingerprint、当前B_native内源item JSON指针、source_dimensions_digest、source/target逐叶类型/位模式、raw/target size digest、三条E证明、raw/publication key、allowed_changed_paths和影子转移/派生一致性凭据。proof_core不得含published ID或自身摘要。
3. `proof_core_digest = digest(proof_core)`；`published_fingerprint = digest({namespace:"geometry_native_shape_publication_policy_v2", backend, backend_binding_digest, raw_pool_sha256, raw_candidate_digest, proof_core_digest, publication_action_key})`，全64位hex。`candidate_id="GP5N2_"+published_fingerprint`，不截断；v17所有候选、mapping、selection及action引用的ID Schema固定正则^GP5N2_[0-9a-f]{64}$（70字符），fingerprint仍为64位hex，不继承旧ID长度限制。重复ID、key碰撞或映射多对一均技术拒绝，不去重。两个后端和不同输入/配置自然分离。
4. P只替换尺寸类型、ID/fingerprint；计算published candidate digest。完成有序mapping行（proof_core引用及摘要、published ID/fingerprint/digest）。每R成员恰一行、每P成员恰一行，ordinal一致；合法空池mapping=[]。
5. 生成 `geometry_candidate_publication_v2`：版本、policy/bridge、config/source/environment、common/backend binding、native/geometry SHA、raw generation/pool引用、ordered mappings、published_pool_digest、validation_counts/timings。语义digest排除timings；timings单独telemetry绑定，不能改变候选身份。
6. 新audit包含原generation不变、publication引用/语义摘要、final_candidates_digest=digest(P)；bundle physical/selectable均P且同序同摘要，不能再用旧断言generation.candidates==P。新后端断言是generation.candidates==R、R→mapping→P三者完整核对；E2原generation仅有items审计而无candidates，要求其原audit字节与独立raw_pool字节同时绑定，不伪造原audit不存在的池字段。

Cxx只由P的原展示顺序映射到新immutable ID。context local_binding绑定config/bundle、physical/selectable、mapping/criteria、publication digest；F0模型可见事实不增加raw audit/bridge诊断/监测结果/未来箱体。selection绑定新context及P的ID。`action_for`仍用P生成原格式精确action envelope（含candidate_id、candidate_set_digest等），不把几何key冒充原action接口。

选后monitor只收到P的已选动作，result/credential绑定P、context/bundle/config及原state。STABLE调用原commit_physical，原oracle复核P并由原place/apply_candidate保存P.size；提交后新箱size必须same_native(T)，原dimensions及pose原样保留。禁止选R却提交P、监测后换类型、原action ID不变但内容替换。UNSTABLE/UNASSESSABLE/ERROR分类及不提交、不改选完全保留。

## 6. 最终拟议接口、Schema与集中路由

下面是定稿的**待实现签名**，本轮没有创建对应生产模块或调用它们：

```python
publish_native_shape_pool_v2(native_raw: bytes, geometry_raw: bytes,
    common_binding: dict, backend_binding: dict, raw_generation_raw: bytes,
    raw_pool_raw: bytes, *, config: dict)
# -> PublishedPoolV2(published_candidates, publication_record, telemetry)
# 不接task、selector、monitor、未来到货、reference_policy；不执行真实提交。

validate_native_shape_publication_v2(native_raw: bytes, geometry_raw: bytes,
    raw_generation_raw: bytes, raw_pool_raw: bytes, published_pool_raw: bytes,
    publication_raw: bytes, *, config: dict, common_binding: dict,
    backend_binding: dict, mode: str)
# mode仅FRESH_PHYSICAL_CHECK或SAVED_IDENTITY_ONLY；恢复不重新生成、桥接或跑影子核对。
# SAVED仅验原blob/证明/结构/身份；原共享恢复转移核验另行完成，不替代它。
```

FRESH先保存R的原字节及输入引用，成功后才发布P与完整proof，再落DECISION_READY。SAVED只消费已存字节，缺件/非法proof失败，绝不调用publish来补件。证明验证可以按现有数据重做精确整数比值比对；不产生新的候选或改写证明。实际返回对象均只含公开P与私有sidecar的不可变序列化副本。

## 8. 三个恢复相位和失败边界

每个新decision的durable sidecar必须同时绑定B_native/B_geometry原字节、R/generation原字节、P原字节、proof/publication语义字节、config及plan/job/source/backend/policy/adapter/environment身份。旧输入blob引用格式可复用，decision包装升v2；checkpoint_v17的execution_binding与geometry_ref必须指向同一组内容。证明不只保存“PASS”，还保存可逐轴核算的原签名和精确比值。

| 相位 | 恢复必须消费及验证 | 新工作/禁止 |
|---|---|---|
| SELECTED | 已存P/context/selection/action、R→P证明、同一before及双快照、plan/config/source/policy身份 | 不再生成、不再桥接、不重选；只完成尚未保存的已选监测与随后一次合法提交。监测未知分发按既有技术状态停止 |
| MONITORED | 上述全部＋原result/credential与P精确动作绑定 | 不覆盖监测、不将类型恢复推迟到此处；STABLE只提交一次，其他分类停止 |

恢复中按原validator在私有副本核验已存before→after的计算，不算第二次实际commit；不得因此重跑FRESH桥接或影子发布验证。proof/source/config/backend/task/scope/float位模式、原字节任一漂移拒绝；缺原R/P/proof/blob不从当前源码重建。v16 checkpoint送v17、v17送v16以及旧源码身份送当前版本均拒绝，禁止重签让其恢复。

拟议错误码均为技术停止，不与预测失稳混合：NUM_BRIDGE_SOURCE_INVALID、NUM_BRIDGE_UNREPRESENTABLE、NUM_BRIDGE_VALUE_MISMATCH、NUM_BRIDGE_UNALLOWED_CHANGE、NUM_BRIDGE_PHYSICAL_DISAGREEMENT、NUM_BRIDGE_DERIVED_DISAGREEMENT、NUM_BRIDGE_MAPPING_INVALID、NUM_BRIDGE_IDENTITY_MISMATCH、NUM_BRIDGE_MISSING_ARTIFACT。缺件/结构/生成预算/存储失败保留原错误和detail，wrapper分类为技术失败，不吞成OK_EMPTY/UNSTABLE。无法完成原子持久化时不发布可供选择的bundle，未知调用不隐式重试。
