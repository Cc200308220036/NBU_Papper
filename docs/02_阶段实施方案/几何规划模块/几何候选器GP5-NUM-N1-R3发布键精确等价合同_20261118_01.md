# GP5-NUM-N1-R3 发布键精确等价合同

2026-11-18；仅 GP5_NUM_N1_R3_KEY_EQUIVALENCE_FIX_AND_REVALIDATION。比较合同版本 `geometry_native_shape_key_equivalence_v1`，追加于原NUM桥接、身份DAG及N1一致性修订，不改历史证明。

原生成器键 Rk 为八字符串列表，发布键 Pk 为 `[item_id,l,w,h,yaw,x,y,z]`，除yaw为原生int外其余为字符串。发布候选的pose、尺寸及原生成器均不修改。`require_action_key_equivalence` 是FRESH和SAVED唯一比较入口：

1. Pk必须是长度8的原生list；item_id为非空原生str；yaw的type恰为int，值仅0/90，bool、float及字符串均拒绝。
2. Pk的尺寸和坐标六槽必须为原生str及规范有限十进制文本：`-?(0|[1-9][0-9]*)(\.[0-9]*[1-9])?`，额外排除`-0`。禁止前导零、正号、指数、空白、尾随零小数及非有限文本。这是原generator.text精确十进制拼写，不进行浮点解析、舍入或容差比较。几何尺寸正性等仍由原生产证明检查。
3. 新后端Rk必须是长度8的原生list且八槽type均为str。yaw只接纳`"0"`/`"90"`，且恰等于已验证原生yaw的十进制拼写。仅此一槽跨类型比较；其余七槽逐字符串精确相等。非规范文本即使两侧相同也拒绝。输入不发生写入。
4. E2仅接纳Rk=null，保持原NOT_AVAILABLE含义；Pk仍完整检查。不从候选伪造E2原key。未知后端拒绝。

保存反例`['synth_1','100','80','60','0','0','0','0']`与仅yaw为int 0的发布键合法等价。错来源、错轴/数值/坐标、错yaw、`00`、`0.0`、float/bool以及缺槽均拒绝。FRESH/SAVED必须执行同一入口，不放宽same_native，不把全键str/int转换后比较。
