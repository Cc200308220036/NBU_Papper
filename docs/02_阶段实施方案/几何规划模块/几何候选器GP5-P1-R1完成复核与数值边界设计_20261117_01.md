# 几何候选器GP5-P1-R1完成复核与数值边界设计

2026-11-17，GP5_P1_R1_LIMITED_REMEDIATION。本文描述本轮合同修订及NUM-01设计，不构成真实内核或订单运行许可，不修改历史合同和摘要。

## 完成复核合同

正式订单门只接受 `geometry_real_kernel_receipt_v2`。旧v1保留文件和集中登记，但不足以满足修订后的完成门。启动仍消费独立launch及外部授权/QA，不依赖自身完成收据；开发替身不能满足真实完成门。

`geometry_kernel_required_coverage_v1`由代码确定必需集合，不由收据填写者删减：K01、K02各两后端、固定local_first，共4个primary job，按计划顺序唯一匹配。K01原600×400容器下实际动作：E2为(-260,-150,0)、新后端为(-260,150,0)，均yaw90、定向尺寸80×100×60。K02为原100×80满底夹具的(0,0,0)及(0,0,60)、yaw0、100×80×60；同型两箱不限定谁先放，候选/任务绑定及公共检查仍逐项验证。此处固定值来自本轮有限合成替身测试，不能称真实内核稳定结论。

每job必须完整EOS、ALL_ITEMS_PLACED、相应件数与逐动作STABLE监测、原成功PLACE提交；技术停止、ERROR-only、缺提交、少case、重复记录均拒绝。每个K01后端另交SELECTED/MONITORED/COMMITTED各一次恢复，共6项：前检查点、后完整record、accounting文件分别引用原字节SHA。共享恢复验证器核对两侧状态与durable blob；选择与动作保持，已有结果摘要不变。

恢复账目绑定plan/job/config及前后检查点规范摘要。本次恢复的selector/singleton均0；SELECTED新增monitor1/commit1，MONITORED重用monitor1、新monitor0/commit1，COMMITTED均0；commit_attempts与commit_successes分开。未知分发不得当0，残留STARTED拒绝恢复。成功完成复核只接收RETURNED及预期增量。

独立 `geometry_kernel_completion_review_v1` 为封闭Schema：version、scope、APPROVED、acceptance_plan_digest、records_digest（有序确切引用集合）、recovery_digest、counter_log（路径及原字节SHA）、coverage_digest，均必需且不接受额外字段。它只消费外部复核，不签发复核。真实计数日志必须原版本/封闭字段、相同plan/预算、连续索引、合法job、全部DONE，数量与收据吻合；每K01的2次入口（primary及SELECTED恢复）、每K02的2次入口，共8次，solver逐次单计且每job非空、总上限仍独立约束。共享数值实现及参数不改。

K03 adapter-only反例及公共负向E2E不进入这四个成功job，也不能由该收据推断为已完成。K03及A03剩余负向项继续NOT_RUN/PARTIAL；后续若需扩大完成语义，应另版本化审查，不能在本合同下偷偷替换集合。P2草案仍最多12入口/512 solver，正式草案仍152/8192，无实际许可。

## 嵌套Schema与指标语义

仅完善v16 checkpoint及其内嵌合同：container、runtime item、pending envelope、placed item、attributes、before/after、observation、bundle、context、selection、action、业务评价及monitor binding/result/diagnostics。复用现有观察和v16结构的封闭定义；attributes/runtime_facts以非空且长度受限的ID为动态键，值为封闭记录；来源文件摘要映射、候选显示映射和拒绝计数映射仍按原合同约束值。诊断使用实际exact_adapter/balance_network/monitor代码的明确字段，禁止未知字段；仅诊断数值叶子另外接纳safe()实际保存的nan/inf/-inf字符串，物理状态及动作数值不接纳这些字符串；并非在共享内核Schema上放宽。

新增 `geometry_order_accounting_v1`，仅在公共循环的既有调用位置观察计数，不复制引擎。run_order_job持久化每次invocation的STARTED/RETURNED/ERROR、resume_phase、前后检查点身份、delta及cumulative；计数分别为selector_calls、singleton_executions、monitor_entries、monitor_reuses、commit_attempts、commit_successes。调用前预留，提交成功返回后另计成功，异常保留。STARTED残留是分发不确定而非安全重试依据。直接开发层episode未启用该账目时显式UNKNOWN_UNINSTRUMENTED/null，不能猜0；真实执行要求活动账目和活动kernel meter。

metrics原counts的真实部分是持久化job累计；test_double_assessments是已保存明确替身结果数。新增accounting区分累计/当前invocation增量，kernel_count_scope另列真实入口/solver累计及本次增量；开发scope禁止真实调用，其两项0由门禁保证，而非把替身次数混入真实次数。未启动run row仍NOT_RUN/metrics=null，无测量不生成虚假0。服务成本NA，本地成本UNKNOWN，完整订单分母及分类不变。v1 metrics/run添加的字段是v16范围的整改补充，原历史文件不补写字段或重签。

## NUM-01：仅设计，OPEN

实际链路为：runtime_task保留原尺寸int/float → geometry_runtime_input捕获共同原生快照并编码独立几何视图 → planner/space_candidates/generator._generation_core → 原evaluate_pose → visible候选 → 原provider/F0 → 原commit_physical → evaluation/state.apply_candidate复制candidate.oriented_size_mm → buffer保存 → 下一次共同快照 `_item`。

生成核心把x/y/z/l/w经 `_physical_number`送入原物理，故l/w成为float；高度仍来自原item。整数诊断原dimensions是[int,int,int]，保存定向尺寸实际为[float,float,int]。下一步 `_item` 按yaw重排原dimensions，以same_native比对保存定向尺寸，因类型不同报RUNTIME_INPUT_INVALID。P1原失败新后端放入1箱后停；本轮回归保留此失败，不把float合成成功当作修复。E2原整数路径的历史成功也不泛化为新后端已就绪。

拟议边界：独立 `geometry_runtime_native_shape_bridge_v2`（尚未实现、未注册）。在新版本候选发布与提交之间，依据原尺寸原生类型及yaw产生明确的定向尺寸视图，同时保存原候选/原物理输出视图、严格数值相等证明、映射摘要和版本。必须先论证这种边界转换是否保持visible候选身份、精确动作及公共oracle输入，再决定采用发布桥接还是独立新profile；不允许在恢复时改历史候选或快照来适配。它不能成为接纳错误尺寸、舍入、溢出或下溢的通道。现有v1共同快照、冻结候选、strict same_native及旧source身份继续原样拒绝。

后续实现若获独立授权，最小验收需覆盖int、float、混合维度、yaw0/90、非方箱、多步、非整值float、超大整值/非有限/下溢拒绝、原错误尺寸拒绝、同前缀双快照可重建、精确提交以及SELECTED/MONITORED/COMMITTED恢复身份。所有不可表示/不严格相等情况停止，不能统一float化或改容差。原生成/压缩算法、物理、LP、监测参数均不在拟议改动范围；如桥接需要改它们，应停止并重新审查授权。
