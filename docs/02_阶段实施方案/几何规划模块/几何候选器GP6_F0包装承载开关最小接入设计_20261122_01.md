# GP6-F0 包装承载开关最小接入设计

2026-11-22（Asia/Shanghai）。**只加一个实验开关，复用 E2、EMS、Jev 和现有订单驱动。** 先用基础订单做 E2／EMS 两项对照，重点看固定容器利用率、装入箱数和预测静态稳定性。本文件用于开发交接。

## 1. 开关的行为

拟议布尔字段 `packaging_top_load_limit_enabled`，由实验计划传到运行配置，默认 `true`。旧计划缺字段时保持原语义。新模式显式设 `false`，与任务、提示、配置摘要和恢复身份一起记录。用项目既有的版本路由承载新增字段和请求形状，旧封闭 Schema 继续生效。

| 模式 | 包装顶部承载上限 | Jev 请求 |
|---|---|---|
| `true` | 按原上限拒绝 `overload` | 沿用原承载字段和提示 |
| `false` | 不按单箱包装顶部承载公斤数拒绝 | 省去 `max_top_load_kg`、`effective_top_permission_kg`、`remaining_top_load_kg`、剩余承载派生字段及“保留承载能力”措辞 |

关闭时保留原始属性、实际重量、载荷传播和支撑边。保留箱体 `stackable`、容器总载重、边界、碰撞、几何支撑与质心检查。Jev 请求仍给尺寸、重量、支撑与几何特征，继续按 `Cxx` 映射精确动作。指标中承载合规或余量记 `NOT_APPLICABLE`，避免把未执行的判定记为零超载。运行结果解释为忽略包装承载时的几何装载与预测静态稳定性。

## 2. 最少接线位置

1. **同一个开关贯穿筛选、放置、保存校验。** 在 [候选物理计算](../../../semantic_pallet_planner/src/semantic_pallet_planner/planner/constraints.py) 与 [独立复核](../../../semantic_pallet_planner/src/semantic_pallet_planner/evaluation/geometry_oracle.py) 中，仅以开关控制 `overload` 拒绝。通过 [公共候选入口](../../../semantic_pallet_planner/src/semantic_pallet_planner/jev_select/candidate_backends.py) 传入 E2、EMS 的枚举和独立复核，覆盖 EMS 已放前缀重建及 [原生候选发布](../../../semantic_pallet_planner/src/semantic_pallet_planner/jev_select/geometry_native_shape_bridge.py) 的独立复核。E2 缓存键包含开关。继续传到 [提交](../../../semantic_pallet_planner/src/semantic_pallet_planner/jev_select/execution.py)、[放置](../../../semantic_pallet_planner/src/semantic_pallet_planner/o4/buffer/buffer_state.py) 和 [保存态验证](../../../semantic_pallet_planner/src/semantic_pallet_planner/jev_select/geometry_execution.py)，以同一规则检查。已保存的评估事实在 `episode.py`、`evaluation.py` 和 `packaging_runtime.evaluate_state` 走同一模式，关闭时也跳过独立的包装超载标记。
2. **Jev 输入按模式投影。** 在 [公开事实与请求组装](../../../semantic_pallet_planner/src/semantic_pallet_planner/jev_select/packaging_runtime.py) 使用同一开关。关闭态用只强调装入、空间和支撑的 `QUESTION`／`OBJECTIVE`，由构建与验证共用同一提示身份。保留原载荷增量或接触信息需要时仅作为物理事实，移除承载上限和余量。上下文校验、摘要、重新构建和候选映射须一起通过。
3. **沿用选后监测和启动链。** exact-v3 现有输入是尺寸、质量、姿态和容器几何，沿用原算法。维持候选 → Jev → 已选动作监测 → 稳定才提交。复用 `run_jev_job`、请求账本与评估/LP 计量。当前正式驱动和计划校验固定四项，首轮两项需在新实验配置中显式登记矩阵，再复用同一批次流程；旧四项条件不放宽。实验用新计划、结果目录和账本，按当前源码生成绑定。启动仍按现有入口，避免另做整套历史回放。

## 3. 开跑前只做两项离线检查

1. **同一个小夹具看开关是否真的生效。** 选一个只违反包装顶部限载的合法几何动作，核对默认模式拒绝，关闭模式在 E2/EMS 候选、独立物理复核和提交/保存校验中一致通过。用同一夹具轻调位置制造明显支撑不足，确认关闭模式仍拒绝。保留老调用默认结果，只需检查相关路径。
2. **检查一份实际构建的关闭态请求。** 核对可发送 JSON 无上限、余量及相应提示，保留质量和支撑信息；`Cxx` 可映射原候选，现有选后监测接线保持开启。使用离线夹具或替身，检查过程零真实调用。

两项通过后交付开关、简短测试收据和可同步的两项计划草案。待新的真实调用授权后，一次运行基础变体 `NEW_00100027_controlled_base` 的 E2＋Jev 与 EMS＋Jev。沿用同一到货、缓冲、展示种子、候选限制及计量；每项拟最多 19 次发送保留、合计 38 次，作为计划上限。承载收紧变体先不纳入，除非核对发现还有独立于承载上限的变量需要研究。报告固定容器利用率、已装箱数、停单原因及预测静态失稳进度，另记垛高和包络利用率。无预测失稳也不能把空池停单解释为全局不可行。

本轮设计以 [历史四项结果](../../03_阶段产出分析/几何规划模块/几何候选器GP6_F0四项真实Jev运行分析_20261122_01.md) 为参照。此前 EMS 末步被几何支撑筛空，关闭包装承载上限不会直接取消该筛选。
