# O3失败归因与轨迹分叉诊断

分析日期：2026-10-19。本轮完成后续推进中的“步骤1：失败归因”，没有修改选择器或候选生成器，没有调用远程模型。

主数据来自 `EXP_OPT_O3B_BUSINESS_OBSERVE_20261016_REMOTE_01`，即业务观察模式。本报告的9个失败任务来自6个独立来源订单；它们不是安全模式的全部13个失败任务，也不是9个独立订单。

## 1. 结论

**当前主要瓶颈是确定性逐步软目标与长期布局的取舍，未发现这9个任务由模型协议或解析偏差导致的证据。** Parser完整离线重算复现了9个任务的原始布局，Flash与Parser在这些任务的对应状态和动作一致。

具体证据：

1. 8个失败任务在第2箱与Geometry首次发生几何布局分叉，另1个在第6箱。9处分叉的两个备选动作都没有放置后业务硬违规；差异体现为Parser追求更小的重箱质量加权中心距离。
2. 在第2箱分叉的8个任务中，两方法放置后地面全高净空总面积相同，但Parser的最大连续净空矩形更小。第6箱分叉的SCN_0054/P1是反例：Parser保留的地面净空更多，却选择更早堆高，后续支撑布局不同。
3. 终止时可分三组：3个任务的全部枚举位姿在边界或碰撞阶段被拒；4个任务仍有无碰撞位姿，但全部支撑不足；2个任务还存在支撑合格位姿，但被不可堆叠或物理承载上限拒绝。
4. 仅在首次分叉改用Geometry当时的动作，再继续原Parser＋Executor，6个任务多放了箱体、4个任务放完，其中2个完整无业务违规。另3个任务放置数未变，表明首次分叉并不能解释全部后续失败。

因此下一阶段应研究**政策允许范围内的形状、支撑与高度保留**。不能只增加K、只最大化空地面积，或仅修改Flash提示词。

## 3. 分析方法与指标边界

### 3.1 轨迹对齐

按同一`episode_id`、到货顺序和`step_index`对齐，比较实际箱体坐标、朝向尺寸与状态，而不是跨方法比较Cxx。Cxx只在本方法本次请求内有效。

分别记录第一次状态哈希差异与第一次箱体包围盒布局差异；后者忽略方形箱冗余yaw造成的等价几何。在本轮9个任务中两者发生在同一次到货，且分叉前状态哈希相同。文中的“第N箱”是`step_index+1`，避免把零基索引误读为到货序号。

### 3.2 空间、支撑与载荷

XY指标按托盘边界和箱体边界构成的非均匀网格精确计算，没有用粗像素采样：

- **地面全高净空面积**：该XY列没有任何已放箱体投影；不包含悬空箱下方可能存在的低矮空间。
- **最大地面净空矩形**：上述净空区域中最大的轴对齐矩形；面积大不保证长宽适合某个箱体。
- **暴露可堆叠顶面**：每个XY列最高箱体的顶面，要求该箱可堆叠。总面积不代表这些面同高、连通或具有足够承载。
- **最大同高顶面连通面积**：同高度、共享边界的暴露可堆叠网格连通块；连通块可为L形，不能当作完整可用矩形。
- **暴露顶面最小剩余物理承载**：从位姿重新传播载荷后计算，属于描述性指标，不是当前箱体一定会经过该支撑的证据。

最终物理可放性以原枚举器和冻结物理检查为准。空间指标不构成全连续空间无解证明，也不替代独立物理复核。空余总体积在同箱数下可能相同，本报告不将其当作有效空间质量的充分指标。

候选漏斗记录**首次拒绝原因**：先边界，再碰撞，再支撑等。某位姿因越界先被拒，不表示它只违反边界而不违反其他条件；各拒绝码不是相互独立的因果贡献。

9处分叉的两个候选放置后硬违规都为0。P0先低位再靠中心：在相关分叉处低位分数相同，居中目标区分动作；P1首先靠中心，SCN_0054/P1甚至为约17.05mm的重箱加权中心距改善，选择将当前箱放至160mm支撑层，而Geometry将其放在地面。

这说明当前规则执行器在忠实执行局部政策时，也可能形成较差的后续布局。不能将这一现象简单归为“模型没有理解指令”。

### 5.1 0052：同样空地总面积，不同碎片形状

第2箱后两方法的全高净空均为809,900mm²，但Parser最大矩形仅315,900mm²，Geometry为720,000mm²。第7箱需要595×400×295mm；Parser失败前最大地面矩形为1200×210mm，面积虽有252,000mm²，但窄边不能容纳该箱任何水平朝向。

终止时Parser垛高605mm，Geometry同到货时刻为355mm；Parser全部位姿在越界/碰撞阶段消失。此处空间形状和高度分布比总剩余面积更有解释力。

### 5.2 0053：支撑、堆叠属性和物理载荷共同限制

Parser失败时还有401,800mm²全高净空，甚至大于Geometry的183,000mm²。但其最大地面矩形仅180×690mm；上层共123个位姿支撑不足，2个触及不可堆叠支撑，8个通过前面检查后因物理承载超限被拒。

这8个`overload`是**物理合成承载上限**，不同于政策中的1/3kg业务限载。只优化地面矩形或最小业务违规，仍不足以解决该案例。

### 5.3 0054/P1：保留更多空地也可能失败

Parser首次分叉后最大地面矩形0.420m²，比Geometry的0.312m²更大，却更早堆高。第12箱到货前Parser/Geometry垛高670/420mm；暴露可堆叠顶面503,200/557,600mm²，最大同高连通顶面119,900/226,200mm²。Parser的70个无碰撞位姿全部因支撑不足被拒，Geometry仍有10个物理候选。

该案例反驳“只最大化地面净空即可修复”的过度归因。[布局及曲线](../../../report/analysis/O3_FAILURE_ATTRIBUTION_20261019_02/figures/O3_SCN_0054_P1.png)

### 5.4 0056、0057、0060：高度与可用形状仍需分别检查

0056/P1失败时两方法垛高均670mm，但Parser/Geometry最大同高可堆叠连通顶面为141,400/486,000mm²；Parser22个位姿在支撑阶段被拒，不能只归因于垛高。

0057/P0失败时Parser/Geometry垛高800/520mm；Parser最大地面矩形215×620mm，无法容纳600×400mm底面。其物理承载裕度描述量较大，也不能抵消无适配空间的问题。

0060/P0在失败前两方法的全高净空总面积均516,500mm²，暴露可堆叠面积也均541,000mm²，但当前590×390mm箱仍只有Geometry有3个物理候选。0060/P1的Parser净空面积更多，最大矩形为280×1000mm，同样存在窄边问题。因此总面积和单一最大面积都不能代替带长宽、支撑和高度的可放性检查。

## 6. 单动作替换：有限的模拟器内因果诊断

操作过程：保持首次分叉之前的同一状态，只把该次Parser动作改成**同一候选集合中的Geometry实际动作**，随后每步继续用原公开Parser＋原Executor、原Top-K、原业务观察模式。每次只向选择器提供当前到货箱；不向决策暴露实际未来序列。新轨迹全部通过物理检查。

这些是离线Parser模拟续跑，不是实际Flash在新状态下的响应。干预点依据历史失败事后选定；强制Geometry动作也可能偏离原政策的严格软最优。它不是可部署的新策略，不能写为新方法在独立测试中提高了成功率。

| 场景/政策 | 原已放→替换后已放 | 替换后放完 | 原最终违规→替换后最终违规 |
|---|---:|---|---:|
| 0052/P0 | 6→8 | 是 | 1→1 |
| 0052/P1 | 6→7 | 否 | 1→1 |
| 0053/P0 | 12→12 | 否 | 4→3 |
| 0053/P1 | 12→12 | 否 | 3→2 |
| 0054/P1 | 11→17 | 是 | 0→0 |
| 0056/P1 | 14→15 | 是 | 4→4 |
| 0057/P0 | 7→8 | 是 | 0→0 |
| 0060/P0 | 7→7 | 否 | 0→0 |
| 0060/P1 | 7→14 | 否 | 0→0 |

在该确定性模拟器与固定后续策略下，一次早期动作变更能够改变6个任务的放置数量，支持早期取舍具有实际后果。4个任务恢复放完不等于4个恢复业务成功；只有0054/P1和0057/P0完整无违规。

0053两政策仍停在12箱，0060/P0仍停在7箱，说明还需分析后续多个决策及支撑结构，不能把“第2箱居中”作为所有失败的唯一充分原因。上述3个未改善放置数的干预，也不证明首次动作完全无影响：0053最终违规实例减少，但后续物理失败仍存在。
