## 2. 执行链与约束

```text
本方法实际状态 → 原候选器 → 公开请求（Schema/泄漏检查）
    → Public Parser AST 或真实 Flash AST（绑定/受限语法检查）
    → 同一个 select_layout 执行器，应用所选变体
    → safe 屏障或 observe_business 提交规则
    → 独立物理检查 → 状态更新与真值指标评价
```

Flash 接口只返回 AST，不沿用旧 `invoke_flash` 已选出的动作。模型 AST 不会被 Parser AST 静默替换。条件 AST 从当前公开箱体解析分支，隐藏真值只参与评价；请求不包含未来到货。

固定配置为 `buffer_size=1`、Top-K=16、seed=20261015、原候选器和三变体 `original`、`relaxed_geometry`、`relaxed_wo_floor`。有限软预算为 `heavy_low=0.05`、`heavy_center=0.25`，属于显式配置的软政策变化，不是原词典序优先级严格不变。

真实调用接口具备：

- 每个实际有候选的 Flash 决策重新调用，不复用缓存；初次失败仅在允许的协议错误时修复一次，传输错误不自动重试。
- 初次请求和修复均在发起前计数。达到上限立即停止调用，保留全部计划任务的终止记录；存在 API/协议故障或上限中断时不能标完整 PASS。
- 公开请求、完整发送内容、初次/修复原始服务响应、AST、绑定与解析状态逐步留档。密钥只从环境读取，不保存 Authorization 头或异常中的任意文本。
- 成功和失败尝试均记录耗时；响应使用量缺失时显式计数；金额为 null，不假设计价。
- 同状态比较采用已保存的 Flash 状态，把 Parser AST 与 Flash AST 分别输入相同执行器；另标闭环状态是否一致。约束数组排序差异先规范化，避免把格式变化当政策变化。

这些远程行为本轮由模拟服务响应与模拟传输验证，不能表述为已完成真实 Flash 验收。

## 4. 新增测试覆盖

22 项新增测试覆盖以下要求；其他物理、业务硬约束与布局特征测试继续由已有套件覆盖：

| 要求 | 验证方式 |
|---|---|
| AST 确实进入三变体 | 修改模拟 Flash 的限载阈值，检查每个变体收到模型 AST，未替换为 Parser AST |
| 合法修复与原始响应留档 | 初次非法 JSON、第二次合法，检查两份原始响应及保存后重解析 |
| 绑定失败不能兜底成功 | request_id/state_hash/policy_digest 三类错误均测试两次失败且不提交 |
| API 异常 | 模拟超时，一次调用后停止，不泄露异常中的秘密字符串 |
| 调用上限 | 限额内初次失败、修复前停止；下一请求不再调用；完整运行器将模拟中断标 PARTIAL |
| 缓存拒绝 | cache_hit=true 响应不产生有效 AST |
| 新状态真实进入下一步请求 | 两步模拟闭环校验状态哈希变化及已提交箱体绑定 |
| 不调用网络的离线模式 | 禁止 socket 建连及客户端 complete，离线运行仍通过 |
| 回放发现篡改 | AST、动作、逐单汇总、总体汇总和 CSV 逐项修改；即使重写事件 digest 仍失败 |
| 原始 AST 与解析一致 | 修改单独保存的 AST，重新解析原始响应后检测不一致 |
| 传输格式与凭据隔离 | 模拟 urlopen，核对实际请求体、超时和返回数据；归档不含密钥 |
| CLI 与误操作 | --help、互斥模式、缺失密钥、重复输出目录、非法来源场景 |
| 语义比较 | 约束和优先级数组重排不产生假差异，阈值改变仍产生差异 |
