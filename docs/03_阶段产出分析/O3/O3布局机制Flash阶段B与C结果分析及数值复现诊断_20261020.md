这些结果支持“Flash 可以在本轮真实闭环状态中稳定执行受限政策解析”。不能据此声称：

- Flash 优于 Public Parser：本轮所有对应方法指标相同，配对差均为零。
- 布局提升来自 Flash：同状态同一 AST 输入同一执行器，收益由软预算与布局选址产生。
- 已证明语言泛化或视觉能力：本轮反复使用 P0/P1 两套固定政策，输入为结构化真值状态，未测试真实图像感知、在线政策切换或复杂自然语言变化。

因此，不建议为相同固定文本继续重复九变体付费调用。后续模型增量测试应在数值复现问题解决后，再设计受控语言与政策变化任务。

## 5. C 验收失败的直接原因

原验收只有 `full_replay=false`，其余 10 项检查为 true。失败列表全部是 Public Parser 的 `historical layout baseline mismatch`：

| 模式 / 任务 | 首个动作分叉（第几箱，1 起算） | 历史 → C 动作 | 汇总影响 |
|---|---:|---|---|
| safe / 0053 P0 | 5 | C11 → C09 | 放置件数 **15/19 → 8/19** |
| safe / 0053 P1 | 7 | C11 → C13 | 主要汇总不变，轨迹已不同 |
| observe_business / 0053 P0 | 5 | C11 → C09 | 最终违规实例 **2 → 3** |
| observe_business / 0053 P1 | 7 | C11 → C13 | 主要汇总不变，轨迹已不同 |
| observe_business / 0056 P1 | 10 | C12 → C15 | 主要汇总不变，轨迹已不同 |

五条均属于 `relaxed_wo_floor`。原策略与几何预算控制未出现该历史动作差异。共同源码文件 SHA256 没有变化，共享数据摘要也相同；不能把它归因于改变了候选器或政策。

C 的 240 条 episode 均完成了自身重建与指标核对。历史对照计数 1436 不应理解为“只有 1436 条可回放”：实现遇到历史不一致便跳过该 episode 的历史步数累计，实际总决策记录为 3028。它依然正确保留 FAIL，没有因自身轨迹能回放而放行历史一致性门槛。

## 6. 数值根因：已在本机复现

布局评分代码使用：

```python
sum(features[k] for k in components) / len(components)
```

布局选择器随后按原始浮点分数排序，再以几何分数和标签破同分，未定义近似同分容差。

取 0053/P0 第 5 箱、候选 C11 的同一组已保存特征：

```text
support  = 0.4833333333333333
capacity = 0.06120739456961294
height   = 0.7176470588235294
```

将完全相同的 JSON 数组分别输入本机两个解释器，得到：

| 解释器 | sum(vector)/3 |
|---|---|
| Python 3.13.5 | 0.42072926224215856 |
| pallet_vlm / Python 3.11.16 | 0.4207292622421585 |

历史日志中的 C09/C11 分数均为前者，同分后选 C11；C 日志中 C09 仍为前者，而 C11 为后者，差约 5.55×10⁻¹⁷，遂直接选 C09。该步公开请求和候选允许集合完全相同，排除了不同输入造成选址变化的解释。

0053/P1 同样出现约一个末位单位的分数变化。0056/P1 的 C12/C15 从历史中的微小差距变为 C 中的同分，之后几何排序改变动作；公开关系数值也有微小舍入差异，但当前物理状态相同。

由此已确认：**当前布局排序对解释器数值细节敏感，极小误差经长期选址反馈放大。** 不只是报告显示位数不同；0053/P0 安全模式少放了 7 件，因而旧结果与 C 不能混用：

- 去地面项 safe 平均件数比例原为 86.43%，C 为 84.59%；总提交步 241 → 234。
- 去地面项 observe 最终违规实例原为 15，C 为 16；完成及无违规完成数未变。

本轮是在两个实际解释器上直接计算复现，不推测具体标准库内部实现。详细输入和结果见分析附件。

## 7. 下一步优先级

1. **先修复并验证数值稳定性，再推进独立测试。** 定义并版本化稳定求和、布局分数的精度/近似同分规则和确定性排序。若几何次级排序也存在近似同分，需一并处理。排序容差不能放宽物理约束或软预算。
2. 添加跨 Python 3.11/3.13 的回归：至少覆盖上述三个来源政策、近同分特征，以及完整十来源三变体两模式。只验证浮点特征误差小不够，还需验证最终动作与轨迹一致。
3. 修复会改变策略决策，须新版本、新目录、重新生成离线基线；保留旧布局实验和本次 C 的 FAIL。不要只把回放误差放宽至 1e-9 后忽略动作差异，也不要手改验收为 PASS。
4. **先做无 API 的数值修复与新基线验证，不立即重复付费实验。** 冻结新版本后，若要声称修复后的真实 Flash 闭环有效，新轨迹须真实调用，不能用本次响应拼接。
5. 通过后再做独立来源、软预算稳健性，以及真正需要模型解析的政策表达/在线变化测试；buffer_size=3 作为后续同条件扩展。

当前可以保留的研究证据是受限解析稳定性和软预算/布局机制的开发期效果；尚不能把这一阶段表述为 VLM 优势、独立泛化或完整期刊证据链已完成。
