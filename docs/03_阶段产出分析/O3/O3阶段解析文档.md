## 一、这次从固定题推进到了什么

O2b 每道题只选一次位置；本次新增的 O3 runner 从**空托盘和完整到货顺序**出发，逐箱运行。每种方法在第 1 步面对同一个当前箱和初始状态；从第 2 步起，各方法依据自己真正提交后的状态生成新候选，所以轨迹可以分叉。业务屏障只拦截违规提议，**不会替选择器改选**。屏障拒放、无候选、解析失败和 API 错误都使首版 episode 明确终止，计划任务仍留在完成率分母。

```text
来源订单 + 公开政策
 → 当前箱（buffer_size=1）与本方法当前托盘
 → 冻结物理生成器 Top-K=16
 → Cxx 候选、公开载荷/接触/距离关系
 → Geometry / Fixed / Public Parser / Flash AST / 真值规则提出候选
 → 公开规则业务屏障 + 独立物理复核
 → 提交或带原因终止 → 状态与属性 before/after/delta → 下一箱
```

## 二、新增代码及其职责

| 文件 | 主要作用 |
|---|---|
| [`attribute_o3_online.py`](../../../semantic_pallet_planner/src/semantic_pallet_planner/runners/attribute_o3_online.py) | 建立来源订单与双政策任务，调度各方法的独立在线 episode；保存逐步原始提议、实际提交、终止、指标、源码快照；生成汇总、来源审计、回放和验收报告。含真实 Flash AST 调用入口，API 失败最多按冻结协议修复一次。 |
| [`o3_online_adapter.py`](../../../semantic_pallet_planner/src/semantic_pallet_planner/runners/o3_online_adapter.py) | 将物理候选转成仅含公开 `Cxx` 编号的 O3 请求，绑定 `state_hash/policy_digest`；从公开状态重算候选关系；业务屏障只放行或拒绝。 |
| [`o3_request.schema.json`](../../../semantic_pallet_planner/src/semantic_pallet_planner/schemas/o3_request.schema.json) | 检查 O3 在线请求结构和候选字段，拒绝额外私有字段。 |
| [`o3_animation.py`](../../../semantic_pallet_planner/src/semantic_pallet_planner/visualization/o3_animation.py) | 从保存的逐步状态绘制两方法并排 3D GIF；每帧在 manifest 关联真实 `episode_id/step_index/request_id`。渲染不参与决策。 |
| [`test_o3_online.py`](../../../semantic_pallet_planner/tests/integration/test_o3_online.py) | 验证双政策状态哈希相同而政策摘要不同、公开映射、非法候选、在线回放篡改检测、来源隔离和伪造的合法 Flash AST 响应链路。伪造客户端只用于接口测试，**不是模型实验结果**。 |

复用的旧模块包括物理生成器、独立几何检查器、载荷重建、O1b 公共指令解析器、O2b 受限 AST 协议和共同 Executor。公开 Parser 与执行器只拿公开文本和事实；真值政策只在评价端及明确标记的特权参考臂使用。新 runner 不修改旧 `PalletEnvironment` 的几何回退行为，而是单独采用“错误或拦截即终止”的 O3 协议。

## 三、本轮数据怎么组成

每个来源订单采用**同一到货顺序、两条公开政策**。P0 是“易碎箱累计承载≤1 kg，电子产品与重箱禁止直接面接触；满足硬规则后优先重箱低位、其次靠中心”；P1 将承载上限改为 3 kg，并交换两项软目标优先级。政策在订单开始前公开，政策变体属于同一个来源订单统计簇。几何尺寸、质量和顺序来自 V1 BED-BPP 派生数据；易碎、类别与承载属性仍是 **synthetic**，不是实测损伤或抗压数据。

| 产物 | 来源与规模 | 用途 |
|---|---|---|
| [O3a 开发试跑](../../../semantic_pallet_planner/outputs/EXP_OPT_O3A_ONLINE_PILOT_20261015_04/acceptance_report.json) | O1b 已使用的 train 来源中前 3 个订单 × 2 政策 × 4 离线方法＝**24 episode** | 检查在线链路、异常和回放；不是独立泛化证据。 |
| [O3b validation 对照](../../../semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_03/acceptance_report.json) | 原 validation 的 **10 个独立来源订单** × 2 政策 × 4 离线方法＝**80 episode** | 开发阶段完整订单对照；旧 validation 已在早期工程中使用，不是未见 test。 |

现阶段实际运行的四臂：Geometry-Greedy、固定属性启发式、Public Parser＋Executor、真值 AST＋Executor。代码已实现第五臂 Flash AST＋Executor，但真实 API 尚未运行。真值 AST 臂是**特权逐步参考**，不是全局最优，也不与非特权方法作为公平竞品。数据清单、来源和跨划分检查见 [O3b 来源审计](../../../semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_03/data/source_split_audit.json)。

## 四、实际验收和评测结果

两个新目录的全部自动检查字段为真：计划 episode 均有记录，已提交物理违规 **0**，回放 **24/24** 与 **80/80**，公开输入 Schema/泄漏审计分别检查 **264** 与 **854** 条请求且失败 **0**；各有 3 组并排动画。验收文件仍标 `PARTIAL`，含义仅是**真实 Flash 臂未运行**，不能写成完整五臂 `PASS`。[O3a 回放](../../../semantic_pallet_planner/outputs/EXP_OPT_O3A_ONLINE_PILOT_20261015_04/replay_report.json)、[O3b 回放](../../../semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_03/replay_report.json)。

O3b validation 的整单结果如下，分母均为 **20 个政策任务**，但独立来源仅 **10 个订单**：

| 方法 | 整单属性成功 | 整单放完 | 平均已放件数比例 | 屏障拦截次数 |
|---|---:|---:|---:|---:|
| Geometry-Greedy | 6/20 | 6/20 | 72.2% | 12 |
| 固定属性启发式 | 6/20 | 6/20 | 69.3% | 1 |
| Public Parser＋Executor | 7/20 | 7/20 | 70.5% | 0 |
| 真值 AST＋Executor | 7/20 | 7/20 | 70.5% | 0 |

本轮没有额外“必达软目标”，且提交前物理和业务硬约束严格检查，所以**整单属性成功与整单放完的计数相同**；后续不能只报成功任务上的软目标质量，还要看全部任务的放置比例与最终属性原始量。Public Parser 相对 Geometry 的配对成功率差为 **+5 个百分点**，以来源订单聚类的探索性 95% bootstrap 区间为 **[-15, +30] 个百分点**；区间跨 0，不能宣称统计上有确定增益。[逐单指标](../../../semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_03/metrics/per_episode.csv)、[配对区间](../../../semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_03/metrics/paired_cluster_ci.json)。

[双政策配对表](../../../semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_03/metrics/policy_pairs.csv)显示，四种离线方法均有 **3/10** 个来源订单在 P0、P1 下都完成。这只是“两政策均成功”的计数；本轮没有逐订单证明政策切换必然要求不同动作，不能把 3/10 直接写成“模型理解政策切换的成功率”。

O3a 的 6 个开发政策任务中，四种离线方法均未整单完成；这是保留的**负结果**，不是代码回放失败。O3b 中有 **41/854** 条逐步记录的 Top-K 没有业务可行候选，完整枚举也没有满足解；**其中 12 条**连物理候选都没有。Top-K 截断导致“全枚举有解但 Top-K 没解”为 **0**。这些计数以**方法自己的分叉轨迹的步骤**为单位，不是 854 个独立订单，也不能直接解释为连续空间全局无解。[O3b 候选覆盖](../../../semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_03/metrics/coverage.json)。

## 五、怎样读一个 O3 episode

以 `SCN_0059/P0` 为例，先看[逐步 CSV](../../../semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_03/metrics/per_step.csv)中的 `episode_id`、`method`、`step_index`：

1. `state_hash` 是本步实际托盘，`policy_digest` 是本次公开指令；`candidate_set_digest` 与私有 `mapping_digest` 让请求和候选编号可重放，映射本身不会送给模型。
2. `proposed_label` 是选择器想放的 `Cxx`，`committed_label` 才是真正放下的；`screen_intervened=true` 且提交为空时，说明业务屏障拦截，不能算选择器成功。
3. `attribute_before/after/delta` 记录易碎箱承载、重箱高度/中心距离及面接触对的变化；`raw_*` 字段评价的是**原始提议**，不能用屏障后的安全结果抹掉错误。
4. `status` 说明继续、放完、屏障拦截、无业务可行候选或无物理候选；[逐单 CSV](../../../semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_03/metrics/per_episode.csv)再汇总完整任务结果。原始公开请求在各 episode 的 `selector_inputs/<request_id>/public_request.json`，隐藏真实候选映射存单独 `.private.json`。

## 六、尚未达到的 O3 验收项与下一步

在本地 `pallet_vlm` 环境配置密钥后，从仓库根目录执行**新的输出目录**（不在离线目录上加 `--resume --remote`，两者计划方法数不同）：

```bash
read -rsp 'DeepSeek API key: ' DEEPSEEK_API_KEY; echo; export DEEPSEEK_API_KEY
PYTHONPATH=semantic_pallet_planner/src python -m semantic_pallet_planner.runners.attribute_o3_online \
  --output semantic_pallet_planner/outputs/EXP_OPT_O3A_ONLINE_PILOT_20261015_REMOTE_01 \
  --split train --limit-orders 3 --remote --render-comparisons
PYTHONPATH=semantic_pallet_planner/src python -m semantic_pallet_planner.runners.attribute_o3_online \
  --output semantic_pallet_planner/outputs/EXP_OPT_O3B_ONLINE_VALIDATION_20261015_REMOTE_01 \
  --split validation --limit-orders 10 --remote --render-comparisons
```

若完整任务中断，用**同一输出目录和同一参数**加 `--resume`；程序会先核对源码、数据哈希与已完成记录的回放。已有部分 episode 目录但未生成完整 `episode.json` 时，会拒绝继续，应先审查该部分产物，不要手工拼接成成功记录。密钥仅来自环境变量，不写入仓库或产物。O3a/O3b 不估算或考核费用，远程请求、错误、token 与时延仍留痕。

远程完成后，应先看两个 `acceptance_report.json` 是否为 `PASS`、`replay_report.json` 和 `audit/schema_leakage_report.json` 是否通过，再比较 Flash 与 Public Parser 的**配对整单属性成功差**及失败原因。若强 Parser 仍持平，论文只能主张该受限规则域下混合执行架构的可靠性，不能宣称 VLM 超过规则系统。稳定在线基线建立后再做语言泛化与 O5/ReMe 记忆实验；本轮 O3 未启用记忆。
