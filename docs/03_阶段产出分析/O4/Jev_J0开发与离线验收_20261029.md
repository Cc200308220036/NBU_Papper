## 4. J0范围与后续门槛

- 模型输出只约定为Cxx。当前实现编号恢复接口，但尚未接收真实响应、提交仿真动作或形成订单选择闭环；这属于J1。
- 公共Parser支持既有工程语法，不承诺理解任意自然语言；不支持的要求在模型调用前失败。本地内部AST仅用于业务判定，不进入模型输出契约。
- 经验字段固定为空；J4再增加检索、沉淀与验证，不把预留字段视作学习能力。
- 候选仅为各箱既有TopK，当前业务合法不保证未来可完成；J0没有验证全局最优、长期收益或未见订单泛化。
- 默认请求字节上限96000；不是token计数。J2需验证实际服务token限制、Choice响应结构、served_model、预算、成本与延迟。当前模型名只作冻结配置，没有执行服务可用性验证。
- 本次使用自包含构造案例，不依赖缺失的F阶段订单快照；J3须另行恢复/导入并冻结真实来源订单，不得把构造案例当测试集。

下一阶段J1应实现离线选择器/服务替身、原生响应解析、编号恢复后提交、账目与回放，以及失败恢复测试。J0通过不代表J1或J2通过。
