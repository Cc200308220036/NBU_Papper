# Jev J3开发验收与真实对照实验

日期：2026-10-29。状态：**执行中，不能视作J3完成报告**。最终实验结果、回放与逐项验收尚待填入。

## 任务与实现边界

J3将执行准入与业务目标分开：全部物理TopK参与选择，候选序号恢复后独立核验物理条件并提交，提交状态持久化后才进行独立业务评价。业务违规、全部候选违规和唯一候选违规均不触发业务停止。碰撞、边界、支撑、不可堆叠和物理承载限制保留。Jev不生成AST，memory_mode=none。

新增execution.py负责物理提交，dataset.py负责公开受控任务及来源审计，batch.py负责冻结、多方法运行及重建。配置、Schema、候选、上下文、状态机、选择器、评价和CLI按v2扩展，v1默认含义与旧证据保留。全部新增代码与测试位于jev_select。

## 数据与公平条件

使用仓库V1的100个基础场景及完整到货序列，派生B1/B2共200个业务任务。100个场景对应99个来源连通组；SCN_0088与SCN_0089共享原始订单。语言和buffer变体不增加独立样本。

保留原几何、重量、stackable、物理承载和原类别。原数据只有general/electronics，另以商品ID和公开固定SHA-256生成合成业务类别与禁压/限载/加固标签，模型事实显式标记synthetic_controlled_v1。该实验验证来源几何订单加受控合成业务任务，不复现原始作业单的全部语义。原私有注释仅用于溯源分组，不生成在线政策。

开发集为固定首个训练来源的两个业务配置，三方法共6个job。正式范围为原ID、几何OOD、语义OOD全部40个基础场景、80个任务、240个job，来源统计单元为39组（20/9/10）。正式计划将在真实开发验收后冻结，不按Jev结果筛选。

三方法为shared_geometry、shared_business_lexicographic与jev_choice。业务启发式只使用公开当前事实及规则，比较新增违规、动作后违规、几何分和固定动作键，不调用私有参考评价，也不删除违规选项。同状态三方法看到相同物理池与事实；动作分叉后按各自真实状态生成后续候选。
