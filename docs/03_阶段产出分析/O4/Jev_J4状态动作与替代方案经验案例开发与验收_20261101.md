## 1. 改变经验的内容

经验应回答“在什么状态下选了什么、造成什么后果、当时有什么其他选择、改变前期选择是否有帮助”，而不是只复述禁止接触、禁止承载或限载规则。本次新增 `inspect-decision-cases` 命令，从保存的真实轨迹提取状态和执行结果，独立重算当时物理候选池，并对有界前期分支做同策略的后续模拟。

新的经验案例采用 `state_action_comparison_prototype_v1`，包括：

| 内容 | 实际记录 |
| --- | --- |
| 当前状态 | 已放箱的尺寸、类别、重量、位置、标签、强化属性；当前可见新箱；生效业务要求 |
| 底箱和支撑链 | 直接支撑与祖先支撑、已有上载、增加上载、生效业务限载、物理承载上限 |
| 实际动作 | 所选新箱、候选绑定、位置、朝向 |
| 违规后果 | 当步新增违规、放置后违规、历史终态违规；按规则分别统计数量与有单位的严重度 |
| 原因证据 | 哪条支撑链累积超过限载；哪些规则被触发；哪些是计算机制而非归纳性因果结论 |
| 当时替代候选 | 原保存物理池内的其他箱体与位置，以及独立计算的单步后果 |
| 前期方案对照 | 相同已执行前缀、不同一个早期动作、相同后续策略的模拟终态与过程违规 |
| 适用边界 | 实际与模拟分开；来源数保持为 1；未发现改进也如实记录；不自动激活 |

完整状态保存在案例 JSON 中；给策略看的文本只保留紧凑的相关状态、后果和对照结果，不泄露全订单未来序列或私有评分。当前文本是预览文件，未实际发送给 Jev。

## 2. 真实案例：为何新箱没有超过标称限载，底箱仍违规

来源为 `EXP_JEV_J4_V2_MODERATE_REST3_20261101_01` 的训练任务 J0000，来源订单 00100153、v2 适中档、B2。真实 Jev 轨迹放置 6/15 件后物理候选为空；历史终态有 8 个违规实例：区域 1、禁止接触 2、业务限载 2、禁止顶部承载 1、相对位置 2。这是本条部分轨迹的终态，不是完成全部订单后的结果。

第 5 次放置（D0004）将一个 8.01 kg 普通货物箱放在强化玻璃箱上。直接支撑的强化玻璃箱有效限载为 23.5 kg，可以承担本次增加的 8.01 kg；但载荷继续向下传到另一只底箱：

| 底箱相关属性 | 值 |
| --- | --- |
| 类别 / 自重 | 家用清洁品 / 9.8 kg |
| 原有顶部载荷 | 6.38 kg |
| 生效业务限载 | 10.5 kg |
| 放置前业务剩余余量 | 4.12 kg |
| 新箱传入载荷 | 8.01 kg |
| 放置后顶部载荷 | 14.39 kg |
| 超出业务限载 | 3.89 kg |
| 物理承载上限 | 89.25 kg |

关键机制是累计载荷沿支撑链传播：`6.38 + 8.01 = 14.39 > 10.5`。检查新箱重量是否小于 10.5 kg，或只检查直接支撑的强化箱，都会漏掉祖先底箱的违规。底箱自重不计入其自身顶部载荷；业务标签与强化覆盖规则决定生效业务限载，物理上限独立检查。

这形成可复用的状态经验：“若祖先底箱剩余业务承载余量小于即将传入的载荷，即使直接支撑箱可承载、物理检查通过，仍会出现业务超载。”它必须带着上述条件和实际数值，不能脱离上下文泛化为某个类别一律不能作为底箱。

## 3. 前期候选对照：保持放置量，检查后续违规

选择最早引入违规的实际动作 D0002（第 3 次放置）作为分叉点，固定前两次真实动作。该步保存物理池中有 48 个候选，其中 6 个独立计算后不新增违规；这 6 个都是同一个食品箱的其他位置，因此不能把它们描述为不同箱体。

实际动作是食品箱 6.36 kg 放在地面 `x=337.5, y=0, yaw=90°`。每个当前可见箱先按单步违规和几何确定一个代表候选，再冻结最多 4 个分支；其中包括实际动作对照、同箱换位和两只其他箱体。后续统一使用本地 `shared_business_lexicographic` 策略，均自然运行至物理候选耗尽，没有按结果提前截断。

| 分支 | 第 3 步选择 | 最终放置 | 终态违规实例 | 过程违规实例步数 | 曾出现的不同违规实例 | 是否支配对照 |
| --- | --- | --- | --- | --- | --- | --- |
| 对照 | 原食品箱，x=337.5 | 6/15 | 4 | 12 | 4 | — |
| 同箱换位 | 原食品箱，x=387.5，其余姿态相同 | 6/15 | 2 | 4 | 2 | 是 |
| 换箱候选 A | 清洁品箱 10.81 kg，x=347.5 | 6/15 | 3 | 9 | 3 | 否 |
| 换箱候选 B | 另一清洁品箱 10.81 kg，x=347.5 | 6/15 | 3 | 9 | 3 | 否 |

“过程违规实例步数”是每次放置后违规实例数之和，用来观察违规持续暴露，不等于不同违规总数。kg、mm 和实例数分别报告，不相加成一个无单位总分。

同箱沿 x 方向移动 50 mm 的分支中，禁止接触实例从 1 降为 0，相对位置实例从 1 降为 0（50 mm → 0）；载荷超限实例仍为 2，累计超限仍为 7.21 kg。这个方案减少了本地受控模拟的最终和过程违规，但没有解决限载问题。两只清洁品换箱方案虽然终态只有 3 个实例，却引入区域和禁止顶部承载违规，存在规则间代价转移，不能认定全面优于对照。

真实 Jev 的历史终态为 8 个实例；本地对照为 4 个实例，因为后续选择策略不同，不能用“8 → 2”宣称某一个前期动作的效果。可比较的是同一后续策略下的“4 → 2”。全部分支都只放了 6/15 件，不能声称改善了整单完成率或找到全局最优排列。

## 5. 离线运行指令与后续接入

在仓库根目录执行，输出目录必须尚不存在：

```bash
PYTHONPATH=semantic_pallet_planner/src python -m semantic_pallet_planner.jev_select inspect-decision-cases \
  --experiment semantic_pallet_planner/outputs/EXP_JEV_J4_V2_MODERATE_REST3_20261101_01 \
  --output /tmp/jev_state_action_case_new \
  --job J0000 --fork-mode first_violation --max-branches 4
```

此命令只允许训练轨迹，核验封存，不访问模型接口、不写经验库。默认选择最早新增违规处，可显式使用 `--fork-mode first_pick` 检查第一步选择；它们是不同问题，应分别登记。

后续正式接入应使用“案例证据 → DeepSeek 压缩解释 → 数值与证据绑定核验 → 语义核验 → 满足来源和准入要求 → 检索注入”的路径。给 DeepSeek 的输入应包含相关实际状态、实际结果、当前可见替代动作，以及另行标注的受控模拟证据；输出需要分别写清触发条件、载荷/空间机制、比较结果和未改善的规则。当前实现止于案例证据与文本预览，既有生成协议、卡片合同和激活门槛尚未改造，未将模拟收益写成真实收益。
