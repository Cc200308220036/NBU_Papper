两模型合计576个episode，其中243个因`invalid_ast`或`invalid_binding`停止，占42.19%。Text为118/288，Image为125/288。零业务违规包含大量提前拒绝，不能据此称为任务效果良好。

Text和Image的全部288条实际已码ID序列分别都是对应Parser序列的前缀。Text的118次协议终止中117次比Parser少放箱，另1次发生在Parser本也将停止的进度点；Image的125次全部损失放置进度。Parser本可无违规完成而模型因协议停止的任务，Text为24个，Image为29个，恰好对应总体完成数差额。

这支持“当前进度差距主要由协议拒绝截断轨迹造成”的归因。它不证明修复后所有模型轨迹必然达到Parser，因为旧运行未观察到停单之后的模型回答。

Oracle固定语义下，启发式17/72仍高于搜索13/72。不能用真实Text中搜索8/72、启发式7/72的差值宣布搜索更优：不同API失败位置已混入该比较。

## 3. 编译与失败归因

| 订单模型指标 | Text | Image |
|---|---:|---:|
| 编译机会 | 2153 | 2064 |
| 首答有效 | 2026（94.10%） | 1936（93.80%） |
| 最终有效 | 2035（94.52%） | 1939（93.94%） |
| 最终失败 | 118 | 125 |
| 有效AST的参考语义一致 | 2035/2035 | 1939/1939 |

允许集合、对象集合和条件/例外的一致计数均等于最终有效AST数。不能只报条件有效率100%而删去失败；全编译机会口径为上述94.52%/93.94%。两模式因轨迹提前终止而访问了不同状态，不能直接把两个总比例差归因于图像。

243次最终失败分类：

| 原因 | 数量 |
|---|---:|
| 未接受的货物类别枚举 | 233 |
| 请求/状态绑定不一致 | 7 |
| 其他AST/schema问题（摘要长度等） | 3 |

类别枚举问题占最终失败的95.88%。典型输出为`glass`、`cleaning_supplies`或`清洁用品`，而系统实际接受`glassware`、`household_cleaner`。

具体案例：编译冒烟`responses/D0000021.json`，业务规则要求食品与清洁用品不得接触。模型已经输出`forbidden_contact`及食品对象，但将清洁用品写为`cleaning_supplies`；两次回答均被`unknown category`拒绝。完整订单`responses/D0000157.json`出现同类问题。

这里存在上一轮实现的公共契约缺口：

1. `o4_d_compile_prompt_v1`列出了允许字段，却没有明确列出所有类别及其中文含义。
2. 输出schema的selector value允许一般字符串；类别枚举主要在后续`normalize.validate_selector`中检查，模型看不到该完整限制。
3. 一次修复只发送`invalid_ast`/`invalid_binding`粗错误码，不发送具体字段路径与允许取值；模型收到的信息不足以定位类别问题。

因此不能将这233次失败直接解释成“模型不理解业务”。它们首先表现为模型输出词汇和程序契约不一致。完整订单255次修复仅救回12次（4.71%），也说明当前修复信息没有有效覆盖主要错误。

为隔离原因，仅对失败响应的**副本**做事后诊断：将上述三个类别别名映射到正式枚举，未改其他规则或绑定。233条响应随后均能通过校验，并与对应参考语义签名一致；编译冒烟4条失败副本也有同样结果。此诊断未更改原始输出或准确率，未补做未来动作，不计作模型成功或修复成功，也不证明新提示能保证同样结果。

## 4. 图像增量与耗时

Text/Image共同到达的相同任务、相同规划器、相同公共状态共有1988组：

- 两者均有效1855组；两者均无效98组。
- 仅Text有效21组；仅Image有效14组。
- 同状态的公共箱面事实逐组一致，仍未出现可支持图像增量优势的证据。

这些状态存在同订单、同轨迹依赖及提前终止的共同前缀选择，不能当1988个独立样本作简单显著性检验。应由尚未运行的配对固定题进一步分离输入模态与轨迹变化。

完整订单请求耗时P50为1.975秒、P95为2.637秒、最大7.835秒；所有attempt累计约8925秒（2.48小时）。该值是客户端尝试耗时之和，包含网络与响应校验，不是纯模型推理时间，也不包含全部图像准备、规划和最终回放。

订单usage为输入58803700、输出1288867、合计60092567 tokens，无缺失。费用仍为null，没有计价或账单依据，不据此估算金额。
