# O4-E5真实完整订单闭环结果分析

2026-10-27。用户已完成冻结计划的20个job前缀与220个job续跑，真实矩阵240/240执行完成。核心结论：模型在本轮混合规则上最终解析正确，真实闭环能够运行；相同规划器下与Parser/Oracle的已保存订单指标一致，未观察到模型或图片带来的结果提升。多数订单未完成，主要限制落在当前候选/业务约束与规划过程，而非本轮最终AST错误。

本次分析只读取已保存指标、账目、故障归因及少量案例，不调用API、不重新运行轨迹、不追加240条全量复查。范围仍为箱体直立、标签顶面朝上、yaw为0°/90°；E3暂缓，E4不在范围内。


具体案例补充：[代表性失败订单可视化与输入输出解析](O4E5代表性失败订单可视化与输入输出解析_20261027.md)，选取6/12箱的中位数订单，区分业务限载、候选拒绝与托盘实际利用率。

这次模型任务是将显式业务文本转成结构化AST，由公共规划器选位置。输入采用规则ID、优先级、覆盖关系、条件和单位都清楚的结构化表达，完整公共事实已提供给Text；不是独立收集的自然表达泛化测试。相同业务规则会在多个状态中重复编译，因此943次决策不是943条独立语言题。

single的Parser、Text、Image、Oracle的订单指标一致；buffer的Text与Oracle在相同规划器下也一致。本轮观察到“模型可以正确接入”，尚无优于强规则系统的增量。single的Text/Image结果相同，未观察到所测指标的图像增量；这不等同于证明所有场景图像都无用。Image未安排buffer实验，不作其缓冲结论。

## 5. 为什么AST全对，订单仍不完整

已保存停止原因如下，按240个方法记录统计：

| 终止原因 | 数量 | 解释 |
|---|---:|---|
| `all_items_placed` | 16 | 所有计划箱放完 |
| `no_compiled_business_candidate` | 184 | 当前方法候选中没有满足已编译业务约束的动作 |
| `fifo_head_blocked` | 24 | FIFO队首受阻，当前策略不能换箱绕过 |
| `no_physical_candidate` | 16 | 当前公开采样未找到物理可行候选 |

另有14条最终诊断标记`topk_coverage_limited`，表示公开采样池与保留Top-K间存在覆盖限制；这是与停止原因交叉的诊断，不再额外加到240。终点诊断的`search_truncated`为0，也不能据此宣称搜索已穷举所有几何状态。

例如来源`00101152`的C0/single，Text将6条业务规则正确编译，最终放入8/12箱，待放`item_09`，余`item_10`—`item_12`尚未到达。最后公开采样有38个物理候选、返回Top-K为16，但完整采样池的参考业务允许数也是0，程序正确停止，未冒险放入违反业务要求的位置。这里不能归因于该步模型解析错误，也没有证据认定只扩大Top-K就能解决。

该状态只证明当前已形成布局和公开采样下没有可行动作，不证明换早期布局或连续空间全局无解。后续若优化，应先用这些停止记录区分布局、区域/承重/接触约束、队首以及候选覆盖的影响，再决定修改候选还是规划策略。
