# O4公共图像A5开发与验收结果解析

日期：2026-10-22。对应《O4阶段任务实现与验收规范_20261021》的A5。**正式A5验收PASS**，`visual_acceptance.json`和独立语料审核均通过。A6实际人工审阅、D真实模型、E扩展均不包含在本轮通过范围。

## 1. 实现与边界

新增代码位于`semantic_pallet_planner/src/semantic_pallet_planner/o4/visual/`，使用规范允许的等价子包组织；保留原A/B平铺源码及原协议。未修改旧Planner、旧三约束执行器、原V1属性、C/F闭环或冻结实验。

| 模块 | 实际开发内容 |
|---|---|
| `facts.py`及`schemas/facts.json` | 单箱/完整缓冲公共输入验证，准确仿真印刷版式，六面本地/全局顶点与法向，未知字段/未来对象拒绝 |
| `rendering.py` | 托盘三视线框、真实待码槽位示意、局部箱面与标签展开卡片，确定性图元及实际PNG |
| `verify.py` | 独立重算文本、顶点、旋转、投影和标签范围；独立栅格化并逐像素比较，不调用生产图元生成函数 |
| `bundle.py` | 场景/卡片/六卡标签页的内容复用，实际PNG与像素摘要、两种输入条件、全部资产校验 |
| `attachments.py` | 安全相对路径、实际字节SHA256、附件后观测/缓冲/整体绑定，封闭离线传输协议 |
| `corpus.py` | 从旧产物只抽取公共request/state；记录全部原始引用，不把私有轨迹直接送入渲染器 |
| `runners/o4_visual.py` | 单输入、冒烟、正式A5验收及只读回放；字体、源码、旧实验保护、网络守卫与报告 |

`pyproject.toml`仅增加视觉子包schema的分发路径，不改变旧运行算法。完整协议见[公共图像与标签箱面协议](../../01_技术原理与数据规范/O4/公共图像与标签箱面协议_20261022.md)。

本轮图像为准确公共事实的确定性技术示意图，不是采集照片；不实现检测、OCR、跟踪、感知置信度或不确定性。标签所属箱面原先缺失，因此新增公开固定的仿真版式`pos_x`，同时提供给文本和图像方法；不能将其称为从真实照片识别所得，也不能将面变换事实写成E4标签朝外业务约束已实现。

## 2. 数据链与实际效果

数据链：原公共观测 → 公共箱面与印刷事实 → 中性场景图/局部标签卡片/标签页 → 文件与像素哈希 → 附件绑定后的公共请求 → 独立事实、几何及像素校验。

- 已码箱按实际位姿绘制XY/XZ/YZ线框，明确允许显示遮挡对象；不是相机遮挡建模。
- 待码箱只在独立槽位示意中出现，未赋予托盘位置、全局箱面顶点或全局法向。
- 标签显示原始禁压和逐箱限载；不显示由当前业务AST计算的有效限值，不因禁压自动把标签值改成0。
- 包装加固、类别等使用准确仿真事实；物理承载等其他参数单独显示，不作为从标签推断的结论。
- 业务说明、请求ID、方法和私有参考不影响像素。颜色固定，不展示Oracle答案、允许候选或违规水印。
- 文本/图像输入拥有相同原公共事实、六面及标签事实，图像条件只额外添加PNG；避免只让VLM获得箱面信息。

一次真实缓冲示例中，已码为item_01、item_02，待码为item_03、item_04、item_05。场景图使用B01—B05索引完整ID，槽位按公共事实显示为槽0=B04、槽1=B05、槽2=B03；三个待码箱均标注托盘位姿未定义。局部标签页显示各自类别、禁压、标签限载和准确尺寸，已码箱是否禁压或可堆叠没有被渲染器改写成任何候选许可结论。具体样例索引见独立证据目录的`gallery.json`。

## 3. 语料范围与验收方法

正式目录：`semantic_pallet_planner/outputs/EXP_O4_A5_VISUAL_20261022_02/`。中间目录`_01`在可变性隔离补测后中断，未验收，不作为通过证据；正式目录重新完整运行。

语料固定为：A/B金标准36＋配对请求144，C全部决策1604，F全部9123个事件的前后公共状态18246，共20030条原始引用。按完整公共输入去重后7431份；图像再按公开视觉内容去重。没有只挑成功订单或模型表现良好的图片，保留失败终止、空队列、EOS和尾单状态。

A5门槛逐项落地：

| 要求 | 实际证据 |
|---|---|
| 全部图像与对象、标签及箱面一致 | 每个资产独立重算图元/文本/面变换及RGB像素；每份bundle重新核对公共原对象与卡片/标签页覆盖 |
| 渲染版本与文件哈希 | 每图PNG版本与事实摘要；资产清单记录文件SHA256和像素SHA256；配置、字体、环境和源码快照 |
| 确定性 | 正式验收逐资产重新生成图元与PNG，要求字节完全相同；存储顺序和业务文本变化的独立测试 |
| 不泄漏未来或参考答案 | 封闭公共schema、拒绝私有/候选字段；独立对照全部原始公开记录及对象集合；只画已码托盘事实 |
| 可用于后续输入 | 实际PNG字节经哈希校验后传输至fake客户端；文本条件无附件且事实相同，未知封装字段和错误绑定拒绝 |
| 兼容与诚实标记 | 旧数据/源码/实验SHA256保护，零API；A6/D/E及整个O4保持未完成 |

独立校验共享Pillow底层绘制及公共输入schema，不共享生产渲染器的最终图元生成函数。它从公共事实重新构造文字、局部六面、旋转法向及投影，再独立栅格化检查PNG实际像素。修改标签文本、已重新计算摘要的箱面法向或PNG像素均会被检测，不能仅凭manifest声明通过。

可变性补测发现首版返回的局部法向/标签UV数组与模板共享引用，现改为独立副本；标签卡片事实及bundle原请求也隔离调用方修改。新测试确认修改导出值不会改变后续请求或原始输入，正式批次使用修正后的源码快照。
