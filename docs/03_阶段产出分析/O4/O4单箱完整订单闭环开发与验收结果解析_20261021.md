## 1. 本轮实现与边界

输入沿用A/B的12个train来源、六份业务配置、准确属性和完整到货流。每个方法从空托盘独立逐箱运行；新候选基于本方法实际提交状态重建，不复用固定题候选或Oracle布局。

| 部分 | 当前实现 |
|---|---|
| 物理候选 | 复用冻结EMS-style生成器，直立yaw=0/90，单箱Top-K≤16，不按参考业务规则剪枝 |
| 编译来源 | Public Parser与Oracle AST两种；普通Parser只接收当前公共观测，Oracle显式使用特权参考AST |
| 业务执行 | 依本方法AST检查禁压、累计限载、接触、对象条件及覆盖关系 |
| 布局适配 | 在O4业务可行集合内构建heavy_low→heavy_center严格锚点，再以0.05/0.25预算选择几何最优；几何近同分用1e-12最大值锚定，再按公开Cxx破同分 |
| 提交屏障 | 请求、观测、指令及候选集合绑定；检查本方法业务规则及独立物理合法性后才提交 |
| 状态更新 | 由独立状态转移函数恢复支撑和传播载荷，实际位姿进入下一步候选生成 |
| 参考评价 | 提议/提交确定之后才读取参考AST，记录真实业务违规；不会替错误编译改选 |
| 终止 | 放完、无物理候选、无编译业务可行候选、非法AST、过期绑定、服务故障分别记录 |
| 网络 | 运行时禁止socket连接；生产验收网络尝试0，真实API调用0 |

新代码组织为`o4/online/planner_adapter.py`、`episode.py`、`cases.py`、`validation.py`及独立`runners/o4_online.py`；配置为`configs/o4_c_online.yaml`。没有改动旧V2或A/B源码。

采用子包而非在o4根目录新增同名文件，是为了保持A/B原有源码枚举与回放契约；属于规范第5节允许的等价组织。实际提交接口为`o4.online.planner_adapter.select_and_commit`，其参数不含参考AST或参考评价。

## 3. 完成率与失败：工程通过不等于整单效果理想

两方法完全相同，下表每行12个任务，仅列一次：

| 配置 | 业务范围 | 放完/无违规放完 | 平均件数比例 | 平均体积比例 | 主要终止 |
|---|---|---:|---:|---:|---|
| 0 | 逐箱标签限载 | 0/12 | 52.30% | 51.08% | 12个业务可行集合空 |
| 1 | 标签限载＋禁压 | 0/12 | 50.38% | 49.05% | 12个业务可行集合空 |
| 2 | 类别间禁止接触 | 3/12 | 85.50% | 84.01% | 1个业务空、8个无物理候选 |
| 3 | 类别与易碎条件限载 | 8/12 | 95.98% | 95.70% | 4个无物理候选 |
| 4 | 标签、禁压与加固例外 | 0/12 | 49.62% | 47.81% | 12个业务可行集合空 |
| 5 | 完整组合业务 | 0/12 | 48.72% | 46.95% | 12个业务可行集合空 |

每方法总体完整且无违规完成11/72（15.28%），任务平均件数比例63.75%、体积比例62.43%。49个任务因编译业务可行集合为空停止，12个因无物理候选停止。

49个业务终止均执行了冻结全枚举审计，参考业务可行集合仍为空，本批未发现“全枚举有解但Top-K遗漏”的终止案例。这里说明的是已形成布局下、该枚举器范围的限制，不能证明连续空间或整个订单全局无解。

Parser与Oracle同轨表明本批公开语法上的解析没有造成方法差异；不能据此声称未来LLM可以或不可以改进未见表达。当前属性派生、业务限制、单箱到货与布局共同制约完成率，不能把提前安全停止计为成功，也不能承诺三箱缓冲必然修复这些订单。

## 4. 从业务语义到实际动作的证据

### 4.1 原144条固定记录

`metrics/fixed.json`重新编译并对同一物理候选打公开标签，使用实际布局排序输出selected_label、selected_pose和锚点/预算trace。参考评价与方法评价逐候选一致；语义不变的24对改写保持允许集合和确定性动作一致。

34对参考允许集合变化不都引起动作变化：其中6对产生不同选址或拒放结果。规则变化但当前最优动作相同的控制对仍保留，避免只展示动作改变的题。

### 4.2 六类预设构造机会

`metrics/opportunities.json`保存独立构造、未按模型表现筛选的六对：禁压标记、逐箱标签限值、货物类别、加固条件、业务阈值、业务适用范围。

每对提供同一物理状态和两个经冻结物理判定生成的候选：居中上层位置与远端地面位置。使用真实几何评分；没有人为改高正确候选分数。第一变体允许上层且几何更优，另一变体按相应业务排除上层，实际改放地面。六对均完成真实状态提交和独立物理复核，不仅比较AST或允许集合。

例如加固玻璃制品：标签限载5 kg、后到箱3 kg。未加固时按5 kg限载，可放其上；准确加固事实为true且作业单明确例外时，按2 kg业务限载，改选地面。物理承载保持原值，没有因“加固”名称自行提高承重。

这些是功能和归因案例，不是自然订单平均收益或统计显著性证据。

### 4.3 合法错误AST会产生可见违规

`metrics/diagnostics.json`的`drop_rules`构造订单只有100×100 mm托盘底面，三箱必须叠放。首箱带禁压标记：

- 正确规则放1箱后停止，明确无编译业务可行候选。
- 注入合法空AST后，方法实际放完3箱，参考判定最终1个业务违规实例；物理违规仍为0。
- 参考没有替主方法纠正错误或拦截业务违规，也没有把错误输出删除。

另有非法AST、绑定错误、模拟服务错误、无物理候选及越界物理提议拒绝。非法提议保持原状态不提交；故障及构造记录不混入正常完成率。
