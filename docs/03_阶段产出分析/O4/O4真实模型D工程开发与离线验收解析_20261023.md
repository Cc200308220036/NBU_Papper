日期：2026-10-23。版本：`o4_d_remote_v1`。依据[O4实施规范](../../02_阶段实施方案/O4/O4阶段任务实现与验收规范_20261021.md)D1—D6实现。

本轮交付O4真实调用工程及离线协议/闭环验收；**真实API调用为0，模型能力实验由用户按手册执行**。A6按用户决定取消其本轮前置要求，以`NOT_REQUIRED_BY_USER`记录；不把旧人工审阅状态改成PASS。

**最终本地工程验收PASS**：规划器414项测试通过（包含新增43项），数据集7项通过；12题编译冒烟、144条固定题四方法矩阵及96个在线episode均完成只读回放。这里的D2明确标记`OFFLINE_ONLY`，不代表真实模型D1—D6已实测通过。

## 1. 实际实现

采用独立`o4/remote/`子包和`runners/o4_remote.py`，不修改冻结A/B/C/F、旧V2选择器、物理候选器、A5传输保护或既有实验。新增代码使用明确命名、类型标注、职责说明和普通分支组织，未延续旧模块大量单行语句的写法。

| 模块 | 职责 |
|---|---|
| `transport.py` | 冻结模型参数、标准库HTTPS、PNG实际字节base64编码、尺寸/数量/请求体限制、禁止重定向、超时/HTTP错误和凭据保护 |
| `protocol.py` | 同事实A5输入绑定、单箱/缓冲独立响应绑定、公开AST语义说明、JSON解析与封闭schema校验 |
| `compiler.py` | 仅公共输入编译、每次尝试写前记账、最多一次格式修复、预算停止、原始响应保存及离线响应消费 |
| `episode.py` | 单箱与最多三箱滚动闭环；复用冻结FIFO、启发式、搜索与物理提交；参考评价在选择/提交后执行 |
| `evaluation.py` | 完整语义、适用对象、条件例外、允许集合与错误放行/拒绝统计；不参与选址 |
| `audit.py` | 独立逐事件守恒、真实提交物理检查、参考业务和搜索计数 |
| `experiment.py` | 预冻结计划、四编译来源×四规划器、逐任务结果、来源汇总、CSV、文件封存和只读回放 |
| `testing.py` | 明确标记的服务替身；从实际HTTP请求体读取公共输入，不能进入`--remote`分支 |

原`o4/client.py`及`visual/attachments.py`继续拒绝非fake客户端，未通过删除旧保护冒充真实接入。D使用新版本入口与经过验证的真实编码路径。

默认配置：[o4_d_deepseek_flash.yaml](../../../semantic_pallet_planner/configs/o4_d_deepseek_flash.yaml)。用户指定`deepseek-flash`；官方图像与Chat Completions文档已核验，详见[运行手册](../../04_运行与复核手册/O4真实模型D运行与验收手册_20261023.md)。

## 2. 执行链与公平性

调用前先prepare，冻结开发题、模型参数、完整源码、提示版本和API尝试上限。run使用另一新目录，将计划完整复制到`frozen_plan/`；不原地续写旧实验。

每个固定题比较Public Parser、准确文本LLM、同事实加图VLM和Oracle AST。每个订单在相同初始状态下分别运行单箱、缓冲FIFO、缓冲启发式和缓冲搜索；每个规划器内部再比较四种编译来源。实际轨迹分叉后按各自公共状态重新编译，不强行共享旧响应。

文本与图像两条件使用同一Flash、参数和对应模式的系统提示；均获得原公共观测以及完整箱面/标签事实，图像条件额外附PNG。图像超限、哈希错误或服务拒绝不会静默删除图像。首答和修复账目分别记录，合法但语义错误的AST不触发修复。

缓冲接收策略仍为`fill_then_plan`；只有环境读取下一次到货。WAIT与EOS不调用模型，实际规划才编译；树中只使用该次AST，在克隆状态搜索，实际仅提交首动作。每箱Top-K≤16、深度≤3、束宽≤8、后继评价≤256保持原值。

公开响应不会获得参考政策、候选许可或未来订单。编译失败后没有Parser/Oracle替换；Oracle只存在于显式命名的特权对照。错误AST可能导致参考业务违规，原错误提交保留，独立物理检查不放宽。

## 3. D1—D6工程映射

| 条款 | 具体实现及验收证据 |
|---|---|
| D1 | 每个计划job独立落盘；每次编译保存公共来源、响应或明确失败；HTTP尝试写前记账，回放核对任务、编译、attempt ID和请求摘要 |
| D2 | `--remote`拒绝注入替身；离线传输明确`test_double=true`；首答/修复分开；合法错误AST原样保留，无参考补全或方法降级 |
| D3 | A5同事实两条件、逐图实际字节核验；单箱及缓冲全状态绑定；封闭公共输入；独立复核每次物理提交；错误业务判定留在结果中 |
| D4 | 无网络/无密钥回放，重算请求体、原始响应解析、修复/预算状态机、物理候选、动作、状态、指标、CSV与验收；篡改后重签文件清单仍拒绝 |
| D5 | AST有效、规范化完整语义、逐规则对象集合、条件例外、允许集合与误放/误拒；完整订单、来源汇总、API首答/修复、usage缺失及耗时均有原始依据 |
| D6 | 包含修复和失败的显式尝试预算；预算或服务失败保留全部计划分母并标记PARTIAL；小冒烟不声称全矩阵完成，真实语义错误不删除 |

完整语义比较沿用独立解释器的规范化签名与有限域见证，报告探测范围，不声称能证明任意逻辑公式等价。`conditions_exceptions_equal`采用完整规则语义一致的保守判据，未把同一个当前动作当作条件例外能力证明。
