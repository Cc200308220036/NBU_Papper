## 一、首先明确：PUSNet 能给你的研究什么启发？

PUSNet 的核心不是单纯使用 GPT-4，而是将 LLM 生成的启发式规则转化为 DRL
可以使用的动作约束，从而改善策略学习。

论文中有三个特别值得借鉴的设计。

### 1. 将专家经验转化为可执行的动作约束

PUSNet 使用 GPT-4 生成三类启发式规则：

-   **Feasibility Heuristics：** 判断动作是否满足物理可行性。
-   **Packing Heuristics：** 筛选更有利于装箱的候选位置。
-   **Unpacking Heuristics：** 筛选值得取出的箱体。

这些规则最终转化为二值动作掩码，与 Actor
输出的动作概率结合，将不合理动作的 Logit
设置为极大负值，使其无法被选择。

这给你的第一个启发是：

**经验不能只以自然语言形式保存在数据库中，而应该进一步转化为能够影响候选动作评分的结构化信息。**

例如，DeepSeek 从历史订单中总结：

> 当缓冲区存在需要较大连续底面空间的长条形箱体时，应避免将其他箱体优先放置在底面中央，以免破坏后续装载条件。

这条经验不能只保存为一句话，而应转化为：

-   **适用条件：** 缓冲区存在特定尺寸的长条形箱体。
-   **风险动作：** 显著分割连续底面空间的候选放置动作。
-   **推荐动作：** 能够保留关键连续空间的候选动作。
-   **影响方式：** 降低风险候选的评分，提高推荐候选的排序。

### 2. 将局部动作与长期收益联系起来

PUSNet 使用两个 Actor-Critic 分支，分别评价装箱和拆箱动作，并比较两个
Critic 的状态价值，选择预期累计收益更高的操作。

它的奖励函数不仅考虑当前箱体的体积贡献，还考虑累计装载体积、浪费空间比例及浪费空间的变化。

这说明：

当前动作是否合理，不能只看当前箱体能否放进去，还要看它是否影响后续箱体的装载。

对于你的研究，这种思想可以转化为：

**让 DeepSeek
从整批订单的最终结果中识别哪些历史选择具有长期收益，哪些局部看似合理的选择实际上损害了后续装载能力。**

### 3. 通过消融实验证明经验机制的作用

PUSNet 在 Table 10 中比较了不同拆箱策略：

  方法                     空间利用率
  ---------------------- ------------
  Packing-only                  69.7%
  Random Unpacking              72.1%
  Rule-based Unpacking          76.3%
  Full PUSNet                   86.1%

这说明引入拆箱机制本身有帮助，但如何选择拆箱对象同样重要，学习到的协同策略效果更好。

你也需要类似的实验逻辑：

-   仅使用 Jev。
-   Jev + 原始历史轨迹。
-   Jev + DeepSeek 总结的经验。
-   Jev + 经过验证的结构化经验。
-   Jev + 经验引导 + 偏好学习。

只有证明最后几种方法确实优于前面的基线，才能说明经验提取和沉淀具有独立研究价值。

## 二、我建议采用的总体架构

我建议将整个经验系统划分为两个相互协作的过程：

1.  **离线经验学习：** DeepSeek
    分析历史订单，提取经验并通过仿真验证，形成动态经验库。
2.  **在线经验引导：** Jev
    在当前码垛过程中检索相关经验，利用经验调整候选排序并完成决策。

这种设计有一个非常重要的好处：

DeepSeek
不需要在每次码垛决策时都重新推理，而是主要在订单结束后进行经验提炼。在线阶段只需要进行轻量化经验检索和候选评分修正。

### 经验沉淀与决策优化总体架构

``` mermaid

        J["Jev 模型<br/>基础候选评分"]
        R["经验检索<br/>匹配历史经验"]
        F["经验引导候选重排序<br/>融合基础评分、长期收益偏好与业务风险"]
```

## 三、经验沉淀的第一步：让 DeepSeek 从什么内容中提取经验？

这是整个研究的基础。

我不建议你直接把一整批订单的最终结果交给
DeepSeek，然后要求它总结经验。这样容易得到一些比较泛化的结论，例如：

-   大箱子优先放置。
-   尽量减少空间浪费。
-   尽量避免空间碎片化。
-   注意箱体承重关系。

这些规则虽然正确，但传统几何启发式已经能够实现其中相当一部分，无法充分体现你的研究价值。

我建议采用**基于决策轨迹的经验提取机制（Decision-Trajectory-Based
Experience Extraction）**。

### 3.1 建立完整的订单决策轨迹数据库

Jev 每完成一次选择和放置，都应该记录一次决策，而不是只记录最终码垛结果。

每条决策轨迹至少包括以下信息：

  记录内容       具体信息                       作用
  -------------- ------------------------------ ------------------------
  当前环境状态   托盘空间、已放置箱体           还原决策发生时的环境
  缓冲区状态     当前所有可选箱体的尺寸、属性   分析箱体选择顺序
  候选动作集合   箱体、姿态、放置位置           分析模型有哪些选择
  Jev 原始评分   每个候选的分数和排序           判断模型原本的选择偏好
  实际执行动作   最终选中的箱体及位置           确定决策结果
  执行后的状态   空间变化、支撑变化、剩余候选   分析动作造成的影响
  订单最终结果   利用率、完成率、业务违规数     评价长期决策收益

这里有一个特别重要的设计：

**一定要保存 Jev 没有选择的候选动作，而不仅仅保存最终执行的动作。**

因为未来需要分析：

假如当时没有选择 A，而是选择 B，整批订单的结果会不会更好？

如果没有保存当时的候选集合和模型评分，后续就很难进行有效的反事实分析。

### 3.2 让 DeepSeek 重点提取三类经验

我建议 DeepSeek 不只是总结失败案例，而是同时分析成功和失败的订单。

#### 第一类：空间布局经验

主要分析箱体放置位置对后续可用空间的影响。

例如：

-   哪些放置位置容易产生不可利用的空间碎片？
-   哪些布局能够保留较大的连续空间？
-   哪些箱体放置顺序有利于后续大尺寸箱体装载？
-   哪些空间布局能够提高整批订单的完成率？

#### 第二类：缓冲区箱体选择顺序经验

这是你与 PUSNet 存在重要区别的地方。

PUSNet
主要是在当前箱体已确定的条件下，协调装箱与拆箱操作。被拆出的箱体进入
Buffer
后，论文采用后进先出的方式优先重新处理，并没有把任意多个待装箱体的自由排序作为主要决策动作。

而你希望 Jev 主动从多个缓冲区箱体中选择下一件物体。

因此，DeepSeek 应重点总结：

-   哪些箱体应该优先装载？
-   哪些箱体适合暂时保留在缓冲区？
-   哪些箱体组合存在明显的顺序依赖关系？
-   当前选择是否会使后续箱体失去合适的放置位置？

#### 第三类：业务约束经验

分析不同箱体属性与业务规则之间的关联。

例如：

-   哪些选择容易造成重量分布不合理？
-   哪些箱体放置方式可能导致易碎品受到不允许的载荷？
-   哪些箱体组合容易违反订单分组要求？
-   哪些局部布局虽然空间利用率较高，却增加了业务违规风险？

这三类经验分别作用于空间布局、箱体选择顺序和业务约束判断。

### 3.3 DeepSeek 输出什么形式的经验？

我建议不要让 DeepSeek
只输出自然语言总结，而是要求它生成统一的结构化经验记录。

例如：

``` json
{
  "memory_id": "M_001",
  "memory_type": "space_reservation",

  "applicability": {
    "buffer_contains_long_box": true,
    "continuous_floor_space": true
  },

  "failure_pattern": {
    "action": "place_small_box_at_center",
    "consequence": "fragmented_floor_space"
  },

  "preferred_pattern": {
    "action": "preserve_continuous_floor_region",
    "target": "long_box_placement"
  },

  "expected_effect": {
    "space_utilization": "positive",
    "order_completion": "positive"
  },

  "evidence": {
    "source_orders": ["Order_001", "Order_008"],
    "verification": "pending"
  },

  "confidence": 0.0
}
```

> 以上为拟设计的经验数据结构，非实际实验输出。

这条经验最重要的不是它说了什么，而是它明确描述了：

1.  在什么情况下适用？
2.  哪种选择容易产生问题？
3.  应该优先考虑什么样的选择？
4.  预计会带来什么结果？
5.  有没有经过实验验证？

我建议把这类结构化经验作为你的核心研究对象。

## 四、最关键的创新：通过反事实验证筛选真正有价值的经验

这一部分我认为应该成为你研究内容四的核心。

原因很简单：

DeepSeek
能够分析历史轨迹，但它并不能仅凭语言推理准确判断某次选择是否真正导致了最终订单结果变差。

举个例子。

假设某批订单最终空间利用率较低，DeepSeek 分析后认为：

> 第三步选择将小箱子 A
> 放在托盘中央，是导致后续大箱子无法放入的主要原因。

这个判断可能正确，也可能错误。

因为最终装载效果还可能受到第五步、第七步的其他决策影响。

所以不能直接将 DeepSeek 的判断存入经验库。

我建议引入 **Counterfactual Experience
Verification（反事实经验验证）**。

### 4.1 核心思想：对比不同候选动作产生的长期结果

假设在第 t 步，Jev 面对三个候选动作：

-   A：选择小箱子，放置在托盘中央。
-   B：选择大箱子，放置在底部连续区域。
-   C：选择小箱子，放置在托盘边缘。

Jev 原本选择了 A。

但是订单结束后，发现 A 的选择导致后续大箱子无法合理装入。

DeepSeek 根据历史轨迹提出：当时应该选择 B。

这时不直接相信 DeepSeek，而是进行反事实仿真。

``` mermaid
flowchart TB
    S["恢复第 t 步的原始状态<br/>托盘布局、缓冲区箱体、业务约束、候选动作"]
    S --> A["原始方案：选择 A"]
    S --> B["替代方案：选择 B"]
    A --> C["继续执行原始策略"]
    B --> D["执行经验建议的替代动作"]
    C --> E["相同后续任务条件下仿真"]
    D --> E
    E --> F["比较整批订单的空间利用率、完成率和业务违规"]
    F --> G["经验有效性评价<br/>重复实验支持后进入高可信度记忆库"]
```

**图2. 基于反事实回放的经验验证流程。**

具体评价可以定义为：

\[ `\Delta `{=tex}J_t = J(`\tau`{=tex}*{`\mathrm{alternative}`{=tex}}) -
J(`\tau`{=tex}*{`\mathrm{original}`{=tex}}) \]

其中：

-   \(J\) 表示整批订单的综合评价指标。
-   (`\tau`{=tex}\_{`\mathrm{alternative}`{=tex}})
    表示替代动作产生的后续轨迹。
-   (`\tau`{=tex}\_{`\mathrm{original}`{=tex}})
    表示原始动作产生的后续轨迹。

如果：

\[ `\Delta `{=tex}J_t \> 0 \]

说明替代动作在该验证条件下优于原始动作。

但是，建议你不要只验证一次。对于具有随机性的任务，应采用相同随机种子进行多次配对仿真，并考察收益是否稳定。

还有一个需要特别注意的科研细节：

如果实际任务是在线码垛，未来箱体在决策时不可见，那么不能把历史订单的完整未来箱体序列直接提供给
Jev。

可以在离线反事实验证时使用历史记录中的后续到达序列作为评价条件，但在线决策只能使用当时实际可观测的信息。对于不同未来到达情况，还应进行多序列采样验证。

### 4.2 建立经验可信度机制

经过验证后，不是所有经验都应该获得相同的使用权重。

我建议根据以下因素计算经验可信度：

  评价因素           作用
  ------------------ ------------------------------
  反事实收益         替代动作是否真正改善最终结果
  重复验证次数       是否在多个测试条件下有效
  适用条件匹配程度   当前状态是否符合经验适用范围
  跨订单表现         是否在其他订单中仍然有效
  业务约束表现       是否产生新的业务风险

最后将经验划分为三个等级：

-   **候选经验：** DeepSeek 已经提取，但尚未验证。
-   **已验证经验：** 经过仿真验证，具有一定的正向收益。
-   **高可信度经验：** 在多个订单及不同场景下均表现出稳定收益。

只有后两类经验能够参与正式的在线决策优化。对于尚未验证的经验，可以保留用于后续实验，但不应直接影响真实机器人动作。

## 五、最重要的问题：经验到底怎样作用于 Jev 模型？

这一部分是整个研究最需要认真设计的地方。

我建议采用三个逐步深入的层次。

### 5.1 第一层：基于经验检索的候选评分修正

**建议优先实现。**

这是最容易实现、也最容易开展消融实验的方案。

假设几何模块生成了 5 个可行候选动作。

Jev 对它们进行评分：

  候选动作                Jev 原始评分
  --------------------- --------------
  A：小箱体，中央位置             0.90
  B：大箱体，底部位置             0.82
  C：小箱体，边缘位置             0.75
  D：中箱体，左侧位置             0.70
  E：中箱体，右侧位置             0.65

如果不使用经验，Jev 会选择 A。

但是，经验库检索到了相关经验：

> 当前缓冲区存在大尺寸箱体，且托盘底面仍有连续区域。历史上，优先将小箱体放置在中央容易破坏后续装载条件。

此时经验模块对候选动作进行评分修正。

  候选动作     Jev 评分   经验修正   最终评分
  ---------- ---------- ---------- ----------
  A                0.90      -0.25       0.65
  B                0.82      +0.12       0.94
  C                0.75      +0.08       0.83
  D                0.70       0.00       0.70
  E                0.65       0.00       0.65

> 表中数值仅为机制演示，不是实际实验结果。

最终模型选择 B，而不是原来的 A。

这就实现了：

**Jev
负责判断当前候选的基本合理性，经验模块负责补充历史任务中的长期收益知识。**

数学上，可以定义：

\[ Q\_{`\mathrm{final}`{=tex}}(s_t,a)=
`\alpha `{=tex}Q\_{`\mathrm{Jev}`{=tex}}(s_t,a)
+`\lambda `{=tex}Q\_{`\mathrm{mem}`{=tex}}(s_t,a,M_t) \]

其中：

-   (Q\_{`\mathrm{Jev}`{=tex}})：Jev 的基础候选评分。
-   (Q\_{`\mathrm{mem}`{=tex}})：经验模块根据相关历史经验得到的评分修正。
-   (M_t)：当前检索到的经验集合。
-   (`\alpha`{=tex},`\lambda`{=tex})：融合权重。

经验评分可以进一步表示为：

\[ Q\_{`\mathrm{mem}`{=tex}}(s_t,a)= `\sum`{=tex}\_{m`\in `{=tex}M_t}
w_m(s_t)`\phi`{=tex}\_m(s_t,a)`\Delta `{=tex}J_m \]

其中：

-   (w_m)：经验的相关性与可信度权重。
-   (`\phi`{=tex}\_m)：判断候选动作与经验建议的匹配程度。
-   (`\Delta `{=tex}J_m)：该经验经过反事实验证得到的长期收益。

这里最重要的是：经验不应该直接替代
Jev，而应该根据当前状态与经验适用条件的匹配程度，适度影响候选排序。

同时，所有不满足物理或强制业务约束的动作，都应该在几何候选生成阶段被过滤，经验不能让不合法动作重新进入候选集合。

### 5.2 第二层：经验参与 Jev 的决策输入

第一层属于外部评分修正。

第二层则是进一步让 Jev 在决策时能够直接利用经验知识。

具体方法是：

**原始输入：**

``` text
当前托盘状态
缓冲区箱体
订单业务约束
候选动作集合
```

**加入经验后：**

``` text
当前托盘状态
缓冲区箱体
订单业务约束
候选动作集合
检索到的结构化经验
```

例如，向 Jev 提供：

``` text
历史经验：

当缓冲区存在长条形箱体，
且当前托盘底部存在连续空间时，

应重点评估当前候选动作是否会
破坏后续大尺寸箱体的装载条件。

请结合当前候选动作集合，
评价各候选对整批订单长期装载结果的影响。
```

这相当于利用历史经验增强 Jev 的上下文决策能力。

但我建议你注意一个问题：

仅仅把经验加入 Prompt，并不能证明模型真正使用了经验。

所以必须记录加入经验前后：

-   Jev 对各候选的评分变化。
-   候选排序变化。
-   最终选择变化。
-   整批订单结果变化。

如果加入经验后模型输出完全没有变化，说明经验虽然进入了上下文，但没有产生有效的决策作用。

### 5.3 第三层：通过经验偏好数据优化 Jev 模型自身

**建议作为核心进阶研究。**

如果你最终的论文目标是提高 Jev
模型本身的选择能力，那么我认为还应该研究这一层。

因为：

如果 Jev
的参数完全不变，仅仅依靠外部经验模块修正评分，那么提升的是整个决策系统的能力，并不能严格证明
Jev 自身已经学习到了新的经验。

因此，可以将反事实验证得到的经验进一步转换为训练数据。

例如：

在相同的码垛状态下：

-   候选 A：原始选择，最终订单收益较低。
-   候选 B：替代选择，最终订单收益较高。

形成一组偏好数据：

\[ (s_t,a^+,a^-) \]

其中：

-   (a\^+)：长期效果更好的候选动作。
-   (a\^-)：长期效果较差的候选动作。

使用成对排序损失：

\[ `\mathcal `{=tex}L\_{`\mathrm{rank}`{=tex}}=
-`\log`{=tex}`\sigma`{=tex} `\left[
Q_\theta(s_t,a^+)
-
Q_\theta(s_t,a^-)
\right]`{=tex}\]

训练 Jev 的候选评分模块，使其逐渐学会：

在类似状态下，优先选择经过历史验证的优质候选动作。

如果 Jev 是可微调的多模态模型，可以采用 LoRA 等参数高效微调方式；如果
Jev 是不可微调的封闭模型，则可以训练一个独立的轻量化排序头。

这样就形成三个阶段：

``` mermaid
flowchart TB
    A["阶段一：外部经验引导<br/>经验检索 + 候选评分修正"]
    B["阶段二：经验条件增强<br/>结构化经验进入 Jev 决策输入"]
    C["阶段三：经验偏好蒸馏<br/>利用验证后的偏好数据优化 Jev"]
    A --> B --> C
```

**图3. 经验逐步转化为选择模型能力的三个阶段。**

我建议你先实现第一层，再逐步实现第三层。不要一开始就直接对 Jev
进行复杂微调，否则很难判断最终性能提升到底来自经验记忆，还是来自额外训练数据。

## 六、如何设计动态经验库，使经验能够持续积累和更新？

我建议你的经验库不要设计成普通的向量数据库，而应该设计成一个**面向码垛决策的结构化经验记忆系统**。

因为普通 RAG 主要解决的是"找到相似文本"，而你的研究需要解决的是：

> 当前状态与历史经验是否相似？这条经验是否适用？它对哪些候选动作有影响？使用后是否真正改善了码垛结果？

### 6.1 经验库的组织方式

建议将经验分为五种类型：

  经验类型         经验内容                                 影响的决策
  ---------------- ---------------------------------------- ----------------
  空间布局经验     连续空间保留、空间碎片化、局部高度控制   放置位置
  箱体顺序经验     大小箱体组合、缓冲区箱体优先级           箱体选择顺序
  物理稳定性经验   支撑面积、重心、承重关系                 放置姿态与位置
  业务规则经验     易碎品、重量、订单分组等                 候选筛选与排序
  操作效率经验     抓取可达性、操作次数、缓冲区周转         综合候选选择

其中，空间布局经验和箱体顺序经验是你最应该重点研究的两类。

### 6.2 经验检索不能只依赖文本相似度

PUSNet 在状态表示中采用 Weighted 3D Voxel
Grid，将空间分为浪费空间、可用空间和已占用空间三种状态，同时利用箱体尺寸图描述当前物体。

你可以借鉴这种空间表示思想，将其扩展为经验检索所需要的状态特征：

-   当前托盘空间占用结构。
-   当前剩余连续空间的尺寸与分布。
-   缓冲区箱体尺寸及属性分布。
-   当前订单剩余任务特征。
-   业务约束条件。

然后采用两级检索：

1.  **适用条件筛选：**
    例如订单类型、箱体属性、业务规则版本和空间状态是否匹配。
2.  **状态相似度排序：** 对通过筛选的经验进行状态相似度排序，选择 Top-K
    条经验。

这样比单纯将当前状态转成文本，再通过向量相似度检索更加可靠。

### 6.3 建立经验更新与淘汰机制

经验不能只增加、不更新。

我建议建立如下生命周期：

1.  **经验生成：** DeepSeek 从历史订单中提取新的候选经验。
2.  **经验验证：** 通过反事实仿真评价其有效性。
3.  **经验入库：** 保存适用条件、收益、证据和可信度。
4.  **经验应用：** 在后续订单中检索并引导 Jev 决策。
5.  **经验反馈：** 记录经验应用后的实际收益。
6.  **经验更新：** 对有效经验提高可信度，对无效经验降低权重或淘汰。

还有一个值得借鉴 PUSNet 的地方：论文中 GPT-4
生成启发式规则时，作者不仅给出规则需求，还提供了基本物理知识和自然语言示例，再让模型生成代码级规则。

因此，你给 DeepSeek
提供经验提取任务时，也应该提供明确的码垛规则、历史案例和输出格式，而不是仅仅让它自由总结。

不过，我建议经验规则采用受约束的结构化表达，而不是直接允许 DeepSeek
生成未经验证的 Python
代码并参与机器人控制。这样更容易实现验证、追溯和版本管理。

## 七、结合 PUSNet，你的研究究竟有什么不同？

这一点对开题报告的创新性论证非常重要。

  ---------------------------------------------------------------------------------------------------------------
  对比维度                PUSNet                                 你的拟研究方法
  ----------------------- -------------------------------------- ------------------------------------------------
  LLM                     GPT-4                                  DeepSeek

  LLM 主要作用            生成装箱、拆箱启发式规则               提取历史订单经验

  知识来源                预设物理知识及已有启发式               历史码垛决策轨迹与结果

  动作影响方式            动作掩码约束                           候选评分修正与偏好学习

  决策方式                装箱与拆箱双分支协同                   缓冲区箱体与放置位置联合选择

  经验管理                主要通过启发式生成指导 DRL             跨订单动态记忆、验证、检索与更新

  优化重点                当前在线装箱任务的空间利用率与稳定性   整批订单的空间利用率、业务合规性和长期选择能力
  ---------------------------------------------------------------------------------------------------------------

我认为，你的研究最值得强调的区别是：

**PUSNet 主要解决如何利用 LLM
生成的启发式规则指导强化学习探索，而你希望解决如何从历史任务结果中持续学习经验，并让这些经验动态改变下一批订单的候选选择。**

这不是简单地将 GPT-4 换成
DeepSeek，而是将研究重点从规则生成拓展到跨订单经验学习。

另外，PUSNet
的装箱与拆箱双分支不建议直接照搬。如果你的实际任务没有允许拆箱重排的操作，就没有必要为了模仿
PUSNet
而增加拆箱动作。你应该将其动作协同思想迁移到缓冲区箱体与放置位置的联合选择上。

## 八、实验应该如何设计，才能证明经验沉淀真的有效？

我建议你至少设计以下七组实验。

  实验组   实验方法                            验证目的
  -------- ----------------------------------- ----------------------------------
  A        几何启发式方法                      传统方法基线
  B        Jev-only                            基础模型性能
  C        Jev + 原始历史轨迹检索              验证直接使用历史案例的效果
  D        Jev + DeepSeek 经验总结             验证 LLM 经验抽象的效果
  E        Jev + 结构化经验（未经验证）        验证结构化表达的作用
  F        Jev + 反事实验证经验 + 候选重排序   验证核心经验引导机制
  G        Jev + 验证经验 + 偏好蒸馏           验证经验能否提升模型自身选择能力

其中 F 和 G 是最重要的实验组。

### 8.1 评价指标

建议围绕你的两个核心目标展开。

  评价维度       具体指标
  -------------- ----------------------------------------------
  空间利用效率   托盘空间利用率、有效装载体积、空间碎片化程度
  订单完成情况   整批订单完成率、未装载箱体数量及体积
  业务合规性     软性业务违规数量、违规严重程度
  执行效率       机械臂操作次数、平均决策时间
  经验有效性     经验应用成功率、经验验证通过率
  长时程学习     随历史订单数量增加，后续订单性能的变化

这里有一个特别重要的实验问题：

如果所有强制业务约束都在候选生成阶段被过滤，那么所有实验组的最终硬约束违规数可能都是零。

因此，应该重点比较软性业务违规、未完成订单数量及无效动作提议数量，而不是单纯依靠硬约束违规数证明经验模块的价值。

### 8.2 最值得做的实验：经验积累曲线

我非常建议你设计一组持续学习实验。

**实验设计：历史订单数量对后续码垛性能的影响。**

具体实验：

1.  先使用一批历史订单构建初始经验库。
2.  每完成一定数量的订单，更新经验库。
3.  使用新的、未参与经验生成的订单测试 Jev。
4.  记录不同经验库规模下的空间利用率、订单完成率和业务违规情况。
5.  比较 Jev-only 和 Jev + Verified Memory 的性能变化。

需要采用严格的时间顺序划分训练订单和测试订单，避免未来订单的信息提前进入经验库。

如果随着历史订单增加，Jev + Memory
在后续未见订单上的表现能够持续改善，就能比较有力地说明你的经验沉淀机制具有长期学习价值。

### 8.3 还需要验证经验是否真的改变了 Jev

建议额外记录三个过程指标：

-   经验加入后，有多少次决策发生了候选排序变化？
-   这些排序变化中，有多少次最终带来了更好的订单结果？
-   有多少条经验在新订单中出现了负迁移？

这样可以建立：

**经验提取 → 候选排序变化 → 实际动作变化 → 订单结果改善**

这条证据链非常重要。

## 九、我建议你最终采用的研究实施顺序

考虑到你的研究同时涉及几何模块、选择模型和
DeepSeek，我不建议一开始就开发全部功能。

建议按照以下顺序推进：

1.  **第一阶段：建立 Jev 基础选择模型。**
    完成缓冲区候选箱体生成、放置位置生成和候选评分，确保 Jev
    不依赖经验也能够独立完成码垛决策。特别要求 Jev
    能够输出每个候选动作的评分或完整排序，而不只是输出最终选择结果。
2.  **第二阶段：建立订单轨迹数据库。**
    记录每次决策的状态、候选集合、模型评分、实际动作及最终订单结果。这是经验提取的数据基础。
3.  **第三阶段：实现 DeepSeek 经验提取。** 让 DeepSeek
    从成功和失败订单中识别关键决策，形成具有适用条件的结构化经验。
4.  **第四阶段：实现反事实仿真验证。** 验证 DeepSeek
    提取的经验是否真正能够改善后续码垛结果，形成可信度分级的经验库。
5.  **第五阶段：实现经验引导的 Jev 候选重排序。** 将经验评分与 Jev
    原始评分融合，观察经验是否改变候选排序和最终动作。
6.  **第六阶段：研究经验偏好蒸馏。**
    将经过验证的候选偏好转化为训练数据，进一步优化 Jev 的评分能力。
7.  **第七阶段：开展长时程订单泛化实验。**
    验证经验库持续积累后，模型在未见订单中的表现是否改善，并分析负迁移和经验失效问题。

另外，建议借鉴 PUSNet
的两阶段训练思想：先在高效率的几何仿真环境中开展大规模候选决策和经验验证，再使用物理仿真评估支撑稳定性及实际放置可靠性。PUSNet
的实验表明，直接在物理仿真中完成全部训练会面临训练效率与空间利用率之间的权衡。

## 十、最终建议：把什么作为你的核心创新？

经过以上分析，我认为你的研究最有价值的不是 DeepSeek
总结经验，也不是建立一个向量数据库，而是以下三个技术环节形成的闭环。

### 建议重点突破的三个技术环节

#### 技术重点一：长时程决策经验提取

DeepSeek
从整批订单轨迹中识别关键选择行为，提取具有适用条件的空间布局、箱体顺序和业务约束经验。

#### 技术重点二：基于反事实验证的经验可信度评价

利用仿真回放对比不同候选动作的长期结果，筛选真正有收益的经验，形成动态结构化经验库。

#### 技术重点三：经验引导的候选选择优化

将经验转化为候选评分修正与偏好训练数据，使 Jev
的选择能力随历史任务积累逐步改善。

### 可以直接用于开题报告的创新点表述

针对传统码垛选择模型主要依赖当前环境状态进行决策、缺乏跨订单历史经验利用能力的问题，提出一种基于视觉语言大模型的经验提取、反事实验证与候选选择优化方法。通过分析历史订单决策轨迹，利用
DeepSeek
提取具有适用条件的结构化码垛经验，并结合反事实仿真验证经验对整批订单空间利用率及业务约束满足情况的实际影响，构建动态经验记忆库。在此基础上，研究经验引导的候选动作评分修正与偏好学习机制，将经过验证的历史决策经验转化为
Jev
模型的候选选择偏好，实现从历史任务经验积累到当前候选决策优化的闭环反馈，提高模型在长时程码垛任务中的决策能力与跨订单适应能力。

### 最后，我想特别强调一个研究判断

你不应该把 DeepSeek 定位成一个帮助 Jev
写提示词的辅助工具，而应该把它定位成一个能够从历史任务结果中提取长期决策知识的经验学习模块。

而 Jev
不应该只是读取经验文本，而应该通过候选评分修正和偏好学习真正改变自己的选择行为。

这样，你的论文就形成了一条清晰的研究主线：

**历史订单产生经验 → DeepSeek 提炼经验 → 仿真验证经验 → 动态记忆沉淀 →
Jev 利用经验优化选择 → 新订单产生新的经验。**

我认为这条路线比单纯做一个"Jev + DeepSeek +
RAG"的组合系统更有研究深度，也更容易通过消融实验建立清晰的创新贡献。
