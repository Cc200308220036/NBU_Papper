## 2. 最小源码改动

- 新增独立 Schema [geometry_operational_order_plan_v1.schema.json](../../../semantic_pallet_planner/src/semantic_pallet_planner/jev_select/schemas/geometry_operational_order_plan_v1.schema.json) 并在 [packaging_versions.py](../../../semantic_pallet_planner/src/semantic_pallet_planner/jev_select/packaging_versions.py#L148-L149) 注册 `GEOMETRY_OPERATIONAL_PLAN = 'geometry_operational_order_plan_v1'`，限定 `scope == 'DEVELOPMENT_SYNTHETIC_ONLY'`、`status == 'DEVELOPMENT_READY'`、`assessment_limit == 0`、`solver_limit == 0`。
- 修改 [packaging_geometry_protocol.py](../../../semantic_pallet_planner/src/semantic_pallet_planner/jev_select/packaging_geometry_protocol.py#L107-L162)：
  - `prepare_operational_order_plan` 仅生成 `geometry_operational_order_plan_v1`（`DEVELOPMENT` 范围），`scope` 为 `ACCEPTANCE` 或 `ORDER` 时直接以 `geometry_operational_development_only` 拒绝；默认选定 `ems_surface_hybrid_v1`，显式 `backend='e2_original_v1'` 选定原 E2。
  - 新增 `validate_operational_order_plan` 校验单后端日常计划；`validate_admission` 与 `draft_run` 按计划版本分流至 `validate_operational_order_plan` 或 `validate_order_plan`。
  - **完全恢复 `validate_order_plan` 对 `geometry_order_plan_v1` 与 `geometry_order_plan_v2` 的严格双后端固定矩阵校验**：`ACCEPTANCE` 四项矩阵必须由 `K01/K02 × E2/EMS` 组成，任何单后端或缺项计划均以 `geometry_order_matrix` 在派发前拒绝。
