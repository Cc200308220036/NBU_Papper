## GP6-F0-REC-01

代码已实现：`validate_jev_saved_checkpoint` 保留公共保存转换验证，并对 checkpoint 已保存的请求型选择强制要求账本 attempt 和 selection 均存在，核对 context 摘要、选择值、选择摘要、发送保留、origin、attempt_ids、原响应摘要和兼容状态：

| checkpoint 选择状态 | 账本状态 | 传输状态 |
|---|---|---|
| selected | SELECTION_SAVED | OK |
| invalid_response | RESPONSE_SAVED | OK |
| unknown_in_flight | UNKNOWN_SEND | UNKNOWN_IN_FLIGHT |
| provider_failure | FAILED | 非 OK 且非 UNKNOWN_IN_FLIGHT |

账本选择为空不再跳过核对。账本自身记录摘要和选择摘要校验继续保留；即使重新封装账本记录摘要，缺失或不一致仍拒绝。

合法分支仍保留：singleton 不需要 attempt，且禁止其出现意外发送；budget_exhausted 允许没有 attempt，或只有未发送、未保存选择的 INTENT；响应或选择已在账本而 checkpoint 仍为 DECISION_READY/无选择时，继续复用持久结果，不要求 checkpoint 提前保存选择。无选择但账本发送不明的原阻断保留。

可信合成夹具经实际 `run_jev_job` 生成已保存选择，再分别删除 attempt、清空 selection、修改选择值、摘要、状态、send_started 或 origin，恢复均拒绝；每项核对零新增发送、评估、LP、提交。另验证 RESPONSE_SAVED / SELECTION_SAVED 早于 checkpoint 选择的合法中断、预算停止 checkpoint 恢复、singleton checkpoint 恢复。新门控、公共保存转换和账本读回未被 mock；只有计算体与传输为离线替身。
