## 1. 本次改了什么

原 O3 在出现违规提议或 Top-K 没有业务可行候选时终止。本次新增模式按方法自己的轨迹逐箱生成候选，只要方法返回合法编号且独立物理检查通过，就执行它；业务违规只记录，不拦截、不替换选择。

```text
当前箱 + 本方法实际托盘 → 物理候选 Top-K≤16
 → 方法选择候选 → 记录是否违反业务规则
 → 独立物理检查 → 提交所选候选 → 更新真实实验状态 → 下一箱
```

支持两种参数：

- `--execution-mode safe`：默认的原有安全策略。
- `--execution-mode observe_business`：业务违规观察策略，所有 `screen_intervened` 应为 false；`would_screen_block` 仍记录原屏障是否会拦截。

物理边界、碰撞、支撑和承重检查继续生效。没有物理候选、非法响应、解析失败或 API 错误仍会产生终止记录，因此“完整订单实验”指从空托盘处理完整到货序列，不保证每种方法都能放完。

## 2. 所有候选都违反业务规则时，怎么继续

原 Executor 没有业务可行候选就返回空。为了继续观察整单效果，观察模式为 Public Parser、Flash AST 和真值 AST 的共同 Executor 增加冻结排序：

1. 最小化新增违规实例数与加重已有违规实例数之和。
2. 再最小化放置后累计违规实例数。
3. 再按公开政策的第一、第二软目标比较。
4. 最后以几何质量和公开候选编号处理同分。

存在业务可行候选时，仍按原先“硬可行→软优先级→几何”选择。非特权方法只使用自己公开解析出的政策；隐藏真值只用于评价和特权参考臂。固定属性臂沿用原有固定政策及最少放置后违规的回退排序，Geometry 按原几何分选址。

这意味着新增模式同时明确了“业务无解时的执行器继续策略”；不能把全部差异称为单纯关闭屏障的效果。`diagnostic_continuation=true` 表示该步在公开业务可行集合为空时仍提交了选择。已有违规可能使全状态可行集合持续为空，此字段不等于“该步新增违规”。

违规实例等权计数是本轮冻结的诊断规则，不代表现实损失金额或业务约束可互相替代。

## 3. 指标怎么读

| 字段 | 含义与分母 |
|---|---|
| `completed_order_business_violation_rate` | 已完整放完且最终存在业务违规的 episode 数 / 全部放完 episode 数；没有放完任务时为 null。必须联合完成率看。 |
| `all_attempt_business_violation_rate` | 实际已提交过程中曾新增或加重业务违规的 episode 数 / 全部计划 episode 数；未完成订单也在分母。它不是任务成功率。 |
| `business_violation_step_rate` | 单 episode 中新增或加重业务违规的已提交步数 / 已提交步数；未放下任何箱体时为 null。旧违规不会使无关后续步骤重复记错。 |
| `committed_business_violation_step_rate` | 方法级总违规提交步数 / 总提交步数，即按步汇总。 |
| `mean_episode_business_violation_step_rate` | 各个非空 episode 步骤违规率的平均值；每个 episode 权重相同。 |
| `final_business_violation_count` | 一个 episode 最终违规实例数：每个超业务限载易碎箱、每对禁止接触箱体各计一次；不是违规箱体比例。 |
| `final_business_violation_ids` | 最终具体违规实例，区分 `load` 和 `contact`，用于逐例检查。 |
| `new_business_violation_instances_total` | 已提交动作新增违规实例数之和；一个动作可能新增多个实例。 |
| `worsened_business_violation_instances_total` | 已提交动作加重已有易碎箱超载的实例次数；与“新增实例”分开记录。 |
| `episode_completion_rate` | 全部箱体放完的 episode / 全部计划 episode。 |
| `clean_completion_rate` | 全部箱体放完且最终无业务违规的 episode / 全部计划 episode；等同本轮 `episode_attribute_success` 的汇总。 |
| `mean_placed_item_ratio` / `mean_placed_volume_ratio` | 所有计划任务的已放件数/体积比例，包含提前停止的任务。 |

主表同时放：完成率、全过程曾违规任务率、完成任务中的最终违规率、步骤违规率、最终违规实例数、无违规完成率。不能仅按一个条件违规率给方法排名，因为各方法完成的订单子集可能不同。

`raw_post_business_violations` 是每步放置后全状态的违规数，不能逐步相加作为新增违规总量；同一违规可能连续存在多步。优先用新增/加重字段与最终实例数解释累计影响。

历史字段 `raw_avoidable_hard_wrong` 依赖“放置后全状态存在硬可行候选”。已有违规累积后，该字段可能为 N/A；本模式的主要步骤指标改用新增/加重违规，不能将 N/A 当成零违规。

## 4. 在 pallet_vlm 中运行真实五方法实验

从仓库根目录运行，密钥使用当前终端已经 export 的 `DEEPSEEK_API_KEY`。新目录用于与既有安全模式对照，不在旧目录上使用 resume。

先运行 3 个 train 开发订单 × 2 政策 × 5 方法，共 30 个 episode：

```bash
conda activate pallet_vlm
cd /home/cyw/NBU_Papper

PYTHONPATH=semantic_pallet_planner/src python -m semantic_pallet_planner.runners.attribute_o3_online \
  --output semantic_pallet_planner/outputs/EXP_OPT_O3A_BUSINESS_OBSERVE_20261016_REMOTE_01 \
  --split train --limit-orders 3 \
  --execution-mode observe_business --remote --render-comparisons
```

检查 `acceptance_report.json`、`replay_report.json` 和 `audit/schema_leakage_report.json`。通过后运行与原 O3b 相同的 10 个 validation 来源订单 × 2 政策 × 5 方法，共 100 个 episode：

```bash
PYTHONPATH=semantic_pallet_planner/src python -m semantic_pallet_planner.runners.attribute_o3_online \
  --output semantic_pallet_planner/outputs/EXP_OPT_O3B_BUSINESS_OBSERVE_20261016_REMOTE_01 \
  --split validation --limit-orders 10 \
  --execution-mode observe_business --remote --render-comparisons
```

五方法为 Geometry、固定属性、Public Parser＋Executor、Flash AST＋Executor、真值 AST＋Executor。真实 Flash 会按本模式产生的新状态逐步调用；不能复用原安全模式停止前后的候选或响应来拼接新轨迹。

完整 episode 间断点续跑时，使用相同目录、相同参数并加 `--resume`，例如：

```bash
PYTHONPATH=semantic_pallet_planner/src python -m semantic_pallet_planner.runners.attribute_o3_online \
  --output semantic_pallet_planner/outputs/EXP_OPT_O3B_BUSINESS_OBSERVE_20261016_REMOTE_01 \
  --split validation --limit-orders 10 \
  --execution-mode observe_business --remote --render-comparisons --resume
```

续跑会检查模式、源码/数据哈希及已有记录回放；已有不完整 episode 时仍拒绝拼接，先检查该 episode 的原始产物。修改过源码或切换模式时应使用新目录。

## 5. 运行后优先看哪些文件

1. `pilot_report.md`：自动生成的方法对照表和分母说明。
2. `acceptance_report.json`：检查 `execution_mode=observe_business`、屏障未干预、物理检查、回放和公开输入审计；完整真实五臂检查通过才标 PASS。
3. `metrics/summary.json`：方法级违规率、完成率及最终违规实例数。
4. `metrics/per_episode.csv`：同一 `source_order_key/policy_id` 的方法配对，包含失败订单。
5. `metrics/per_step.csv`：检查提议与提交一致、发生违规的当前箱、`would_screen_block`、`diagnostic_continuation` 和属性增量。
6. `metrics/business_violation_comparison.json`：各方法减 Public Parser 的配对差与探索性 95% 区间。每个来源订单先平均两政策差值，再按来源订单聚类 bootstrap；步骤率比较采用 episode 平均口径。
7. `visualization/*/comparison.gif`：原有 Geometry 与 Public Parser 并排动画，关联真实状态。Flash 全轨迹另查其 episode 日志。

配对统计只有 10 个独立 validation 来源订单，不是 100 个独立样本。真值 AST 为特权参考，不代表完整订单全局最优。Flash 是否优于其他方法以实际差异为准；当前固定文本政策中，它仍可能与 Public Parser 得到相同选择。

## 6. 实现与验证记录

- `runners/attribute_o3_online.py`：执行模式、无业务屏障提交、逐步/整单违规指标、来源聚类配对比较、报告、模式绑定和独立回放。
- `selectors/policy_executor_v2.py`：显式开启时才启用业务不可行候选的确定性继续策略，默认调用语义不变。
- `tests/integration/test_o3_online.py`：业务违规提议被实际提交、无业务可行解时继续、Flash 模拟协议两种模式、模式串用拒绝及指标篡改检测。

回放严格校验已保存请求的候选摘要，再与重新生成的公开事实比较；仅有限浮点数允许 `1e-9` 绝对误差，解决跨 Python 数学实现的微小差异。编号、状态/政策绑定、结构、计数与 N/A 仍要求完全一致，此误差不改变业务或物理判定阈值。

实际验证命令：

```bash
PYTHONPATH=semantic_pallet_planner/src pytest -q semantic_pallet_planner/tests

PYTHONPATH=semantic_pallet_planner/src python -m semantic_pallet_planner.runners.attribute_o3_online \
  --output semantic_pallet_planner/outputs/EXP_OPT_O3_BUSINESS_OBSERVE_OFFLINE_20261016_03 \
  --split validation --limit-orders 10 \
  --execution-mode observe_business --render-comparisons
```

结果：测试命令退出码 0，**120 passed in 56.42s**。离线实验命令退出码 0；80 个 episode 回放全部通过，1030 条公开请求 Schema/泄漏检查失败 0，业务屏障干预 0，已提交物理违规 0，三组动画检查通过，源码快照哈希与当前实现一致。真实 Flash 尚未在本模式调用，因此完整五臂验收标为 PARTIAL，离线部分为 PASS。旧 O3a 远程安全模式另做只读回放，30/30 通过，没有改写旧实验报告。
