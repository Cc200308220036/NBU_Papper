## 排序协议

- 控制臂 `original` 与软预算参照动作继续使用冻结的原 Executor；物理检查、业务可行集合、最小伤害层级、软预算及其原有 EPS 不改变。
- `relaxed_wo_floor` 的三项特征均值使用 `math.fsum`；原几何/布局特征定义与权重不调参。
- 布局排序先求候选集合最大分 `M`，保留 `score >= M−1e-12`；在保留集合内，对几何评分再独立求最大值并以同样范围保留，最后按公开 Cxx 编号升序选择。
- `relaxed_geometry` 仅使用上述几何同分层；`original` 完全使用原排序。
- 这是固定的无量纲排序精度，不是物理、业务或软预算容差；不得利用扩大回放误差忽略动作不同。最大值锚定避免成对“近似相等”比较的非传递性。
- 版本：`layout_preserving_v2_fsum_max_anchor_1e-12`；新运行器 `layout_flash_validation_v2`。V1 模块不修改。

## 前四步的验收矩阵

1. 冻结旧三类实验、阶段 A/B/C 的全部文件清单与源码，记录两解释器及已安装依赖，不升级环境。
2. 对近同分、明确非同分、候选重排、无效评分、业务硬层、软预算及三个已发现问题来源补充测试。
3. 使用 Python 3.11 和 3.13，在相同保存请求上比较 V2 实际动作，不能只比较特征误差。
4. 两个解释器各自从空托盘运行 120 episode（10来源×2政策×3变体×2模式），3.11 为主基线，3.13 为独立交叉复本；这仍是 120 个逻辑任务，并非 240 个独立样本。要求动作、物理状态哈希、候选标签、允许集合及终止完全一致；连续数值使用原有有限浮点绝对误差 1e-9 作复算比较。不得用该误差跳过离散动作差异。

主基线本身只与历史 `original` 控制臂核对，另外两个 V2 策略以新协议建立新基线。交叉复本通过 `--baseline` 与主基线全部三变体逐步核对。主基线建立时 `cross_runtime_status=NOT_CHECKED`，全矩阵复本完成后由单独 `cross_runtime_report.json` 记录整体认证，保留原生成时点的验收文件。
