# O3布局机制 Flash 验证操作与验收清单

日期：2026-10-20。`layout_flash_validation` 接口现已实现，支持下述 CLI。阶段 A 的实际测试与离线验收结果另附报告；真实 API 冒烟与配对验证属于后续阶段，不能将离线 PASS 当作远程验收。

## 1. 当前接口状态

- `runners.layout_ablation` 已支持离线布局消融，只有 `--output`、`--split`、`--limit-orders`、`--variants`，没有 `--remote`。
- 新增 `runners.layout_flash_validation` 支持指定场景、三个变体、两模式、离线与真实 Flash；旧 `runners.attribute_o3_online` 不支持新的布局变体。
- 当前 O3 使用 `DeepSeekClient`、模型标识 `deepseek-flash` 和环境变量 `DEEPSEEK_API_KEY`；不要根据“Flash”名称切换到其他供应商。服务可用性与实际返回模型必须在运行时核验和记录。
- 已完成的布局验证证明离线机制可运行，尚未证明新布局轨迹上的真实 Flash 端到端有效性。

后续顺序：接口开发与离线验收 → 三来源订单真实冒烟 → 十来源订单三变体配对验证。后两阶段必须等待前一阶段验收通过。

## 2. 阶段 A：开发接口并完成离线验收

可直接交给开发执行者的操作指令：

> 新增独立运行器 `semantic_pallet_planner.runners.layout_flash_validation`，复用现有公开请求、Flash 政策解析协议、布局选择器与独立物理检查。对同一批来源订单、双政策、两执行模式和三个布局变体，分别运行 Public Parser 和真实 Flash AST 两种政策解析来源。两者只在 AST 来源上不同，随后调用同一个布局执行器。不得直接调用旧 `invoke_flash` 后把它已选出的旧策略动作当作布局动作；应拆开“调用并校验 AST”与“依据变体执行 AST”。
>
> 支持下节命令定义的参数；开发期允许 `--offline-only`，正式 `--remote` 禁止使用模拟客户端、缓存响应或以 Parser 替代失败的 Flash。实现请求/原始响应/修复/AST/执行轨迹归档、调用计数与上限、异常终止记录、源码和数据快照、独立回放及配对汇总。保留既有实验目录。先通过无网络测试，再实际调用。

已实现的命令行契约：

| 参数 | 要求 |
|---|---|
| `--output` | 新目录，目录已存在时拒绝覆盖 |
| `--split validation` | 使用既有 validation 开发来源，不宣称独立测试 |
| `--scenarios SCN_0055 SCN_0054 SCN_0060` | 明确选来源场景，自动展开各场景 P0/P1 |
| `--limit-orders 10` | 选完整十来源；与显式场景参数互斥 |
| `--variants original relaxed_geometry relaxed_wo_floor` | 固定三个变体 |
| `--execution-modes safe observe_business` | 模式独立运行 |
| `--offline-only` / `--remote` | 互斥；前者仅运行 Parser，后者运行 Parser 与真实 Flash |
| `--max-api-attempts N` | 初次请求、修复及任何重试均计数；超限前停止，标记未完成 |
| `--replay-only` | 对 `--output` 指定的已有目录重新校验，不写入、不发起 API 调用 |

保持 `buffer_size=1`、Top-K=16、候选器、基础政策文本、软预算和布局参数不变。`relaxed_*` 仍是显式软政策变体，不因 Flash 返回相同基础 AST 就变成原优先级严格不变。

## 3. 阶段 B：三来源真实 API 冒烟

预先固定 `SCN_0055`（原策略成功）、`SCN_0054`（机制改善代表）、`SCN_0060`（仍失败代表）。这是基于已有结果选取的调试样本，不能用于估计总体收益。

确认密钥已在环境中配置；下面只检查存在性，不打印密钥：

```bash
python -c 'import os; assert os.environ.get("DEEPSEEK_API_KEY"), "DEEPSEEK_API_KEY 未设置"; print("API key configured")'
```

以下命令仅在阶段 A 完成后使用：

```bash
MPLCONFIGDIR=/tmp/layout-flash-mpl PYTHONPATH=semantic_pallet_planner/src \
python -m semantic_pallet_planner.runners.layout_flash_validation \
  --output semantic_pallet_planner/outputs/EXP_OPT_O3_LAYOUT_FLASH_SMOKE_20261020_01 \
  --split validation --scenarios SCN_0055 SCN_0054 SCN_0060 \
  --variants original relaxed_geometry relaxed_wo_floor \
  --execution-modes safe observe_business --remote \
  --max-api-attempts 1200
```

计划 72 个 episode：36 Parser + 36 Flash。请求不是每个 episode 一次，而是 Flash 每个实际有候选的决策步一次，必要时增加至多一次修复。三个订单各有 17、17、17 件，Flash 决策最多 612 步；若每步均修复，最多 1224 次尝试。1200 是本阶段保护上限，不承诺覆盖极端修复情况。运行前必须由实际任务计划重新计算件数上界；上限触发时停止并报告 PARTIAL，不能标完整 PASS。

记录供应商、请求模型、返回模型（若服务提供）、温度、提示词版本、超时及修复设置。金额仅在有核验过的计价依据时计算，否则记录 tokens 和金额未知，不估造价格。

阶段 B 验收：

1. 72 个计划 episode 均有记录，API/协议失败不能被删除或替换；完整正常结束或可解释的几何/业务终止与 API 故障分开统计。
2. 每个 Flash 决策均有真实请求及对应响应或失败证据；无旧响应复用，无 Parser 兜底。每步最多一次修复，所有网络尝试计数。
3. 公开输入 Schema 与泄漏扫描失败为 0；request/state/candidate/AST 绑定校验通过。
4. 已提交物理违规为 0；业务硬约束候选筛选与最少伤害回退符合各自解析 AST 和冻结配置；相对评估真值的违规单独报告，不能把模型误解析隐藏掉。
5. 相对原策略锚点的软预算越界为 0；提议与提交一致或有明确拒绝原因。观察模式业务屏障干预为 0。
6. AST、动作和整单指标回放通过；API 故障、无效 AST、证据缺失须先修复或解释，不能仅因文件齐全就放行正式阶段。

Flash 与 Parser 的 AST 或动作不一致不自动判工程失败；需要解释是否为模型差异。不能以“两者必须完全相同”作为通过标准。冒烟阶段如调整提示词或代码，保留原目录，以新版本新目录重跑。

## 4. 阶段 C：十来源三变体真实配对验证

阶段 B 通过后冻结代码、提示词、预算、来源与统计方法。以下命令依赖阶段 A 的新接口：

```bash
MPLCONFIGDIR=/tmp/layout-flash-mpl PYTHONPATH=semantic_pallet_planner/src \
python -m semantic_pallet_planner.runners.layout_flash_validation \
  --output semantic_pallet_planner/outputs/EXP_OPT_O3_LAYOUT_FLASH_VALIDATION_20261020_01 \
  --split validation --limit-orders 10 \
  --variants original relaxed_geometry relaxed_wo_floor \
  --execution-modes safe observe_business --remote \
  --max-api-attempts 4000
```

计划 240 个 episode：10来源×2政策×3变体×2模式×2解析来源，其中真实 Flash 120 个。运行前输出所有订单件数之和；Flash 最大决策数为该和×2政策×3变体×2模式，包含修复的最大尝试数再乘2。4000 是操作上限，不是实际调用量或金额预算；不足时报告 PARTIAL。阶段 B 的响应不得用于拼接阶段 C。

三组比较必须分开：

- 同一变体：Flash − Parser，评价解析来源差异。
- 同一解析来源：`relaxed_geometry − original`，评价显式软预算与几何选址变化。
- 同一解析来源：`relaxed_wo_floor − relaxed_geometry`，评价相同预算下开发期选出的布局代理方案。

按来源订单配对，先汇总双政策，再以 10 个来源订单为簇计算探索性区间；两执行模式分别报告。失败任务保留在计划分母。去地面项变体来自先前消融选择，仍存在选择偏差；这不是新的独立测试集。

## 5. 必须交付的文件

下表是产物规范。离线阶段没有模型请求，因此 `selector_inputs/` 不产生远程调用文件，一致率 CSV 只有表头；`real_flash_status=NOT_RUN`。测试记录通过验收归档补充至 `verification_report.json`，不会伪造为模型记录。

| 产物 | 验收内容 |
|---|---|
| `README.md`、`results.md` | 范围、实际命令、矩阵、实际调用量、工程状态和研究结论 |
| `manifest.json`、`snapshots/`、`config.snapshot.json`、`data/tasks.private.json` | 源码/数据/提示词/配置/任务计划及摘要；包含变体和软预算版本；私有任务不进入模型输入 |
| `acceptance_report.json` | 各门槛结果、计划与实际 episode 数、真实模型状态；不以新方法获胜作为 PASS 条件 |
| `selector_inputs/<mode>/<variant>/<parser>/<episode_id>/<step>/` | 公开请求、发送内容、初次/修复原始响应、`attempts.json` 中的解析 AST、校验与异常记录；不得含密钥 |
| `episodes/.../steps.jsonl` | 状态、候选绑定、AST来源、原策略锚点、允许集合、布局评分、软损失、提议/提交及终止原因 |
| `metrics/per_episode.csv`、`metrics/summary.json` | 两模式分开，完成率、无违规完成率、件数/体积比例、违规步分子分母及最终实例数 |
| `metrics/parser_flash_agreement.csv` | 每个已保存 Flash 状态上，将 Parser AST 与真实 Flash AST 输入同一执行器，比较 AST 与动作；另标闭环状态是否相同，不能强行按步号比较分叉后的轨迹 |
| `metrics/paired_cluster_comparisons.json` | 三组预定对照、来源聚类探索性区间及样本量 |
| `api_usage.json` | 初次/修复/重试/失败尝试数、tokens、延迟分布、缺失 usage 数、调用上限；金额可为 null |
| `replay_report.json` | 不调用网络，验证保存响应→AST→同一执行器动作→独立物理检查→状态→汇总 |
| `audit/` | Schema/泄漏、软预算、提议提交、源码数据绑定和原实验保护核验 |
| `verification_report.json` | 实际测试命令、退出码、通过数量；不能直接复制先前 141 passed 作为新代码验收 |
| `delivery_manifest.json` | 最终交付文件清单和摘要 |

对“同状态”一致率，使用相同物理状态、当前箱、候选集合、政策及变体，在该状态对两份 AST 运行同一确定性执行器；若需要额外 Flash 请求，必须真实调用并计入调用预算。各自闭环轨迹分叉后，不能按步号强行配对 Cxx。AST 比较应先规范化语义结构，区分格式差异、规则差异与动作差异。

## 6. 研究结论验收

- 工程通过：证据完整、真实调用可核验、状态与指标回放正确、边界约束实现正确；不要求 Flash 胜出。
- 若 Flash 与 Parser 基本一致：结论为 Flash 可在新布局轨迹中提供政策解析，观察到的布局收益主要归于执行器机制，未显示模型增量。
- 若 Flash 更差：保留失败与差异，区分协议错误、规则误解析、实体绑定及后续轨迹放大。
- 即使 Flash 更好：本轮仍是已见数据上的开发证据；后续才进入独立来源、政策变化/表达泛化验证。当前真值结构化状态实验不能据此宣称视觉感知或多模态优势。
