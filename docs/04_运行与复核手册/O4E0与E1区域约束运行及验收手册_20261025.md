# O4-E0/E1区域约束运行与验收手册

2026-10-25。专用入口：`python -m semantic_pallet_planner.runners.o4_extensions`。本手册只覆盖E0公共契约与E1区域，不代表E2/E3完成。标签固定顶面朝上，E4按用户要求OUT_OF_SCOPE。已有D实验、旧图像及旧评分不重跑、不覆盖。

## 1. 环境与已实现命令

在项目根目录`/home/cyw/NBU_Papper`、`pallet_vlm`环境运行。运行时可设置`PYTHONDONTWRITEBYTECODE=1`避免写入源码缓存。以下子命令均有实际实现：

```bash
python -m semantic_pallet_planner.runners.o4_extensions --help
```

| 命令 | 完成的任务 | API |
|---|---|---|
| prepare | 构建24金标准、12非法题、12对固定题、12构造订单，冻结数据、配置、源码与文档 | 0 |
| validate-plan | 校验计划封存、源码版本及96条订单job身份 | 0 |
| run | 48条固定题记录、96条订单主记录、48次Oracle重复、48次恢复、旧金标准回归及故障/图像核验 | 0 |
| verify | 只读复算新E1产物，不是旧D replay | 0 |
| remote-prepare | 冻结E1真实编译冒烟或固定题计划、模型参数及提示 | 0 |
| remote-run | 用户显式执行新E1真实编译，不运行在线订单 | 预算内真实请求 |

输出目录必须不存在，不能位于源码、数据集或已封存实验内部。代码变更后使用原计划源码快照，不能编辑旧manifest。

## 2. 离线完整验收

先构建一次独立计划：

```bash
python -m semantic_pallet_planner.runners.o4_extensions prepare \
  --output semantic_pallet_planner/outputs/PLAN_O4_E1_OFFLINE_READY_20261025_03

python -m semantic_pallet_planner.runners.o4_extensions validate-plan \
  --plan semantic_pallet_planner/outputs/PLAN_O4_E1_OFFLINE_READY_20261025_03
```

运行整个E0/E1离线矩阵，保护清单是本轮开发前实际已有文件的SHA256，包含原源码、测试、配置及实验：

```bash
python -m semantic_pallet_planner.runners.o4_extensions run \
  --plan semantic_pallet_planner/outputs/PLAN_O4_E1_OFFLINE_READY_20261025_03 \
  --output semantic_pallet_planner/outputs/EXP_O4_E1_OFFLINE_20261025_03 \
  --protection report/analysis/O4_E0_E1_DEVELOPMENT_20261025_01/protected.before.json
```

本轮开发者执行上述离线工作；结果以该目录`acceptance_report.json`为准。若目录已经存在，不重复覆盖；独立复现时改用新编号的输出，原计划仍可复用。使用源码快照时，前缀设置：

```bash
export PYTHONPATH="$PWD/semantic_pallet_planner/outputs/PLAN_O4_E1_OFFLINE_READY_20261025_03/code_snapshot/semantic_pallet_planner/src"
```

如需独立核验新结果，可执行以下只读命令；不要求用户重跑已完成D的replay：

```bash
python -m semantic_pallet_planner.runners.o4_extensions verify \
  --experiment semantic_pallet_planner/outputs/EXP_O4_E1_OFFLINE_20261025_03
```

注意：仓库根目录存在`semantic_pallet_planner/__init__.py`引导包，单独设置PYTHONPATH仍可能优先加载当前工作区。后续代码改变、需要强制使用已设置PYTHONPATH的冻结源码时，应使用Python 3.11的`python -P -m ...`，例如：

```bash
python -P -m semantic_pallet_planner.runners.o4_extensions validate-plan \
  --plan semantic_pallet_planner/outputs/PLAN_O4_E1_OFFLINE_READY_20261025_03
```

同理，冻结版run/verify/remote-run使用`python -P -m`；prepare在当前开发源码中执行。原命令适用于当前源码与计划完全一致的情况，源码不一致会明确拒绝，不能重写封存摘要。

## 3. 新E1真实API编译（由用户执行）

只有E1离线验收通过后才交接这部分。模型配置复用已有D配置文件作为显式输入，计划封存其参数，不声称已实时验证提供方服务能力。密钥仍从该配置指定的环境变量读取，不写入文件。下列命令可以先准备计划，不产生请求：

```bash
python -m semantic_pallet_planner.runners.o4_extensions remote-prepare \
  --development-plan semantic_pallet_planner/outputs/PLAN_O4_E1_OFFLINE_READY_20261025_03 \
  --profile compile-smoke \
  --model-config semantic_pallet_planner/configs/o4_d_deepseek_flash.yaml \
  --output semantic_pallet_planner/outputs/PLAN_O4_E1_SMOKE_READY_20261025_01

python -m semantic_pallet_planner.runners.o4_extensions remote-prepare \
  --development-plan semantic_pallet_planner/outputs/PLAN_O4_E1_OFFLINE_READY_20261025_03 \
  --profile fixed \
  --model-config semantic_pallet_planner/configs/o4_d_deepseek_flash.yaml \
  --output semantic_pallet_planner/outputs/PLAN_O4_E1_FIXED_READY_20261025_01
```

真实调用：

```bash
python -m semantic_pallet_planner.runners.o4_extensions remote-run \
  --plan semantic_pallet_planner/outputs/PLAN_O4_E1_SMOKE_READY_20261025_01 \
  --output semantic_pallet_planner/outputs/EXP_O4_E1_SMOKE_REAL_20261025_01 \
  --api-budget 48 --remote

python -m semantic_pallet_planner.runners.o4_extensions remote-run \
  --plan semantic_pallet_planner/outputs/PLAN_O4_E1_FIXED_READY_20261025_01 \
  --output semantic_pallet_planner/outputs/EXP_O4_E1_FIXED_REAL_20261025_01 \
  --api-budget 96 --remote
```

冒烟12题×4来源=48条记录，Text/Image基础请求24次，含最多一次格式修复的上限48次；固定题24状态×4来源=96条记录，基础请求48次，上限96次。预算包括失败和修复，耗尽保留未执行/失败记录并记PARTIAL。语义合法但错误的回答不修复、不用Parser/Oracle替代。工程PASS不代表模型准确率PASS。

Text/Image同一模型参数、同准确事实，只差实际PNG字节。格式修复不提供参考AST。真实在线E1订单入口尚不在本轮交付范围；本轮四种规划器为离线真实仿真提交，不能据此宣称模型在线实验完成。

## 4. 产物阅读与范围

- `plan.json`与`private/data.json`：冻结分母、业务定义、解析证明和预期，不作为模型输入。
- `metrics/gold.json`、`invalid.json`、`pairs.json`、`pair_checks.json`：逐题真假及配对允许集合/动作变化。
- `metrics/episodes.json`、`episodes/`：四规划器全部96个订单主记录，失败、待码与未到货箱保留。
- `repeats/`、`restores/`、`audit/episode_recomputation.json`：独立重复、检查点恢复和逐事件复算。
- `metrics/candidate_coverage.json`：原候选与公共区域补点后的差异；Top-K截断不代表全局无解。
- `public/images/`与`audit/visual.json`：新顶面标签PNG、精确公共facts和独立核验。
- `audit/faults.json`、`protected.json`：实际故障执行、错误AST暴露及旧件保护。
- `acceptance_report.json`、`delivery_manifest.json`：EA-01—EA-10、E1-A—E1-E与封存校验。

12个构造订单是工程测试来源，部分共享基础尺寸；不属于12个真实独立订单，不作为未见泛化证据。每种规划器会保留预先设定的4个受限任务，未全部完成不是删题理由；工程验收检查是否符合独立预期。
