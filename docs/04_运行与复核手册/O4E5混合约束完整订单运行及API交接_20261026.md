## 3. 中断和失败如何处理

明确中断后沿用同一计划、同一输出和同一预算，使用`--resume`；不要删除账目、改编号、覆盖旧输出或重新给预算。续跑的`--max-jobs`按尚未执行job计数。未知in-flight请求仍占预算，不自动重发；已保存原始响应用于恢复，避免重复请求和提交。

格式或绑定无效最多修复一次；语义合法但错误的AST照实际回答执行和评分，无Parser/Oracle兜底。模型错误、网络失败和未执行任务均保留，不能删除失败记录。预算不足或未跑完保留PARTIAL。

取消的是本轮运行后的额外全量复算；执行时的绑定、状态、提交及账目检查仍正常保留。本手册不安排额外verify命令。

## 4. 主要产物怎么看

| 文件或目录 | 用途 |
|---|---|
| `acceptance_report.json` | 当前执行范围、完成状态和未测项；执行PASS不等于整单完成或模型全对 |
| `metrics/summary.json` | 按来源、C0/C1、后端、规划器统计完成、无违规完成、件数、体积和编译表现 |
| `episodes/` | 实际WAIT/PLACE/EOS/STOP、请求、AST、候选、before/after及下游参考检查 |
| `responses/` | 保存的原始首答和修复响应 |
| `audit/ledger.json`、`compilations.json`、`budget.json` | attempt、编译和跨任务实际预算 |
| `checkpoints/` | 中断恢复所需状态与事件 |
| `audit/coverage.json` | 物理采样、Top-K、参考同池和当前方法限制 |
| 离线`verification_policy.json`、`audit/readonly_verify.json` | 明确额外全量复查已按用户要求跳过 |

编译率包含失败分母，未执行组保留计划分母；无提交或无编译的指标为N/A，不伪写100%。`clean_completed`要求最终及历史真实提交均无业务违规。旧开发来源上的结果不等于未见泛化，Text/Image差异应等真实结果产生后再分析。
