# O4-E5空间规划V1运行手册

状态更新（2026-10-27）：依用户要求，空间V1已从活动代码、配置和测试中撤回并归档；正式E5入口恢复到空间改进前版本。下文为历史实现/实验分析，不代表当前启用算法；其中空间V1运行命令不再适用于活动工作区。58条历史结果和评分不变。归档位于`semantic_pallet_planner/outputs/ARCHIVE_O4_E5_SPATIAL_V1_ROLLBACK_20261027_01/`。

2026-10-27。新入口只执行Parser/Oracle本地规划对照，没有remote选项，也不需要API密钥。原E5真实运行手册和旧冻结计划继续对应原算法；要使用新空间版本，需使用本入口或显式配置，不能以为旧remote-run自动升级。

## 1. 新实验运行

在项目根目录、pallet_vlm环境执行。运行新源码入口时重新指定PYTHONPATH，避免此前导出的旧在线计划快照优先导入：

```bash
export PYTHONPATH="$PWD/semantic_pallet_planner/src"
python -P -m semantic_pallet_planner.runners.o4_e5_spatial \
  --source semantic_pallet_planner/outputs/EXP_O4_E5_090_REAL_20261026_01 \
  --output semantic_pallet_planner/outputs/EXP_O4_E5_SPATIAL_LOCAL_20261027_01
```

这是本轮开发者执行的58条新算法实验；交付完成后无需用户重复运行。现有输出拒绝覆盖。如确需独立重复，采用新的输出目录。

`--max-jobs N`按本次新增job计数，未执行项保留计划分母并报告PARTIAL。明确中断后沿用同一源码、配置、源数据与输出，增加`--resume`；只跳过已落盘完整episode，未完成本地job会从头执行，没有模型请求。示例：

```bash
python -P -m semantic_pallet_planner.runners.o4_e5_spatial \
  --source semantic_pallet_planner/outputs/EXP_O4_E5_090_REAL_20261026_01 \
  --output semantic_pallet_planner/outputs/EXP_O4_E5_SPATIAL_LOCAL_20261027_01 \
  --resume --max-jobs 4
```

完整封存后拒绝续跑。源码或配置漂移也拒绝续跑，不能把不同算法拼进同一结果。

## 2. 产物

- `plan.json`：四组开关、58个job、输入与源码摘要、冻结任务选择、验收范围。
- `code_snapshot/`、`config.snapshot.json`、`private/tasks.json`：运行时源码及输入快照。
- `episodes/`：原事件/状态/AST/动作保持原E5格式；新增`measurement`单列本轮分组、时间、空间指标和覆盖损失，不改写原summary定义。
- 事件的`groups[].generation.retention`：候选保留/淘汰理由与公开几何标签。
- `groups[].trace.spatial_qualities`：软预算内候选的平面空间分；搜索trace记录版本、节点及预算。
- `metrics/summary.json`：按来源类型、消融组、规划器、后端汇总。
- `acceptance_report.json`：测量是否完整、安全及源文件保护；不单凭PASS宣称全部方法收益。
- `progress.json`：进度；失败时保留`failure.json`，不抹除已保存记录。
