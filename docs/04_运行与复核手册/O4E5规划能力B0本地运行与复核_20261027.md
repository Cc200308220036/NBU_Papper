
仅在确认原运行已终止、需要继续未完成任务时对同一命令加 `--resume`；可用 `--max-jobs N` 做有界执行。仍存活的进程应先观察其原session，不另起重复执行。`run.lock` 用于排他，`progress.json`、`jobs.json`、`checkpoints` 保存实际现场。FAIL停止，先检查errors，不能跳过失败后继续扩大。

通过后，活动源码不得改变，运行 `prepare-final` 冻结F=B0、门槛和新的72条任务。该命令核验小样本源码摘要，不接受悄悄换算法的F。

## 复核口径

每次实际提交仍由原绑定、业务执行器与独立物理检查守门。单任务少2箱或完成转未完成单列HOLD。平均体积、件数、无违规完成数按single/search分别比较，不能用布局观感或工程PASS替代性能。

成本只测新F、同状态A/F、3个独立进程；区分冷/热、候选全池工作、逻辑评价与端到端。历史V2-D延迟不得沿用。最终报告分别给工程、性能和默认替换资格；即使达到门槛，也仅给可审查建议，原A继续默认。

本轮成本获得3个有效独立进程的72冷+72热调用，另外有1个元数据描述字段缺失导致的失败进程，2冷+2热调用后中断。`timing_plan.json`、`timing_worker_v1_failed.py`、`timing_instrumentation_failure.json` 保留失败前版本；`timing_plan_v2.json` 冻结仅修复计时描述字段后的脚本，未改变F/样本/阈值。没有补跑订单。完整账目和冷热统计均在新报告目录。
