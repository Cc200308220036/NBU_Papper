## 2. 冻结代码运行与恢复

本轮实际执行命令如下。已有结果不应再次执行首跑；以下用于理解运行身份。

```bash
env \
  PYTHONPATH=/home/cyw/NBU_Papper/semantic_pallet_planner/outputs/PLAN_O4_E5_LAYOUT_V2_20261027_01/code_snapshot \
  PYTHONDONTWRITEBYTECODE=1 \
  /home/cyw/anaconda3/envs/pallet_vlm/bin/python -B -P \
  -m semantic_pallet_planner.runners.o4_e5_layout_v2 run \
  --plan semantic_pallet_planner/outputs/PLAN_O4_E5_LAYOUT_V2_20261027_01 \
  --output semantic_pallet_planner/outputs/EXP_O4_E5_LAYOUT_V2_L2_20261027_01
```

`-P`防止工作区引导包抢先导入；这里指向新计划的 `code_snapshot`，不是旧E5真实计划。运行器核对计划摘要、快照摘要和自己的实际导入位置。不能更改快照后沿用同一计划身份。

只有确认原进程已终止后才允许恢复。在同一命令末尾加 `--resume`；可加 `--max-jobs 1`限定本次处理的未完成job数。恢复保留已完成job，使用保存的检查点，既有状态、请求和提交校验继续执行。不要删除 `jobs.json`、`run.json` 或检查点来重置进度。

完成本轮不需要额外执行整批verify。初次执行已经运行独立物理提交检查、绑定检查与下游参考评价；重复/恢复限定在已保存的代表构造，不追加全矩阵重复。

## 3. 复现新批次的准备顺序

只有主动要求重新实验时，才按下列顺序使用全新输出目录。参数应先冻结，不根据正在运行的结果改变。

1. `p0 --output 新P0目录`：记录保护摘要和三类历史状态诊断，不执行历史订单。
2. `local-checks --output 新L0目录`：对固定公共状态记录A/B/C/D选择。当前开发入口的案例来源固定为本轮P0目录；更换案例集需要新版本，不能静默替代。
3. 运行针对变化的行为检查，保存新的XML；既有测试结果可直接阅读，不以重复次数增加证据。
4. `prepare --output 新计划目录 --l0 新L0目录 --l1-xml 对应XML`：冻结48条核心消融、8条兼容检查、参数和代码。`prepare`拒绝覆盖旧目录。
5. 用该新计划的快照运行 `run`，结果写入另一个新目录。

本轮L3的72条任务定义已预先冻结，但执行入口未开放；必须先根据L0/L1/L2结果形成明确准入证据。若L2没有收益或有明显退步，停止扩大实验，保留负结果供检查。

## 4. 产物读取与有限成本核对

|文件|用途|
|---|---|
|`plan.json`、`manifest.json`|计划分母、输入/源码摘要、分组配置和保护索引|
|`jobs.json`、`progress.json`|逐任务状态；未执行和失败保留在计划分母|
|`episodes/`|实际到货、公共请求、AST、候选、排序、动作、停止与下游参考指标|
|`metrics/rows.json`、`summary.json`|逐任务和分组统计；批次收尾时生成|
|`metrics/decision_times.json`|主运行的决策耗时、缓存与逻辑评价数|
|`errors/`、`checkpoints/`|错误现场和恢复状态|
|`acceptance_report.json`|执行状态；最终工程/性能/默认替换资格须结合交付审计阅读|
|`delivery_acceptance_report.json`|独立的最终交付审计；初始执行报告、episode和评分保留原样|

辅助分析位于 `report/analysis/O4_E5_LAYOUT_V2_DEVELOPMENT_20261027_01/`。`analyze.py`只读取本轮保存结果生成配对表和可视化，不执行订单。`analyze_stops.py`只读取P0公共状态计算面积和载荷上界。两者均不读取旧模型响应后重新绑定。

`timing_worker.py`用于成本核对：在六个L2任务、两种方法的已保存第二个决策状态上，比较A/D各一次冷缓存及一次热缓存；一个进程共24次冷调用和24次热调用，不是24条订单重跑。主批次结束后已依次运行3个独立进程，使用冻结快照，分别写 `timing_process_1.json`、`timing_process_2.json`、`timing_process_3.json`。已有输出拒绝覆盖。

```bash
env \
  PYTHONPATH=/home/cyw/NBU_Papper/semantic_pallet_planner/outputs/PLAN_O4_E5_LAYOUT_V2_20261027_01/code_snapshot \
  PYTHONDONTWRITEBYTECODE=1 \
  /home/cyw/anaconda3/envs/pallet_vlm/bin/python -B -P \
  report/analysis/O4_E5_LAYOUT_V2_DEVELOPMENT_20261027_01/timing_worker.py \
  --plan semantic_pallet_planner/outputs/PLAN_O4_E5_LAYOUT_V2_20261027_01 \
  --experiment semantic_pallet_planner/outputs/EXP_O4_E5_LAYOUT_V2_L2_20261027_01 \
  --output report/analysis/O4_E5_LAYOUT_V2_DEVELOPMENT_20261027_01/timing_process_1.json
```

计时对照区分主运行的不同实际轨迹、同状态冷缓存核对和热缓存；不把缓存零耗时当作算法加速。全池元数据重建、质量评价与路径评分成本另报，256仅是沿用的逻辑候选评价预算。
