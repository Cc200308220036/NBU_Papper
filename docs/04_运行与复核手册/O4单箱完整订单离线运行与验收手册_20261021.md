# O4-C单箱完整订单离线运行与验收手册

> 后续状态（2026-10-22）：F已通过离线验收，见[F运行手册](O4待码缓冲离线运行与验收手册_20261021.md)。本工作树新增F模块/schema后，C原回放器的完整源码清单检查会检测到新增项；复核原C实验请在仓库根目录运行`PYTHONDONTWRITEBYTECODE=1 python report/analysis/O4_F_BUFFER_20261021_01/replay_legacy_c.py`。原源码、清单及实验不改写。

版本：`o4_c_online_v1`。本手册只覆盖O4-C，不启动Flash、不需要API密钥。完整结果及C1—C8证据见[开发与结果解析](../03_阶段产出分析/O4/O4单箱完整订单闭环开发与验收结果解析_20261021.md)。

## 1. 运行边界

- 使用已验收A/B交付中的12个开发来源、六份业务配置、准确属性和任务定义。
- `public_parser`和`oracle_ast`各72任务，合计144个episode；Oracle只提供特权AST，不是整单全局最优规划器。
- 物理候选保持旧生成器、buffer_size=1、每步Top-K≤16；业务筛选使用本方法AST。
- 固定布局为O4适配的relaxed_geometry：先业务硬可行，再以heavy_low→heavy_center严格锚点及0.05/0.25软预算选几何位置。
- 实际只提交独立物理复核通过的动作；无物理候选、无编译业务可行候选、协议或服务错误分别记录。参考业务评价不能替方法选址。
- 网络连接被运行时守卫禁止。O4-F三箱缓冲、O4-D真实模型、A5正式图像和A6人工审阅均不由本命令完成。

## 2. 当前代码入口

O4-C执行模块放在`o4/online/`子包：`planner_adapter.py`、`episode.py`、`cases.py`、`validation.py`。这与规范允许的等价模块组织一致，避免改变A/B根目录源码枚举和历史回放行为。

命令入口为`semantic_pallet_planner.runners.o4_online`，独立于早期统一CLI及A/B runner。配置为`semantic_pallet_planner/configs/o4_c_online.yaml`，本版本拒绝更改既定预算、候选数、方法和网络边界；改策略须新版本。

## 3. 运行命令

从`NBU_Papper`根目录执行。所有新建命令要求输出目录不存在，已存在时换新后缀。

```bash
PYTHONPATH=semantic_pallet_planner/src /home/cyw/anaconda3/envs/pallet_vlm/bin/python \
  -m semantic_pallet_planner.runners.o4_online --help

# 小规模冒烟：默认2任务×2方法；明确PARTIAL，不能替代完整C1
PYTHONPATH=semantic_pallet_planner/src /home/cyw/anaconda3/envs/pallet_vlm/bin/python \
  -m semantic_pallet_planner.runners.o4_online smoke \
  --limit-tasks 2 \
  --output semantic_pallet_planner/outputs/EXP_O4_C_SMOKE_REPRO_NEW

# 完整C验收：144个episode，每个从空托盘独立重复，再执行保存数据回放
PYTHONPATH=semantic_pallet_planner/src /home/cyw/anaconda3/envs/pallet_vlm/bin/python \
  -m semantic_pallet_planner.runners.o4_online acceptance \
  --baseline semantic_pallet_planner/outputs/EXP_O4_AB_OFFLINE_20261021_01 \
  --config semantic_pallet_planner/configs/o4_c_online.yaml \
  --output semantic_pallet_planner/outputs/EXP_O4_C_ONLINE_REPRO_NEW

# 已有交付的只读回放；不联网、不改日志、不改原验收
PYTHONPATH=semantic_pallet_planner/src /home/cyw/anaconda3/envs/pallet_vlm/bin/python \
  -m semantic_pallet_planner.runners.o4_online replay \
  --output semantic_pallet_planner/outputs/EXP_O4_C_ONLINE_20261021_01
```

验收默认保护运行前已有的数据、源码及实验文件。`--protection-before`可额外指定开发前SHA256清单，清单会复制到交付audit目录；正常复现不需要原开发者的临时文件。

`smoke`退出码为0时仍需看范围：`PARTIAL`表示小矩阵成功但完整C1未满足。只有`acceptance`全矩阵、C1—C8均为true且独立回放成功，才能称O4-C通过。来源仍为开发数据，不能升级成未见test结论。

## 4. 验收检查入口

| 检查 | 文件及关注点 |
|---|---|
| 阶段状态 | offline_acceptance.json：scope、status、criteria和counts |
| 正常任务分母 | plan.json、metrics/per_episode.json与CSV：144记录，提前停止也保留 |
| 逐配置结果 | metrics/summary.json：完成、无违规完成、件数/体积比例和终止原因 |
| 真实闭环轨迹 | episodes/方法/任务/steps.jsonl：请求、AST、候选映射、锚点、预算、提议/提交及前后状态 |
| 编译输入 | selector_inputs/方法/任务/步号.json：只有已到货公共事实和文本，不含候选参考答案 |
| 固定配对 | metrics/fixed.json：原144条记录及实际布局动作，语义不变对动作应相同 |
| 跨业务机会 | metrics/opportunities.json：六类预设机会对，允许集合与最终位置变化 |
| 不变性 | metrics/invariance.json：候选重排、对象ID及显式ID指令映射、模拟图像元数据顺序 |
| 与冻结排序等价 | metrics/legacy_equivalence.json：在相同不受业务限制池上比较V2锚点、预算允许集合与动作 |
| 方法一致 | audit/parser_oracle_agreement.json：72条对应订单的完整轨迹一致性 |
| 独立重复 | audit/repeat_run.json：144个episode分别从空状态再次运行的摘要及比较结果 |
| 负例及故障 | metrics/diagnostics.json：合法漏规则、非法AST、过期绑定、服务错误、无物理候选及物理拒绝 |
| 软预算 | audit/soft_budgets.json：实际检查次数及越界记录 |
| 篡改检测 | audit/tamper.json：AST、提交动作、候选映射、汇总四类检测 |
| 冻结与网络 | audit/protected.after.json、audit/network.json：变化0、连接尝试0 |
| 回放 | replay_report.json及独立replay命令的实际返回 |
| 版本 | manifest.json、config.snapshot.json、code_snapshot/及delivery_manifest.json |

参考也无可行候选时，终止步保存全枚举审计：Top-K和冻结枚举空间有解与否分别解释。全枚举仍只是该候选枚举器覆盖范围，不是连续空间或全订单的全局无解证明。

## 5. 复核原则与故障处理

- 不能把“业务违规为0但提前停止”计为无违规完成；整单完成率分母是全部72任务/方法。
- 独立重复与回放属于同一逻辑任务的复现证据，不能按新增独立来源统计。
- 接触左右交换、规则顺序或对象ID变化不应制造收益；构造机会对的改善也不能推导自然订单平均提升。
- 发生源码、A/B输入或交付摘要漂移时，回放返回FAIL；保留旧目录，用新版本新目录开发，不扩大浮点容差掩盖离散动作差异。
- 本轮采用单箱模式，不能将其完成或失败解释为三箱缓冲效果。

## 6. 何时需要你调用Flash

**O4-C验收不需要Flash。** 规范C8要求网络调用为0，当前命令也没有`--remote`或Flash方法，不能把旧O3 API指令用于新O4 AST。

真实调用属于O4-D。届时需先完成对应模式离线验收、真实客户端、公共图像A5及模型能力核验，再交付含实际模块、模型配置、请求预算和输出目录的专用指令。当前不提供尚未实现的O4-D命令，也不要求你为C阶段重复付费运行旧矩阵。
