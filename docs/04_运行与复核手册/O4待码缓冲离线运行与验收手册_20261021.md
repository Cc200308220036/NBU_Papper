# O4待码缓冲离线运行与验收手册

日期：2026-10-21。范围：O4-F，准确观测下最多三个已到货箱的待码、顺序与位置联合规划。本入口不调用网络；真实模型属于O4-D。

## 运行前提

从仓库根目录执行以下命令。使用已有Python环境及项目依赖；无需安装新包。设置`PYTHONPATH`使用工作区代码，测试禁用系统ROS自动加载的pytest插件，避免与项目无关的`lark`依赖错误。

```bash
export PYTHONPATH="$PWD/semantic_pallet_planner/src"
python -m semantic_pallet_planner.runners.o4_buffer --help
```

配置：`semantic_pallet_planner/configs/o4_buffer_offline.yaml`。依赖已验收A/B和C实验；默认C目录为`semantic_pallet_planner/outputs/EXP_O4_C_ONLINE_20261021_01`。不修改原数据、冻结代码和旧实验。已有输出目录会拒绝覆盖，请每次使用新目录。

## 完整验收与小规模冒烟

```bash
python -m semantic_pallet_planner.runners.o4_buffer smoke \
  --output /tmp/EXP_O4_F_SMOKE_NEW --limit-tasks 2 --workers 2

python -m semantic_pallet_planner.runners.o4_buffer acceptance \
  --output semantic_pallet_planner/outputs/EXP_O4_F_BUFFER_REPRO_NEW --workers 4
```

`--workers`为1至4个CPU进程，不是模型并发。正式验收固定72任务：四规划器Oracle各72条，加72条强规则搜索，共360条逻辑记录；全部重新运行，不复用C记录冒充新实验。每条另做独立重复与中断恢复。冒烟不满足F3，至多为PARTIAL。

容量1/2/3均可单任务试跑；正式矩阵固定容量1与3：

```bash
python -m semantic_pallet_planner.runners.o4_buffer rollout \
  --output /tmp/EXP_O4_F_CAPACITY2_NEW --method buffer_search --capacity 2 --task-index 0

python -m semantic_pallet_planner.runners.o4_buffer rollout \
  --output /tmp/EXP_O4_F_SINGLE_NEW --method single_greedy --capacity 1 --task-index 0
```

单任务运行的PASS仅表示该入口运行成功，不能代替F1—F10验收；订单提前终止也会保存真实结果。

## 恢复与只读回放

完整运行将每条轨迹的中断状态保存于`checkpoints/<method>__<backend>/<task_id>.json`。选择一个实际文件：

```bash
python -m semantic_pallet_planner.runners.o4_buffer resume \
  --checkpoint <实际checkpoint文件> --output /tmp/EXP_O4_F_RESUMED_NEW

python -m semantic_pallet_planner.runners.o4_buffer replay \
  --output semantic_pallet_planner/outputs/EXP_O4_F_BUFFER_20261021_01

python -m semantic_pallet_planner.runners.o4_buffer replay \
  --output semantic_pallet_planner/outputs/EXP_O4_F_BUFFER_20261021_01 --rerun
```

常规回放校验交付清单、源码、开发前保护清单、公开状态绑定、事件连续性、独立物理与业务、全部指标、独立重复及恢复摘要。`--rerun`额外从空状态重跑全部规划器，核对完整搜索trace、候选、动作和终止。耗时测量不要求逐次相等；其余内容参与确定性比较。两种回放均只读。

## 协议与结果解释

- `fill_then_plan`：有空槽且未EOS则接收；满容量或EOS后规划，每次实际提交一箱，随后补货并重规划。默认最后一箱后的下一次合法空读才返回EOS。
- 三个独立可取暂存槽；不允许暂存区堆叠，也不移动已码箱。容量包括最新到货箱。
- 每箱Top-K至多16，三箱联合首层至多48；深度至多3、束宽至多8、后继评价至多256。预算不足时保守截断并报告原因。
- `fifo_head_blocked`表示队首箱受阻但其他待码箱仍可放；`buffer_no_physical_action`和`buffer_no_compiled_business_action`分别表示整个待码集合的物理/业务无可行动作。
- 完成率使用全部72计划订单为分母；件数/体积比例使用完整订单，而不是仅已到货部分。未到货与待码余箱分别保留。
- 占用为事件采样；耗时为CPU规划/生成耗时，不表示真实等待时长或机器人吞吐率。

核心文件为`buffer_acceptance.json`、`episodes/*/*/events.jsonl`、`metrics/per_episode.json`与CSV、`metrics/per_source.json`、`metrics/resources.json`、`cases/`和`audit/`。构造案例通过不代表自然订单普遍改善。

## 历史A/B、C回放兼容性

原回放器将匹配到的全部`o4_*.json`（A/B）和全部包源码（C）视为当时的完整清单。新增F schema和模块会触发其“清单增加”检查，即使旧文件SHA256完全不变。不能为绕开这一检查修改冻结源码或原manifest。

本轮用C交付时保存的完整源码快照执行历史逻辑，再将数据/保护检查的工作区解析映射回实际原路径；无旧文件修改。实际结果见`report/analysis/O4_F_BUFFER_20261021_01/legacy_ab_snapshot_replay.json`和`legacy_c_snapshot_replay.json`。F自己的回放使用当前源码完整清单，不跳过新增源码。

可重现A/B历史回放：

```bash
PYTHONDONTWRITEBYTECODE=1 python report/analysis/O4_F_BUFFER_20261021_01/replay_legacy_ab.py
```

`PYTHONDONTWRITEBYTECODE=1`用于避免在冻结快照中产生新的缓存文件。C完整历史回放的实际调用上下文和结果已保存在独立证据目录；本轮的每条单箱轨迹还直接与C原始实际码放序列对照。
