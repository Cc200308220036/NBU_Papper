# O4-D真实模型运行与验收手册

日期：2026-10-23。实现版本：`o4_d_remote_v1`。默认模型为用户指定的 `deepseek-flash`。

本轮交付真实调用工程与离线验收，**未替用户发起真实API实验**。服务替身的协议通过、首答和语义统计不代表真实模型准确率。A6按用户决定不作为本轮前置条件；未伪造人工审阅或改写旧验收。

## 1. 接口、模型与输入

入口：`python -m semantic_pallet_planner.runners.o4_remote`。仅使用标准库HTTP，无需安装模型SDK。配置见 `semantic_pallet_planner/configs/o4_d_deepseek_flash.yaml`。

- endpoint：`https://api.deepseek.com/chat/completions`。
- model：`deepseek-flash`；文本与图像两条件共用模型、温度0、禁用thinking及8192输出token上限。
- 图像通过user消息中的 `image_url`、PNG base64 Data URL及 `detail=original`传输。发送的是校验后的实际文件字节。
- 同一公共状态下，文本与图像方法获得相同准确观测、完整指令及箱面/标签事实；图像条件额外附图。图片超过冻结限额时明确失败，不裁图、不降级成文本。
- 本地冻结上限为16张、每图10000000字节、16000000像素、每边8192像素（15图以上限制为4096），整个编码请求30000000字节。以上为本工程保守限制。

开发时已核验DeepSeek官方[图像文档](https://api-docs.deepseek.com/guides/vision/)与[Chat Completions接口](https://api-docs.deepseek.com/api/create-chat-completion/)。官方支持Flash图像与JSON输出；账号权限、服务可用性和真实业务编译表现仍由以下冒烟实测。未依据模型名称推断接口能力。

## 2. 环境与密钥

从仓库根目录执行，每条命令使用尚不存在的输出目录。若目录已存在，换新编号；不要删除旧实验后原地重跑。

```bash
conda activate pallet_vlm
cd /home/cyw/NBU_Papper
export PYTHONPATH="$PWD/semantic_pallet_planner/src"

python -m semantic_pallet_planner.runners.o4_remote --help

python -m semantic_pallet_planner.runners.o4_remote run --help

read -rsp 'DeepSeek API key: ' DEEPSEEK_API_KEY
export DEEPSEEK_API_KEY

```

不把密钥写入YAML、命令参数或实验文件。`prepare`和`replay`不需要密钥；只有 `run --remote`读取配置指定的环境变量。

## 3. 首先执行12题编译冒烟

先冻结计划，再运行。12题的ID在代码中预声明，覆盖禁压、限载、接触、集合、条件、例外及允许/拒绝边界，不按真实回答好坏重新挑题。

```bash
python -m semantic_pallet_planner.runners.o4_remote prepare \
  --profile compile-smoke \
  --output semantic_pallet_planner/outputs/PLAN_O4_D_COMPILE_SMOKE_20261023_01

python -m semantic_pallet_planner.runners.o4_remote run \
  --plan semantic_pallet_planner/outputs/PLAN_O4_D_COMPILE_SMOKE_20261023_01 \
  --output semantic_pallet_planner/outputs/EXP_O4_D_COMPILE_SMOKE_REAL_20261023_01 \
  --api-budget 48 --remote

python -m semantic_pallet_planner.runners.o4_remote replay \
  --output semantic_pallet_planner/outputs/EXP_O4_D_COMPILE_SMOKE_REAL_20261023_01
```

计划为12题×4来源＝48条固定题记录。其中规则和Oracle不调用API，文本/图像共有24次基础编译；每次至多一次格式修复，所以真实尝试上限48。`--api-budget`计入失败HTTP尝试和修复，达到上限后不再发出请求。

检查：

1. `acceptance_report.json`中 `test_double=false`，真实请求有账目，D4回放通过。
2. `metrics/summary.json`的 `api.by_condition`分别报告首答、修复后和最终有效；`served_models`保留服务实际返回的标识。
3. `responses/D*.json`保存公共输入、图像绑定、原始服务JSON及文本、解析结果和错误；不能只看AST格式合法率。
4. 图像条件的请求包含真实PNG。若服务拒绝图像，保留失败，不能改用文本后声称视觉通过。
5. 模型合法但漏规则、错对象或错阈值，属于语义结果；不会触发参考答案修复，也不要求模型必须达到100%才允许分析。

如仅想先验证本地链路，使用同一计划和**新的输出目录**，将 `--remote`换成`--offline`。结果明确为服务替身，不消耗真实API；不能把该目录当真实冒烟结果。

## 4. 单箱与缓冲在线冒烟

默认取冻结任务表的前两个开发任务；每个任务比较4种编译来源和4种规划器，共32个episode。四规划器为单箱、缓冲FIFO、缓冲启发式及缓冲有界搜索。这里没有把“搜索更好”写成验收条件。

```bash
python -m semantic_pallet_planner.runners.o4_remote prepare \
  --profile orders-smoke --task-limit 2 \
  --output semantic_pallet_planner/outputs/PLAN_O4_D_ORDERS_SMOKE_20261023_01
```

读取命令输出或 `plan.json`中的`maximum_api_attempts`。可直接用该上限作为预算：

```bash
O4_ORDER_BUDGET=$(python -c 'import json; print(json.load(open("semantic_pallet_planner/outputs/PLAN_O4_D_ORDERS_SMOKE_20261023_01/plan.json"))["maximum_api_attempts"])')

python -m semantic_pallet_planner.runners.o4_remote run \
  --plan semantic_pallet_planner/outputs/PLAN_O4_D_ORDERS_SMOKE_20261023_01 \
  --output semantic_pallet_planner/outputs/EXP_O4_D_ORDERS_SMOKE_REAL_20261023_01 \
  --api-budget "$O4_ORDER_BUDGET" --remote

python -m semantic_pallet_planner.runners.o4_remote replay \
  --output semantic_pallet_planner/outputs/EXP_O4_D_ORDERS_SMOKE_REAL_20261023_01
```

也可自行指定更小的正整数预算；预算不足时结果为`PARTIAL`，未执行编译及余箱均保留。上限按每箱可能一次编译再一次修复计算，实际调用通常更少。WAIT接收和EOS不计API请求；搜索树内没有API调用。

## 5. 正式开发矩阵

完成两种冒烟并核对账目后，冻结正式开发计划。可拆分运行，降低一次运行的规模：

| profile | 固定题 | 完整订单任务 | 逻辑记录 | API尝试上限 |
|---|---:|---:|---:|---|
| `fixed` | 144 | 0 | 576条固定记录 | 576 |
| `orders` | 0 | 72 | 1152个episode | 18720 |
| `full` | 144 | 72 | 576条固定记录＋1152个episode | 19296 |

上述数值来自当前冻结开发任务；完整矩阵的19296次是包含最多一次修复的保守请求上限，不是预计实际调用量。先完成冒烟再决定是否执行完整矩阵。下面命令取计划中的全部尝试上限作为预算；也可显式采用更小预算，此时缺项如实标记PARTIAL。金额未知保留null，不将token数量换算为未经核验的费用。

```bash
python -m semantic_pallet_planner.runners.o4_remote prepare \
  --profile full \
  --output semantic_pallet_planner/outputs/PLAN_O4_D_FULL_20261023_01

O4_FULL_BUDGET=$(python -c 'import json; print(json.load(open("semantic_pallet_planner/outputs/PLAN_O4_D_FULL_20261023_01/plan.json"))["maximum_api_attempts"])')

python -m semantic_pallet_planner.runners.o4_remote run \
  --plan semantic_pallet_planner/outputs/PLAN_O4_D_FULL_20261023_01 \
  --output semantic_pallet_planner/outputs/EXP_O4_D_FULL_REAL_20261023_01 \
  --api-budget "$O4_FULL_BUDGET" --remote

python -m semantic_pallet_planner.runners.o4_remote replay \
  --output semantic_pallet_planner/outputs/EXP_O4_D_FULL_REAL_20261023_01
```

`fixed`及`orders`同样使用prepare/run/replay，只替换profile和目录名。不同profile重跑是独立API调用，不复用冒烟响应。所有12个来源均属于已见开发数据；正式未见测试的来源、重复次数和统计判据仍须另行冻结。

## 6. 产物与状态解释

| 路径 | 用途 |
|---|---|
| `frozen_plan/` | 调用前冻结的计划、模型参数、私有输入和完整源码快照 |
| `run.json` | 本次预算、真实/替身标志及运行状态 |
| `prompts/` | 单箱/缓冲实际系统提示；文本和图像共用对应提示 |
| `responses/D*.json` | 每次编译的公共来源、附件绑定、首答/修复及失败 |
| `public/assets.json`、`public/assets/` | 实际PNG和摘要；不显示参考答案或候选许可 |
| `audit/attempts.json` | 写前记账；每次HTTP尝试、usage、耗时、错误和响应 |
| `episodes/J*.jsonl` | 每次WAIT、PLACE、终止、候选、搜索trace及独立参考结果 |
| `jobs/J*.json` | 每个计划任务的结果，包含失败和终止 |
| `metrics/summary.json` | AST、完整语义、适用对象、条件例外、允许集合、整单及API指标 |
| `metrics/per_source.json`、`per_episode.csv` | 来源聚合与逐订单结果，六配置不算独立来源 |
| `audit/events.json` | 独立守恒、实际物理、参考业务及搜索预算审计 |
| `acceptance_report.json` | 当前profile的验收结果及D1—D6对应项 |
| `delivery_manifest.json` | 文件集合和SHA256；回放还重算请求、动作与指标 |

`PASS`仅表示**该profile的工程测量完整且可回放**，不保证语义全对、订单全完成或模型优于规则。`compile-smoke`通过不等于完整D通过；`full_o4_status`仍为`INCOMPLETE`，未见泛化仍为`NOT_MEASURED`。

运行器在自动回放前先落盘阶段结果，此时可能已有`status=PASS`但`D4=REPLAY_REQUIRED`。只有命令正常结束、`D4=true`且只读回放通过，才是最终验收；回放期间中断的目录仍须复核，不能只看PASS字符串。

服务/预算失败造成缺项时为`PARTIAL`，退出码2；协议/文件/代码校验异常退出码1。合法但错误AST导致业务违规时保留原动作和参考判错，独立物理检查始终执行。

当前版本不提供付费请求断点续跑。进程被终止时，已发起尝试保留`in_flight`或已落盘结果，`run.json`可能仍为`RUNNING`；该目录不能当作完整通过。请保留原件并使用新计划/新运行目录，不用旧回复冒充新调用。

回放不联网、不读取密钥、不改原目录。若源码后续变化，使用该运行 `frozen_plan/code_snapshot/semantic_pallet_planner/src`作为PYTHONPATH，并设置`PYTHONDONTWRITEBYTECODE=1`，避免解释器向冻结快照写入缓存；不要改旧清单迎合新代码。回放本身不算独立随机重复实验。
