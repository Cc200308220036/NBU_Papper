## 3. Profile填写规则

模板为 `semantic_pallet_planner/configs/o5_s2_provider.template.json`。字段为闭合结构，未知字段拒绝。密钥只在运行时从 `credential_env` 引用的环境变量读取，模板中不能放密钥。

必须核实provider/HTTPS endpoint、精确请求模型名与预期返回model、快照能力说明、非敏感账户标识、seed支持、timeout、图片detail及输出参数。模型能力未核实时不将 `transport_verified` 当作真实验证证据，实际预检原件才是依据。

输入预算采用文本UTF-8字节保守上界＋provider有依据的固定framing上界＋两图各自上界，包含系统提示与修复错误码，合计不超过12000。每图上界必须覆盖实际发送尺寸/detail；不能从合成夹具的256 token示例推断真实服务图像费用。发送图片不做隐式缩放。输出上限256。provider不满足该估计契约时需另立有证据的适配版本，不能把不足的估计写成已验证。

新版profile显式选择 `amount_policy=unlimited`（默认）或 `capped`。unlimited不要求价格/币种/金额：可以省略pricing或将字段留null；已知完整价格时照常估算，未知费用记null/UNKNOWN。若选择capped，则仍要求非负十进制单价、币种、来源日期和 `input_includes_images_all_fees_bounded` 覆盖口径；缺项时COST_NOT_FROZEN，不能发送。

capped下预检、pilot及二者合计分别有金额上限、币种相同；unlimited不检查金额上限。两种模式请求上限仍分别≤8和290。unknown_attempts和known_subtotal分别报告未知请求与已知费用部分，有未知项的总额为null，不以0代替。

## 4. 账本和恢复

全局campaign保存profile/身份、全部预检和pilot作业、逐attempt的发送体、图片摘要、token上界、预留费用、原始响应、usage、provider请求ID及状态。作业本地ledger是指向campaign身份的闭合引用，不另建一份可重置额度。

先排他锁、校验请求数、落盘attempt，再写sent并发送；capped额外校验金额并落盘费用预留，unlimited未定价时预留为null。原始响应先持久化，再结算和解析。重复恢复复用同一attempt原件，既不重发也不重复提交。

- reserved确定未发：同一attempt可继续，不重复预留。
- sent无持久化结果：UNKNOWN_IN_FLIGHT，整个campaign停止，已知预留保留、未知费用仍为null，不重发。
- receipt已落盘但账本未结算：校验并从原件结算，不重发。
- 普通明确服务错误：终止本单，不使用格式修复或G0兜底。
- 首次429、认证/模型/重定向错误、返回model漂移、实际usage超上界、连续两次5xx：停止批次。
- 格式/绑定错误：最多一次修复，只附错误码；候选/图片/请求目标不变。
- 缺账本、改body/响应/图片/映射/源码：拒绝恢复，不重建空账本。

只读verify不构造远程client，既重建完整订单，也验证中断任务已提交prefix和待执行请求。report调用verify后输出CSV/HTML及摘要；本轮报告为工程示例，不输出模型收益结论。完整三维回放及D0封存门槛属于后续S2-C交付，不凭当前文本报告宣称已完成。

## 5. 后续由用户运行的真实API步骤

以下命令实际入口已经存在，但当前缺真实provider配置、图文token依据和具体计划授权，**不能照抄空模板执行**。应先核实服务文档和配置，冻结具体计划，再由用户在环境执行；unlimited无需先补价格和金额。仅 `preflight` 和 `run-pilot` 可联网；其余准备和复核命令零网络。

1. 填写新profile，使用 `prepare-preflight --dataset <DATA03> --provider-config <实际profile> --output <新PLAN>`。此时仍保留DRAFT标签，由预检命令进一步检查成本和授权；无须伪造预检已通过。
2. 准备与该plan摘要严格匹配的授权JSON，字段如下。`instruction_reference`必须关联用户实际运行指令；生成模板不会自动产生授权。unlimited使用v2授权并明确amount_policy，可省略金额/币种字段；capped金额与profile须完全一致。campaign是预检/pilot共用的新O5输出目录。

```json
{
  "schema_version": "o5_s2_operator_authorization_v2",
  "amount_policy": "unlimited",
  "plan_digest": "实际plan.json的canonical摘要",
  "campaign_path": "/home/cyw/NBU_Papper/semantic_pallet_planner/outputs/CAMPAIGN_O5_DIRECT_MEMORY_MY_RUN",
  "profile_digest": "实际profile的canonical摘要",
  "account_id": "非敏感账户标识",
  "stage": "preflight",
  "instruction_reference": "用户对该具体计划的运行指令出处"
}
```

摘要可用仓库函数计算：`python3 -B -c 'from semantic_pallet_planner.o5.common import read,digest; print(digest(read("实际plan路径/plan.json")))'`；profile摘要取plan中的profile对象，不是含空白格式的文件字节SHA。

```bash
# 用户运行：会调用API。凭据按实际profile的环境变量名配置，不写入文件或命令历史。
python3 -B -m semantic_pallet_planner.runners.o5_s2_pilot preflight \
  --plan <实际预检PLAN> --authorization <预检授权JSON> --output <新预检EXP>

# 零网络：预检通过后，绑定真实预检原件和同一campaign，生成待具体授权的pilot计划。
python3 -B -m semantic_pallet_planner.runners.o5_s2_pilot prepare-pilot \
  --preflight <已通过预检EXP> --output <新pilotPLAN>

# 用户运行：pilot授权stage改为pilot、绑定新plan摘要，campaign不变；仅capped需要pilot金额字段。
python3 -B -m semantic_pallet_planner.runners.o5_s2_pilot run-pilot \
  --plan <实际pilotPLAN> --authorization <pilot授权JSON> --output <新pilotEXP>
# 正常中断后可加--resume；UNKNOWN不得用重发解除，必须保留现场。

# 零网络：把完整运行目录提供给代理做独立复核，不只给一张“成功”截图。
python3 -B -m semantic_pallet_planner.runners.o5_s2_pilot verify --experiment <pilotEXP>
python3 -B -m semantic_pallet_planner.runners.o5_s2_pilot report \
  --experiment <pilotEXP> --output <新O5报告目录>
```

预检固定两组双色形状探针，分别经过两图路径，再验证一个固定开发公共状态的选择契约；每视觉探针1次、契约最多2次，当前任务矩阵最多4次，不擅自用满8次。错误探针不跳过、不反复换题直到成功。预检不是完整pilot，不合并成新的独立样本。

当前没有真实预检通过记录，因此不能生成已通过真实预检的pilot计划；不能用fixture/单元测试产物替代它。后续完整S2-C还需真实协议整数、trace、物理、费用与难度判定，达到条件后才封存D0；不自动进入S3。
