# O3 阶段任务实现文档：在线属性感知码垛

> 编写日期：2026-10-15。本文是**待实施方案**，不是 O3 已完成的验收报告。O3a 先完成可回放的在线框架，O3b 再运行独立来源的 validation 对照；正式新 test 须在协议冻结后另行运行。本文不设置人工复核或人工签认要求，所有验收项由自动检查及原始产物证明。

## 1. 本阶段要解决的问题

O2b 已让六种方法在同一批**固定的一步候选题**上做选择，但固定题不会反映“前一步放错，后面空间被占用”的后果。O3 将同一语义决策链路接到逐箱到货的完整订单：每种方法从相同初始订单出发，每步只见当前箱，依据**自己实际提交后的托盘状态**重新生成候选，直到全部放完或明确终止。

本阶段的核心问题是：文本政策经公开 Parser 或 Flash 解析为受限 AST，再交给确定性 Executor 选址，并由业务屏障保护后，是否能在完整订单中维持物理合法、改善属性布局和完成率？结果还要与几何、固定属性和强公开 Parser 对照。若强 Parser 仍持平，应如实报告；**Flash 获胜不是工程验收条件**。

已具备的基础：[`PalletEnvironment`](../semantic_pallet_planner/src/semantic_pallet_planner/environment.py)和[`EpisodeRunner`](../semantic_pallet_planner/src/semantic_pallet_planner/runners/core.py)支持旧版逐箱在线执行；[`policy_executor_v2.py`](../semantic_pallet_planner/src/semantic_pallet_planner/selectors/policy_executor_v2.py)、[`attribute_metrics_v2.py`](../semantic_pallet_planner/src/semantic_pallet_planner/evaluation/attribute_metrics_v2.py)及[`attribute_o2b.py`](../semantic_pallet_planner/src/semantic_pallet_planner/runners/attribute_o2b.py)支持固定题的规则解析、属性评价和屏障。**目前还没有把 O2b 的 `policy_digest`、AST、属性轨迹和屏障完整接入在线提交**；不要把旧在线基线当作 O3 成果。[现有 O3 路线](属性感知O3在线码垛框架与论文创新验证路线.md)与[指标规范](metrics_v2_spec.md)是本方案的依据。

## 2. 范围、版本和输入权限

- 保留 V1、V2、O1b、O2b 的源码快照及全部实验目录。O3 使用新代码版本、新配置和 `EXP_OPT_O3A_ONLINE_PILOT_*`、`EXP_OPT_O3B_ONLINE_VALIDATION_*` 输出目录；禁止 `--resume` 到旧阶段目录。
- 冻结现有**物理候选生成器、Top-K=16、`buffer_size=1`、真值当前状态**。不接入 Gazebo/ROS 2、未来箱体、视觉独有属性、动态记忆或新候选器。O3 不把这些未加入的组件列为完成项。
- 所有非特权方法同一时刻只能读取相同类型的公开信息：当前箱、已放箱、容器、属性、公开自然语言政策、物理候选及可由公开状态计算的关系特征。方法的轨迹分叉后，实际当前状态可以不同；“同权限”不等于强制不同方法每步仍有相同候选。
- 隐藏真值 AST、Oracle 分数、真实候选 ID 映射和未到货箱只由评价端或特权参考臂读取。真值规则在线贪心仅是**候选内、逐步**参考，不是全局 episode 最优。
- O3a/O3b **不记录、不估算、不考核费用**。费用字段省略或为 `null`；保留请求数、模型与 Prompt 版本、错误、修复、token（若服务返回）和必要时延，便于回放协议行为。

## 3. 在线数据流与最重要的接口

```text
来源订单＋公开业务政策 → 重置在线场景
  → 当前箱与当前状态（不含未来箱）
  → 现有生成器产生物理合法 Top-K=16
  → 从公开状态计算候选关系；生成 Cxx 显示编号及绑定摘要
  → Geometry / Fixed / Public Parser / Flash AST / 真值参考提出候选或 abstain
  → 保存原始提议和解析轨迹 → 独立物理检查＋公开政策业务屏障
  → 提交或按明确原因终止 → 重算属性 before/after/delta
  → 下一箱从本方法实际状态重新生成候选 → episode 汇总与独立回放
```

每步最少保存 `episode_id`、`step_index`、`request_id`、`state_hash`、`policy_digest`、`candidate_set_digest`、`mapping_digest`、`proposed_label`、`committed_label`、`screen_intervened`、`termination_reason`、当前箱 ID、公开请求及响应。`policy_digest` 必须包含政策文本及语法/版本；同一物理状态换政策时摘要必须变化，远程缓存键不得只用 `state_hash`。模型仅返回或引用公开 `Cxx`；真实候选 ID 在受控适配层内部还原，不能进公开请求、Prompt 或检索材料。

### 3.1 提交与终止语义

| 情况 | 处理 | 统计 |
|---|---|---|
| 原始提议物理及业务均可行 | 独立物理复核通过后提交 | 记录提议与提交，更新状态及属性量 |
| 提议违反可执行的公开业务硬规则 | 屏障拦截，**不自动改选**；首版终止当前 episode | `screen_abstain`，原始业务错误仍计入，完成率记失败 |
| Top-K 有物理候选但无业务可行候选 | 明确 `no_business_feasible_candidate`，不以几何回退冒充成功 | 记录 Top-K 与全枚举覆盖；后者仅作诊断 |
| 无物理候选 | `no_physical_candidate` | 计划 episode 仍留在分母 |
| 自愿 `abstain`、政策解析失败 | `selector_abstain` / `policy_parse_error` | 不提交；不算完成 |
| 模型/API/绑定/映射错误 | 按冻结的一次修复协议重试；仍失败则 `provider_error` / `invalid_response` | 首答、修复及最终状态分开记；不静默几何回退 |
| 独立物理复核拒绝、内部异常 | 不提交，`physical_rejection` / `internal_error` | 工程检查失败并保留事件，禁止删除失败样本 |
| 全部箱体提交 | `all_items_placed` | 再判断最终业务硬约束和必达目标，确定属性任务成功 |

首版采用“屏障拦截即终止”，以免不同方法获得不等量的重选机会；若以后允许重选，须另立协议并给所有方法相同次数。原有 `PalletEnvironment.step()` 支持无效响应几何回退，**O3 不能直接沿用这一行为作为业务错误处理**：应使用新适配层或 `abort` 路径，保存原始错误与实际提交。对于初始状态已有业务违规的诊断场景，屏障应区分历史违规实例与本步新增实例；主实验优先使用初始业务状态可行的订单，不把旧违规归罪于无关动作。

## 4. 需要新增或扩展的内容

下表是建议的文件/职责，**不是宣称文件已经存在**；可以调整命名，但不得省掉功能或改写旧实验产物。

| 建议模块或位置 | 具体实现 |
|---|---|
| `runners/attribute_o3_online.py` | O3 专用在线调度：每方法独立环境、按订单逐步运行、终止记录、断点续跑、配置与源码摘要。断点续跑前重放已有事件并核验源数据/版本哈希。 |
| `runners/o3_online_adapter.py` | 将旧环境的物理候选与状态转换为 O2b 公开关系请求；候选显示编号、`request_id/state_hash/policy_digest`、映射摘要绑定；仅在提交端还原真实候选 ID。 |
| `selectors/o3_methods.py` | Geometry、固定属性、Public Parser＋Executor、Flash AST＋Executor、真值规则在线贪心五臂；前三臂离线可跑。Flash 臂复用 O2b 受限 AST 协议，真值臂明确标记 `privileged_input=true`。Direct-Text 可作为额外诊断臂，不能代替五臂必需矩阵。 |
| `evaluation/o3_business_screen.py` | 仅使用公开解析的政策 AST 对原始提议作提交前业务复核；输出可审计的违规实例与拦截原因，只能放行或拒放，不能替选择器选新位置。 |
| `evaluation/o3_episode_metrics.py` | 每步重算属性 `before/after/delta` 和新增/全状态违规；整单计算完成率、Episode Attribute Success、件数/体积放置比例及最终属性原始量。N/A 不记成功。 |
| `evaluation/o3_replay.py` | 不调用已存的评价字段作真值，按初始订单和提交动作独立重建状态、载荷、候选/映射/政策绑定与终止原因；逐步比较哈希和指标。 |
| `data` 构建脚本及 Schema | 独立来源订单、政策配对、属性来源、订单分组/划分及可见字段清单；验证所有公开/私有 JSON 的 Schema 和跨引用。 |
| `visualization` 扩展 | 从真实每步状态渲染至少三组同初始订单的对照动画，含成功与失败轨迹；每帧关联 `episode_id/step_index`。 |

优先复用 O1b/O2b 的解析器、受限 AST Schema、公开关系数学原语和响应协议。**评价器**使用隐藏真值政策，**执行器与屏障**只使用公开解析政策；共享几何/载荷计算函数可以，传递隐藏 AST 不可以。条件规则必须按当前箱属性选择分支，并记录所走分支及解析错误。冻结的规则范围延续 O1b/O2b：易碎箱业务限载、重箱低位/靠中心、品类禁止面接触和两级软优先级；物理承重上限与业务限载分开。

## 5. O3a：先把在线框架做对

### 开发顺序

1. **定义在线协议及任务清单**：确定输入 Schema、请求/响应绑定字段、终止码、屏障处理、指标分母和文件结构；固定候选生成器配置。创建 O3 专用新目录，不以 O1b 的固定题状态充当完整在线 episode。
2. **接通离线五臂中的四臂**：Geometry、固定属性、Public Parser、真值参考实际运行；Flash AST 臂先用本地模拟响应验证接口和错误分支，不对模拟结果报告模型性能。每臂同订单同到货顺序，但拥有独立状态及候选缓存。
3. **接入真实 Flash AST 调用**：只有离线端到端回放、泄漏扫描、非法响应注入和断点续跑检查通过后才在少量开发订单上运行；API key 只从运行环境读取。O3a 的框架验收可在无密钥时标记“离线部分 PASS、远程臂待运行”，不能写成完整五臂实测通过。
4. **生成审计和回放报告**：保存每步请求、AST、原始提议、屏障、实际动作、状态/属性变化、异常与终止；独立重算并对比。旧阶段文件哈希保持不变。

### O3a 自动验收

- [ ] 五臂接口均实现；至少四个离线臂完成冻结开发订单矩阵，Flash 臂完成模拟协议测试和少量真实调用的独立验收记录。若远程环境不可用，只标记该项待完成，其余离线工作继续。
- [ ] 同初始订单、同到货顺序、`buffer_size=1`、Top-K=16；同政策比较时公开输入权限一致。每步候选 `state_hash` 与该臂实际前状态一致，政策切换使 `policy_digest`/缓存键改变，未来箱不进入公开请求。
- [ ] 计划中的每个 episode 都生成 `episode.json`、完整步骤事件和唯一终止码；失败、拒放、异常不从分母删除。所有实际提交动作独立物理违规为 **0**；回放的状态、载荷、政策绑定与指标逐步一致。
- [ ] 屏障只能拦截，不能替换候选；测试包含违法提议、无业务可行候选、无物理候选、非法 `Cxx`、过期状态、错误政策摘要、API 失败、原有违规、间接载荷和条件分支。
- [ ] 原始提议、实际提交、屏障原因、可行候选覆盖、属性 `before/after/delta` 均有逐步字段；Schema、公开输入泄漏、来源划分和断点续跑检查通过。
- [ ] `acceptance_report.json` 区分 `PASS`、`PARTIAL`、`FAIL` 和待运行项；研究假设另记为 `not_tested` / `inconclusive` / `supported` / `not_supported`，不得因工程通过自动写成模型优势。

## 6. O3b：完整在线 validation 对照

**数据**：使用与 O1b 开发订单隔离的独立来源订单，提供有标记来源的物料属性和公开政策。每个来源订单可派生多条政策，但所有政策/同义变体留在同一划分和同一统计簇。先做候选覆盖及难度审计；“无业务解”诊断题保留并单列，不因某方法失败而删题。旧实验已查看的 test 只作回归，不能作为新 test 或调参材料。

**运行**：对同一初始订单运行至少 Geometry、固定属性、Public Parser＋Executor、Flash AST＋Executor、真值规则在线贪心。远程调用采用真实独立请求；原始响应和修复请求都保存，失败也计入计划任务。不同方法可沿不同状态轨迹前进，不能在第 2 步以后强制复用另一方法的固定候选。若要在同订单比较政策切换，需冻结每条政策的公开文本、作用时点和 `policy_digest`；不能用“未来政策”提示当前步骤。

**主指标与分母**：

| 指标 | 判定及分母 |
|---|---|
| `episode_attribute_success` | 所有计划箱体放完、已提交物理违规 0、最终适用业务硬约束及预先声明的必达目标均满足；分母是全部计划 episode，提前终止记失败。 |
| `episode_completion_rate` | 全部箱体实际提交的 episode 比例；单独于属性成功，避免“拒放很安全”造成虚高。 |
| `placed_item_ratio` / `placed_volume_ratio` | 实际放下件数/体积占订单总数/总体积；所有失败订单也计算。 |
| `final_attribute_metrics` | 易碎箱承载及业务超载数、禁止接触对、重箱质量加权高度与中心距离；无适用目标时记 N/A。 |
| `raw_avoidable_hard_wrong`、`screen_intervention_rate` | 在当前 Top-K 有硬可行候选时原始提议仍硬违规的比例；屏障拦截率另列。不能把屏障保护算成模型选对。 |
| `topk_business_coverage` | 每步 Top-K 中有无业务可行候选，并区别完整枚举也无解与 Top-K 截断丢解；这是候选器诊断。 |
| `physical_violations`、协议合法率、失败/修复、回放 | 逐步提交物理安全与远程协议质量；未提交、非法响应和 API 错误保留在计划分母中。 |

整单属性成功率为预先指定的主终点；报告各方法**配对差值**及按独立来源订单聚类的 95% 区间、订单组数、政策配对组数、N/A 数和各类终止原因。不要把步骤数、同一订单的政策变体或同一模型多次调用当作独立订单。至少保存三组同初始订单的左右对照动画，覆盖成功、业务失败或拒放；动画仅辅助解释，结论依据日志与独立回放。

### O3b 自动验收

- [ ] validation 来源及划分审计无跨组重合；正式对照前冻结政策文本、主指标、分母、场景筛选、方法版本、Prompt、种子、重复次数及修复/缓存策略。
- [ ] 五臂全部完成计划在线矩阵；每个调用和 episode 都有原始记录与明确结果，远程失败不被静默删除；已提交物理违规为 **0**，独立回放全部通过。
- [ ] 同一初始订单下各臂的轨迹可独立重建；报告 Episode Attribute Success、完成率、放置比例、最终属性量、屏障干预、候选覆盖、协议错误和按订单聚类的配对区间。
- [ ] 至少三组成功与失败的对照动画关联逐步事件；输出异常案例分类：解析、候选覆盖、屏障、数值关系、长期布局和协议。
- [ ] 报告分别写明“工程检查状态”和“研究假设状态”。Public Parser 达到或超过 Flash 时照实记录，不能以更换分母或筛掉失败订单制造优势。

建议自动检查分四层运行：①单元测试验证接触/间接载荷、业务限载与物理限载、优先级及条件分支；②集成测试验证逐箱状态分叉、终止、屏障和断点续跑；③Schema/泄漏扫描验证公开请求及 Prompt（包括修复请求）没有隐藏规则、Oracle、真实候选映射或未来箱；④独立回放重新生成候选与状态，核对每步哈希、放置、载荷、指标和最终结果。实际实施时在验收报告保存**真实执行的命令、退出码、通过/失败数量、代码提交或源码哈希**；本文件中的路径与检查项是交付规范，不冒充已经跑过的测试结果。

## 8. O3 完成后如何决定下一步

O3a 通过表示在线数据链路可靠；O3b 通过表示完整 validation 矩阵和证据完整。**研究上是否支持 Flash 的增量价值，要看与同权限 Public Parser 的配对差异**，且 O2b 的受限语法中 Public Parser 已达到候选内上界，不能预设 Flash 优势。若需要检验未见语言/政策组合，应在 O3b 稳定后另立冻结的语言泛化轨道；依据独立 validation 的方差和失败率确定新 test 的来源订单组数、重复次数及阈值，冻结后才运行正式 test。

O3 每步保留政策、候选关系、原始提议、屏障结果与可观察反馈，为后续 **O5/ReMe 式经验沉淀**准备因果日志；本阶段不启用记忆。这样 O5 可与 O3 的无记忆在线基线比较，检验经验新增、检索、修订与政策变化后的失效，而不会混淆在线框架和记忆的贡献。
