# 属性感知码垛实验优化阶段方案

> 日期：2026-09-27。适用对象：NBU_Papper 当前阶段1C之后的实验优化。本文是新增实验与实现计划，不代表这些功能已经完成。
> 目标：验证加入VLM后，系统是否能理解变化的业务要求，并改善不同属性物料的放置关系和最终布局。
> 文中数据规模、性能目标和阈值均为本项目建议，不是引用论文给出的标准；须在train/validation上确定并冻结后再评测新的test。

## 1. 当前结论与需要调整的问题

当前已完成阶段0数据接口、阶段1A统一平台、阶段1B几何规划，以及阶段1C正式固定候选实验的自动验收。`EXP_1C_DEEPSEEK_FLASH_FINAL_V1`包含360题、六方法、2160条决策；Text/Visual平均效用分别为0.695990/0.698657，Geometry-Greedy为0.637921。已有产物保留为V1基线，新实验采用新数据版本、新Prompt版本、新实验目录。

当前`selectors/baselines.py`中的Handcrafted Rule直接获得隐藏`rules`，对候选状态调用`evaluation/semantic.py`，按违规记录数量、平均语义分、几何分和ID排序。Candidate Oracle读取离线最佳候选ID。当前五类单规则任务中，两者排序结果重合，因此都命中360/360并不意味着规则程序从自然语言中理解了任务。

但也不能据此假定VLM一定具有实用优势：若全部要求都已结构化、稳定且可编程，确定性规则执行通常是合理选择。论文需要验证的是语言理解、属性关系、未见组合与政策变化带来的收益，并与拥有相同公开输入的强规则系统比较。

现有指标的不足：

1. 唯一Oracle ID命中率惩罚语义等价候选，不能直接解释业务正确。
2. `soft_utility`是整个放置后状态的评分，掩盖当前动作对已有易碎箱的影响。
3. 业务违规记录列表长度与真实接触对数量不同；多个接触可能只形成一条`electronics_heavy_contact:N`记录。
4. 固定题来自参考轨迹，VLM不能展示自己早期选择对后续布局的影响。
5. JSON已经给出大量空间与属性信息，渲染图可能只是冗余信息，不能仅凭“有图片”声称视觉贡献。

## 2. 研究问题与证据要求

| 研究问题 | 必须控制的条件 | 需要的证据 |
|---|---|---|
| H1：语义输入改善属性放置 | 同状态、同物理Top-K、同物料属性 | 相对Geometry/固定属性启发式的业务满足率、属性质量增益 |
| H2：VLM理解指令组合与优先级 | 与公开指令解析基线获得相同信息 | 未见组合/例外/优先级切换上的配对差异 |
| H3：改善能累积到完整任务 | 同初始场景和到货顺序，后续允许轨迹分叉 | episode完成率、最终属性布局质量和代价 |
| H4：图像提供必要信息 | 明确哪些信息只来自图像，提供完整真值上界 | 感知准确率、下游属性改善、图像缺失消融 |
| H5：经验支持长期适应 | 相同反馈、记忆预算、因果时序 | 学习曲线、政策切换恢复时间、负迁移与消融 |

工程验收通过表示实现与证据合格；研究假设可能支持、不支持或证据不足。不能将“VLM必须优于所有方法”设为工程退出条件，也不能通过删除困难案例或削弱规则对照制造优势。

## 3. 评价体系：先判断满足要求，再评价适配质量

### 3.1 三层要求

| 层级 | 举例 | 处理方式 |
|---|---|---|
| 物理不可违反 | 边界、碰撞、支撑、承重、不可堆叠、载荷 | 所有方法共享确定性过滤与提交复核 |
| 业务硬约束 | 指定易碎箱新增承载≤1 kg；A类与B类禁止直接接触 | 根据公开指令决定，单独统计满足率；可配套显式屏障实验 |
| 业务软偏好 | 重物尽量低且靠中心、同类尽量集中 | 报告连续量、按指令优先级比较 |

真实必须执行的业务硬约束不应完全依赖模型。首轮可保留“选择后评价”的诊断实验；后续增加“指令解析→确定性业务屏障”模式，分别报告模型提议违规率、屏障干预率与实际提交违规率。两种模式不能混作同一个结果。

### 3.2 主指标一：属性业务约束满足率（APSR）

对每个决策预先确定适用规则集合，当前箱体或被本次动作影响的已有箱体都计入。使用冻结业务阈值判断硬约束和可明确阈值化的软目标是否满足。

```text
decision_attribute_success = 1[全部适用且已定义判定阈值的属性要求满足]
APSR = sum(decision_attribute_success) / N_applicable_decisions
```

仅有“尽量”表达且没有业务阈值的任务，不强行赋予二元正确标签，进入连续质量指标。分母必须报告；无目标物料或规则不适用的任务为N/A，不记成成功。

同时输出：

- `business_hard_satisfaction_rate`：至少存在一条适用业务硬约束的题中，全部硬约束满足的比例。
- `attribute_goal_satisfaction_rate`：有明确定义业务阈值的属性目标满足比例。
- `new_business_violation_count`：本步新增违反的规则实例/关系对数。
- `post_state_business_violation_count`：放置后全状态违规数量，包含已有违规。
- `all_attempt_success_rate`：以所有计划决策尝试为分母，包含解析失败、abort与无候选，不用过滤后的成功响应替代系统成功率。

APSR使用全状态还是本步增量必须写入指标版本；首版定义为相关对象的放置后满足率，另外报告新增违规。禁止旧违规使后续无关动作被误判为“新造成违规”。

### 3.3 主指标二：最终属性安全任务成功率（Episode Attribute Success）

```text
episode_attribute_success =
  1[所有要求物料放置完成
    且实际提交物理违规为0
    且最终所有适用业务硬约束满足
    且预先声明的必达属性目标满足]
```

分母为全部计划episode；提前终止算任务失败。连续偏好另行报告，不擅自加入“必达”条件。成功任务上的属性质量只能作补充，必须同时公布全任务完成率、放置数量/体积比例，避免少放箱体获得虚高保护分。

### 3.4 属性原始量：直接解释箱体是否放得合适

设箱体质量为m，底面高度为z，XY中心为(x,y)，已承载质量为L，物理承载上限为C。集合H/F/E分别表示重物、易碎物、目标类别。

| 字段建议 | 定义 | 优化方向与适用条件 |
|---|---|---|
| `fragile_added_load_kg` | 本步已有易碎箱承载增量之和 | 越低越好；每箱分项同时保留 |
| `fragile_load_ratio_max` | max(L/C)，遍历已放易碎箱 | 越低越好；C必须>0，业务上限另字段 |
| `fragile_business_overload_count` | 易碎箱L超过指令业务上限的箱数 | 0为满足；不能与物理超载混用 |
| `heavy_mass_weighted_z_mm` | Σ(mz)/Σm，遍历H | 越低通常越好 |
| `heavy_center_distance_mm` | Σ[m√(x²+y²)]/Σm，遍历H | 越低通常越好；非总体质心 |
| `forbidden_contact_pair_count` | 冻结规则定义的禁止接触无序箱体对数 | 越低越好；同一对不重复计数 |
| `same_category_pair_distance_mm` | 目标类别箱体中心的平均两两3D距离 | 越低越集中；不足两个为N/A |
| `zone_assignment_success_rate` | 适用箱体完整足迹位于公开指定区域的比例 | 越高越好；跨界判失败 |
| `minimum_support_ratio` | 非地面箱体最小底面支撑比例 | 物理门槛，当前≥0.70 |
| `placed_item_ratio` / `placed_volume_ratio` | 已放数量/体积占订单总量 | 防止通过拒放降低属性风险 |

“易碎箱放高”只在指令明确要求时作软目标，不能替代“少承载”的直接指标。合成承载值也不能被称为实测损伤概率或真实抗压能力。

每个属性原始量同时记录`before`、`after`和`delta`。对目标集合改变的动作，增量的含义要注明，例如加入重箱后的平均高度变化不能解释成已有箱体被移动。

### 3.5 主指标三：条件语义质量与优先级正确性

每个软目标q_r归一化到[0,1]，归一化尺度使用容器尺寸或冻结业务尺度，不用test最大最小值。只在适用目标之间宏平均，N/A不记为1。

规则排序采用：物理合法→业务硬可行→第一优先级软目标→第二优先级软目标→几何同分处理。每级可有明确的容差或同级权重；权重与容差必须预先公开定义或由明确的业务配置确定，不能对相同指令暗设不同权重。

```text
rank(candidate) = (hard_violation_vector,
                   -q_priority_1, -q_priority_2, ...,
                   -geometry_score)
```

不同硬约束发生冲突时，不能用简单违规总数随意交换：必须由指令指定不可放宽项和可放宽顺序，否则标为无法满足/需要澄清。默认业务约束等重要时，先定义明确的可行集合，再比较软目标。

`priority_optimal_rate`表示命中词典序最优等价集合的比例；各优先级regret分别报告。用于业务质量的汇总分不得用高软分掩盖硬违规。

### 3.6 Oracle、等价率与候选覆盖诊断

保留`oracle_hit`作为旧版诊断，新版使用最佳等价集合。完整候选集为C_phys，业务可行集合为C_B。

- `business_feasible_candidate_coverage`：存在至少一个业务可行候选的题数/全部适用题数。
- `conditional_hard_satisfaction_rate`：存在业务可行候选的题中，系统最终选择业务可行候选的比例。
- `oracle_equivalent_rate`：在存在业务可行候选且软目标适用的题中，命中最优语义等价集合的比例。
- `unavoidable_candidate_violation_rate`：当前Top-K没有业务可行候选的题比例。不能由此宣称整个连续空间无解。

单软目标时，等价集合是C_B中q达到最佳值减ε的候选；多优先级时逐级限制等价集合。严格版本仅用浮点容差，如1e-6；近似版本ε=0.01可作为待验证的辅助设置，并报告0/0.01/0.05敏感性。ε不是行业“正确”标准。

若C_B为空：业务成功记0，条件选择指标N/A，另报告最小违规诊断。Oracle是候选集内参考，不能代表全局最优；在线贪心真值规则选择器也不是最优episode上界。

### 3.7 指令适应、稳定性与代价

- `policy_pair_success_rate`：相同物理场景两条要求均选到各自正确等价集合的配对组比例。
- `language_consistency_rate`：同义改写下业务满足判定与语义等价质量的一致率，不要求候选ID相同。
- `mapping_consistency_rate`：同题候选重编号后恢复真实动作的等价一致率。
- `priority_switch_regret`：优先级改变后相对新规则最优集合的分项损失。
- 物理提交违规、模型提议业务违规、业务屏障干预、最终业务违规分别统计。
- API合法率、fallback、abort、token、时延p50/p95、实际费用和缓存命中保留。未知费用为null，不能聚合成免费。

## 4. 规则设计：公开自然语言，隐藏形式化评价

### 4.1 规则原语与边界

| 原语 | 推荐首版含义 | 示例指令 |
|---|---|---|
| 负载保护 | 指定属性箱体累计承载不超过明确业务值 | 易碎箱最多承载1 kg |
| 低位 | 重箱底面高度最小化，或明确不超过阈值 | 重箱底面不高于200 mm |
| 中心 | 重箱中心到托盘中心距离最小化 | 在满足保护约束后，重箱尽量靠中心 |
| 接触隔离 | 指定两类不得面接触；支撑属于Z面接触 | 电子产品不得直接接触重箱 |
| 空隙隔离 | 最小表面距离≥公开阈值，单独于接触规则 | 电子产品与指定物料留出50 mm间隙 |
| 同类集中 | 指定类别平均两两距离最小化 | 满足隔离后，同类尽量集中 |
| 区域放置 | 箱体完整XY足迹落在公开区域内 | A类放在托盘左半区域 |
| 条件例外 | 可执行属性谓词决定适用目标 | 同类集中，但易碎箱不作为支撑 |

电子产品与重物接触禁止是本项目任务规则，不是普遍工业规范。区域、阈值、优先级和对象必须在指令或公开业务附件中可得；不能只存在隐藏标注中。气味、污染、危险品兼容性等暂不扩展，除非有真实属性来源和适用依据。

### 4.2 四种任务层级

1. 单规则校准：保留五类旧任务，验证新评价器未改变V1定义。
2. 无冲突组合：保护易碎箱，同时重物靠中心；联合可行且有候选差异。
3. 优先级冲突：低位/集中等软偏好之间存在冲突，但硬约束保持可行。
4. 条件、例外与政策切换：相同物料和状态，改变规则作用对象或软优先级。

自然语言歧义与明确无解任务设为独立诊断轨道，不混入“应当正确选择”的主测试。若要评价澄清/拒绝能力，需要新增返回协议和完整终止定义。

### 4.3 新版规则示例（设计草案）

公开要求：“易碎箱累计承载不得超过1 kg；满足此要求后，重物尽量放低；低位效果相同时优先靠近中心。”隐藏评价记录如下：

```json
{
  "schema_version": "pallet_policy_eval_v2",
  "policy_version": "protect_then_low_v1",
  "hard_constraints": [
    {
      "predicate": "fragile == true",
      "metric": "supported_load_kg",
      "operator": "<=",
      "threshold": 1.0
    }
  ],
  "soft_priorities": [
    {"priority": 1, "metric": "heavy_mass_weighted_z_mm", "direction": "min"},
    {"priority": 2, "metric": "heavy_center_distance_mm", "direction": "min"}
  ]
}
```

这是待实现Schema，不是当前工程已经支持的接口。物理承载上限C与业务上限1 kg分开存储：物理允许承载5 kg，不代表业务要求也允许。

同义文本必须由同一规则记录派生并经人工核对。未见规则主要指未见组合/条件表达；如果底层原语仍已知，不应宣传“理解任意全新规则”。完全新原语需新增评价器、清楚定义公开语义，并单列为探索实验。

## 5. 场景如何搭建

### 5.1 三类数据共同组成测试

**可解释微场景**：3～6个箱体，精确构造负载、接触和距离差异。用于独立检查器和规则评价器单元验收。

**订单派生场景**：保留BED-BPP尺寸、质量、顺序来源，8～20箱、同一容器设置；语义属性来源明确标记为synthetic/manual/measured。旧V1已查看的test只能用于回归，不能视为新方案未见测试。

**完整在线场景**：buffer_size=1、逐箱到达；各方法相同初始状态和到货顺序，每一步根据实际提交状态生成候选。提前无候选属于有效结果，不删除。

### 5.2 六类推荐场景族

| 场景族 | 构造方法 | 必须验证的候选差异 |
|---|---|---|
| F1易碎保护 | 下层有承载余量但业务限载较低的易碎箱，旁边可放当前箱 | 有压住与不压住易碎箱的合法候选 |
| F2重物位置 | 中心低位、边缘低位和高位合法候选共存 | 当前重箱距离/高度与总体质心不完全一致 |
| F3类别关系 | 至少两个同类及一个限制接触的异类 | 同类距离和禁止接触存在不同组合 |
| F4属性冲突 | 同一箱体兼具heavy/fragile等属性 | 主次偏好改变能改变正确等价集合 |
| F5条件分区 | 两区域公开定义，箱体尺寸确保边界可判定 | 至少一个完整落区、一个跨界/错区候选 |
| F6长期布局 | 属性混合订单，多层支撑与空间竞争 | 可形成可解释的不同最终布局，不能向模型泄漏未来箱体 |

不要把“为某个未公开的未来重箱预留位置”作为在线正确答案。若业务公开了后续需求摘要，所有方法获得同一摘要；若有lookahead，则作为独立可见缓冲区设置。

### 5.3 一个首批微场景

托盘1200×1000×850 mm。已有易碎箱A，质量4 kg、尺寸400×300×200 mm、物理承载上限10 kg、业务承载上限1 kg；当前箱B质量6 kg，可合法放在A上或另一地面位置。

- 候选a：B支撑于A，物理承载通过，但给A新增6 kg，业务失败。
- 候选b：B放地面，A新增承载0，业务通过。
- 评价器应输出a物理违规0、业务违规1；b两者都为0。
- 再构造另一候选c，使b/c在高度、中心距离或区域目标上不同，测试优先级。

不能仅凭这个明显例子宣称VLM优势；它首先验证定义正确，并检查固定启发式也能解决。真正比较来自组合、改写和情境切换。

### 5.4 推荐规模与划分

先做12个微场景和30个validation状态的低成本试验，检验数据有区分度、评价器正确、调用预算可承受。

扩展候选方案：150个独立物理场景组，train/validation/test分别60/30/60组；六场景族每划分尽量均衡。每组3个状态，每状态2条业务情境指令，共900道固定题。两条指令中有差异的组用于政策配对；同义改写/映射重排另设冻结子集，不能都当独立物理样本。

- 同来源订单、同物理状态、同义语言变体、政策变体必须在同一划分组。
- 尽量使用未被旧实验消耗的来源订单；另报告article/geometry重合情况。
- 组合泛化：留出完整规则组合；语言泛化：留出模板族；属性泛化：留出预定义属性组合。
- 不要求任意任务都有零违规解。主可满足任务与无解/覆盖不足诊断分层保存，报告生成、拒绝和保留数量。
- 采样与筛选规则在模型运行前冻结，不能按VLM答对/答错筛选。
- 推荐主轨道至少70%的保留题存在两种不同语义结果；这是建议的数据区分度门槛，不是性能要求。其余无差异题作控制集。

### 5.5 候选生成与覆盖审计

主实验继续使用冻结的物理生成器与K=16；同物理状态不同指令共享Candidate Set和映射，隔离指令作用。增加候选关系特征时，所有同权限基线获得相同事实。

审计全枚举候选与Top-K的业务可行覆盖，区分“枚举空间没有满足解”和“Top-K丢失满足解”。若要修改生成器为属性感知Top-K，作为独立版本并做2×2消融：旧/新生成器×规则/VLM选择器，同K、同计算预算；不能把候选改善全部归因于VLM。

## 6. 基线与消融设计

| 方法 | 使用的信息 | 主要回答的问题 |
|---|---|---|
| Geometry-Greedy | 公开几何事实 | 无业务语义时的结果 |
| Fixed-Attribute-Heuristic | 公开物料属性，冻结通用优先级 | 属性本身是否足够 |
| Public-Instruction-Parser + Executor | 相同自然语言、公开业务附件与属性 | 非LLM规则解析是否足够 |
| LLM-Policy-Parser + Executor | 相同公开输入，LLM输出受限规则AST | 语言理解交给LLM、数值推理交给程序是否更可靠 |
| VLM-Direct-Text | 相同公开结构化输入，直接选编号 | 直接候选决策能力 |
| VLM-Direct-Visual | 同上加图像 | 图像增量价值 |
| Ground-Truth-Rule / Candidate Oracle | 隐藏形式化规则/离线最佳候选 | 参考上界，不能视作同权限竞争者 |

Public Parser预先公开支持语法、阈值与优先级解析规则，允许充分开发；不识别表达时按冻结策略失败/回退并计入结果，不故意限制到只认五个关键词。

LLM Parser使用固定白名单AST、数值范围和字段类型校验；禁止执行任意模型生成Python。必须记录原始AST、解析错误、修复和最终执行规则，评测对象/阈值/硬软/优先级各项解析准确率。它不能从隐藏规则拷贝AST。

三组必要消融：

1. 属性消融：去除非物理必需的语义属性，对比同输入协议下的选择质量；物理安全器始终保留完整属性，不能靠增加物理风险证明属性有效。
2. 指令消融：固定同一通用策略或去掉情境指令，检验同状态政策切换是否真的发生。
3. 关系特征消融：原JSON vs 增加当前箱中心距离、受影响箱新增承载、接触对、同类距离。特征从公开状态计算，不包含Oracle分/排序/隐藏规则ID。

物理哈希不能单独绑定业务政策：相同物理状态不同指令可以共享state_hash，但必须有独立request_id与policy_digest。缓存键、响应绑定与回放均校验policy_digest，防止政策切换后重用过期选择。

## 7. 统计设计与研究结果判定

### 7.1 配对与重复

- 固定题每方法面对同题同候选；在线任务从同组场景起始。
- 以来源物理场景组为聚类单位bootstrap，整组重采样所有状态、指令、语言变体、调用重复；不能把900题或重复调用当900个独立场景。
- 远程模型主方法建议每题/episode独立调用3次；开发期用1次。3次是预算建议，不保证统计功效。新重复须独立请求且不能复用同一响应缓存。
- 固定政策配对至少一组共同映射，位置审计子集使用第二映射种子；同义表达和编号稳定性独立报告。
- 多个远程模型方法交错调用，记录时间与供应商版本信息，降低时段差异；保留所有异常与重试成本。
- 正式前用validation估计方差和失败率，进行样本量/最小可检测差异规划；测试完成后不能追加样本直到显著。

### 7.2 主终点与效应量

固定题主终点：适用硬规则的满足率差；纯软任务的首优先级质量差。在线主终点：Episode Attribute Success差。APSR为有冻结阈值的任务主指标，不把阈值未定义任务混入。

报告百分点差、95%配对聚类置信区间、样本组数、N/A数量和分场景族结果；多主比较用预先声明的Holm校正或分层检验，探索分组清楚标识。

建议预注册的实用目标：相对最强同权限非LLM基线，业务成功率提升至少5个百分点，且episode完成率下降不超过3个百分点；也可接受属性质量改善且成本明显更低的混合架构。以上数值是待业务/validation确定的项目目标，不是普适门槛。

若要主张“不降低完成率”，需要差值置信区间下界高于冻结非劣界-3个百分点；点估计接近不能证明非劣。若置信区间跨0，结论为证据不足；若规则系统更好，如实报告适用边界。

### 7.3 调用预算

首批30状态×2指令×3个远程方法×1次=180次基础调用。扩展900题×3远程方法×3次=8100次基础调用，尚未包含修复、视觉与记忆消融、在线episode。冻结配置前先测每类请求token和费用；已有FINAL_V1价格为null，不能拿0元估预算。先完成小规模验证，再依据功效与预算决定正式规模。

### O1：规则评价器与场景V2（对应阶段1C+数据基础）

任务：实现独立属性评价、规则AST Schema、before/after/delta、新场景构建与划分、候选覆盖审计。

验收：

- [ ] 至少12个可手算微场景，覆盖六场景族、等价候选、无目标物料、无业务可行解、接触计数、优先级和已有违规。
- [ ] 评价器不调用生成器私有结果，也不使用模型自述作为真值；独立复算并与手算一致。
- [ ] 支撑与接触计算具有冻结毫米容差；负载传播考虑间接下层，新增/累计负载均正确。
- [ ] 所有规则参数可从公开指令或附件确定，隐藏标注只用于评价/上界。
- [ ] 主可满足题附候选内满足解见证；无解诊断题显式分层，不能静默排除。
- [ ] 同订单和所有配对视图跨划分重合为0；所有JSON通过Schema和交叉引用校验。
- [ ] 开发试验至少30个validation状态、两情境指令，完成区分度和采样审计。
- [ ] 扩展规模由预注册固定；未实现上述基础前不启动全量付费实验。

产物：新数据发布目录、规则说明、生成参数、Schema、单元/集成测试、来源和划分manifest。

### O2：同权限语义决策实验（对应阶段1C+核心对照）

任务：实现公开Parser、LLM Parser+Executor、直接选择器、公开关系特征；运行固定题矩阵。

验收：

- [ ] 至少完成Geometry、固定属性启发式、公开Parser、LLM Parser+Executor、Direct-Text与真值规则上界；Direct-Visual放在视觉子阶段或额外对照。
- [ ] 同题所有主方法物理候选完全一致；公开特征一致；权限差异在日志显式标记。
- [ ] 请求绑定request_id、state_hash、policy_digest，候选映射图文一致；所有非法坐标注入被拒绝。
- [ ] 模型最终合法响应率≥98%，fallback不能计入模型自身合法率；修复最多一次或按新冻结协议明确规定。
- [ ] 原始输入及修复请求均通过禁止键/值、真实候选ID、未来物料检查；图像来源与20组人工抽查留档。
- [ ] 主终点、对照、随机种子、样本量、重复次数、阈值和缓存策略在新test前冻结。
- [ ] 完成全部计划记录；异常、N/A、调用失败不删除；输出分属性与分规则组合配对CI。
- [ ] 未见组合、同义语言、优先级切换分别报告，不合并包装为任意规则泛化。

研究出口：依据最强同权限基线决定主架构。Direct劣于Parser+Executor时允许选择混合架构；工程PASS与研究支持状态分别写入报告。

### O3：完整在线属性布局（对应阶段1D）

任务：接入选定VLM/混合选择器；每步动态生成候选；记录布局与属性轨迹。

验收：

- [ ] buffer_size=1，无未来箱体泄漏；每步候选由本方法实际状态重生成。
- [ ] 至少完成Geometry、固定属性策略、公开Parser、O2选定主方法、在线真值贪心规则参考。
- [ ] validation试验后，新的test场景组按冻结矩阵运行；建议覆盖六族、每族10个独立test组，远程方法3次重复。
- [ ] 计划任务全部有终止记录；no_feasible/abort/provider_error/完成分别区分。
- [ ] 所有已提交动作独立物理违规0，状态/负载/哈希完整回放通过。
- [ ] 主报告全episode属性成功率、完成率、数量/体积放置比例、最终属性原始量与费用；失败任务不从分母移除。
- [ ] 至少三组同初始场景的左右对照动画，展示属性收益和失败，均关联日志。
- [ ] 真值贪心规则仅为参考，不称为全局episode最优。

### O4：视觉信息贡献（可选，与阶段1D后续并行设计）

任务：先用受控包装标签图，再考虑真实RGB-D；明确图像独有属性来源和置信度。

验收：

- [ ] 列出每个属性来源：JSON、图像、业务附件或未知；图像独有属性不能由颜色编码/文件名/隐藏JSON泄漏。
- [ ] 至少30个独立物理组试验，图像/纹理变体留在同组；正式规模另据功效冻结。
- [ ] 比较部分信息Text、相同信息预算Visual、完整真值Text上界，以及图像缺失或遮挡消融。
- [ ] 单列属性识别准确率、未知/遮挡处理与下游成功率；不把识别错误解释成规划错误。
- [ ] 传图内容、时间与缓存哈希可审计；不给模型未来布局或Oracle着色。
- [ ] 若视觉无改善，保留负结果，主系统可继续使用Text/混合模式。

只有存在相关信息缺口，才适合主张图像必要；不要为了证明视觉而在正常有主数据的部署场景里人为删除信息。

### O5：程序性经验与政策变化（对应阶段1E）

任务：接入ReMe-style经验卡；先做冻结检索，再做新增、验证、修订和失效；Stationary/Policy-Shift流隔离。

验收：

- [ ] 至少完成NoMemory、FrozenRetrieval、FullMemory、w/o-Verify、w/o-Refine五方法，底层模型/候选/预算相同。
- [ ] 沿用4条stationary和4条policy-shift、每条10episode、3重复作为工程最小矩阵；统计推断以独立stream为单位，规模不足需增加独立流而非把episode当独立样本。
- [ ] 各方法/种子/stream记忆物理隔离，同一初始快照；决策t只读<t反馈。
- [ ] 主实验反馈是可部署来源，如执行结果、可观察负载/接触检查、操作者确认；若部署需要规则解析，所有方法使用同一冻结反馈模块。
- [ ] Oracle对比经验只允许train离线构建；测试Oracle延迟反馈单列为“特权教师反馈实验”，不能声称无需真值的自主学习。
- [ ] 每条经验有适用条件、禁用条件、policy_scope、来源、验证与修改历史；特定答案ID不进入检索内容。
- [ ] 保存每步/episode读写快照并通过未来反馈注入反例测试。
- [ ] 回放至少一个新增、修订/纠错和失效案例；新经验在独立开发验证集上验证后激活。
- [ ] 报告AULC、政策切换恢复时间、负迁移、属性违规与额外费用；恢复阈值与连续满足窗口在测试前冻结，未恢复记右删失而非0步。

记忆收益归因须控制额外上下文token；增加同长度无关经验对照或预算匹配，不能把更多推理调用的收益全部称为记忆收益。

### O6：真实属性与执行验证（后续机器人阶段）

任务：校准物料主数据、承载与易碎属性，接入真实观测、可达性、抓取与动作执行。

验收：

- [ ] synthetic/manual/measured来源字段完整；承载测量方案、误差和业务保护阈值有记录。
- [ ] Gazebo/仿真中新增抓取与可达性过滤，属性失败、感知失败与执行失败分别记录。
- [ ] 小规模真机试验有冻结任务、统一起始条件和人工可核验结果；先建议每条件至少10次可重复试验，再按功效扩展。
- [ ] 报告规划与执行位姿偏差、任务成功、接触/倾倒/损伤观察、恢复与节拍；零几何违规不等于零真实损伤。
- [ ] 不把合成属性实验的结论直接推广为工业部署效果。

## 10. 真实论文调研与对本项目的启发

调研日期2026-09-27。下列均核查一手论文页面、摘要与元数据；GOPT与Code as Policies另访问公开全文HTML。本文为面向实验设计的定向调研，不是系统综述，也没有复现原论文实验。每条“本项目建议”是由论文思路作出的迁移判断，不是原论文已经证明的码垛语义收益。

### [1] BED-BPP：真实订单基准

Florian Kagerer、Maximilian Beinhofer、Stefan Stricker、Andreas Nüchter，2023，*BED-BPP: Benchmarking dataset for robotic bin packing problems*，IJRR 42(11):1007–1014，DOI 10.1177/02783649231193048。作者页面给出订单、物料尺寸、质量与顺序的数据结构。[作者数据集页面](https://floriankagerer.github.io/dataset/)，[论文DOI](https://doi.org/10.1177/02783649231193048)。

Hang Zhao、Qijin She、Chenyang Zhu、Yin Yang、Kai Xu，*Online 3D Bin Packing with Constrained Deep Reinforcement Learning*，AAAI 2021，arXiv初稿2020。研究在线到货、碰撞与稳定约束，使用可行动作约束帮助学习。[论文](https://arxiv.org/abs/2006.14978)。

### [3] 实际可行策略与支撑关系

Hang Zhao、Chenyang Zhu、Xin Xu、Hui Huang、Kai Xu，*Learning Practically Feasible Policies for Online 3D Bin Packing*，arXiv初稿2021，页面注明Science China Information Sciences。论文介绍stacking tree稳定分析以及面向机器人运动的策略设计。[论文](https://arxiv.org/abs/2108.13680)。

本项目建议：将支撑图、载荷传播与运动可达性分层建模，后期加强稳定性验证；不要把当前中心落入单个支撑矩形的代理判定当作完整真实稳定性。

### [4] GOPT：候选与泛化

Heng Xiong等，2024，*GOPT: Generalizable Online 3D Bin Packing via Transformer-based Deep Reinforcement Learning*，IEEE RA-L，DOI 10.1109/LRA.2024.3468161。将Placement Generator与Packing Transformer结合，研究不同容器尺寸的泛化。[论文](https://arxiv.org/abs/2409.05344)，[全文](https://arxiv.org/html/2409.05344v2)。

本项目建议：单独审计候选预算与几何OOD，控制生成器/选择器贡献。当前EMS-style极值点实现不是完整GOPT，未训练同等模型不能称为复现基线。

### [5] SayCan：语言与可执行性结合

Michael Ahn等，2022，*Do As I Can, Not As I Say: Grounding Language in Robotic Affordances*。用语言任务知识与技能可执行性结合选择行动。[论文](https://arxiv.org/abs/2204.01691)，[作者项目](https://say-can.github.io/)。

本项目建议：保留VLM高层语义与低层可执行约束分工；物理候选合法不等于业务语义满足。该论文不是“VLM比所有规则系统更好”的证据。

### [6] Code as Policies：语言转程序化执行

Jacky Liang、Wenlong Huang、Fei Xia、Peng Xu、Karol Hausman、Brian Ichter、Pete Florence、Andy Zeng，*Code as Policies: Language Model Programs for Embodied Control*，arXiv初稿2022，ICRA 2023。用语言模型组合机器人API与程序逻辑生成策略。[论文](https://arxiv.org/abs/2209.07753)，[全文](https://arxiv.org/html/2209.07753v4)。

本项目建议：增加语言→受限规则AST→确定性执行对照，检验直接VLM手算距离/载荷是否必要。AST白名单是本项目为当前候选接口作出的实现选择，并非照搬原论文任意程序生成。

### [7] Inner Monologue：反馈闭环

Wenlong Huang等，*Inner Monologue: Embodied Reasoning through Planning with Language Models*，arXiv初稿2022，CoRL 2022论文集PMLR 205（2023发布）。研究成功检测、场景描述与交互反馈辅助语言规划。[论文](https://arxiv.org/abs/2207.05608)，[论文集PDF](https://proceedings.mlr.press/v205/huang23c/huang23c.pdf)。

本项目建议：在阶段1D加入当前可观察的状态与失败反馈；反馈来源与时序必须记录，不能把隐藏Oracle答案包装成自然环境反馈。

### [8] CLIPort：语义与空间信息

Mohit Shridhar、Lucas Manuelli、Dieter Fox，*CLIPort: What and Where Pathways for Robotic Manipulation*，arXiv初稿2021，CoRL 2021论文集PMLR 164（2022发布）。结合语义与空间路径，研究语言条件操作及未见语义概念。[论文](https://arxiv.org/abs/2109.12098)，[论文集PDF](https://proceedings.mlr.press/v164/shridhar22a/shridhar22a.pdf)。

本项目建议：区分识别什么属性与放在哪个位置，分别评测。CLIPort采用学习型视觉操作架构，其结果不能直接作为本项目JSON加渲染图的视觉贡献证据。

### [9] ReMe：动态程序性经验

Zouying Cao、Jiaji Deng、Li Yu、Weikang Zhou、Zhaoyang Liu、Bolin Ding、Hai Zhao，2026，*Remember Me, Refine Me: A Dynamic Procedural Memory Framework for Experience-Driven Agent Evolution*，Findings of ACL 2026，16803–16822，DOI 10.18653/v1/2026.findings-acl.829；arXiv初稿2025。提出经验提炼、情境复用与效用驱动修订，评测领域为BFCL-V3/AppWorld。[正式论文页面](https://aclanthology.org/2026.findings-acl.829/)，[预印本](https://arxiv.org/abs/2512.10696)。

本项目建议：O5验证经验生命周期、政策作用域与失效；原论文不证明码垛属性收益，必须补独立任务流和消融。仓库的软件接口随版本变化，接入时冻结具体commit，不能把当前ReMe-main目录直接等同于论文完整实现。

## 11. 实施优先级与最终论文呈现

优先顺序：O0指标与旧结果诊断→O1评价器和小规模V2→O2强基线与组合指令→O3在线闭环→O5记忆。O4只有出现明确视觉信息需求时推进；O6在基础质量明确后进行。不要同时扩大候选器、缓冲区、视觉、记忆和机器人范围，否则贡献难以归因。

推荐首批交付为：12微场景、30validation状态两指令、属性原始量、公开Parser与LLM Parser对照、180次以内基础远程调用试验。此阶段明确哪些错误来自语言理解、数学关系推导、候选缺失或在线长期效果，再决定投入完整规模。

论文结果建议按六张主表/图组织：

1. 数据与信息权限表：属性来源、场景组、任务层级、候选覆盖。
2. 固定题表：同权限方法的业务满足率、分属性原始量、优先级质量、费用。
3. 政策配对图：同状态不同要求的正确等价集合与所选动作。
4. 在线表与动画：完整任务成功、完成率、最终布局及代价。
5. 视觉/关系特征消融：把感知信息、数值辅助与决策贡献分开。
6. 记忆曲线：stationary收益、政策变化恢复、负迁移和token代价。

可以支持的最终表述应与证据对应：“在冻结物理候选空间和相同公开输入下，框架改善了某些属性组合/政策变化任务的满足率与完整布局质量，同时保持物理安全，并报告计算代价。”如果强规则或混合架构更好，论文应说明VLM适用于语言理解与情境适应的部分，不要求其承担所有数值排序。
