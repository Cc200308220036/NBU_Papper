## 1. 总目标与完成形态

阶段1A—1B要将阶段0的“可运行演示脚本”改造为“可替换方法、可批量评测、可重放、可动画展示的真值码垛规划平台”。

完成后应具备：

1. 统一的Repository、Environment、CandidateGenerator、Selector、Runner和Evaluator；
2. 在360个固定Decision Case上做单步配对比；
3. 在100个基础Scenario上从第一箱运行到episode结束；
4. Random、Lowest、Geometry-Greedy、Pareto-Greedy、Handcrafted-Rule和Candidate Oracle选择器；
5. 逐决策、逐episode和聚合指标；
6. 取料区、码垛区、Top-K候选、选中结果和GIF/MP4；
7. 后续只需新增VLM Selector即可进入1C，不重写环境。

```text
semantic_pallet_dataset_v1（只读）
       ↓
DatasetRepository
       ↓
FixedCaseRunner / EpisodeRunner
       ↓
CandidateGenerator → CandidateSet
       ↓
Selector → candidate_id
       ↓
ProtocolValidator → Environment.step
       ↓
Evaluator + Logger + Renderer
       ↓
semantic_pallet_planner/outputs/<experiment_id>/
```

## 3. 实现原则

- **数据集只读**：新日志、图像和结果不得写入`tasks/`、`candidates/`、`annotations/`、`splits/`和`streams/`。
- **生成与复核独立**：`planner/constraints.py`做生成期过滤，`evaluation/geometry_oracle.py`独立重算碰撞、支撑和承重。
- **Selector只选ID**：不得生成或覆盖坐标，位姿由Environment从当前CSET恢复。
- **科学结果不是验收门槛**：几何方法是否显著改善应如实报告，不能调test数据以迎合结论。
- **最小依赖**：建议Python 3.11、NumPy、Matplotlib、Pillow、jsonschema、PyYAML和pandas；GIF作为必做，VTK和MP4可选。

Selector响应最小格式：

```json
{
  "schema_version": "pallet_selector_response_v1",
  "request_id": "...",
  "state_hash": "...",
  "candidate_id": "cand_xxx",
  "confidence": null,
  "reason": "geometry_greedy"
}
```

## 5. 阶段1A具体实现

### 5.1 A1：领域对象与Repository

`domain.py`定义Item、PlacedItem、PalletState、Candidate、CandidateSet、SelectionRequest、SelectorResponse和StepResult。优先使用不可变dataclass或深拷贝，防止Selector修改共享状态。

```python
class DatasetRepository:
    def get_scenario(self, scenario_id): ...
    def get_decision_case(self, decision_case_id): ...
    def get_candidate_set(self, candidate_set_id): ...
    def get_oracle(self, decision_case_id): ...
    def list_cases(self, split): ...
    def list_scenarios(self, split): ...
```

加载时检查文件名与ID、DC到SCN/CSET引用、状态哈希、Oracle候选ID和Schema。代码产出：`domain.py`、`repository.py`、`test_repository.py`和`test_dataset_links.py`。

### 5.2 A2：真值PalletEnvironment

```python
reset(scenario_id, max_steps=None) -> Observation
observe() -> Observation
generate_candidates() -> CandidateGenerationResult
step(selector_response) -> StepResult
snapshot() -> immutable_state
```

`reset()`按`arrival_order`初始化，`buffer_size=1`只暴露当前箱体，不向Selector提供未来物料。`step()`依次校验请求、哈希和候选ID，从CSET恢复位姿，独立复核，更新支撑负载和已放箱体，再生成新哈希。

终止原因为`all_items_placed`、`no_feasible_candidate`、`max_steps_reached`、`invalid_selector_response`或`internal_error`。非法响应默认记录后执行Geometry-Greedy fallback；只有配置`fallback_policy=abort`才终止。

代码产出：`environment.py`、`test_environment.py`和`test_episode_state_transition.py`。

### 5.3 A3：CandidateGenerator协议

```python
class CandidateGenerator:
    name: str
    version: str
    def generate(self, state: PalletState) -> CandidateGenerationResult: ...
```

返回值必须有Candidate Set、拒绝直方图、去重数、Pareto数、Top-K覆盖和`enumerate/filter/score/top_k/total`分阶段耗时。新audit和timing存到实验日志，不直接改动已冻结的V0.1 CSET Schema。

### 5.4 A4：Selector接口

```python
class Selector(Protocol):
    name: str
    def select(self, request, *, rng, memories=None) -> SelectorResponse: ...
```

| Selector | 可见信息 | 冻结规则 |
|---|---|---|
| RandomValid | 公开候选 | 按实验种子均匀选择 |
| LowestHeight | 位姿和几何特征 | `z_base`、结果高度、质心偏移、ID升序 |
| GeometryGreedy | 几何特征 | 几何总分降序，ID稳定打破平局 |
| ParetoGreedy | 几何分项 | 先Pareto前沿，再用冻结tie-break |
| HandcraftedRule | 结构化真值规则 | 语义硬违规、软分、几何分字典序 |
| CandidateOracle | Oracle标注 | 返回`oracle_candidate_id` |

HandcraftedRule和CandidateOracle必须标记`privileged_input=true`。`memories=None`仅为1E预留，1A—1B方法必须忽略它。

### 5.5 A5：Runner和数据逻辑

FixedCaseRunner：

```text
DC + 已缓存CSET → SelectionRequest → Selector
→ 协议校验 → 动作后读Oracle → per_decision
```

它不在线生成候选，也不更新下一步状态，作用是保证不同方法面对完全相同的题目。

EpisodeRunner：

```text
Environment.reset(SCN) → 在线生成当前CSET
→ Selector → Environment.step → 评价+日志+渲染 → done
```

第t步不得读参考轨迹的第t+1步CSET。每步日志至少保存experiment/method/scenario/step/request/state hash、候选漏斗、选中ID、fallback、前后指标、耗时和状态。

### 5.6 A6：评价和产物

| 指标 | 定义 |
|---|---|
| placed item ratio | 已放数/请求放置数 |
| completed | 是否全部放完 |
| volume utilization | 已放箱体体积/容器体积 |
| max height | 已放箱体顶面最大Z |
| COM offset | 总质心水平偏移 |
| support ratio | 上层箱体最小/平均支撑率 |
| hard violations | 独立复核违规数 |
| generation/planning time | 候选生成和Selector用时，不含渲染 |

1A还需支持候选选定后的隐藏语义评价：`hard_violations`、`soft_utility`、Oracle regret、`semantic_decision_required`和非平凡案例命中率。这些内容只能在Selector返回后读取。

产出`per_decision.csv`、`per_episode.csv`和`summary.json`；聚合结果按method+split分组，包含样本数、均值、中位数、标准差和95%置信区间。

## 7. 阶段1B具体实现

### 7.1 B1：抽取EMS-style候选生成器

当前数据生成逻辑：

```text
当前箱体0°/90°
→ 从容器边界、已放箱体边缘和支撑顶面枚举点
→ 计算硬约束和几何特征
→ 去重 → Pareto前沿 → 多样性Top-K
→ CandidateSet + Audit
```

准确名称是“基于极值点和支撑层的EMS-style候选生成器”，不是完整GOPT复现。

物理过滤顺序：

1. X/Y边界和最大Z；
2. 容器总载荷；
3. 三维AABB不重叠；
4. 非地面候选支撑率不低于0.70；
5. 箱体中心投影位于有效支撑区；
6. 不放在`stackable=false`箱体上；
7. 按支撑面积比例向下传播质量；
8. 支撑箱体不超过合成顶部承重上限。

重物低放、易碎品靠上等业务语义不进入几何合法性过滤，否则VLM会失去选择空间。

迁移期间用已生成DC做golden对比。等价后，数据构建器可通过薄适配器调用共享实现，或冻结原脚本作为V0.1 reference。

### 7.2 B2：几何评分与Top-K

```text
geometry_score = 0.35 * compactness
               + 0.25 * height
               + 0.25 * stability
               + 0.15 * balance
```

必须冻结每个分项的数学定义、值域、优化方向和tie-break。Top-K至少区分floor/upper、center/edge、0°/90°、支撑箱体数和几何Pareto差异。

每步记录`raw_candidate_count`、`physical_valid_count`、`duplicate_count`、`pareto_candidate_count`、`returned_count`、`pareto_recall_at_k`和`epsilon_optimal_recall_at_k`。

### 7.3 B3：几何规划方法

必做方法：LowestHeight、GeometryGreedy、ParetoGreedy和固定DC上的CandidateOracle。

严格在线`buffer_size=1`在第t步不能看第t+1个箱体。因此beam search只能按下表定义：

| 方法 | 可见信息 | 实验定位 |
|---|---|---|
| BufferBeam | 只搜索当前buffer中的物料和位置 | `buffer_size>1`的公平方法 |
| LookaheadBeam-H | 读取未来H个箱体 | 离线上界，标记`future_visible=true` |

Lookahead不得与严格在线方法作同等信息条件的排名。建议开发值为`beam_width=4, H=2`，仅在validation调整。

### 7.4 B4：3D渲染与动画

抽取现有`color_for`、`draw_box`、`setup_pallet`、`render_workspace`、`render_montage`、`render_selected_result`和`render_final_layout`。

每帧显示：

- 取料/缓存区的当前箱体、尺寸、质量和属性；
- 码垛区的已放箱体、容器边界和选中虚影；
- Top-K缩略图和与JSON一致的编号；
- scenario、step、method、选中ID、坐标、yaw和支撑率；
- 完成数、体积率、最大高度和耗时；
- “确定性3D规划可视化（非Gazebo物理仿真）”。

固定相机、轴范围、颜色和画布尺寸。按step输出`frame_before.png`和`frame_selected.png`，用Pillow合成`animation.gif`；MP4可选。渲染开关和渲染失败都不得改变规划结果。

### 7.5 B5：批量实验

1. 360个固定DC：Lowest、GeometryGreedy、ParetoGreedy、CandidateOracle；
2. 100个基础`buffer_size=1` Scenario：Lowest、GeometryGreedy、ParetoGreedy；
3. Lookahead上界（可选）：仅validation/Test-ID，单独标记`future_visible=true`；
4. Top-K灵敏度：仅validation比较`K={4,8,16,32}`，冻结1C的K。

完整episode不使用现有固定Oracle，因为Oracle只标注了参考轨迹抽取的DC；方法早期选择不同后，后续状态没有预生成Oracle答案。

## 8. GOPT源码如何使用

结论：需要阅读、对照和引用GOPT思路，但首版1A—1B不将GOPT仓库作为强运行时依赖，也不训练GOPT网络。

| GOPT文件 | 可借鉴内容 | 本阶段用法 |
|---|---|---|
| `envs/Packing/ems.py` | `compute_corners`、`compute_empty_space`、`compute_ems` | 对照EMS空间生成，构建小型golden case |
| `envs/Packing/container.py` | `check_box`、`check_box_ems`、`is_stable`、`candidate_from_EMS` | 对照边界、高度图支撑、旋转和action mask |
| `envs/Packing/env.py` | Gym式`reset/step/observation` | 参考Environment生命周期，不照搬观测向量 |
| `model.py` | item—EMS交叉注意力 | 留给后续学习型GOPT基线 |
| `render.py` | VTK容器、箱体、相机和PNG | 参考高质量渲染，首版仍用Matplotlib |

不直接照搬的原因：GOPT使用从容器角点出发的整数栅格高度图，当前数据是真实mm尺寸和底面中心原点；GOPT稳定性与当前0.70支撑率+重心投影定义不完全一致；GOPT没有质量、不可堆叠和传播承重。

建议使用次序：

1. 审查当前极值点是否遗漏明显候选；
2. 用小型整数容器对比两边EMS/极值点覆盖；
3. 若增加GOPT适配器，将它的输出转为统一Candidate，再经过本项目全部硬约束过滤；
4. 只在后续有足够时间时统一观测、动作和预算，重训`model.py + masked_ppo.py`。

未完成适配和训练时，方法名必须是`GOPT-inspired EMS-style`，不能写为完整GOPT复现。

## 9. ReMe源码如何使用

阶段1A—1B不需要导入或运行ReMe源码。ReMe正式接入属于1E；现在引入会把记忆、索引和几何错误混在一起。

1A只预留：

- 稳定的experiment、episode、step、request和state ID；
- JSONL追加日志，作为未来原始经验证据；
- 选择前摘要、选择结果和动作后评价；
- Selector的`memories=None`扩展参数；
- 实验目录中的空`memory/`位置，但不生成伪经验卡。

1E再借鉴ReMe的`components/keyword_index/bm25_index.py`、`steps/index/bm25_search.py`、`steps/index/search.py`、`vector_search.py`和`steps/evolve/`。首版1E也可先实现轻量领域记忆，再决定是否封装为ReMe Step/Component。

## 11. 1A与1B的配合关系

- Repository为1B读取固定DC和完整Scenario；
- Environment为1B执行多层真值状态转移；
- Generator接口在1B接入EMS-style实现；
- Selector接口在1B接入Lowest、Geometry和Pareto基线；
- FixedCaseRunner运行360个DC，EpisodeRunner运行100个Scenario；
- Evaluator保证1B与后续VLM使用相同评价口径；
- Renderer的图像将直接成为1C的VLM-Visual输入；
- JSONL日志将成为1E的原始经验证据。

## 12. 后续Agent开发顺序

3. 实现FixedCaseRunner和基础Selector；

7. 实现Environment和EpisodeRunner在线转移；

9. 增加逐步帧和GIF；

11. 在validation运行Top-K灵敏度并冻结K；
12. 生成1A—1B验收报告，再进入1C。

每个子任务交付必须包含代码、配置、正例测试、反例测试、启动命令和实际产物路径。

## 13. 目标命令行

以下CLI已实现；当前可直接从工程根目录以`python3 -m semantic_pallet_planner.cli`调用。详细参数和正式验收命令见阶段开发说明：

```bash
python -m pip install -e ./semantic_pallet_planner
python -m pytest semantic_pallet_planner/tests -q

python -m semantic_pallet_planner.cli run-fixed \
  --config semantic_pallet_planner/configs/stage1a_fixed_cases.yaml \
  --split validation \
  --selectors random_valid,geometry_greedy,handcrafted_rule,candidate_oracle

python -m semantic_pallet_planner.cli run-episode \
  --config semantic_pallet_planner/configs/stage1b_geometry_greedy.yaml \
  --scenario SCN_0051 --selector geometry_greedy --render

python -m semantic_pallet_planner.cli benchmark \
  --config semantic_pallet_planner/configs/stage1b_geometry_compare.yaml \
  --selectors lowest,geometry_greedy,pareto_greedy --all-base-scenarios

python -m semantic_pallet_planner.cli sweep-topk \
  --config semantic_pallet_planner/configs/stage1b_geometry_compare.yaml \
  --split validation --values 4,8,16,32

python -m semantic_pallet_planner.cli replay --experiment outputs/EXP_1B_xxx
python -m semantic_pallet_planner.cli validate --experiment outputs/EXP_1B_xxx
python -m semantic_pallet_planner.cli report --experiment outputs/EXP_1B_xxx
```

## 15. 明确暂缓项

- 不调用VLM API；
- 不创建、检索或改写ReMe经验卡；
- 不把Oracle解释放入普通Selector输入；
- 不将LookaheadBeam伪装成严格在线方法；
- 不将程序化3D动画称为Gazebo物理仿真；
- 不修改`aubo_ros2_ws`机械臂逻辑；
- 不为迎合Aubo单层Demo缩放数据集箱体。

阶段1A—1B的合格输出应是一个独立、可测试、可批量运行和可动画回放的真值三维码垛规划平台，它将成为后续VLM和ReMe实验的稳定底座。
