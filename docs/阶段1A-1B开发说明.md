## 4. 输入数据和可见性

### 4.1 DatasetRepository读取内容

| 数据 | 路径 | 用途 |
|---|---|---|
| Scenario | `tasks/scenarios/SCN_xxxx.json` | 容器、物料、到货顺序、buffer和自然语言指令 |
| Decision Case | `tasks/decision_cases/DC_xxxxx.json` | 固定当前状态和CSET引用 |
| Candidate Set | `candidates/candidate_sets/CSET_xxxxx.json` | 固定实验原始候选，任何方法均不能替换 |
| Oracle | `annotations/oracle_candidate_scores/DC_xxxxx.json` | 动作后评价；仅CandidateOracle可在选择前读取 |
| Ground-truth rules | `annotations/ground_truth_rules/SCN_xxxx.json` | 动作后业务评价；HandcraftedRule可特权读取 |
| Split | `splits/*.json` | 运行器挑选样本与评价分组，不注入Selector请求 |
| Dataset config | `configs/mvd_v0.1.json` | 固定几何权重、旋转、支撑率等基准配置 |
| 现有图像 | `views/rendered/DC_xxxxx/` | 固定案例可见输入；按需视觉钩子也可重新生成输入图 |

`streams/`、经验卡和记忆检索不参与1A/1B运行。实验manifest记录数据文件哈希，但这些元数据不进入Selector。

### 4.2 固定Decision Case数据流

```text
split → DC → Scenario + 固定CSET
                 ↓
       白名单SelectionRequest
                 ↓
       Selector只返回candidate_id
                 ↓
       Schema / request_id / state_hash / ID校验
                 ↓
       动作后读取Oracle → 独立几何检查 → 计算假设放置结果
                 ↓
       steps.jsonl + per_decision.csv
```

固定评测不修改环境，不接着运行下一箱；日志中的`after`是该候选的假设动作后状态，`committed=false`表示没有提交在线环境。不能把同一Scenario的三个DC拼成一条新轨迹。

`--top-k`不改变固定CSET。固定实验始终使用数据集冻结的候选和顺序，保证不同方法面对完全相同的选项。

### 4.3 完整episode数据流

```text
Scenario → 按arrival_order reset
       ↓
只暴露当前箱体 + 当前已放状态
       ↓
在线生成CSET → Selector → 协议校验
       ↓
独立物理复核 → 提交位姿 / 向下传播载荷
       ↓
新状态、新hash → 动作后隐藏语义评价 → 日志
       ↓
下一箱重新生成候选，直到终止
```

Scenario完整物料列表只由环境持有。`buffer_size=1`每步请求只有一个当前箱体；Selector看不到未来到货。方法早期选择不同时，后续状态自然分叉，不读取参考轨迹后续CSET。

公开数据的负载与支撑比例存在四舍五入。`restore_placed()`根据实际位姿、接触面积和质量重建内部支撑图，避免把多次舍入值持续反馈到生成器；环境动作提交也独立重新计算支撑和载荷，不信任生成器私有`result_state`。

## 5. 几何定义、Top-K和方法

### 5.1 坐标和合法性

- 容器底面中心为原点；长度单位mm，质量单位kg。
- `x_mm/y_mm`是箱体底面中心，`z_base_mm`是底面高度。
- 默认容器1200×1000×850 mm；在线生成器实际使用当前Scenario的容器。
- 只允许yaw=0°或90°，保持直立。
- 检查容器边界、最大高度、总载荷、AABB不重叠、支撑面积比≥0.70、中心投影、不可堆叠及传播承重。
- 独立复核还检查选取物料、旋转、旋转后尺寸、有限数值、支撑ID、报告支撑率、结果高度和体积率。
- 支撑中心判定为箱体中心位于至少一个有效接触矩形内；不是完整刚体动力学或支撑凸包稳定性分析。

### 5.2 固定几何评分

四个分项均在[0,1]，越大越好：

| 分项 | 定义 |
|---|---|
| compactness | 所有已放箱体总体积 / 轴对齐整体包络体积，上限1 |
| height | `max(0, 1 - 当前最高顶面 / 容器最大高度)` |
| stability | 当前候选支撑面积比，上限1；地面候选为1 |
| balance | `max(0, 1 - 质量加权水平质心到原点的距离 / 托盘半对角线)` |

`geometry_score = 0.35*compactness + 0.25*height + 0.25*stability + 0.15*balance`。

先将分项保留6位小数，再计算总分保留9位，保持阶段0定义。`volume_utilization`使用固定容器体积作为分母，不能与`compactness`混用。

### 5.3 Top-K模式

- `legacy_v01`：保持阶段0候选分层与挑选行为，用于golden回归。
- `diverse_v1`：原floor/upper、center/edge、支撑箱数、物料分层，再增加yaw和是否属于Pareto前沿；先选各层最佳，再按几何分填充。

Top-K仍可能截断部分Pareto候选；必须报告真实覆盖率。当前不是先剔除所有非Pareto候选再选K个，保留非Pareto候选有助于后续语义决策空间的多样性。

`raw_candidate_count`为极值点集合与yaw组合的枚举数；`duplicate_count`统计生成器这一层重复的位姿+yaw键，极值点函数自身已做集合去重，正常数据中该值可为0。方形箱的0°/90°仍是两个姿态键。

`epsilon_optimal_recall_at_k`沿用V0.1字段，实际是“Top-K中是否存在距全体合法候选最优几何分不超过0.05的候选”的布尔值；其聚合均值为命中率，不是所有epsilon最优候选的集合召回率。

### 5.4 六个Selector

| 名称 | 冻结选择规则 | 特权输入 |
|---|---|---|
| `random_valid` | 按可复现随机数均匀选择公开候选 | 无 |
| `lowest` | 底面z升序→结果最高顶面升序→质心偏移升序→ID升序 | 无 |
| `geometry_greedy` | 固定几何总分降序→ID升序 | 无 |
| `pareto_greedy` | 先Pareto前沿，再height、stability、balance、compactness降序→ID升序 | 无 |
| `handcrafted_rule` | 业务硬违规数升序→语义软分降序→几何分降序→ID升序 | 结构化真值规则 |
| `candidate_oracle` | 返回缓存Oracle的指定ID | Oracle标注，仅固定DC |

HandcraftedRule自行执行规则函数，未用Oracle候选评分替代规则计算。Handcrafted与Oracle均记录`privileged_input=true`。本阶段全部方法`future_visible=false`，`memories=None`仅预留参数。

## 6. 请求响应协议和失败处理

公共request沿用`pallet_vlm_request_v1`白名单，包括：

```text
request_id、state_hash、instruction_text、container、placed_items、
available_items、candidates、visual_inputs
```

候选包括显示编号、真实ID、pick_item_id、pose、尺寸、支撑、承重信息和几何分项；不附Oracle答案、结构化规则、split、原始订单或未来物料。

内部统一响应为：

```json
{
  "schema_version": "pallet_selector_response_v1",
  "request_id": "SCN_0051_STEP_000",
  "state_hash": "64位SHA256",
  "candidate_id": "cand_xxxxxxxxxxxx",
  "confidence": null,
  "reason": "geometry_greedy"
}
```

前四项必填，confidence可选且只能是null或[0,1]数值，reason可选且为字符串。禁止额外坐标字段和`selector`等未声明字段。方法名记录在日志元数据中。

默认非法响应使用Geometry-Greedy fallback，并记录原始响应、解析错误和最终响应；`fallback_policy: abort`则结束在线任务，或为固定任务保留一条失败记录。确定性基线正式验收要求没有意外fallback。

| 终止原因 | 含义 |
|---|---|
| `all_items_placed` | 全部到货物料放完 |
| `no_feasible_candidate` | 当前箱体没有通过物理约束的候选 |
| `max_steps_reached` | 用户设置的演示步数上限已达到 |
| `invalid_selector_response` | abort模式下响应不合法 |
| `internal_error` | 生成、执行或独立复核出现内部异常 |

300场正式1B实验只允许前两种终止原因。无候选是规划结果，保留在完成率分母中。限制步数的演示不混入完整episode主统计。

```text
├── representative_episodes.json      1B五个动画的位置与类别
├── visual_validation.json            GIF帧可解码及固定画布检查

```

并非所有300场景都渲染图片，只有代表episode具有`frames/`和GIF；所有episode均保留完整数值轨迹，随时可以通过`render`重建动画。根目录`steps.jsonl`与各episode日志内容有重复，这是为全局分析和单场景携带回放而有意保留。

## 8. 指标与统计口径

### 8.1 单步与episode指标

- `hard_violations`：独立物理检查违规数量。
- `semantic_hard_violations`：业务规则违规数量，不能与物理违规混合。
- `soft_utility`：当前动作后的业务语义软分。
- `oracle_hit`：是否选中缓存Oracle指定的ID。
- `oracle_regret`：Oracle软分减选择软分；若Oracle优先减少硬违规，它不一定具有最高软分，所以此值可能为负。
- `oracle_hard_violation_regret`：选择的业务硬违规数减Oracle硬违规数，与soft regret一起解释。
- `semantic_decision_required`：数据集冻结的非平凡语义决策标签，只在选择后用于评价。
- `placed_item_ratio`：已放箱数/完整Scenario请求箱数，步数截断演示也不修改分母。
- `completed`：仅`all_items_placed`时为true。
- `volume_utilization`：已放总体积/固定容器体积。
- `max_height_mm`：已放箱体最大顶面高度。
- `center_of_mass_offset_mm`：质量加权水平质心偏离托盘中心的距离。
- `minimum_support_ratio/mean_support_ratio`：上层箱体最小/平均支撑率；没有上层时约定1。
- `generation_time_s/selection_time_s`：固定DC生成时间为0；episode中为所有尝试步骤累计耗时，不含事后动画渲染。

`steps.jsonl`还包含`metrics_before`、动作后`metrics`、CSET、请求响应、前后状态、fallback、错误和候选审计。

### 8.2 耗时和置信区间

每次在线生成记录`enumerate/filter/score/top_k/total`秒数；`top_k`包括Pareto计算与多样性选择。`total`还包含状态恢复等开销，分阶段之和不要求严格等于total。无候选的失败尝试也计入生成耗时。

`summary.json`按track、method、split分组，给出样本数、均值、中位数、样本标准差、95%区间，以及p50/p95/最大值。区间采用固定种子的1000次percentile bootstrap；固定DC以Scenario为簇计算区间，避免将同一场景的多个DC当作独立场景。原始行的均值和标准差仍在DC级别给出。

重复运行哈希只覆盖确定性决策、状态、终止和fallback，不包含墙钟耗时、实验目录名和图片压缩字节；这些非确定性或环境相关产物另有文件SHA256用于完整性核对。

### 8.3 Top-K冻结规则

只使用validation的30个固定状态：选择平均Pareto覆盖≥0.90且epsilon命中率=1.0的最小K；若没有K达标，选择所测最大K并显式记录`target_met=false`。耗时同时报告，但不根据test结果调K、几何权重或tie-break。

该实验测量固定验证状态下的候选覆盖，没有额外声称完成了不同K的全episode灵敏度。1B主基线K在配置中冻结，`topk_selection.json`给出1C后续使用的K。

### 9.4 参数含义

| 参数 | 默认值 | 含义及适用命令 |
|---|---|---|
| `--config` | 内置默认配置 | YAML路径；生成实验的命令使用 |
| `--dataset` | `semantic_pallet_dataset_v1` | 只读数据集根目录 |
| `--output-root` | `semantic_pallet_planner/outputs` | 实验父目录；禁止位于数据集内部 |
| `--experiment-id` | UTC时间戳生成 | 本次输出目录名；已有同名目录拒绝覆盖 |
| `--seed` | `20260912` | 随机Selector与统计重采样种子；方法和案例ID进一步派生独立随机流 |
| `--top-k` | `16` | 在线候选返回上限；不改变固定DC已缓存CSET |
| `--topk-mode` | `diverse_v1` | `legacy_v01`兼容回归，`diverse_v1`增加yaw和Pareto分层 |
| `--split` | `validation` | 固定/benchmark任务划分；固定`all`为全部360 DC，benchmark的`all`为100基础场景；sweep只允许validation |
| `--selectors` | 随命令 | 逗号分隔方法名；run-fixed默认Random/Geometry/Handcrafted/Oracle，benchmark默认Lowest/Geometry/Pareto |

| `--max-steps` | 不限制 | run-episode/benchmark的正整数步数上限；不能用于完整阶段验收 |

## 10. 回放和验收分别证明什么

`validate`检查配置哈希、冻结数据哈希、manifest中已登记的产物哈希、日志Schema、请求可见性、状态连续性、候选合法性、独立动作提交、固定Oracle指标及图像编号映射。

`replay`在上述基础上，重新运行在线生成器，从每个保存的before状态生成完整CSET并比较。因此它不只重读已保存的选中ID。另有`reproducibility_report.json`记录真正再次运行Selector/Environment的结果，以证明同种子下决策可复现。

`report`只读取现有证据，不会把缺失测试、缺失动画或未完成批量实验标记成完成。普通run-fixed/run-episode输出若不满足完整阶段门槛，报告FAIL是预期的完整性提示。

重新绘图可能受Matplotlib/Pillow/字体版本影响；原始数值轨迹与布局不受影响。严格文件哈希检查能够发现图像或日志在正式验收后发生变化。

## 11. 1C如何接入

新增实现`select(request, *, rng, memories=None)`的Selector类，设置`name`、`privileged_input=False`，通过`selectors.baselines.register()`注册工厂，再使用现有Runner。无需改变Environment的提交协议或Evaluator。

需要图片的Selector设置`requires_images=True`，Runner会通过输入渲染钩子准备工作区和候选图，再把有效图片路径放入request。输入绘图函数只接收选择前公开状态，不包含选中结果或隐藏标注。阶段1B的演示渲染仍是事后独立操作。

1C需要在自己的适配器中完成VLM客户端、prompt、缓存、超时/修复、候选显示编号映射和成本统计。候选确定性打乱必须同时作用于JSON和图像；该特性属于1C实验实现，本阶段不声称已经通过VLM位置偏差消融。

1E可复用JSONL的选择前状态、结果、动作后反馈和稳定ID构造经验，但不得把Oracle标注、split或未来反馈注入当前决策。当前`memory/`为空，未生成伪经验卡。

## 12. 已知边界和后续任务

- 只有`buffer_size=1`可运行；buffer3明确拒绝，避免把联合选箱任务误当成固定到货顺序。

- 候选Oracle是当前固定候选集内的上界，不是完整episode全局最优。
- 规则基线看结构化真值，不能与只看自然语言的方法混同信息条件。
- 本数据集经过参考策略可行性和多层条件筛选，存在构造选择偏向。
- 顶部承重是合成属性，几何判定不等价于机器人路径可达或真实稳定性。
