# 阶段 1C 验证集 20 案例独立审查记录

## 审查范围与身份

本记录由 Codex 助手逐案例审阅已保存的实验产物，并非研究者本人签署的人工审查。逐方法、逐案例的结论和可核对证据已填写在[阶段1C人工审计.csv](阶段1C人工审计.csv)；如论文或项目流程要求自然人审阅签认，研究者仍需复核并签署。本次没有修改数据集、模型请求、响应、评分或既有实验目录，也没有重新调用 API。审计表共有 64 行：原 validation 的 60 行中已填写 40 行，另追加正式实验 4 条异常调用记录；`experiment_id` 列区分来源。

- 实验：`semantic_pallet_planner/outputs/EXP_1C_DEEPSEEK_FLASH_VALIDATION`。
- 样本：20 个不同 Decision Case；每例核对 `vlm_text` 与 `vlm_visual`，共 40 条响应。覆盖 `fragile_protect` 5 例、`category_group` 5 例、`heavy_center` 6 例、`heavy_low` 2 例、`category_separate` 2 例。
- 证据：每例两种模式的 `public_request.json`、`prompt.json`、`response.json`、`mapping.audit.json`、`leakage_report.json`，视觉模式的 `workspace.png` 和 `candidates_montage.png`，以及数据集的 `annotations/oracle_candidate_scores/DC_*.json`、`metrics/per_decision.csv`。20 张视觉候选拼图均已打开检查，候选编号与保存的映射一致；物品属性和支撑关系以结构化请求及 Oracle 复核为准。
- 边界：Oracle 是事后评价证据，不能视为模型输入。审查能核对保存的图文请求和选择结果，不能证明模型内部确实利用了图像。validation 没有修复或回退；正式全量实验的 1 次 Text 修复和 3 次 Visual 供应商错误已在同一审计表追加审查，未混入上述 20 例的 validation 统计。

## 审查口径

选择结果、模型解释和接口合法性分别评价。若 `oracle_hit=False` 但 `oracle_regret=0`，该选择在冻结语义评分下与最佳候选同分，不判作语义失败。正 regret 表示所选候选的语义效用低于最佳候选；小差值仍注明“轻微次优”。`hard_violations` 在本审查中指业务语义硬规则，不能与物理硬约束违规混同。模型说“硬规则”也不等于数据集真的把该规则标为 hard；以 `ground_truth_rule.hard_or_soft` 为准。

20 例中，Text 与 Visual 对每例都选择相同的真实候选。**14 例出现正 Oracle regret，6 例语义效用与最佳候选相同**；其中 `DC_00177` 的选择触发一次电子产品与重物接触的语义硬规则违规。两模式选择相同并不代表理由相同：部分视觉或文本理由独自误认了物品类别、易碎属性或规则等级。物理违规在这 20 例中为 0。

| 规则 | 审查案例 | 主要发现 |
|---|---|---|
| 易碎品保护 | 151、152、153、157、158 | 151 放底层而漏掉更高且不压易碎品的候选；153、157 把箱体放在易碎箱上却声称未增加其承载。152 最优；158 与最佳同分，但 Text 把非易碎支撑箱称为易碎箱。 |
| 电子产品集中 | 160、161、163、164、165 | 五例均有正 regret；160、163、165 尤其明显，模型把较远的候选称为“同区/附近”。164 只差 0.009981，应标为轻微次优。 |
| 重物靠中心 | 166、167、168、178、179、180 | 除 168 选对外，其余五例以“放置后的整体质心偏移小”代替“当前重箱自身的 XY 位置靠中心”。168 虽选对，理由仍主要依赖整体质心代理指标。 |
| 重物靠低层 | 171、172 | 两例选择均与最佳候选一致，且位于本题最低候选高度；部分理由把 `soft` 偏好误称为“硬规则”。 |
| 电子产品与重物隔离 | 154、177 | 154 无已放物品，所有候选语义同分，Visual 却把 general 箱说成电子箱。177 把电子箱放在 heavy 箱 `item_04` 上，Oracle 标记 `electronics_heavy_contact:1`；两模式均误认支撑箱属性。 |

## 四个优先复核的证据链

1. **`DC_00153`：支撑关系反向理解。** Text/Visual 都选 C07，映射到 `cand_39b8620ffc23`，语义分 0.267306；Oracle C05 为 0.433653。C07 的 `support_item_ids=["item_06"]`，而 `item_06.fragile=true`。模型称放在其上方却“不增加其承载”，与请求中的支撑关系矛盾。
2. **`DC_00177`：语义硬规则违规。** 两模式都选 C05，电子产品 `item_09` 支撑在 `item_04` 上；`item_04.weight_class=heavy`。Oracle 对所选候选记录 `electronics_heavy_contact:1` 和 0.666667 分，无接触的 Oracle C02 得 1.0 分。该问题是业务规则违规，实验的物理硬约束检查仍可为 0。
3. **`DC_00178`：评价量混淆。** 两模式选 C08，新重箱自身 XY 距托盘中心约 545 mm；Oracle C01 约 160 mm。模型引用的 87.7 mm 是**放置后整体质心偏移**，并非当前重箱位置；所选与最佳语义分分别为 0.301935 和 0.795742，差 0.493807。
4. **`DC_00154`：同分与理由错误并存。** 本题没有已放物品，待放 `item_01` 是 general/light，隔离规则未触发；所选虽非唯一 Oracle ID，但语义效用同为 1.0。Visual 理由把该物品说成电子产品，故“选择等价正确”和“理由事实错误”须分开记录。

## 正式实验的修复与回退专项审查

以下四例来自 `EXP_1C_DEEPSEEK_FLASH_FINAL_V1`，用于补足 validation 中缺席的异常类别。它们是正式结果的**事后审计**，不用于选择更有利的 test 配置。逐行事实及来源标在审计表的 `experiment_id` 列。

| 案例与方法 | 异常 | 审查结论 |
|---|---|---|
| `DC_00274` Text | 首次响应的 `state_hash` 与请求不一致；第二次修复响应一致 | 解析器未接受首次响应，仅提交修复后的 C01；2 次真实请求、`repair_count=1`、无回退，所选与最佳语义分同为 0.675294。 |
| `DC_00324` Visual | `provider_error: DeepSeek response shape is invalid`，无可解析模型响应 | 按冻结策略回退 Geometry-Greedy。回退后的业务语义接触数为 3、语义分 0.25；最佳候选接触数为 2、语义分 0.50。全部 16 候选的事后接触数至少为 2，因此不宣称本题存在零接触候选；回退结果比最佳候选多 1 个接触。物理硬违规仍为 0。 |
| `DC_00335` Visual | 同类供应商响应形状错误 | 按策略回退且恰好命中 Oracle，语义分 1.0。 |
| `DC_00338` Visual | 同类供应商响应形状错误 | 按策略回退，语义分 0.587419，最佳为 0.701961，regret 0.114542。 |

三次 Visual 失败的 `response.json` 都只有错误类别和“响应形状无效”，`attempts=[]`，未保存供应商原始响应体。因此只能确认适配器无法解析响应，**不能**据此断定是图片解码、网络、配额还是模型输出格式造成。`DC_00324` 说明自动验收 PASS 的“物理违规为 0”并不等于业务语义硬规则没有风险；应在后续研究报告中单列 fallback 的语义后果。

## 后续处理

这份审查补齐了 validation 的逐案例证据，也记录了正式实验中的修复和回退案例；正式全量实验的自动验收仍以 `EXP_1C_DEEPSEEK_FLASH_FINAL_V1/acceptance_report.md` 为准。若要把“至少 20 例**人类研究者**抽查”作为字面验收条件，还需研究者复核 CSV 并记录签认。正式实验已执行，不应因看到 test 结果修改现有 FINAL_V1 的提示词或覆盖目录；后续如修订公开特征与提示词，应在 train/validation 上开发，升版本并产生新的独立实验。

研究上应优先区分三个问题：① 当前重物位置与整体质心是不同量；② 支撑于易碎箱会增加其负载；③ 电子产品聚类应比较所有相关同类箱，而不只凭单个邻近箱或几何平衡分。`DC_00177` 还说明业务硬约束需要单独的错误率统计，不能用物理违规数 0 代替。
