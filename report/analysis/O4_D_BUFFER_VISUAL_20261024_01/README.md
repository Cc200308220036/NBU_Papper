# O4-D 缓冲真实订单可视化

直接用浏览器打开 [index.html](index.html)，无需服务器、联网或 API key。支持四编译来源、四规划器、逐事件播放、暂存区和立体/俯视布局。也可查看 [静态总览 PNG](overview.png) 或 [PDF](overview.pdf)。

全部数据来自 `EXP_O4_D_ORDERS_REAL_20261023_01`；展示 3 个任务 × 4 编译来源 × 4 规划器，共 48 条真实轨迹。

| 案例 | 选择理由 | Oracle 下单箱 / FIFO / 启发式 / 搜索 |
|---|---|---|
| O4_ORDER_02_2 | 搜索相对单箱件数增量最大；所有编译来源均重现该件数结果 | 9 / 9 / 19 / 19，共 19 箱 |
| O4_ORDER_07_0 | 多放但未完成，避免把改善等同于成功 | 7 / 7 / 12 / 13，共 16 箱 |
| O4_ORDER_00_3 | 搜索由完成退化为失败；真实模型又有独立协议问题 | 16 / 16 / 16 / 15，共 16 箱；Text/Image 均 0 箱 |

箱号、姿态、尺寸、类别、暂存区和终止状态均取自保存事件。坐标单位 mm，箱体 X/Y 为中心，Z 为底高；绘制使用 `oriented_size_mm`，不重复应用 yaw。立体图是投影示意，悬停可读属性；俯视图上层会遮挡下层。播放的统一轴是各轨迹事件序号，不是相同墙钟时间。

页面中的“到货”只显示轨迹已实际接收的箱子；协议失败后保持原来的已码状态，不补上后续箱子。所有任务分母仍包含未到货/未放箱。完整矩阵表从全部 1152 份 job 汇总生成，每方法分母 72。

`build.py` 只读取冻结产物，核对所展示轨迹最终件数及实际提交顺序，导出 `data.json`、`source_hashes.json` 和单文件网页。`plot.py` 生成 PNG/PDF。源文件摘要记录 48 份 job 与 48 份事件文件。重建命令（仓库根目录）：

```bash
python report/analysis/O4_D_BUFFER_VISUAL_20261024_01/build.py
MPLCONFIGDIR=/tmp/o4-buffer-matplotlib python report/analysis/O4_D_BUFFER_VISUAL_20261024_01/plot.py
```

本产物是既有实验的展示，不是新实验、完整规划器回放或正式测试集。当前已见来源和案例选择限制见 [真实实验分析](../../../docs/03_阶段产出分析/O4/O4D真实编译冒烟与完整订单实验结果分析_20261024.md)。
