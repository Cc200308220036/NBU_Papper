## 2. 总目标与研究边界

最终链路：传统规划器产生公共可执行候选→Jev选择箱体及精确位置→公共监测器检测选后布局→稳定则提交，否则按原因停单→训练订单的有限分叉对比→保存更优轨迹/提炼经验→冻结经验→未见来源订单验证。

重点研究长期箱体/位置选择对装入量、空间紧凑性与承载资源保留的影响。稳定性监测是所有方法共用的评价与停止机制，不是本项目选择器专属优势。禁止将公共硬检查保证的零违规当成Jev或经验收益。

范围继续为轴对齐0/90、均匀刚性箱、实际质量、合成包装承载参数、竖直准静态反力；不加入区域、食品清洁品相容性、AST、冲击、摩擦滑移、变形及真实坍塌动力学。

本规范定义后续实施范围，不表示一次授权执行所有阶段。每个目标模式只执行明确指定的阶段，满足退出条件后交付，不自动启动下一阶段或扩大付费矩阵。

## 4. 所有阶段的公共合同

### 4.1 方法公平性

同一比较块冻结数据、到货顺序、缓冲规则、候选器、TopK、展示顺序种子、旧物理检查、监测内核和开关。默认主比较开启监测。开关关闭只作明确注册的诊断，不将未检测称稳定。

所有方法只能访问当前已到货状态；完整订单只能由私有运行器用于到货和评价。不能将未来箱体、完整订单统计、见证、参考动作、测试结果或监测预评写入模型输入。若后续研究允许订单先验，必须另建协议与对照，本规范不默认允许。

监测只作用于已选动作；无候选预过滤、排序、稳定性提示、失稳改选。UNASSESSABLE/ERROR独立停止，不混为失稳；规则违规不新增业务停单，既有物理硬检查继续保留。错误响应不得用本地方法代选后混记为Jev成功。

### 4.2 运行身份与恢复

保留v4/v5及历史记录，不删除旧入口或扩展封闭旧Schema。新正式运行、真实模型和非空经验各自显式版本化；具体版本在开发初始冻结。版本路由必须集中注册，不以零散字符串比较或“后续都按v5”规避验证。

复用已有SELECTED→MONITORED→COMMITTED/TERMINATED与UNKNOWN_SEND语义。已存选择不重发，已存监测不覆盖，已提交不重复放置。网络请求发送结果不明时不能声称恰好一次调用，记技术状态并停止，禁止静默重试。模型/提示/经验快照变化须新建运行。

## 6. JN1：真实Jev无经验选择与整单对照

### 6.1 开发目标

让真实Jev在新包装属性、完整订单及统一监测协议下选择候选，得到可信无经验基线。旧J3模型运行不能替代本阶段验收。

### 6.2 具体改动

当前`JevSelector.select()`显式拒绝packaging协议，`packaging_runtime.METHODS`也只开放本地替身。必须新增受验证的协议路由与方法注册，不能只删除拒绝语句。复用`JevTransport`、请求账本、严格JSON解析和候选映射，逐项检查config/context/selection/checkpoint/metrics是否接受新版本。

输入复用当前`build_context`：容器、当前已放/可选箱、缓冲、实际质量、尺寸、stackable、承载与剩余承载、面积支撑/载荷变化、候选几何特征；无经验时memories为空。原监测反力、PCT结果/证书不进入选择输入。输出仍为一个Cxx候选标签，映射回不可变candidate_id和精确动作，不生成AST。

开发时按当时官方文档核对现有endpoint、原生Choice请求/响应及概率语义，保存官方链接和访问日期；不凭本文件推测API。不将概率当解释或物理置信度；原始精度保存，不从四位显示值推断真实并列，不编造模型理由。若接口仅返回标签或部分概率，按真实字段记录；服务端并列规则未知就记UNKNOWN，不自行宣称其算法。

请求账本补真实origin/model、实际请求次数、明确失败阶段、请求/响应摘要及可得usage；修正目前summary硬编码`LOCAL_TEST_DOUBLE_NOT_JEV`和model_calls=0的问题。单候选自动执行仍是singleton，不计真实模型请求。请求内容不得持久化鉴权头或密钥；配置仅记凭证引用方式。

预算不设置默认费用上限；实际费用/请求数仍记录。以冻结的订单/方法/阶段范围控制任务，不自动扩大实验，无隐式重试。真实请求只在该阶段被明确执行时进行，本规范编写不触发调用。

### 6.3 总体实验与交接边界

JN1-A与JN1-B分别执行以下6.4/6.5合同：A只做一个真实多候选决策，B才做最多2个开发订单的完整真实运行，互不冒充完成。模型费用不设默认上限，但有明确任务/尝试清单。API不可用或凭证缺失先完成可独立的代码和合同验证，再如实交付PARTIAL，不用替身冒充真实通过。

不同模型轨迹的逐步状态自然不同；同候选池公平指同一公共状态采用同生成器，不强求不同轨迹每一步池相同。

## 7. JN2：训练订单的有限分叉与长期收益证据

### 7.1 开发目标

验证“改变某一步选择能否改善后续结果”，产出可用于学习的对比材料，不把“第二/第三名”本身当作经验。

### 7.2 分叉合同

- 仅训练/开发来源；冻结可用决策、分叉步、最多两个替代动作、后续策略、选择种子及目标；不得对测试订单搜索后用于建库。
- 从决策前精确已提交状态、到货游标、缓冲及原候选恢复；前缀只验保存记录，不重新调用模型回放前缀。分叉是新注册干预实验，不是断网回放实验。
- 替代动作必须来自该决策保存的公共可执行池。真实概率完整可用时可预先选择top2/top3；并列需冻结去重与候选摘要排序规则。缺失排名时按事先固定的候选特征规则取样，不能伪造概率或当成模型第二名。
- 混合选箱主线应允许不同箱体和同箱不同位置，但分别标记干预类型。只做同箱分叉不能支持长期选箱收益结论。
- 每个替代动作先走公共监测，失稳立即停该分支，禁止另换动作补救。后续每步重新生成候选，不能沿用原轨迹后缀的Cxx或动作。
- 第一轮建议所有分支采用同一确定性后续策略。必须另跑原始选中动作＋同一后续策略，作为配对参考；不能把“替代动作＋几何后续”直接对比“原始Jev整轨迹”并将差异归因于该动作。
- 使用Jev继续分支是另行注册的实验，需报告额外调用与非确定性。不得在得到好结果时提前停搜索或仅保存获胜分支。

首轮最多2个训练订单、每单2个预注册决策、每决策原动作加最多2个替代动作，共最多12个后缀运行；先执行1个决策的机制验证再展开。无正收益也是合法结果。

### 7.3 对比与交接

**版本边界（2026-11-04补充）：**下段冲突合并规则保留为原JN2-B v1历史合同。未来新实验按[评价v2方案](Jev_JN2评价规则v2与经验准入只读再分析改进方案_20261104.md)事前冻结 `jev_branch_comparison_rule_v2`：稳定完整完成 → 完整任务体积装入比例 → 件数/质量Pareto → 装入等价后的高度/包络Pareto。装载层胜出时，增高及其他反向指标单独报告，不能否决该层收益；保留有效性、等价阈值、指标缺口和代价。紧凑性改善不自动进入装载正例。

原8对已按用户调整目标进行**事后只读再分析**，见[独立v2验收](../../03_阶段产出分析/Jev/Jev_JN2评价规则v2与经验输入再分析验收_20261104.md)。v1原标签、原NOT_READY、执行源码及报告均保留；v2新收据只替代后续材料准入引用，不改写原实验预注册结论。经验候选非空、证据审核通过、JN3-A输入就绪、实际注入和收益成立必须分开。

冻结比较顺序：排除技术失败对子作因果收益标签但仍保留全部分母；优先稳定完整完成/装入体积比例，兼报件数、质量、终止原因及空间紧凑性。目标有冲突时标TRADE_OFF，不强造唯一winner。构造经验的结果优势不能来自技术截断差异。

输出`ComparisonRecord`：source_group、fork/状态/候选摘要、参考与替代动作、后续策略身份、全部结果、各指标delta、停止原因、comparison_valid、improved/trade_off/neutral/degraded和证据定位。无效/无收益对比保留，禁止只有好轨迹。

“观察到更优”不证明全局最优，也不证明经验有效。JN3只能读取验证通过的训练对比收据。

## 8. JN3：案例轨迹与对比经验两条路线

### 8.1 开发目标

分别实现用户提出的两种记忆：T案例轨迹、E对比经验，避免将有检索或模型输出误称已发生自我进化。模型权重不变，实际机制为外部记忆增强。

### 8.2 共同接口与隔离

审计复用旧memory_store/retrieval/审核/生成账本，但为包装属性建立独立版本，禁止混入旧食品清洁品、区域经验和旧成绩。将`build_context`中固定memories=[]改为显式、受限MemoryView输入；无经验模式保持空视图且可验证，不通过全局变量注入。

`MemorySnapshotReceipt`至少含mode、版本、来源分组、卡片/案例摘要、生成模型/提示身份、审核状态、检索规则、长度限制、冻结时间；运行绑定snapshot_digest。检索只读取当前公开几何与属性，不读未来任务、测试成绩、参考动作、PCT诊断或失败预测。

### 8.3 T：保存优质轨迹案例

完整轨迹作为私有可审计证据，模型输入只检索与当前决策相关的有限公开状态/动作片段，不能每步塞入整单。片段体现尺寸、质量、承载资源和位置关系，标明来自历史案例，不复用Cxx或坐标作当前硬动作。私有来源ID/结果保留审计，输入使用抽象或匿名对象，不能靠订单编号匹配答案。

T材料保留未来结果在私有侧供选择案例；公开片段不包含当前任务的未来箱体或事后答案。同样历史结果若向E展示，就必须为T定义公平的结果摘要规则，避免信息量差异冒充提炼收益。

### 8.4 E：对比提炼经验

使用DeepSeek对有效训练对比作条件化总结。每条经验至少包含：适用状态、可观察属性关系、建议方向、预期长期作用、反例/不适用条件、证据对比ID、支持/反驳数量与审核状态。不能总结“选第二名”“某Cxx更好”或把单案例因果推断扩大为普遍定律。

采用事实/推断分离：尺寸、质量、分流与指标delta由程序提供；模型可以提出策略解释，但无证据的因果机理标HYPOTHESIS，不写成已证明。每项事实声明链接具体轨迹事件或指标，自动审计后再语义审核；审核失败不入正式快照。保存失败、成本和生成结果，不无限重试求好卡片。

### 8.5 验收及交接

以同一组有效训练对比构建T/E；第一版至少一个真实非空案例与一张有证据的经验通过审核，并在构造/开发决策中实际进入请求。若没有有效对比或卡片全部拒绝，报告NOT_READY，不用fixture冒充真实经验。

冻结每决策注入条目数和字符/字节限制；比较T/E时尽量匹配信息预算并报告实际长度，不声称等长就完全公平。保存查询、检索候选、命中与实际注入摘要，区分库非空/检索非空/请求非空。

交付`experience_readiness.json`、T/E快照及检索接口，JN4只能使用已冻结快照，测试运行中禁止在线更新。

## 9. JN4：未见来源验证与消融

### 9.1 数据准入先于实验

现有来源已用于工程或被暴露，不自动作为严格未见测试。建立来源级train/dev/test清单与暴露记录，按source_order_key分组，同一原始订单、包装变体、相似复制及其分叉不能跨分区。若没有足够独立未见来源，先补充并静态核验新来源；不得仅随机拆16任务宣称独立泛化。

数据补充不按模型好坏反复筛选；冻结长度/异质性分层、已知可满足性及UNKNOWN标签。可在小规模来源做先导，但明确统计能力有限，不把4个来源的变体当大量独立样本。

### 9.2 方法与分析计划

主比较：几何基线、固定顺序基线、Jev无经验、Jev+T、Jev+E。各方法共同使用监测、数据和候选协议；T/E取自相同训练对比，Jev基础提示/模型相同，变化仅为明确注册的记忆输入。

原生概率、输出是否确定以及模型版本变化须记录。配对分析以独立来源为单位，变体嵌套于来源；有重复运行也不能伪造独立订单数。报告逐来源差异、均值/中位数及区间；小样本以描述性结果为主，不强求显著性或事后选检验。

## 10. 公共指标合同

JN0先实现并冻结，后续复用。新指标若依赖未实现分析应标NOT_IMPLEMENTED，不写虚假0值。

| 指标 | 计算与解释 |
|---|---|
| 完整完成率 | 全部计划箱体实际提交的订单比例；稳定完整完成另要求每次开启监测且STABLE |
| 件数/体积/质量装入比例 | 已提交量/完整订单计划量；未到货但计划内箱仍在分母，失败尝试不计 |
| 固定容器利用率 | 已装体积/(L×W×Hmax)，同时报告装入比例；同订单全装满时相同，不能据此声称布局更优 |
| 垛体高度与包络利用率 | 已装体积/(L×W×实际垛高)，空垛定义为NA；与装入量共同解释，避免少装矮垛看似更优 |
| 预测失稳与首次进度 | 证书支持的UNSTABLE停单比例及停前提交进度，不称实际坍塌率 |
| 技术/范围失败与覆盖 | UNASSESSABLE原因、ERROR、接口错误、看门狗、取消、未运行分列；给出选择后可评价覆盖 |
| 承载资源诊断 | 原面积账本的最大容量占用、剩余容量分布；与PCT反力分开。剩余容量简单求和不代表可用空间或未来可装箱数 |
| 长期决策收益 | 固定后续策略的对比分支装入差异；反事实收益仅对注册分支有效，不称最优性差距 |
| 时延与成本 | 决策/请求/监测/整体墙钟分开，p50/p95及样本量，真实请求/失败/不明发送数、实际费用或UNKNOWN |
| 记忆行为 | 有效卡片数、检索/注入命中率、每步长度、训练来源覆盖、生成审核拒绝及成本 |

公共物理违规数仍可作为一致性检查；如硬过滤后恒为0，不作为论文核心优势。空间与承载目标冲突时给配对结果/权衡，不临时调综合权重。

每个新目标提示词必须包含：本规范对应小节/验收ID、父报告与收据、当前身份、允许修改文件/版本、任务/API累计范围、验收、下一接口与停止条件。进入时核对适用AGENTS和工作区，明确“报告声明/代码实现/归档证据/本机复验”，不照抄历史测试数作本次通过。

子目标验收ID是N01—N14的细化，不替换历史编号：JN1由A+B共同支撑N05—N07；JN2由F+G支撑N08—N09；JN3由T+E+C支撑N10—N11及进入验证的判断；JN4由D+V支撑N12—N13；JN5由P支撑N14。任一子目标接口完成不能代替整阶段真实实验完成。

无法满足父门槛时，完成可独立的工程和诊断并交付缺口，不伪造数据/经验/真实调用、不静默扩大实验。费用没有默认上限，任务和调用清单仍须冻结；新窗口不重置已用额度。完成指定子目标后停止，合并执行必须由任务明确指定。
